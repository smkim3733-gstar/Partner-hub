# 한기평 파트너 허브 · Partner Hub

주식회사 한국기업가치평가원의 기업컨설팅 협업 포털입니다. 협업신청부터 기업진단, 반복 상담, 서류요청, 견적·계약, 컨설팅 수행과 사후관리까지 관리합니다.

이 저장소는 **개발 코드와 비식별 기획·검증 자료**의 보관본입니다. 실제 회원·기업·계약·녹취 데이터와 API 키는 포함하지 않습니다. GitHub 업로드는 운영 사이트 배포나 운영 데이터 백업을 의미하지 않습니다.

## 현재 개발 기능

현재 구현과 순차 점검 목록은 [현재 상태 안내](docs/CURRENT_STATUS.md)를 기준으로 봅니다. 날짜별 문서와 아래 선행 검증 수치는 각 단계의 기록입니다.

- 파트너 유형: 한기평 컨설턴트 / 타사 컨설턴트 / 보험설계사 / 기타
- 신규 가입: 이름, 핸드폰번호, 소속, 이메일 아이디, 사이트 전용 비밀번호 → 대표 승인 후 이용
- 이메일·비밀번호 로그인: ChatGPT 계정 없이 이용. **네이버·구글 메일 서비스의 비밀번호를 입력하는 방식이 아닙니다.**
- 기존 파트너: 대표 본인 확인 후 30분 유효 일회용 비밀번호 설정 링크 발급. 관리자 및 기존 ChatGPT 로그인 경로 유지
- 관리자 직접등록·승인·정지·조건부 삭제, 기본 권한과 실제 접속 기록 관리
- 새 협업신청에 사업자등록증, 크레탑, 기타 기업자료와 녹취자료 첨부
- 계정별 신청서 텍스트 임시저장·재접속 복구, 여러 창의 오래된 저장 요청 차단
- 신청 첨부 업로드 재시도 시 브라우저 MIME·한글 파일명 NFC/NFD 차이와 무관하게 기존 원본 재사용, 부분 실패 시 원본 보존
- 신청 첨부 선택 중복은 정규 파일명과 실제 바이트로 판정하고 내용 확인 중 제출을 잠가 메타정보 충돌·선택 경합의 파일 누락 방지
- 대표 전용 원본 보관 현황: 미연결·업로드 대기·삭제 잔여 기록 조회와 원본 존재·크기 확인
- 대표 확인 후 기존 신청에 미연결 원본 회수: 동일 기업·담당 계정·진행번호 대조, 확인 사유 기록과 중복·충돌 차단
- 상담 횟수를 고정하지 않는 상담 기록·예약·서류요청·진행솔루션 관리
- 대표·파트너 각각의 보고서 분석 완료 확인, 반복 상담, 담당자별 진행 공유
- 상담 FLOW 응답 유실 재시도는 정규 파일명과 실제 첨부 바이트로 같은 명령 ID를 유지하고, 내용이 달라지면 새 명령으로 구분
- 1차 진단 근거자료 검토와 생성 전 점검, 승인된 1차·4차 AI 초안 생성 경로
- 상담 녹취자료는 DOCX/TXT 또는 검토한 본문 중심. 음성 원본은 보조 보관
- 2차 보고서·3차 PPT·5차 견적서·6차 경영자문용역계약서 등록과 출력
- 서명본과 약정 계약금 입금 확인을 분리하고, 이후 수행·사후관리로 연결
- 대표 공유 일정, 업무·기한, 비공개 첨부파일과 상담 FLOW 저장
- 기업자료 원본 ID·파일명·크기 조합과 자료 종류별 형식을 검증하고 기존 원본 사실의 일반 저장 변경·삭제 차단
- 새 기업자료 원본 연결은 D1 파일 원장의 파일명·크기·기업·자료종류·담당 계정·진행과 R2 존재를 대조하고 업로드 대기·삭제·불일치 원본 차단
- 포털 기업자료 카드에 연결된 원본은 직접 삭제를 거절하고 D1 삭제 결정과 상태 저장 경쟁에서도 카드·원장·R2를 함께 보존
- 기업자료 다운로드 직전 D1 원장 크기와 R2 실제 객체 크기를 재대조하고 조회 중 변경·손상된 본문 반환 차단
- 상담 FLOW 첨부 다운로드 직전 저장 크기와 R2 실제 객체 크기를 재대조하고 조회 중 파일 변경·손상된 본문 반환 차단
- 상담 FLOW 파일 소유권·객체 증거 원장은 생성 후 수정·삭제를 차단하고, 파일 메타데이터는 원본 사실을 고정한 채 `source`에서 `source_archived`로의 정상 전이만 허용
- 상담 FLOW의 D1 진행·담당·revision 열과 JSON payload를 조회·대시보드 투영 전에 대조하고 불일치·손상 JSON 격리
- 상담 FLOW 저장 전 진행·담당 ID 불변과 revision 1단계 증가를 강제하고 D1·payload 수정시각 불일치 격리
- 상담 FLOW payload의 필수 문자열·배열·객체 최상위 구조를 서버 저장 읽기·SQLite 축소 투영·클라이언트 응답에서 공통 검증
- 상담 FLOW 저장 파일의 목적과 용도별 5MB·8MB·25MB 상한을 업로드·상세·SQLite 축소 전 검사에서 공통 검증
- 상담 FLOW 저장 파일의 확장자·고정 MIME·목적 조합을 업로드 정책·상세·SQLite 축소 전 검사에서 공통 검증
- 상담 FLOW 저장 파일의 R2 키를 `consulting-flow/{파일 ID}`에 결속하고 다른 비공개 객체 참조를 상세·다운로드·SQLite 축소 전 검사에서 차단
- 상담 FLOW 저장 파일명을 업로드와 동일한 NFC·경로 구분자·제어문자·공백·180자 정규형으로 상세·다운로드·SQLite 축소 전에 검증
- 상담 FLOW 파일 ID·R2 키를 D1 소유권 원장으로 진행에 전역 결속하고 교차 진행 복제 참조를 상세·다운로드·SQLite 축소·저장에서 차단
- 상담 FLOW 파일의 이름·고정 MIME·크기·생성시각·현재 용도·원본 유입 증빙을 가산 D1 원장에 결속하고 유효값끼리의 변조도 차단
- 신규 상담 FLOW 파일의 R2 ETag·고정 MIME을 가산 D1 원장에 결속하고 같은 크기 바이트 교체·객체 MIME 변경을 다운로드와 AI 입력 전에 차단
- 신규 기업자료 원본의 R2 ETag·고정 MIME을 가산 D1 원장에 결속하고 같은 크기 바이트 교체·객체 MIME 변경을 다운로드·AI 입력·회수 전에 차단
- 대표 전용 원본 보관 현황에서 본문을 읽지 않고 신규 ETag·MIME 또는 기존 크기·MIME 검증 범위와 객체 무결성 불일치를 구분해 표시
- 원본 보관 목록에서 기업 원본 객체 무결성 원장 누락·MIME 결속 오류를 개별 R2 확인 전 `메타데이터 확인 필요`로 분류
- 기업자료 원본의 정확한 R2 저장 키를 가산 원장에 결속하고 다운로드·AI 입력·회수·재시도·보관 진단 전 교차 객체 참조 차단
- 기업자료 삭제도 정확한 R2 저장 키 원장을 먼저 확인하고 내구성 삭제 결정에서 재검사해 교차 객체 삭제와 검증 직후 키 변경 경쟁 차단
- R2 삭제 뒤 D1 정리도 결정 당시 저장 키가 유지될 때만 수행하고 경합 시 원본 행·무결성·담당 원장과 tombstone 보존
- 기업자료 원본의 파일명·기업·종류·제목·담당 표시·업로더·MIME·크기·생성시각을 가산 D1 원장에 결속하고 유효값끼리 변조도 다운로드·AI 입력·회수·삭제 전에 차단
- 기업자료 전체 메타데이터 원장의 직접 수정과 부모 원본이 남은 선행 삭제를 D1에서 거절하고 정상 부모 삭제의 외래 키 연쇄 정리만 허용
- 기업자료 R2 저장 키·객체 무결성 원장도 직접 수정·선행 삭제를 D1에서 거절하고, 운영 코드의 세 불변 원장 직접 변경 재도입을 정적 차단
- 기업자료 최초 담당 계정·진행 연결 원장도 직접 수정·선행 삭제를 D1에서 거절하고 정상 부모 삭제의 연쇄 정리만 허용
- 기업자료 업로드 멱등 영수증의 식별값과 전진 수명주기를 D1에서 강제하고 삭제 tombstone의 수정·삭제·지연 재시도 부활을 차단
- 기업자료 원본 기본행은 생성 뒤 직접 수정을 D1에서 거절하고 저장 키·전체 메타데이터 재검증을 통과한 정상 부모 삭제만 허용
- 업무·기업자료·일정의 필수 표시값과 상태·분류·공개범위 허용값을 서버·화면에서 공통 검증하고 손상된 운영 상태 격리
- 업무·기업자료·일정의 미존재 진행·담당 계정과 서로 상충하는 담당 연결을 서버·화면에서 공통 차단
- 진행 타임라인의 필수 표시값·선택적 안정 ID·진행 연결을 서버·화면에서 공통 검증하고 안정 ID의 진행 이동·중복 병합 차단
- 새 저장소의 대표 선택형 초기 기준선, 가상 예시를 제외한 운영 지표, 관리자 전용 저장 용량·잠정 경보
- 저장 경로별 익명 충돌 집계와 대표 전용 최근 7일 운영 지표

## 아직 자동화하지 않은 기능

Google Calendar 자동 쓰기/양방향 동기화, 음성 자동전사 서비스, 카카오톡·이메일 자동 발송, 자동 PPT 생성, 전자서명, 은행 입금 자동 확인은 연결 완료로 간주하지 않습니다. 현재는 해당 링크·자료 등록·수동 확인 흐름을 사용합니다.

Claude 프로젝트 웹 화면을 자동 조작하는 구조가 아니라 프로젝트 지침을 반영한 서버 API 경로입니다. API 키, 잔액, 실제 이용 가능한 모델과 기업별 외부 전송·비용 승인은 운영 시 별도 확인이 필요합니다. AI 결과는 대표 검토용 초안이며 정책·세무·법률·보험 판단이나 승인을 보장하지 않습니다.

## 로컬 실행

다른 컴퓨터로 개발을 옮길 때는 [개발 인수인계 안내](docs/CONTINUE_ON_ANOTHER_COMPUTER.md)에서 현재 커밋, 검증 결과, 기존 Sites 배포 대기 상태와 제외해야 할 비밀값을 먼저 확인하세요.

Windows에서 이 작업 폴더를 사용하는 경우 `partner-hub.cmd`를 실행하면 개발 서버가 시작됩니다. Node.js 경로 설정과 검증 명령은 [Windows 로컬 설정 안내](docs/LOCAL_SETUP.md)를 참고하세요.

검증 환경은 Node.js 24 계열이며 프로젝트 엔진 최소값은 Node.js 22.13입니다. 기존 패키지 관리자와 lockfile을 유지합니다.

```sh
pnpm install --frozen-lockfile
pnpm dev
```

개발 서버가 출력하는 Local 주소로 접속합니다. 가입·로그인 화면은 `/account`, 비밀번호 설정 화면은 `/account/setup`입니다. 로컬 Sites 테스트 로그인과 실제 운영 로그인은 구분됩니다. 개발 서버를 인터넷에 그대로 노출하지 마세요.

외부 AI 연결을 시험할 경우 `.dev.vars.example`을 참고해 로컬 전용 `.dev.vars`를 만들거나 실행 환경의 비밀값 관리 기능을 사용합니다. `.dev.vars`와 `.env*`는 Git에 올리지 않습니다. 예시 모델 이름은 프로젝트 설정값이며 실제 계정에서 사용 가능한 모델임을 보장하지 않습니다.

```sh
pnpm test
pnpm typecheck
pnpm build
node tests/password-worker-smoke.mjs
```

마지막 명령은 workerd와 격리 D1 데이터베이스에서 인증을 검증합니다. 실제 계정, 운영 DB, 이메일 또는 유료 AI를 사용하지 않습니다. Windows 보안 환경에 따라 로컬 실행 허용이 필요할 수 있습니다.

`pnpm start`는 빌드 후 로컬 Worker 미리보기를 실행합니다. GitHub Pages용 정적 사이트가 아닙니다. DB/R2와 동적 Worker 경로가 필요합니다.

## 구조

```text
app/                  화면 및 서버 API
components/           업무 화면과 공통 UI
lib/                  상담 FLOW, 권한, 인증, 파일·AI 처리
db/                   D1 테이블 정의
drizzle/              추가형 DB 마이그레이션
tests/                가상 자료 기반 자동 검증
docs/                 기획, 명세, 현황·검증 문서
public/               브랜드 이미지·정적 리소스
.openai/hosting.json   기존 Sites 프로젝트 식별자와 논리 DB/R2 연결명
```

## 운영·보안 주의

- `.openai/hosting.json`은 기존 사이트 연결을 유지하기 위한 메타데이터이며 비밀키가 아닙니다. 다른 사이트로 독립 배포하려면 본인의 호스팅/DB/R2 설정이 필요합니다.
- 운영 데이터는 D1/R2에 별도 저장됩니다. 이 저장소만 복제해도 실제 파트너나 기업자료가 복구되지는 않습니다.
- 비밀번호는 salt를 적용한 scrypt 해시로 별도 보관하며, 세션/일회용 링크 원문은 DB에 저장하지 않습니다.
- 회원 가입과 비밀번호 설정 링크는 이메일·휴대폰 소유권을 자동 검증하지 않습니다. 대표가 **기존에 알고 있는 연락처로 본인을 확인한 후** 승인·전달해야 합니다.
- 이메일·비밀번호 기능과 선행 권한 보완은 2026-08-31 공개 사이트 버전 34에서 배포 완료를 확인했습니다. 실제 파트너 계정의 실사용 파일럿은 별도 확인합니다.
- 로컬 후속 정비에서 공통 UI/hook의 기존 lint 오류 19건을 수정·분류했습니다. 전체 lint, 테스트 81개, 타입검사와 빌드가 통과했습니다. 일부 범용 UI의 검사 오탐에는 해당 줄에만 사유를 적은 예외를 적용했습니다. 당시 검증 범위는 [검증 기록](docs/VALIDATION_2026_08_31.md)을 참고하세요.
- 이어진 권한 점검에서 동명이인 자료 접근·수정 방어를 보완했습니다. 현재 테스트 87개와 격리 Worker/D1/R2 검증 31개가 통과했습니다. 이름만 연결된 자료의 담당자가 모호하면 파트너 접근을 차단하고 대표 확인을 유지합니다. 이 선행 변경은 버전 34에 배포했습니다. 전체 레거시 데이터의 ID 이관은 수행하지 않았습니다. [운영 반영 준비사항](RELEASE_READINESS.md)을 확인하세요.

- 후속 파일 보완은 새 원본파일을 담당 계정 ID에 연결합니다. 대표는 이름·이메일로 공유 계정을 선택하거나 대표 전용으로 보관할 수 있습니다. 회귀 테스트 91개와 격리 Worker 검증 43개를 통과했습니다. 사용 방법과 기존 자료의 제한은 [파일 계정 연결 안내](docs/FILE_ACCOUNT_LINKS_2026_08_31.md)를 참고하세요.

## 문서 읽는 순서

대표는 기업별 자료함의 `원본 보관 현황`에서 미연결 파일과 업로드 대기 기록을 확인할 수 있습니다. [보관 현황 사용 안내](docs/FILE_INVENTORY_2026_08_31.md)와 [기존 신청 원본 회수 안내](docs/FILE_RECOVERY_2026_08_31.md)를 참고하세요. 회수는 대표의 원본 대조·확인 사유·명시적 확인 후에만 수행하며 다른 신청 배정이나 자동 삭제는 하지 않습니다.

신청 첨부가 실패하면 같은 파일·자료정보로 재시도할 수 있습니다. 앞서 저장된 원본을 재사용하고 자동 삭제하지 않습니다. 새로고침 후 재선택과 제외된 첨부의 보관 범위는 [첨부 업로드 재시도 안내](docs/UPLOAD_RETRY_2026_08_31.md)를 확인하세요.

작성 중인 신청은 `신청서 임시저장` 성공 후 같은 계정에서 복구할 수 있습니다. 첨부는 다시 선택하며, 여러 창의 저장 충돌은 덮어쓰지 않고 안내합니다. [임시저장·복구와 충돌 방지 안내](docs/DRAFT_RECOVERY_2026_08_31.md)를 먼저 확인하세요.

신청서의 기업정보·연락처·요청 배경 등을 접수 기록에 저장하고 진행 상세에서 확인할 수 있습니다. 저장 범위와 기존 접수의 호환은 [신청 항목 저장 안내](docs/APPLICATION_DETAILS_2026_08_31.md)를 참고하세요.

신청은 서버 저장 확인 후 완료 안내를 표시하며, 실패하면 열린 화면에서 같은 신청을 다시 저장할 수 있습니다. 새로고침 전 주의사항과 보관 범위는 [저장 확인·재시도 안내](docs/SAVE_RETRY_2026_08_31.md)를 참고하세요.

같은 기업의 새 신청도 별도 진행으로 등록하고, 새 첨부와 요청서류를 신청별로 연결합니다. 기존 자료의 범위와 저장 시 주의사항은 [동일 기업 재신청 안내](docs/REPEAT_APPLICATIONS_2026_08_31.md)를 참고하세요.

진행판·업무목록도 담당 계정 기준으로 정비했습니다. 동명이인 필터, 이름 변경 후 표시, 새 업무의 계정 배정 및 진행 연결 업무의 완료 저장은 [업무 계정 연결 안내](docs/TASK_ACCOUNT_LINKS_2026_08_31.md)를 참고하세요.
