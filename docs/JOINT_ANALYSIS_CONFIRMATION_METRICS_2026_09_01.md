# 1차 공동분석 확인 간격 지표

## 목적

현재 상담 FLOW의 최신 1차 보고서에서 대표와 담당 파트너가 각각 확인한 상태를 대표 대시보드에 제공한다. 이 지표는 두 역할의 독립 확인 순서와 간격을 보여 주는 현재 상태 스냅샷이다. 파트너가 산출물을 대표에게 넘기는 업무 인계나 제품 전체의 대표 승인 대기시간을 뜻하지 않는다.

## 측정 정의

- 대표만 1차 보고서를 등록하며 대표와 파트너는 순서 강제 없이 본인 계정에서 각각 확인한다.
- 현재 운영 상태에 존재하고 가상 예시가 아닌 진행만 집계한다.
- `analysis.reportId`가 FLOW 보고서 배열에서 마지막 1차 보고서 ID와 일치할 때만 현재 보고서 확인으로 인정한다.
- 양쪽 미확인, 파트너만 확인, 대표만 확인, 파트너 선확인 완료, 대표 선확인 완료, 잘못된 시각을 서로 겹치지 않게 분리한다.
- 파트너 확인부터 대표 확인까지의 간격은 두 시각이 모두 유효하고 대표 시각이 같거나 늦은 완료 건에서만 계산한다.
- 유효한 파트너 선확인 완료가 5건 미만이면 시간 구간을 표시하지 않는다.
- 1차 보고서가 개정되면 기존 확인 시각은 현재 보고서 지표에서 제외되므로 과거 누적 승인 이력으로 해석하지 않는다.

## 개인정보와 API 경계

- 새 집계 테이블이나 이벤트 이력을 만들지 않고 기존 FLOW의 서버 기록을 조회 시점에 합산한다.
- 응답에는 회사·진행·파트너·보고서 ID와 개별 시각을 포함하지 않는다.
- 대표의 `/api/state` 응답 최상위에만 요약을 제공하고 저장 상태 원문과 파트너 응답에는 넣지 않는다.
- 기존 신청→첫 상담 지표와 하나의 좁은 `consulting_flows` 조회를 공유한다. 지표 계산 실패는 운영 상태 응답과 FLOW 확인 기능을 바꾸지 않는다.
- 보관·삭제 정책, D1/R2 구조, 공개 범위는 변경하지 않는다.

## 검증 결과

- Node 자동 검사 232개 통과.
- 격리 workerd + 실제 D1/R2 검사 119개 통과.
- 타입검사, lint, 프로덕션 빌드 통과.
- 가상 진행으로 양쪽 미확인·각 역할 단독 확인·두 확인 순서·현재 보고서 불일치·잘못된 시각·가상 예시 제외·삭제된 진행 제외·5건 공개 기준을 확인했다.
- 파트너 응답 및 저장 상태 원문 비노출, 관리자 지표 조회 실패 격리를 확인했다.
- 격리 검증의 외부 요청, 운영 쓰기, 메일 발송, 외부 AI 호출은 0건이다.

## 남은 측정 범위

제품 기획의 `파트너에서 대표로 넘어가는 승인 대기시간`은 일부만 다룬다. 현재 코드에서 실제 인계에 가까운 `서류 수령 → 대표 검토` 흐름은 서류 수령 시각을 저장하지 않아 아직 측정할 수 없다. 이를 측정하려면 서버가 쓰는 `receivedAt`을 새로 추가하고 기존 자료와 레거시 기록의 측정 경계를 별도로 검수해야 한다.

## Duet 검수

Duet가 초기 `인계` 표현이 실제 독립 확인 구조를 잘못 설명한다고 지적해 명칭과 설명을 수정했다. 대표 선확인 대기 상태 누락을 보완하고 모든 상태를 배타적으로 분리했으며, 기존 상담 지표와 FLOW 조회를 공유하도록 구현했다. 네이티브 Windows에서는 고위험 실행에 필요한 샌드박스 검사를 제공할 수 없어 최종 차이 검토 완료 판정은 제한될 수 있다.
