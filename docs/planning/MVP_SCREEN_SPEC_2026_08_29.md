# 한기평 파트너 허브 MVP 화면별 상세기획서

- 문서명: 한기평 파트너 허브 MVP 화면별 상세기획서
- 서비스 가칭: 한기평 파트너 허브(KEVE Partner Hub)
- 작성일: 2026-08-29
- 발주·운영 주체: 주식회사 한국기업가치평가원
- 작성자: 김성민 대표
- 문서 상태: 화면설계 및 개발견적용 1차 확정안

## 1. 핵심 결론

한기평 파트너 허브는 일반 홈페이지가 아니라 다음 세 기능을 결합한 로그인형 업무 시스템으로 구축한다.

1. 교육생·협업 파트너의 기업 협업신청 포털
2. 한기평 내부의 상담·서류·견적·계약 진행관리 시스템
3. 교육생이 본인 사건의 진행상황과 요청사항을 확인하는 협업 대시보드

가장 중요한 설계 원칙은 `고정 진행단계`와 `반복 업무기록`을 분리하는 것이다.

- 진행단계: 접수 → 기업진단·사전검토 → 상담·협의 진행 → 계약 진행 → 업무수행·사후관리 → 종료
- 반복 업무: 상담, 서류요청, 견적서, 계약서, 내부업무

상담은 1차·2차·3차로 고정하지 않는다. 필요한 만큼 `상담 #1, 상담 #2, 상담 #3…`을 무제한 등록한다. 서류요청·견적서·경영자문용역계약서도 특정 단계에 종속하지 않고, 어느 시점에서든 생성할 수 있게 한다.

## 2. MVP 목표와 성공 기준

### 2.1 운영 목표

- 교육생의 협업신청을 누락 없이 접수한다.
- 같은 기업의 중복접수를 관리자가 조기에 발견한다.
- 대표와 내부 담당자가 현재 막혀 있는 업무를 한 화면에서 확인한다.
- 교육생이 전화나 메신저 문의 없이 진행상황을 확인한다.
- 상담·서류·견적·계약의 생성자와 변경이력을 보존한다.
- 기업컨설팅 자료와 보험·CEO 자산관리 자료의 접근권한을 분리한다.

### 2.2 MVP 성공 기준

- 한 신청에서 상담을 10회 이상 등록해도 화면과 데이터 구조가 변하지 않는다.
- 한 상담 후 서류요청·견적서·다음 상담을 동시에 등록할 수 있다.
- 상담과 연결하지 않고도 최초 서류요청이나 견적서·계약서 초안을 만들 수 있다.
- 여러 서비스를 신청한 기업의 서비스별 진행상태를 따로 관리할 수 있다.
- 교육생은 본인이 참여한 사건만 볼 수 있다.
- 모든 중요 변경은 활동 타임라인에 남는다.

## 3. 사용자와 권한

| 역할 | 주요 권한 | 제한사항 |
|---|---|---|
| 대표 관리자 | 전체 조회·배정·승인·상태변경·문서발송·설정 | 없음 |
| 내부 담당자 | 배정 사건 처리, 상담·서류·견적·계약 초안 작성 | 최종 발송·종료는 승인 필요 |
| 교육생·협업 파트너 | 본인 사건 등록·조회, 요청서류 제출, 일정 확인 | 내부 메모·원가·타 교육생 정보 열람 불가 |
| 외부 전문가 | 배정된 서비스 과업과 지정 자료만 조회 | 기업 전체 이력과 타 서비스 열람 불가 |
| 기업대표 | MVP에서는 계정 미제공 | 2단계에서 일회용 보안링크 검토 |

### 3.1 권한 원칙

- 교육생 가입은 `가입신청 → 관리자 승인 → 이용 가능` 순서로 한다.
- 한 사건에는 주관 교육생 1명과 공동 협업자 여러 명을 지정할 수 있다.
- 중복기업 경고와 기존 신청자 정보는 관리자에게만 보인다.
- 메모는 `교육생 공유 메모`와 `내부 전용 메모`를 분리한다.
- 견적서와 계약서는 작성자와 최종 승인자를 분리할 수 있게 한다.
- 보험·CEO 자산관리 서비스는 별도 권한그룹과 문서보관 영역을 사용한다.

## 4. 핵심 데이터 구조

```text
기업 마스터
└─ 협업신청 1~N건
   ├─ 서비스 과업 1~N개
   ├─ 상담 0~N회
   ├─ 서류요청 0~N건
   │  └─ 요청서류 항목 1~N개
   ├─ 견적서 0~N건
   │  └─ 견적 버전 1~N개
   ├─ 계약서 0~N건
   │  └─ 계약 버전 1~N개
   ├─ 내부업무 0~N건
   ├─ 알림 0~N건
   └─ 활동이력
```

### 4.1 기업 마스터

한 기업이 여러 번 협업신청되더라도 기업정보는 하나의 마스터로 관리한다.

주요 필드:

- 기업 고유번호
- 기업명
- 사업자등록번호
- 대표자명
- 개인·법인 구분
- 업종·주요사업
- 소재지
- 설립일
- 홈페이지
- 매출·근로자 수
- 담당자명·연락처
- 개인정보·민감자료 포함 여부
- 최초 등록일·최종 수정일

### 4.2 협업신청

한 기업에서 시기나 목적이 다른 요청이 발생하면 새로운 협업신청을 만든다.

주요 필드:

- 신청번호
- 신청일시
- 신청 교육생
- 주관 교육생
- 공동 협업자
- 기업과의 관계
- 요청 배경
- 긴급도
- 상담 희망시기
- 전체 진행상태
- 내부 담당자
- 중복검토 결과

### 4.3 서비스 과업

한 신청에서 여러 서비스를 선택하면 서비스별 과업을 각각 생성한다.

서비스 유형:

- 기업인증
- 정책자금
- 특허·지식재산
- 영업권 평가·법인전환
- 부동산 프로젝트
- CEO 자산관리
- 보험 법인영업
- 기타 기업컨설팅

각 서비스 과업은 별도의 담당자, 진행단계, 우선순위, 다음 행동, 완료기준을 가진다.

## 5. 진행상태 설계

### 5.1 전체 진행단계

| 코드 | 단계 | 의미 |
|---|---|---|
| S1 | 접수 | 신청이 제출되고 중복·필수항목을 확인하는 단계 |
| S2 | 기업진단·사전검토 | 기업자료 검토와 진단보고서를 준비하는 단계 |
| S3 | 상담·협의 진행 | 상담, 보완자료, 제안과 조건협의를 반복하는 단계 |
| S4 | 계약 진행 | 견적 수락 후 계약 조건과 계약서를 협의하는 단계 |
| S5 | 업무수행·사후관리 | 계약 업무 수행, 산출물, 추가상담, 사후관리 단계 |
| S6 | 종료 | 완료·미계약·취소 등으로 사건이 종료된 상태 |

### 5.2 보조상태

진행단계와 별도로 다음 보조상태를 표시한다.

- 고객 서류 대기
- 교육생 확인 대기
- 내부 검토 대기
- 상담 일정 대기
- 견적 승인 대기
- 계약서 서명 대기
- 보류
- 기한 초과

보조상태는 여러 개가 동시에 존재할 수 있다. 예를 들어 `상담·협의 진행 + 고객 서류 대기 + 견적 승인 대기`가 가능하다.

### 5.3 종료사유

- 계약 완료 후 업무 종료
- 사후관리 종료
- 미계약 종료
- 고객 취소
- 교육생 철회
- 중복접수 병합
- 진행 불가
- 장기보류 종료

종료 시 사유와 승인자를 필수로 기록한다. 기록은 삭제하지 않고 보존한다.

## 7. 화면별 상세기획

## AUTH-01 로그인

### 목적

승인된 교육생과 내부 사용자가 안전하게 로그인한다.

### 화면 구성

- 로고와 서비스명
- 이메일 또는 아이디
- 비밀번호
- 로그인 버튼
- 비밀번호 재설정
- 교육생 가입신청 버튼
- 개인정보처리방침·이용약관 링크

### 처리 규칙

- 승인대기 계정은 로그인 후 `승인대기 안내화면`으로 이동한다.
- 이용정지 계정은 관리자 문의 안내를 표시한다.
- 오류는 입력칸 근처에 표시하고 제출 실패 시 화면 상단 오류요약도 제공한다.
- 로그인 버튼은 처리 중 중복 클릭되지 않게 비활성화한다.

## APP-02 새 협업신청

다단계 입력폼으로 구성하고 상단에 `1/4 신청자 → 2/4 기업 → 3/4 서비스 → 4/4 자료·동의` 진행표시를 제공한다.

### 1단계: 신청자·협업정보

- 신청 교육생 자동입력
- 주관 교육생
- 공동 협업자
- 기업과의 관계
- 소개 경로
- 고객 자료 제출 권한 확인
- 대표에게 전달할 내용

### 2단계: 기업정보

- 기업명
- 사업자등록번호
- 대표자명
- 법인·개인 구분
- 업종·주요사업
- 주소
- 설립일
- 매출액
- 상시근로자 수
- 기업 담당자·연락처
- 홈페이지

사업자등록번호 입력 후 중복검사를 수행한다. 교육생에게는 기존 사건 내용이나 기존 신청자의 개인정보를 노출하지 않고 `관리자 확인이 필요한 기업입니다`라고만 표시한다.

### 3단계: 요청서비스

- 서비스 복수 선택
- 서비스별 요청내용
- 희망 진행시기
- 필요금액 또는 사업규모
- 긴급도
- 현재까지 진행한 내용
- 상담 희망일

서비스 선택 시 서비스별 추가 질문과 권장서류를 펼쳐 보인다.

### 4단계: 자료·동의

- 사업자등록증
- 크레탑 자료
- 재무제표
- 회사소개서
- 인증·특허 자료
- 기타 파일
- 민감정보 마스킹 안내 확인
- 자료제출 권한 확인
- 최종 제출 동의

### 완료 처리

- 제출 후 신청번호를 표시한다.
- 교육생과 관리자에게 접수 알림을 보낸다.
- 관리자가 중복·필수자료를 확인하기 전에는 `접수 검토 중`으로 표시한다.

## CASE-01 기업·사건 상세

### 상단 정보

- 기업명·신청번호
- 주관 교육생·내부 담당자
- 요청 서비스
- 전체 진행단계
- 보조상태
- 다음 행동·담당자·기한
- 최종 업데이트

### 요약 배지

- 상담 횟수
- 미제출 서류 수
- 유효 견적서 상태
- 계약서 상태
- 기한초과 업무 수

### 탭

```text
전체 타임라인 | 서비스 과업 | 상담 | 서류요청 | 견적서 | 계약서 | 내부업무 | 기업자료
```

### 권장 화면 배치

```text

│ A기업 / 신청번호 / 담당자 / 현재단계 / 보조상태             │
├─────────────────────────────────────────────────────────────┤
│ 상담 4회 │ 미제출 2건 │ 견적 검토 중 │ 계약서 미작성        │
├───────────────────────────────┬─────────────────────────────┤
│ 전체 활동 타임라인            │ 빠른 업무 등록             │
│                               │ [상담] [서류요청]          │
```

## CONS-01 상담 목록·상세

### 상담 생성 원칙

- 상담번호는 협업신청 기준으로 자동 증가한다.
- 차수 제한을 두지 않는다.
- 계약 진행이나 사후관리 단계에서도 상담을 추가할 수 있다.
- 한 상담을 여러 서비스 과업과 연결할 수 있다.

### 상담 상태

```text
상담 필요 → 일정 요청 → 일정 확정 → 상담 완료
```

예외 상태:

- 일정 변경
- 상담 취소
- 고객 회신 대기
- 보류

### 입력항목

- 상담번호 자동부여
- 상담 제목·목적
- 관련 서비스 복수 선택
- 상담 요청일
- 후보 일정
- 확정 일정
- 상담방식: 방문·전화·화상·기타
- 장소·회의링크
- 참석자
- 상담 주요내용
- 고객 요구사항
- 확인된 사실
- 미확인 사항
- 상담 결과
- 다음 행동
- 다음 행동 담당자
- 처리기한
- 교육생 공유 메모
- 내부 전용 메모

### 상담완료 후 후속조치

상담 저장 후 다음 버튼을 동시에 여러 개 선택할 수 있다.

```text
[다음 상담 등록]
[서류요청]
[견적서 작성]
[계약서 작성]
[내부업무 등록]
[보류]
[상담 종료]
```

선택한 후속조치는 상담번호와 자동 연결하되 사용자가 연결을 해제하거나 다른 상담으로 변경할 수 있다.

## 9. 알림 설계

### MVP 채널

- 사이트 내 알림
- 이메일 알림

MVP 이메일 알림은 가입된 사용자와 등록된 내부 담당자에게 보낸다. 기업대표 직접 알림·업로드는 별도 동의와 보안링크가 준비되는 2단계에서 적용한다.

### 주요 알림

| 발생조건 | 수신자 |
|---|---|
| 신규 협업신청 | 대표·접수담당자 |
| 접수 승인·보완요청 | 신청 교육생 |
| 새 서류요청 | 교육생·요청대상 |
| 제출기한 임박·초과 | 교육생·담당자 |
| 상담 후보일정 등록 | 교육생 |
| 상담 확정·변경·취소 | 참석자 |
| 견적·계약 승인요청 | 승인권자 |
| 견적·계약 발송 | 교육생·담당자 |
| 7일 이상 미진행 | 담당자·대표 |

알림은 제목만으로 기업명, 해야 할 행동과 기한을 이해할 수 있게 한다. 민감한 자료의 상세내용은 알림에 포함하지 않고 로그인 후 확인하게 한다.

## 10. 보안·개인정보·컴플라이언스

- 주민번호·계좌번호 등 불필요한 개인정보는 수집하지 않는다.
- 크레탑·재무·보험자료는 필요한 범위만 받고 마스킹 안내를 제공한다.
- 업로드 파일은 권한에 따라 조회·다운로드를 제한한다.
- 파일 다운로드, 열람, 교체와 삭제요청 이력을 기록한다.
- 공유링크는 만료시간과 접근권한을 둔다.
- 퇴사·협업종료 계정은 즉시 정지할 수 있어야 한다.
- 기업컨설팅과 보험·CEO 자산관리 자료는 권한과 문서 명의를 분리한다.
- 대외 견적·계약 발송은 최종 승인 후 가능하게 한다.
- 정식 출시 전 개인정보, 신용정보 자료 취급, 보험 모집 관련 문구와 동의절차는 전문가 검토를 거친다.

## 11. UI·접근성 원칙

- 전문성과 신뢰를 강조하는 네이비·블루 계열을 사용한다.
- 대시보드는 고밀도 구조로 설계하되 본문 글자는 16px 이상을 기본으로 한다.
- 버튼과 모바일 터치영역은 최소 44×44px로 한다.
- 상태는 색상만으로 구분하지 않고 상태명과 아이콘을 함께 표시한다.
- 키보드 탐색과 명확한 포커스 표시를 제공한다.
- 다단계 신청폼은 현재 단계와 전체 단계를 표시한다.
- 오류는 해당 입력란 가까이에 표시하고, 제출 실패 시 상단 오류요약도 제공한다.
- 저장·제출·발송 후 성공 또는 실패 결과를 명확히 안내한다.
- 목록과 타임라인에서 기업명·업무명 등 핵심 텍스트를 의미가 사라지도록 잘라내지 않는다.
- PC 1440px·1024px, 태블릿 768px, 모바일 375px에서 가로 스크롤 없이 사용 가능하게 한다.

## 14. 개발 인수기준

아래 항목이 모두 통과되어야 MVP 완료로 판단한다.

1. 한 신청에 상담 10회를 연속 등록할 수 있다.
2. 상담번호가 자동 증가하며 수정·취소해도 기존 번호와 기록이 보존된다.
3. 상담 없이 서류요청·견적서·계약서를 만들 수 있다.
4. 한 상담에서 여러 후속조치를 동시에 생성할 수 있다.
5. 서류요청 한 건 안에서 각 서류의 제출상태를 따로 관리할 수 있다.
6. 견적서와 계약서 수정본이 기존 버전을 덮어쓰지 않는다.
7. 계약서 초안만으로 계약완료 처리되지 않는다.
8. 여러 서비스의 진행상태를 각각 관리할 수 있다.
9. 교육생이 타 교육생 사건과 내부 메모를 볼 수 없다.
10. 중복기업의 기존 신청정보가 교육생에게 노출되지 않는다.
11. 주요 변경이 전체 타임라인과 감사기록에 남는다.
12. PC와 모바일에서 신청·상담·서류제출 핵심 기능을 사용할 수 있다.

- 교육생에게 공개할 상담기록 범위
- 자료 보관·파기 기준
- 사이트 도메인과 최종 서비스명
