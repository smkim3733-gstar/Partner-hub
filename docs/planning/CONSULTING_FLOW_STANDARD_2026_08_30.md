## 1. 핵심 결론

파트너 허브의 업무 흐름과 Claude의 상담FLOW는 하나의 고정 순서로 합치지 않는다. 다음 두 개의 축으로 분리하여 연동한다.

1. **CRM 진행 축**: 접수 → 기업진단보고서 준비 → 상담요청·예약 → 상담 진행 → 계약 → 사후관리
2. **AI 산출물 축**: Step 0 사전가설 → 1차 정밀분석 → 2차 대표브리핑 → 3차 PPT → 4차 심화분석 → 5차 견적서 → 6차 계약서

상담은 필요한 횟수만큼 반복할 수 있고, 서류요청·견적서·계약서는 특정 상담 차수에 고정하지 않는다. 다만 AI 산출물은 승인 게이트와 내용 상속 규칙을 지킨다.

> **핵심 설계 원칙:** 상담 차수는 반복 가능한 `이벤트`이고, 1차~6차는 문서 종류와 승인 상태를 나타내는 `산출물 게이트`이다.

- 대상기업: 기업명, 대표자명, 사업자등록번호, 연락처, 소재지
- 요청 솔루션: 기업인증, 정책자금, 특허, 영업권·법인전환, 부동산, CEO 자산관리, 기타
- 대표의 핵심 요청사항과 희망 일정
- 개인정보 처리 동의, 제3자 제공 동의, 녹취자료 처리 동의

| 신용자료 | CRETOP 기업종합보고서, 신용평가자료 | 신용등급, 차입, 담보, 연체, 재무요약 |
| 재무자료 | 재무제표, 부가세과세표준증명, 원가자료 | 3개년 매출·영업이익·부채·현금흐름 |

### 4.3 접수 보안 게이트

1. 확장자·파일 크기·악성파일 여부를 검사한다.
2. 녹취자료는 당사자 동의 여부를 확인한다.
3. 주민등록번호, 계좌번호, 개인 신용정보는 분석 목적에 불필요한 부분을 마스킹한다.
4. 원본파일과 AI 투입용 마스킹 파일을 분리 보관한다.
5. AI 입력·처리·다운로드 이력을 감사로그에 남긴다.
6. 동의 또는 권한이 확인되지 않은 자료는 AI 분석 큐에 넣지 않는다.

## 5. Step 0~6 산출물 자동화 규칙

### 5.1 Step 0 — 사전가설 보고

**목적:** 자료를 모두 읽은 뒤 1차 보고서 작성 가능 여부와 핵심 가설을 김성민 대표에게 보고한다.

**처리 순서**

1. 파일별 OCR·텍스트 추출·녹취 변환을 수행한다.
2. 기업명, 기간, 금액, 출처 페이지를 포함한 `근거대장`을 만든다.
3. 동일 항목의 자료 간 불일치를 탐지한다.
4. 자료 판독 요약, 핵심 이슈 후보, 요청 솔루션별 1차 가설을 작성한다.
5. 미확보 자료와 확인이 필요한 질문을 제시한다.
6. 파일을 생성하지 않고 대표 승인 대기 상태로 전환한다.

**필수 표시:** 모든 정책자금·인증 판단은 `1차 가설` 또는 `검토 필요`로 표기한다.

### 5.2 1차 — 컨설팅 정밀분석보고서

**형식:** DOCX, 내부 상담 준비용, 문어체 `~한다`.

**표준 구조**

1. 핵심 진단 요약
2. 기업 개요
3. 재무 정밀 분석
4. 신용·부채 구조 분석
5. 비재무 분석
6. 핵심 이슈 도출
7. 컨설팅 매칭 분석
8. 매칭 근거 상세
9. 리스크 및 탈락 위험요소
10. 상담 진단질문 10개
11. 종합 결론 및 권고
12. 별첨: 제공자료, 추가자료, 공식 근거

**자동생성 조건**

- Step 0 승인 완료
- 최소 입력자료 판독 완료
- 근거대장 생성 완료
- 누락·불일치 목록 생성 완료
- 사용자 동의와 접근권한 확인 완료

**자동생성 결과 상태:** 곧바로 고객에게 공개하지 않고 `대표 검토 대기`로 저장한다.

### 5.3 2차 — 대표 브리핑 보고서

**형식:** DOCX, 고객 대면용, 전문 높임말 `~입니다/~합니다`.

- 승인된 1차 보고서를 3분 이내 판단 가능한 7단 구조로 압축한다.
- 정식 표지와 김성민 대표 인사말을 포함한다.
- 표지에는 `2차`라는 표현을 사용하지 않는다.
- 견적, 비용, 수수료, 계약조건을 넣지 않는다.
- 대표 승인 전 파트너 또는 고객에게 공개하지 않는다.

### 5.4 3차 — 대표 브리핑 PPT

**형식:** PPTX, 16:9, 맑은 고딕, 네이비·골드 디자인.

- 승인된 1차 보고서의 목차 순서를 그대로 따른다.
- 표준 13장 매핑을 사용하고 필요하면 16장 내외로 나눈다.
- 수치, 솔루션 우선순위, 핵심질문 10개, 결론을 1차와 일치시킨다.
- 금액·견적·성공보수·계약조건은 모두 제외한다.
- 8개 점검항목 중 하나라도 실패하면 재작성한다.

### 5.5 4차 — 심화분석보고서

**생성 시점:** 특정 상담 차수에 고정하지 않는다. 필요한 상담이 완료되고 핵심질문 답변과 추가자료가 확보되면 생성한다.

- 상담 답변과 추가자료를 근거대장에 추가한다.
- 1차의 보류 분석을 완성한다.
- 1차의 수치·판단이 변경되면 변경 사유와 출처를 명시한다.
- 계약금액은 포함하지 않는다.

### 5.6 5차 — 견적서

**생성 시점:** 1차·2차·3차 등 특정 상담 횟수 뒤로 고정하지 않는다. 어느 상담 뒤든 서비스 범위와 거래조건이 결정되면 대표가 생성 요청할 수 있다.

**필수 전제**

- 견적 요청 또는 대표 승인
- 서비스 범위 확정
- 표준 단가표 최신본 조회
- 고객·계약 주체 확인

**12항목 구조:** 표제부, 고객정보, 견적사유, 서비스 범위, 단가·산출내역, 총액, 결과물, 일정, 지급조건, 제외사항, 유효기간, 기대효과.

부가세 포함·별도 여부를 명확히 표시하고, 유효기간은 기본 30일로 하되 대표가 변경할 수 있게 한다.

### 5.7 6차 — 경영자문용역계약서

**생성 시점:** 상담 횟수와 무관하며, 견적 조건이 수락되고 계약 당사자·범위·대가·일정이 확정된 뒤 생성한다.

- 표준 14개 조항을 사용한다.
- 갑은 위임인인 고객, 을은 수임인인 주식회사 한국기업가치평가원으로 표기한다.
- 견적서의 범위·금액·일정과 계약서가 일치해야 한다.
- 법률·성공보수·분쟁 조항은 필요 시 변호사 검토 상태를 별도로 기록한다.
- 서명 전에는 `계약서 초안`으로 표시한다.

## 6. 상담·서류요청·견적·계약의 유동형 구조

### 6.1 상담 기록

상담은 `1차 상담`, `2차 상담`, `추가상담` 같은 고정 컬럼으로 만들지 않고 `consultation_sessions`에 한 건씩 추가한다.

| 필드 | 설명 |
|---|---|
| `session_no` | 해당 진행 내 자동 순번 |
| `type` | 전화, 화상, 방문, 기타 |
| `scheduled_at` | 예정일시 |
| `started_at`, `ended_at` | 실제 진행시간 |
| `participants` | 참석자 |
| `agenda` | 상담 목적 |
| `result` | 상담 결과 |
| `next_action` | 다음 행동 |
| `related_artifact_id` | 관련 보고서·견적서·계약서 |
| `status` | 예정, 완료, 취소, 연기, 노쇼 |

### 6.2 서류요청

서류요청은 어느 단계·어느 상담 뒤에도 여러 번 만들 수 있다.

- 요청서류명과 요청 사유
- 요청 대상: 기업대표, 파트너, 내부담당자
- 관련 상담·관련 솔루션
- 요청일, 제출기한, 리마인드 일정
- 제출 상태: 요청, 일부제출, 제출완료, 검토완료, 재요청
- 제출파일과 검토 의견

### 6.3 견적과 계약의 연결

하나의 진행에 견적이 여러 번 수정될 수 있으므로 견적서는 버전으로 관리한다. 계약서는 반드시 고객이 수락한 견적 버전과 연결한다.

> `상담 N회 → 견적 v1 → 조건협의 → 상담 N+1회 → 견적 v2 수락 → 계약서 초안 → 서명완료`

## 8. AI 연결 방식

### 8.1 권고 방식

Claude 웹 프로젝트 화면 자체를 웹사이트 백엔드가 직접 호출하는 구조로 만들지 않는다. 운영 시스템에서는 Anthropic API를 호출하고, 상담FLOW 지침을 다음 프롬프트 묶음으로 이식한다.

1. `CORE_RULES`: 한기평 공통 원칙·금지표현·보안·면책
2. `FLOW_STAGE_RULES`: Step 0~6 단계별 입력·출력·승인조건
3. `COMPANY_PROFILE`: 한기평 공식 정보
4. `CASE_EVIDENCE`: 마스킹된 기업자료 근거대장
5. `APPROVED_PARENT`: 직전 승인 산출물
6. `OUTPUT_SCHEMA`: 목차, 표, JSON 메타데이터, 파일 규칙
7. `QA_RULES`: 수치 일치, 비용 노출, 금지표현, 인원 기준 등

Claude 웹 프로젝트의 메모리는 고객 사례가 섞여 있으므로 그대로 복사하지 않고, 공통 운영규칙만 선별하여 버전 관리한다.

### 8.2 1차 보고서 자동생성 파이프라인

`업로드 → 권한·동의 확인 → OCR·녹취변환 → 마스킹 → 자료분류 → 근거대장 → 누락·충돌검사 → Step 0 가설 → 대표 승인 → 1차 DOCX 초안 → QA → 대표 검토 → 파트너 공개`

오류·누락이 있으면 자동생성을 중단하고 `보완 필요` 상태로 전환한다. AI가 읽지 못한 값이나 추론한 값은 사실처럼 확정하지 않는다.

### 8.3 승인 게이트

| 게이트 | 자동화 가능 범위 | 사람의 결정 |
|---|---|---|
| Step 0 | 자료판독·가설 초안 | 1차 착수 승인 |
| 1차 | 보고서 초안·QA | 내용 승인·수정 |
| 2차 | 고객용 요약 초안 | 고객 공개 승인 |
| 3차 | PPT 생성·교차검증 | 발표본 승인 |
| 4차 | 상담답변 통합·심화분석 | 전략 확정 |
| 5차 | 견적서 조립 | 가격·조건 승인 |
| 6차 | 계약서 초안 조립 | 계약·법률 판단·서명 |

## 9. 최신 공식 기준 반영 사항

기존 2026-08-09 매뉴얼의 연구전담요원 기준은 `중소기업 3명, 중견기업 5명`으로 단순화되어 있어 그대로 자동화하면 오류가 발생할 수 있다. 2026-08-30 확인 기준은 다음과 같다.

## 10. 공통 QA 규칙

### 10.1 사실과 수치

- 모든 핵심 수치는 근거대장의 출처파일·페이지와 연결한다.
- 계산은 별도 계산 모듈에서 수행하고 결과와 계산식을 저장한다.
- 불일치 수치는 임의 선택하지 않고 `확인 필요`로 표시한다.
- AI 추론과 원문 사실을 별도 필드로 구분한다.

### 10.2 표현과 컴플라이언스

- `100% 승인`, `무조건 통과`, `확실히`, `보장` 등 단정 표현을 차단한다.
- 정책자금·인증은 기관 심사 결과에 따름을 고지한다.
- 세무·법률은 세무사·변호사 등 전문가 검토 필요성을 명시한다.
- 보험상품 분석·권유 문서는 컨설팅 문서와 분리하고 더베스트금융서비스㈜ 명의 기준을 적용한다.

### 10.3 문서 형식

- 파일명은 `문서명_기업명_YYYY_MM_DD_버전` 규칙을 사용한다.
- DOCX·PPTX 글꼴은 맑은 고딕으로 통일한다.
- DOCX 자동 번호 매기기를 사용하지 않고 번호를 텍스트로 직접 입력한다.
- 표 너비, 페이지 번호, 목차, 금지표현을 자동검사한다.
- 최종 고객 공개 전 사람의 시각검수를 거친다.

## 11. 파트너 화면 공개 범위

파트너는 본인이 신청한 진행만 볼 수 있다.

- 현재 CRM 진행 상태
- 완료된 단계와 다음 예정 행동
- 상담 일정과 완료 여부
- 본인에게 요청된 서류와 제출기한
- 대표 승인 후 공개된 보고서·견적서·계약서
- 수정 요청과 처리 결과

다음 정보는 파트너에게 공개하지 않는다.

- 내부 가설과 민감한 평가 메모
- 다른 파트너의 고객·진행 정보
- 대표 승인 전 문서 초안
- 고객의 불필요한 개인정보와 신용정보 원문
- 내부 단가표와 계약 협상 메모

## 12. MVP 구현 순서

1. 자료 업로드·권한·동의·마스킹
2. 근거대장과 누락자료 목록 생성
3. Step 0 사전가설 화면과 대표 승인
4. 1차 정밀진단보고서 초안 자동생성
5. 반복 상담·서류요청·리마인드
6. 2차·3차·4차 산출물 승인 게이트
7. 버전형 견적서와 연결 계약서
8. 파트너 공개·알림·감사로그
9. 사후관리와 소개·재구매 추적

## 13. 대표 브리핑용 요약

- 웹사이트의 `상담 진행`과 Claude의 `1차~6차 문서 단계`는 서로 다른 축으로 관리한다.
- 상담·서류요청은 횟수 제한 없이 반복 등록한다.
- 견적서와 계약서는 상담 횟수에 묶지 않고 조건 충족 시 생성한다.
- 1차 보고서는 자료 자동판독 후 바로 고객에게 공개하지 않고 대표 승인 게이트를 둔다.
- Claude 웹 프로젝트에 직접 연결하는 대신 API용 통합 지침과 근거대장을 사용한다.
- 기존 매뉴얼의 연구소 인원 기준은 최신 공식 기준으로 수정한다.

## 14. 그래서 지금 무엇을 해야 하는가

다음 개발 단계는 **MVP 1차 자동진단 입력명세**를 확정하는 것이다. 사업자등록증·CRETOP·녹취록을 각각 어떤 필드로 추출하고, 어떤 누락 조건에서 자동생성을 중단하며, Claude API에 어떤 JSON으로 전달할지를 정의해야 한다. 그다음 이 명세를 현재 파트너 허브의 업로드 화면과 `기업진단보고서 준비` 단계에 연결한다.
