# 계정 상태 변경 인증수단 폐기 무결성 경계

2026-09-05 기준. 대표가 파트너 계정을 정지한 뒤 다시 활성화해도 정지 전에 발급된 로그인 세션과 일회용 비밀번호 설정 링크가 되살아나지 않도록 계정 상태 저장 경계를 보완했다.

## 확인한 위험

- 기존 비밀번호 세션은 계정이 정지된 동안 요청마다 차단됐지만 D1 세션 행 자체는 12시간 만료 전까지 남았다.
- 정지 전에 발급된 30분 일회용 설정 링크도 계정 상태 검사로 일시 차단될 뿐 행은 남았다.
- 같은 유효기간 안 계정을 다시 활성화하면 기존 세션이나 설정 링크가 다시 유효해질 수 있었다.
- 계정 상태 저장과 인증수단 폐기가 별도 작업이면 중간 실패 시 계정 상태만 바뀌는 불완전 저장이 가능하다.

## 적용한 경계

- 계정 이메일·로그인 상태 변경과 계정 삭제 시 해당 회원 ID의 기존 비밀번호 세션을 폐기한다.
- `정지` 진입 또는 `정지` 해제, 이메일 변경과 계정 삭제 시 기존 일회용 비밀번호 설정 링크도 폐기한다.
- 승인대기·초대대기 계정의 정상 승인 과정은 아직 전달할 수 있는 설정 링크를 유지한다. 로그인 세션만 상태 전환 시 정리한다.
- 포털 상태 CAS 저장과 대상 세션·설정 링크 삭제를 하나의 D1 `batch` 트랜잭션으로 실행한다.
- 폐기 SQL은 같은 트랜잭션에서 최종 포털 payload가 정확히 저장된 경우에만 실행한다. 경쟁 저장에서 CAS가 실패한 요청은 다른 계정의 인증수단을 지우지 않는다.
- 세션 또는 링크 폐기가 실패하면 포털 상태 저장도 함께 롤백한다. 화면에 성공을 반환하지 않는다.
- 비밀번호 해시 계정은 삭제하지 않는다. 다시 활성화된 파트너는 기존 비밀번호로 새 세션을 발급받을 수 있고, 설정 링크는 대표가 새로 발급해야 한다.

## 검증

- Node 자동 테스트 470개 통과.
- 격리 workerd/D1/R2 검사 147개 통과.
- 정지와 세션·설정 링크 폐기, 재활성화 뒤 재사용 차단, 새 로그인 성공을 실제 격리 D1에서 확인했다.
- 폐기 SQL 실패 시 회원 상태·명단 revision·세션이 모두 이전 상태로 롤백되는지 확인했다.
- 승인대기 계정의 설정 링크가 정상 승인 뒤에도 사용 가능한지 확인했다.
- 타입검사, 전체 lint, 프로덕션 빌드 통과.
- 로컬 운영 빌드에서 `/`, `/account`, `/account/setup` HTTP 200과 화면 보안 헤더를 확인했다.
- 보호 API 3곳은 익명 요청에 HTTP 401과 비공개 캐시·참조정보·MIME 경계를 반환했다.
- 실제 운영 데이터 쓰기, 메일 발송, 유료 AI 호출, 외부 요청은 0건이다.

## 운영 영향

- DB 스키마와 비밀번호 해시, 파트너 권한, 보관·삭제 정책은 변경하지 않는다.
- 기존 회원·세션·설정 링크를 배포 과정에서 일괄 수정하지 않는다. 배포 뒤 대표가 해당 계정의 이메일·상태를 변경하거나 삭제할 때만 대상 회원의 인증수단을 폐기한다.
- 기능 커밋 `71279b1956ee2bc744dc8b78fb030afac908946a`를 GitHub `main`과 Sites 소스에 반영하고 Sites 버전 110 (`appgprj_6a92514801988191b79eb9bd314e3fcd~appgver_74c30c3d8a708191a69ec596f98922b2`)으로 저장했다.
- 현재 공개 운영본은 Sites 버전 107이다. 버전 109는 저장만 되었으며 버전 110으로 대체해 공개 배포하지 않는다. 버전 110은 사용자 명시 승인 전까지 공개 배포하지 않는다.
