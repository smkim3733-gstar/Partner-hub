# 사건 ID 무결성 경계

기준일: 2026-09-05

## 확인한 문제

포털 진행(`cases`)의 ID가 비어 있거나 두 진행에 중복돼도 관리자 일반 상태 저장이 이를 수용했다. 파트너 응답은 본인 진행 ID 집합으로 타임라인을 고르고, 연결 업무·자료·일정은 같은 ID의 첫 진행을 찾아 권한을 판단한다. 따라서 서로 다른 파트너 진행이 같은 ID를 가지면 사건 경계를 확정할 수 없고 타임라인 노출 또는 연결 기록 오판이 가능했다.

## 적용한 경계

- 모든 사건 ID는 공백 없는 문자열이어야 하며 앞뒤 공백을 허용하지 않는다.
- 한 상태 안의 사건 ID는 고유해야 한다.
- 비어 있거나 중복된 사건 ID를 포함한 관리자 일반 저장은 403으로 거절한다.
- 이미 저장된 상태가 이 조건을 위반하면 파트너 조회는 403, 관리자 조회와 일반 저장은 503으로 격리한다.
- 비관리자 상태 투영 함수도 손상 상태 원문을 그대로 반환하지 않고 실패 폐쇄한다.
- 기존 ID 없는 타임라인 항목은 레거시 호환을 위해 유지한다. 이번 경계는 진행 식별자에만 적용한다.

## 검증

- 수정 전 재현: 공백·중복 사건 ID 관리자 저장 200, 중복 사건 상태의 파트너 조회 200과 연결 타임라인 반환.
- 수정 후 신규 회귀검사: 관리자 저장 403, 손상 상태 파트너 403, 관리자 조회·일반 복구 저장 503.
- Node 자동 테스트 512/512 통과.
- 격리 workerd+D1+R2 검사 218/218 통과.
- 타입검사, 전체 lint, 프로덕션 빌드 통과.
- 로컬 프로덕션 `/`, `/account`, `/account/setup` HTTP 200 통과.
- 실제 운영 쓰기, 메일 발송, 유료 AI 요청, 외부 요청 0건.
