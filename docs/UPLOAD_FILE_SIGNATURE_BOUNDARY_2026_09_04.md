# 업로드 실제 파일 형식 보안 경계

## 목적

기업자료와 상담 FLOW 첨부가 파일명 확장자만 통과한 뒤 다른 형식의 내용을 R2에 저장하지 않도록 한다.

## 적용 범위

- PDF, PNG, JPEG, 구형 XLS, DOCX, XLSX, PPTX, MP3, M4A, WAV의 실제 파일 표식을 서버에서 확인한다.
- DOCX, XLSX, PPTX는 ZIP 컨테이너와 `[Content_Types].xml`, 형식별 내부 디렉터리를 함께 확인한다.
- 파일명만 허용 확장자로 바꾼 HTML·텍스트·다른 Office 형식은 R2 저장 전에 HTTP 400으로 차단한다.
- 기업자료는 이미 읽은 바이트를 검증과 저장에 함께 사용하며, 상담 FLOW는 저장 명령 실행 전에 새 첨부를 검증한다.
- TXT와 Markdown은 기존 텍스트 추출·마스킹 검증 경계를 그대로 사용한다.

## 유지한 경계

허용 확장자·파일 크기·개수·동의·인증·담당 계정·권한 재확인, D1/R2 스키마와 보관 정책은 변경하지 않았다. 파일 내용은 외부 서비스에 보내지 않으며 검증 실패 파일은 저장하지 않는다.

## 재발 방지

허용 바이너리 형식의 정상 표식과 위장 파일 차단, OOXML 내부 형식 일치, 텍스트 경로 유지, 두 업로드 라우트의 저장 전 검사 순서를 자동 테스트로 고정했다.

## 검증 결과

- 관련 실제 형식 회귀검사 5개와 업로드 API 회귀검사 통과
- 전체 자동 테스트 444개 통과
- 격리 workerd/D1/R2 검사 129개 통과
- TypeScript 타입검사, 전체 lint, 프로덕션 빌드 통과
- 격리검사 중 운영 쓰기, 메일, 유료 AI, 외부 요청 0건

운영 반영 승인 완료. 검증한 커밋을 GitHub `main`과 기존 공개 Sites에 순차 반영하고 배포 결과를 별도 기록한다.
