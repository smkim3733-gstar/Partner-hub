# 파일 재고 FLOW 완료 예약·영수증 고아 기록 가시성

기준일: 2026-09-07

## 확인한 문제

FLOW 첨부 업로드가 완료되면 `consulting_flow_upload_requests`의 상태가 `ready`로 전진하고 `consulting_flow_upload_completions`에 완료 명령 영수증이 남는다. 두 원장은 삭제할 수 없는 저장 증거이지만, 파일 payload·소유 원장·메타데이터·객체 무결성·체크섬 원장이 모두 사라진 손상 상태에서는 관리자 파일 재고가 두 증거를 조회하지 않았다.

수정 전 회귀 테스트에서 다음 두 ID가 모두 목록과 전체 증명 적용 현황에서 사라졌고 개별 현재 R2 확인은 404를 반환했다.

- `ready` 예약만 남은 파일 ID
- 완료 명령 영수증만 남은 파일 ID

새 단위 회귀는 기존 코드에서 20개 중 19개 통과·1개 실패했고, 증명 불가 건수가 기대한 `+2` 대신 `+0`인 `7 !== 9`를 기록했다.

## 적용한 경계

- `ready` 예약과 완료 영수증의 파일 ID 합집합을 만든다.
- 같은 ID에 소유 원장, 실제 payload 파일 또는 하위 증명 원장이 있으면 기존의 더 구체적인 격리 후보를 우선한다.
- 나머지 고아 기록은 ID당 한 항목만 `inconsistent`·증명 없음으로 표시하고 전체 적용 현황의 `unavailable`에 한 번 포함한다.
- `ready` 예약이 남아 있으면 파일명·목적·크기·사건·생성시각 중 화면 계약에 허용된 값만 사용한다.
- 완료 영수증만 남으면 저장 키나 명령 ID를 추정·노출하지 않고 메타데이터를 `null`로 유지한다.
- 완료 영수증과 `pending` 예약이 함께 남은 비정상 조합도 두 항목으로 중복하지 않고 고아 기록으로 격리한다.
- 개별 현재 R2 확인은 저장 키를 추정하거나 `head`를 호출하기 전에 503으로 닫는다.
- 자동 복구, 삭제, 운영 D1/R2 읽기나 쓰기는 추가하지 않는다.

후보 SQL은 기존 실제 D1의 compound SELECT 항 제한을 유지하도록 새 최상위 후보 분기를 만들지 않고 기존 고아 재고 CTE에 결합했다.
