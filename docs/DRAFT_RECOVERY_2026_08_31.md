# 신청서 임시저장·재접속 복구와 저장 충돌 방지 — 2026-08-31

> 후속 변경: 동일 신청의 첨부를 재선택하면 앞서 업로드한 원본을 재사용하고 부분 실패 때 자동 삭제하지 않도록 보완했다. 현재 원본 보존·재시도 범위는 [첨부 업로드 재시도 안내](UPLOAD_RETRY_2026_08_31.md)를 따른다. 첨부 본문 자동 복원과 미연결 원본 자동 삭제는 포함하지 않는다.

## 사용하는 순서

1. 협업신청을 열면 현재 로그인 계정의 서버 임시저장을 확인한다. 저장본이 있으면 기업정보·신청자·서비스·요청 문구와 작성 단계를 복구한다.
2. 작성 중 `신청서 임시저장`을 누르고 성공 안내를 확인한다. 필수 항목을 아직 채우지 않았거나 사업자번호·날짜를 입력 중이어도 길이 제한 안에서 보관한다. 마지막 저장 이후 수정한 내용은 자동 보관하지 않는다.
3. 같은 계정으로 재접속하여 협업신청을 열면 저장한 텍스트를 이어서 작성한다. 계정당 한 건이며 다른 파트너나 대표 계정의 작성 중인 신청을 불러오지 않는다.
4. 첨부파일은 다시 선택하고 제출 동의를 다시 확인한다. 이전에 첨부를 선택했던 저장본은 파일을 재선택하거나 `첨부 없이 진행하겠습니다`를 명시적으로 선택해야 제출할 수 있다.
5. 제출은 최신 임시저장을 확인한 뒤 파일 업로드와 접수 저장을 진행한다. 성공한 접수의 임시저장만 비우고 접수·타임라인·원본파일은 보존한다. 응답 유실 후에는 같은 신청 ID로 재시도하거나 이미 접수된 신청을 안내하여 중복 생성을 막는다.

`기존 접수를 남기고 새 신청 작성`은 이미 접수된 신청의 임시저장만 비운다. 기존 접수 기록과 원본파일을 삭제하지 않는다.

## 여러 창에서 수정할 때

운영 데이터를 불러올 때 저장 버전을 함께 받고, 저장 요청에서 그 버전을 확인한다. 두 창이 같은 내용에서 출발해 서로 다른 수정을 저장하면 먼저 저장한 변경만 반영하고 다른 요청은 409 충돌 안내를 받는다. 서버의 실제 쓰기에도 조건을 걸어 확인과 저장 사이에 들어온 변경까지 보호한다. 단순 접속 횟수·최근 접속시간은 업무 변경으로 취급하지 않는다.

임시저장도 별도 버전을 사용한다. 다른 창에서 수정하거나 비운 저장본을 오래된 창이 덮어쓰거나 되살릴 수 없다. 최종 접수는 본인 임시저장 ID와 최신 버전이 일치해야 하며, DB가 접수를 기록하는 시점에도 이 조건을 다시 확인한다. 동일 내용 재전송은 이미 저장된 내용을 바꾸지 않을 때만 성공 응답을 허용한다.

충돌이 나면 현재 입력을 남겨 두고 새 탭에서 최신 운영 내용을 확인한다. 신청서는 임시저장 성공을 확인한 뒤 새로고침하여 복구할 수 있다. 임시저장 자체도 충돌한 경우에는 현재 문구를 먼저 별도로 보관하고 최신 저장본과 비교해야 한다. 단순 반복 저장이나 강제 덮어쓰기로 충돌을 없애지 않는다. 일반 업무·일정 등 서로 다른 변경을 자동 병합하는 기능은 포함하지 않는다.

## 보관과 검증 범위

- `0006_application_drafts.sql`은 계정별 임시저장 테이블을 추가한다. 기존 D1/R2 연결·공개 범위·회원·접수·파일을 초기화하거나 이관하지 않는다. 본문을 지운 행에는 이전 ID와 버전을 남겨 오래된 요청의 재생성을 막는다.
- 초안 API는 인증·협업신청 권한·로그인 계정·동일 출처·JSON 형식·요청 크기를 검사한다. 파트너 이름과 담당 ID는 서버 인증 결과로 지정한다. 응답은 비공개·캐시 금지이며 고객 텍스트를 브라우저 영구 저장소에 복제하지 않는다.
- 자동 테스트 128개, 격리 workerd/D1/R2 검증 64개를 통과했다. 본인 계정 복구, 타인 접근 거부, 미완성 입력, 동시 쓰기, 접수 직전 초안 변경, 중복 재시도, 완료 후 정리, 기존 마이그레이션 반복 적용과 자료 보존을 확인했다.
- 운영 고객 데이터 쓰기, 실제 계정 생성, 메일 전송, 유료 AI 호출과 브라우저 클릭 시험은 수행하지 않았다. 격리 Worker의 외부 요청은 0건이다.

서버 임시저장은 **텍스트와 첨부 선택 여부만** 보관한다. 파일 본문·제출 동의는 보관하지 않으며, 저장 버튼 이후 변경한 내용·과거 저장되지 않은 문구를 복구하지 않는다. 업로드 응답 유실 시 미연결 원본 회수, 새로고침 후 파일 복구, 일반 운영 데이터의 자동 충돌 병합은 후속 과제다. 임시저장의 별도 자동 만료·정리 정책도 아직 없다.

선행 운영 소스는 `78d07c7`, 버전 39다. 이번 운영 반영 결과는 Sites 배포 이력과 로컬 `outputs/release/` 완료 기록에 남긴다. 다음 점검은 업로드 응답 유실과 미연결 파일의 안전한 회수 범위부터 진행하며, 운영 자료 삭제나 외부 유료 서비스 연결은 별도 영향 검토를 유지한다.
