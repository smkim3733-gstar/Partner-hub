# 기업자료 등록 입력 안전성

2026-09-03. 사용자의 연속 개발 요청으로 기업자료 등록창의 가상 기업명·자료명 기본값, 이전 등록정보 재사용, 필수 입력 표시와 실제 처리의 불일치를 보완했다.

## 변경

- 기업명과 자료명은 빈 상태로 시작한다. 가상 기업명이나 이전 등록값을 실제 원본의 메타정보로 보내지 않는다.
- 기업명·자료명·자료종류를 업로드 직전에 공백 정리하고 다시 검증한다. 빈 자료명을 자료종류로 자동 대체하지 않는다.
- 기업명 100자, 자료명 150자로 제한한다. 화면과 서버가 공통 검증을 사용하며 서버도 초과 입력을 조용히 잘라 저장하지 않는다.
- 기업명·담당 계정·자료종류·자료명·파일 중 하나라도 바꾸면 제출 권한과 개인정보 마스킹 동의를 해제한다. 변경된 정보로 제출하려면 다시 확인해야 한다.
- 등록 성공 또는 창을 닫은 뒤 기업명·자료명·담당·종류·파일·동의·오류를 안전한 초기값으로 되돌린다. 업로드 실패 시에는 동일 요청 재시도를 위해 현재 입력과 파일을 유지한다.

## 검증 경계

- 자동 테스트 264개, 타입검사, lint, 프로덕션 빌드 통과.
- 공백 정리, 필수값, 허용 자료종류, 화면·서버 길이 제한과 서버 초과 입력 거부를 회귀검증한다.
- 격리 workerd/D1/R2 검사 129개 통과. 실제 쓰기·메일·유료 AI·외부 요청은 0건이다.
- localhost `/` 응답은 HTTP 200이다.
- 기존 자료와 운영 데이터는 다시 쓰지 않는다. DB/R2 스키마, 파일 접근 권한, 보관·삭제 정책도 변경하지 않는다. GitHub 푸시와 공개 Sites 배포는 사용자 승인 전까지 수행하지 않는다. 반영 뒤 결과는 `outputs/release/portal-document-entry-safety-deployment.json`을 기준으로 한다.
