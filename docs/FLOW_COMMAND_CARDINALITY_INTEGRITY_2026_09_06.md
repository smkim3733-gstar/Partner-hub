# 상담 FLOW revision별 명령 개수 무결성

기준일: 2026-09-06

## 보완 내용

한 FLOW revision에 여러 사용자 명령을 함께 넣어 서로 다른 action의 허용 효과·상태 범위를 합칠 수 있던 공백을 차단했다.

- 최초 FLOW 삽입은 사용자 명령 ID를 최대 한 건만 포함한다.
- 후속 revision도 새 사용자 명령 ID를 최대 한 건만 추가한다.
- 정상 API 요청 하나, 멱등 영수증 하나, 감사기록 하나와 업무 상태 변경 하나의 결속을 유지한다.
- 애플리케이션 커밋 검사가 D1 접근 전에 복수 새 명령을 거절한다.
- 추가형 `0069` D1 삽입·갱신 트리거가 앱 경로를 우회한 직접 SQL에도 같은 규칙을 강제한다.
- 기존 명령 이력은 그대로 보존하며, 명령 없는 내부 AI 작업 전이도 영향을 받지 않는다.

## 검증·배포

- 같은 `set_ai_policy` action 두 건을 한 revision에 넣어 다른 모든 명령 증거를 정상으로 구성한 앱·D1 공격을 거절했다.
- 복수 명령이 포함된 최초 직접 삽입과 기존 FLOW 후속 갱신을 모두 거절했다.
