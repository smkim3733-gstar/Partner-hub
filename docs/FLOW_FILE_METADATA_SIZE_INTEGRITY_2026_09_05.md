# 상담 FLOW 파일 목적·크기 무결성 경계

기준일: 2026-09-05

## 확인한 문제

FLOW 업로드 경로는 용도와 형식에 따라 5MB, 8MB, 25MB 상한을 적용했지만 저장 payload 구조 검증은 파일 크기를 0 이상의 안전한 정수로만 확인했다. 손상된 D1 payload의 빈 파일, 비현실적인 크기, 알 수 없는 목적이 상세 응답까지 전달될 수 있었고, 대시보드는 파일 배열을 SQLite에서 제거한 뒤 축소 구조를 검사하므로 같은 손상을 발견하지 못했다.

## 적용한 경계

- 저장 가능한 파일 목적을 `source`, `source_archived`, `report`, `recording`, `transcript`, `requested_document`, `signed_contract`로 고정했다.
- AI 근거자료와 보관본은 8MB, 전사문과 DOCX/TXT 녹취자료는 5MB, 음성·보고서·요청서류·계약서는 25MB 상한을 적용한다.
- 업로드 정책과 저장 구조 검증이 같은 목적별 상한 함수를 사용한다.
- 크기 0, 안전한 정수가 아닌 값, 목적별 상한 초과, 알 수 없는 목적은 저장 FLOW 상세 조회에서 격리한다.
- SQLite 대시보드 투영으로 파일 배열을 제거하기 전에 같은 목적·크기 계약을 검사한다.
- 새 빈 파일은 내용 판독 전에 거절한다.
- 기존 다운로드의 D1 저장 크기와 R2 실제 객체 크기 재대조는 유지한다.
- D1 스키마, R2 원본, 인증·권한, 보관·삭제 정책은 변경하지 않았다.

## 검증

- 빈 보고서, 25MB 초과 보고서, 8MB 초과 보관 근거, 5MB 초과 전사문, 미등록 목적을 상세 조회와 대시보드가 모두 거절한다.
- 실제 workerd+D1에서 25MB를 초과한 저장 보고서 메타데이터를 상세 조회와 SQLite 축소 대시보드가 동일하게 HTTP 503으로 격리한다.
- Node 자동 테스트 590/590 통과.
- 격리 workerd+D1+R2 검사 384/384 통과.
- 타입검사, 전체 lint, 변경 파일 포맷 검사, 프로덕션 빌드 통과.
- 로컬 프로덕션 `/`, `/account`, `/account/setup` HTTP 200과 CSP·`DENY`·`nosniff`·`no-referrer` 확인.
- 실제 운영 쓰기, 메일 발송, 유료 AI 요청, 외부 요청 0건.

## 다음 감사

FLOW 저장 파일의 이름 확장자, 고정 MIME, 목적 조합이 실제 업로드 정책과 일치하는지 확인한다. 손상된 D1 payload가 실행 불가능한 형식이나 위장 MIME을 정상 첨부처럼 상세 응답·다운로드 판단·대시보드에 전달하지 못하도록 공용 등록표와 SQLite 사전 검사를 일치시킨다.
