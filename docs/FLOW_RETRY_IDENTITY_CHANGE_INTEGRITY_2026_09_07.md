# 상담 FLOW 재시도 계정 식별정보 변경 무결성

기준일: 2026-09-07

## 확인한 위험

파트너의 전사문·음성 2슬롯 업로드가 첫 R2 객체만 저장한 채 실패한 뒤 대표가 담당 파트너의 표시명이나 로그인 이메일을 변경하면, 이전 표시·이메일을 이용한 요청이 남은 객체를 저장하거나 새 계정으로 예약 소유권이 잘못 넘어갈 위험이 있다.

## 확인한 현재 경계

- 정상 파트너의 첫 전사문 객체 저장 성공과 두 번째 음성 저장 실패를 결정적으로 재현했다.
- 표시명 변경과 로그인 이메일 변경을 각각 실제 관리자 상태 저장 경로로 적용했다.
- 표시명 변경은 ChatGPT 안정 사용자 ID와 파트너 회원 ID 결속을 유지한다. 정확한 명령 ID·본문·첨부 재시도만 기존 두 파일 ID와 R2 키로 완료된다.
- 로그인 이메일 변경은 기존 ChatGPT 결속을 상태 변경과 같은 D1 저장 단위에서 제거한다. 이전 이메일 요청은 HTTP 403으로 거절되고 R2 `put`을 한 번도 호출하지 않는다.
- 같은 ChatGPT 안정 사용자 ID가 변경된 새 이메일로 다시 확인되면 원래 파트너 회원 ID에 재결속된다. 정확한 재시도는 기존 두 파일 ID와 R2 키를 이용해 완료된다.
- 거절과 재결속 사이에도 FLOW 본문, 기존 전사문 객체 바이트와 두 `pending` 예약의 파일 ID·R2 키·상태는 그대로 유지된다.
- 완료 영수증의 행위자 키는 `member:<회원 ID>`를 유지하고 감사 표시명은 FLOW가 처음 결속한 담당자 이름을 유지한다. 현재 프로필 표시명이나 이메일을 예약 소유권으로 사용하지 않는다.

기존 구현이 요구 경계를 만족해 런타임 코드는 바꾸지 않고 계정 식별정보 변경 회귀 증거를 추가했다. 표시명 변경은 동일 계정의 업무 연속성을 유지하고, 로그인 이메일 변경은 이전 이메일의 미결속 접근을 차단한 뒤 안정 사용자 ID와 새 이메일의 명시적 재확인만 허용한다.
