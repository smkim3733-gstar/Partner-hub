# 상담 FLOW 부분 R2 쓰기 실패 복구 무결성

기준일: 2026-09-06

## 확인한 위험

전사문과 보조 음성을 함께 저장할 때 첫 R2 쓰기는 성공하고 두 번째 쓰기가 실패하면 FLOW 본문은 커밋되지 않지만 일부 객체만 남는다. 이 상태를 일반 500 오류로만 돌려주면 사용자는 안전한 재시도 가능 여부를 알기 어렵고, 잘못된 오류 정리는 이미 예약된 복구 증거를 없앨 수 있다.

## 적용한 경계

- 모든 예약 업로드는 한 함수에서 R2 쓰기와 객체 결속 메타데이터 생성을 수행한다.
- 알 수 없는 저장소 오류는 내부 예외를 노출하지 않고 503과 동일 자료 재시도 안내로 변환한다.
- 두 번째 슬롯 저장 실패 뒤 첫 객체와 두 슬롯의 `pending` 예약을 모두 보존한다.
- 새 명령 ID로 같은 첨부를 재시도하면 기존 파일 ID와 R2 키를 재사용해 두 슬롯을 완성한다.
- FLOW 본문은 두 객체와 D1 결속이 모두 준비되기 전에는 변경하지 않는다.
