# 상담 FLOW 예약 입력 안전성

2026-09-03 기준. 상담 FLOW의 예약 종류와 참석 방식이 업무 단계만으로 자동 확정되지 않도록 보완한 기록이다.

## 확인한 문제

- 상담 종류가 진행 상태에 따라 초회·추가·계약상담 중 하나로 자동 선택됐다.
- 참석 방식은 신규 예약에서도 `파트너 + 김성민 대표`가 첫 항목으로 자동 선택됐다.
- 초회상담 제출 시 화면 선택과 관계없이 참석 방식을 `동반`으로 덮어써 실제 입력과 서버 명령이 달라질 수 있었다.
- 공동분석 전이나 아직 초회상담이 끝나지 않은 단계에도 등록 폼이 보여 서버에서 거절될 입력을 만들 수 있었다.

## 적용한 동작

- 공동분석을 마친 첫 예약은 서버 업무 규칙인 `초회상담·파트너와 김성민 대표 동반`을 읽기 전용으로 명확히 표시한다.
- 첫 예약 뒤에는 상담 종류와 참석 방식을 선택 안내만 보이는 빈 상태로 시작하며 두 항목 모두 직접 선택해야 제출한다.
- 계약상담은 추가서류 검토와 5차·6차 보고서 준비가 끝난 경우에만 선택할 수 있다.
- 공동분석 전 또는 예약된 초회상담을 완료하기 전에는 등록 폼 대신 다음 조건을 안내한다.
- 제출 명령은 화면에서 전달된 상담 종류와 참석 방식을 그대로 사용하며 임의로 덮어쓰지 않는다.
- 기존 서버는 빈 값·임의 값, 중복 초회상담, 잘못된 단계와 초회 단독 참석을 계속 거절한다.

## 운영 경계

- 기존 상담 예약·완료·취소 기록을 변경하거나 재분류하지 않는다.
- 초회상담 동반 규칙, 예약 가능 단계, 참석자별 처리 권한과 일정 겹침 검증은 변경하지 않았다.
- DB/R2 스키마, 인증·권한, 일정 공개범위와 보관 정책은 변경하지 않았다.
- 실제 상담 예약·운영 데이터 쓰기·일정 외부 전송·메일·유료 AI·외부 요청은 검증 중 모두 0건이다.
