# 상담 FLOW 첫 R2 쓰기 실패 복구 무결성

기준일: 2026-09-06

## 확인한 위험

전사문과 보조 음성 두 슬롯을 예약한 뒤 첫 R2 쓰기가 객체 생성 전에 실패하면 R2에는 아무 객체도 없지만 D1에는 두 예약이 남는다. 재시도가 예약을 잃거나 새 키를 만들면 미완료 예약과 실제 파일 연결이 분리될 수 있다.

## 확인한 현재 경계

- 두 슬롯 예약 직후 첫 R2 쓰기 선행 실패를 결정적으로 재현했다.
- 응답은 내부 오류를 숨긴 503과 동일 자료 재시도 안내만 반환한다.
- 기존 FLOW 본문은 변경하지 않고 R2 신규 객체 0개와 두 `pending` 예약을 유지한다.
- 새 명령 ID의 같은 전사문·음성 재시도는 두 예약의 기존 파일 ID와 R2 키를 재사용한다.
- 재시도 완료 뒤 정확히 두 객체가 생성되고 FLOW 녹취 연결은 두 예약 ID와 일치한다.

기존 구현이 요구 경계를 만족해 런타임 코드는 바꾸지 않고 회귀 증거를 추가했다.
