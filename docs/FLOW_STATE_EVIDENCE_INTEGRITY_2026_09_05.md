# 상담 FLOW 상태·시각 증빙 무결성 경계

기준일: 2026-09-05

## 확인한 문제

FLOW 항목 형식과 내부 참조가 정상이더라도 상태와 증빙 시각이 모순될 수 있었다. 완료 상담에 완료시각이 없거나, 서류가 확인 완료인데 수령·검토·확인시각이 없거나, 대기 중 AI 작업에 시작시각이 붙은 상태가 저장되면 대시보드와 운영 메트릭이 실제 진행보다 앞서 표시될 수 있었다.

계약·입금 영역도 서명본 종류, 계약상담 완료, 약정 계약금 충족과 수행 시작시각 사이의 일관성을 저장 경계에서 다시 확인할 필요가 있었다.

## 적용한 경계

- 상담 `completed` 상태는 시작 이후의 완료시각을 반드시 요구한다. 예정·취소 상태에는 완료시각을 허용하지 않는다.
- 서류요청 날짜는 실제 달력 날짜만 허용하고, `requested`·`received`·`needs_fix`·`verified` 상태별 파일·수령·검토·확인 증빙 조합을 강제한다.
- 서류요청 생성·발송·수령·검토·확인시각이 역전되면 거절한다.
- AI 작업 `queued`·`processing`·`blocked`·`failed`·`complete` 상태별 시작·완료·결과 보고서 증빙 조합을 강제한다. 작업 시각 역전도 거절한다.
- 계약일·입금일·후속 점검일은 실제 달력 날짜만 허용한다. 입금일은 서버 기록일보다 미래일 수 없다.
- 계약은 완료된 계약상담과 `signed_contract` 용도의 실제 서명본을 요구한다.
- 약정 계약금이 충족된 경우에만 수행 시작시각이 존재할 수 있고, 충족 시 수행 시작시각이 반드시 존재해야 한다. 사후관리는 수행 시작 이후만 허용한다.
- 대시보드에서 제거되는 AI 작업은 SQLite에서 상태별 증빙 조합을 먼저 검사한다. 계약 서명본 용도도 민감 파일 정보를 제거하기 전에 확인한다.
- 모든 규칙은 상세 읽기, 브라우저 성공 응답, 대시보드 투영과 D1 쓰기 직전에 같은 fail-closed 경계로 적용된다.

## 검증

- 완료시각 없는 완료 상담, 확인시각 없는 확인 완료 서류, 시작시각이 붙은 대기 AI 작업을 상세 조회 전에 거절한다.
- 상태 증빙이 모순된 AI 작업을 저장 함수가 D1 쓰기 전에 거절하고 새 행을 남기지 않는다.
- SQLite 대시보드가 투영에서 제거할 완료 AI 작업에 시작·완료·결과 증빙이 없으면 차단한다.
- 격리 Worker의 실제 D1 경로에서 완료시각 없는 완료 상담을 상세·대시보드 모두 HTTP 503으로 차단하고 복구 뒤 정상 조회가 재개된다.
- Node 자동 테스트 578/578 통과.
- 격리 workerd+D1+R2 검사 367/367 통과.
- 타입검사, 전체 lint, 포맷 검사, 프로덕션 빌드 통과.
- 로컬 프로덕션 `/`, `/account`, `/account/setup` HTTP 200과 CSP·`nosniff`·`no-referrer` 확인.
- 실제 운영 쓰기, 메일 발송, 유료 AI 요청, 외부 요청 0건.
