# 업무·지원요청 상태 변경 확인 안전성

## 문제

업무 카드의 체크 버튼과 지원요청의 `처리 시작` 버튼은 누르는 즉시 `tasks` 상태를 바꾸고 상위 자동저장으로 이어졌다. 잘못 누르면 저장 전 취소할 기회가 없었다. 일반 업무 완료는 오늘 마감·기한 지연 알림에서 제외되며, 지원요청 처리 시작·종료·재개는 서버 응답시각·처리주기·처리시간 지표를 확정한다.

## 변경

- 완료·재개·지원요청 처리 시작은 원본 업무를 바꾸지 않고 확인 초안만 만든다.
- 확인창에서 업무명·기업·업무종류·담당·마감·현재 상태·변경 후 상태와 운영 영향을 확인해야 저장할 수 있다.
- 취소하거나 확인창을 닫으면 초안을 폐기하고 기존 상태를 유지한다.
- 저장 직전 업무 ID·내용·종류·담당 계정·마감·현재 상태·지원요청 주기와 현재 관리자/파트너 역할을 다시 검사한다.
- 확인 초안의 변경 후 상태나 역할을 임의로 바꾸면 적용을 거절한다.
- 파트너가 완료된 지원요청을 다시 열면 `대기`, 관리자가 다시 열면 `진행`이 되는 기존 서버 규칙을 유지한다.
- 지원요청 처리 시작·종료는 확인 저장 뒤 서버가 기존 방식으로 시각과 처리 주체를 기록한다.

## 유지한 운영 경계

- 업무 생성·담당·마감·지원요청 분류와 기존 계정별 접근권한은 변경하지 않았다.
- 지원요청 서버 시각 보호·처리주기·대표 전용 집계·revision/CAS와 DB/R2 스키마·보관 정책은 변경하지 않았다.
- 메일·메신저·외부 알림·유료 AI·외부 API 호출을 추가하지 않았다.
- GitHub 푸시와 공개 Sites 배포는 사용자 승인 전까지 수행하지 않는다.
