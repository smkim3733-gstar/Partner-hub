# 파일 재고 FLOW 영수증 의미 결속

기준일: 2026-09-08

## 문제

완료 FLOW 첨부의 파일·명령 ID, 예약 메타데이터, 영수증 `actorKey`와 `fingerprint`가 모두 맞아도 새 형식 명령 영수증의 표시 행위자 `actor` 또는 동작 `action`만 같은 명령 감사기록과 어긋날 수 있었다.

수정 전 회귀에서는 두 변조가 파일 재고의 정상 증명을 유지해 개별 확인이 R2 객체 `head`까지 1회 진행했다. 영수증 의미가 손상된 상태에서 객체 존재를 신뢰할 수 있는 공백이었다.

## 적용

파일 재고 목록·증명 현황과 개별 현재 R2 확인이 공유하는 완료 영수증 결속에 다음 조건을 추가했다.

- `actor`와 `action`이 있는 새 형식 영수증은 두 필드가 모두 있어야 한다.
- 같은 명령 ID의 감사기록이 정확히 한 건이어야 한다.
- 영수증 `actor`·`action`은 그 감사기록의 표시 행위자·동작과 정확히 같아야 한다.
- 두 의미 필드가 모두 없던 기존 영수증은 레거시 호환 대상으로 유지한다.
- 한 필드만 남거나 새 형식 두 필드 중 하나가 어긋나면 `inconsistent`·증명 없음·`unavailable`로 격리한다.
- 격리된 파일의 개별 확인은 저장 키 추정이나 R2 `head` 전에 503으로 닫는다.
- 위조 표시값, 명령 ID, 영수증 내부 필드, 지문과 저장 키는 응답에 노출하지 않는다.

스키마와 마이그레이션은 바꾸지 않았다. 기존 추가형 98개를 그대로 두고 읽기 검증을 강화했다.
