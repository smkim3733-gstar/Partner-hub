# 상담 FLOW AI 작업 생성 감사 ID 무결성

기준일: 2026-09-06

## 문제·적용

새 작업 수와 생성 감사기록 수는 맞았지만, 작업 ID와 감사 ID가 서로 직접 결속되지 않아 같은 시각·같은 명령 유형의 별도 감사기록으로 작업 생성을 덮을 수 있었다. 이제 새 작업 ID는 정확히 `생성 감사 ID-job` 형식이어야 하며 애플리케이션과 추가형 `0049` D1 트리거가 이 관계를 일대일로 강제한다.

## 감사·보존 경계

- 새 1차 작업은 같은 revision에 추가된 단일 `queue_report1` 감사 ID에서 파생돼야 한다.
- 새 4차 작업은 같은 revision에 추가된 단일 `save_recording` 감사 ID에서 파생돼야 한다.
- 작업·감사의 시각과 유형이 맞더라도 ID가 다르면 저장을 거절한다.
- 기존 작업과 과거 감사기록은 바꾸지 않으며 최초 D1 행의 대기·보류 작업에도 같은 ID 규칙을 적용한다.
- 앱 커밋 우회와 D1 직접 수정 모두 차단하고 기존 행과 운영 자료를 변경하지 않는 추가형 트리거만 설치한다.
