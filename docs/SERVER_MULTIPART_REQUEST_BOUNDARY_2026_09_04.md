# 서버 멀티파트 요청 경계 통합

## 목적

기업자료와 상담 FLOW의 파일 업로드 요청을 공용 멀티파트 스트림 경계에서 처리한다. 잘못된 미디어 유형·본문 크기 선언·멀티파트 framing·FLOW payload가 서버 오류나 저장 시도로 이어지지 않도록 요청 단계에서 차단한다.

## 적용 내용

- `multipart/form-data` 미디어 유형을 대소문자와 정상 매개변수 범위에서만 인식한다.
- `multipart/form-datax`와 일반 텍스트 매개변수에 포함된 문자열은 멀티파트로 인정하지 않는다.
- 숫자가 아닌 `Content-Length`, 허용량을 넘는 선언 크기와 실제 스트림 크기를 거절한다.
- boundary 누락·손상 등 해석할 수 없는 멀티파트 본문을 HTTP 400 오류로 변환한다.
- 상담 FLOW의 멀티파트 `payload`가 손상된 JSON이면 저장·R2 업로드 전에 HTTP 400으로 차단한다.
- 기업자료와 상담 FLOW API의 직접 `.formData()` 호출을 제거하고 공용 경계 재사용을 정적 검사한다.

## 유지한 경계

기업자료의 25MB 파일 제한과 요청 여유분, 상담 FLOW의 31MB 요청 제한, 파일 개수·종류·동의·권한·동일 출처·재확인 규칙은 유지한다. D1/R2 스키마와 보관·삭제 정책도 변경하지 않았다.

## 검증 결과

- 대상 회귀검사 34개 통과
- 전체 자동 테스트 418개 통과
- 격리 workerd/D1/R2 검사 129개 통과
- TypeScript 타입검사, 전체 lint, 프로덕션 빌드 통과
- 로컬 Workers `/` HTTP 200 확인
- 격리검사 중 운영 쓰기, 메일, 유료 AI, 외부 요청 0건

현재 공개 운영본은 Sites 버전 76이다. 이번 멀티파트 경계 변경의 GitHub 푸시와 공개 Sites 배포는 별도 운영 반영 승인 전까지 수행하지 않는다.
