# 대표 대시보드 저장 데이터 연결 점검

2026-09-01. 사용자의 「다음진행」 요청에 따라 이전 가상 화면 점검에서 관찰된 대표 대시보드의 고정 예시 표시를 확인했다. 기존 자동 점검은 일시 중지 상태를 유지하며 신규 기능이나 외부 서비스를 추가하지 않았다.

## 재현한 문제

새 메모리 전용 D1/R2에서 기업·자료·일정이 모두 비어 있는데도 대표 대시보드는 신규 접수 12건, 서류 보완 8건, 이번 주 상담 15건, 계약 검토 4건을 표시했다. 예시 기업 3개와 장기 미진행 수치도 그대로 보였고, 날짜는 2026년 8월 29일로 고정되어 있었다.

목록 버튼은 진행 ID를 전달하지 않고 기존 선택 진행을 여는 코드였다. 또한 이 화면은 실제 연동 상태를 조회하지 않으면서 Google 계정 연결 확인 문구를 표시했다.

## 수정 범위

- 대표 화면에 서버가 허용한 `cases`, `companyDocuments`를 전달해 요약을 계산한다. 집계 근거가 없는 일간 증가·주간 상담·승인 건수는 제거했다.
- 요약 이름과 설명을 접수 단계, 자료함 보완, 상담 전·진행, 계약 진행으로 맞췄다. 자료함 보완은 기업자료함의 요청중·보완필요 항목이며 별도로 저장되는 FLOW 서류 요청 전체를 의미하지 않는다.
- 긴급 표시 또는 저장된 경과일 7일 이상인 진행을 긴급 우선·경과일 순으로 표시한다. 전체 건수를 보여 주고 목록은 최대 5건이며, 항목의 진행 ID로 기존 상세/FLOW 이동 함수를 호출한다.
- 장기 미진행 집계는 현재 진행 단계와 저장된 `idleDays`를 사용한다. 레거시 경과일 계산이나 갱신 정책을 바꾸지 않았다.
- 대표 화면 날짜를 한국시간의 현재 날짜로 표시한다. 빈 요약·일정·주의 목록·장기 미진행에 0건 또는 빈 상태 안내를 표시한다.
- 일정 영역은 저장된 순서의 최대 3건이라는 범위를 명시하고 Google 연결 확인 문구를 사이트 등록 건수로 바꿨다. 외부 캘린더의 실시간 연결을 확인하거나 새로 연결하지 않았다.

권한, DB/R2 저장, 자료 보존, FLOW와 기존 일정 페이지는 수정하지 않았다. 변경한 화면은 대표 대시보드뿐이다.

## 가상 데이터 검증

| 조건 | 수정본 관찰 결과 |
| --- | --- |
| 기업·자료·일정 없음 | 요약 4개가 모두 0, 긴급·장기 미진행 0건, 예시 기업·고정 통계 없음. 빈 일정과 목록 안내가 표시됐다. |
| 가상 진행 5개·자료 상태 4개 | 접수 1 / 자료함 보완 2 / 상담 전·진행 2 / 계약 1로 기대값과 일치했다. 제출완료·검토완료 자료는 보완 건수에서 제외됐다. |
| 긴급 1개·경과일 6/7/8일 | 주의 목록은 3건이며 긴급 항목이 첫 번째였다. 7일과 8일 항목만 장기 집계에 포함되고 6일 항목은 제외됐다. |
| 동일 기업명으로 접수·계약 진행 2개 | 계약 항목을 누르자 `dashboard-case-2`, 기업인증, 계약 단계와 해당 다음 행동이 표시됐다. 첫 접수로 잘못 이동하지 않았다. |
| 일정 1건 | 가상 일정의 날짜·시간·장소와 사이트 등록 1건이 표시됐다. |
| 복귀·화면 | 대표 대시보드로 복귀한 뒤 집계가 유지됐다. 1280px 화면에서 문서 폭 1265px, 오류 알림 0개였다. 이번 변경의 별도 모바일·전체 키보드 검증은 하지 않았다. |

가상 계정과 가상 상태만 사용했으며 실제 고객 자료는 읽거나 변경하지 않았다. 외부 요청 0건, 실제 가입·연락·메일·유료 AI·자료 삭제 0건이다. 로컬 점검 보조 파일과 가상 데이터는 운영 배포에 포함하지 않는다.

## 검증 및 반영 기록

- Node 테스트 183개, 타입검사, lint, 빌드 통과. 변경한 집계와 이동은 위의 가상 화면으로 확인했다. 서버 변경이 없으므로 기존 110개 저장소 회귀검증은 반복하지 않았다.
- `outputs/validation/admin-dashboard-before.json`, `admin-dashboard-seed.json`, `admin-dashboard-runtime.json`, `admin-dashboard-results.json`에 환경·준비 자료·확인 결과를 구분한다. 자동 검사 로그는 `admin-dashboard-tests.log`, 빌드 로그는 `admin-dashboard-build.log`다.
- 기존 사이트의 공개 범위와 DB/R2 연결을 유지한다. 확정 배포 결과는 `outputs/release/admin-dashboard-deployment.json`을 기준으로 한다.
- 실제 파트너·대표 SSO 실사용, 전체 화면·전체 FLOW 분기·모바일·키보드 접근성 검증 완료로 해석하지 않는다. 자동 실행은 재개하지 않았다.
