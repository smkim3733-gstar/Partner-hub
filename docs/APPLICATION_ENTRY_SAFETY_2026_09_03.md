# 협업신청 핵심 입력 안전성

2026-09-03. 사용자의 연속 개발 요청으로 새 협업신청의 요청서비스 자동 선택, 신청자 유형 변경 뒤 남는 자료제출 동의, 화면과 임시저장의 길이 제한 불일치를 보완했다.

## 변경

- 새 신청과 임시저장 비우기 뒤 요청서비스는 선택되지 않은 상태로 시작한다. `정책자금`이나 일반 서비스명을 사용자가 확인하지 않은 신청에 자동 기록하지 않는다.
- 신청자 이름·기업명·요청서비스를 단계 이동과 최종 제출 직전에 같은 공용 함수로 정규화하고 검증한다. 신청자 이름 80자, 기업명 100자 제한을 화면과 임시저장 규칙에 맞춘다.
- 요청서비스는 허용 목록에서 한 개 이상 직접 선택해야 한다. 중복 값은 최종 제출 전에 한 번으로 정리하고 임의 서비스 값은 거부한다.
- 신청자 유형을 바꾸면 기존 자료제출·녹취 공유 동의를 해제한다. 신청자 이름·자료 공유 계정·기업명 변경에 적용하던 기존 동의 초기화도 유지한다.
- 빈 기업명은 `신규기업`, 빈 서비스는 `기업컨설팅`으로 대체하지 않는다. 최종 진행과 첨부에는 검증된 신청자 이름·기업명·서비스만 사용한다.
- 서버에서 복구한 기존 임시저장의 선택값은 자동으로 지우거나 바꾸지 않는다. 새 신청의 초기 상태와 사용자가 명시적으로 임시저장을 비운 경우에만 선택을 비운다.

## 검증 경계

- 자동 테스트 270개, 타입검사, lint, 프로덕션 빌드 통과.
- 신규 서비스 무선택 상태, 단계별 필수값·길이, 공백 정리, 중복 서비스 정리와 임의 서비스 거부를 회귀검증한다.
- 기존 계정별 임시저장·동시 수정·응답 유실 재시도 검증도 함께 통과했다.
- 격리 workerd/D1/R2 검사 129개 통과. 실제 쓰기·메일·유료 AI·외부 요청은 0건이다.
- localhost `/` 응답은 HTTP 200이다.
- 기존 신청·임시저장·운영 데이터는 다시 쓰지 않는다. DB/R2 스키마, 인증·권한·보관 정책도 변경하지 않는다. GitHub 푸시와 공개 Sites 배포는 사용자 승인 전까지 수행하지 않는다. 반영 뒤 결과는 `outputs/release/application-entry-safety-deployment.json`을 기준으로 한다.
