# 첨부 업로드 재시도·원본 보존 — 2026-08-31

> 후속 변경: 대표 자료함에 [원본 보관 현황](FILE_INVENTORY_2026_08_31.md)을 추가했다. 미연결·업로드 대기·삭제 잔여 기록을 조회하고 원본 존재를 확인할 수 있다. 아래의 목록 미구현 설명은 선행 버전 기록이며 자동 삭제·보관 기간 정책은 여전히 적용하지 않는다.

## 사용하는 방법

협업신청 제출 중 업로드 오류가 나면 **같은 파일과 자료정보를 유지한 채 다시 제출**한다. 서버는 계정별 업로드 요청과 파일 내용·기업명·자료종류·담당 계정·진행 연결을 확인하여 앞서 저장한 파일 ID와 결과를 재사용한다. 여러 첨부 중 뒤쪽 파일이 실패해도 앞서 저장한 원본을 자동 삭제하지 않는다.

임시저장을 복구한 신청에서는 같은 첨부를 다시 선택하고 제출 동의를 다시 확인한다. 같은 신청 ID·파일 이름·내용·자료정보가 유지되면 이전 업로드를 찾아 재사용한다. 파일 본문을 브라우저에 영구 보관하거나 자동 복원하는 기능은 아니다. 다른 파일이나 변경된 자료정보는 별도 업로드로 취급한다.

일반 자료함 업로드도 열린 화면에서 선택한 같은 파일과 자료정보로 재시도하면 기존 결과를 재사용한다. 일반 자료함에서 새로고침하거나 파일을 새로 선택하여 시작한 등록은 별도 요청이다. 다른 신청이나 의도적인 새 등록까지 모두 같은 파일로 합치지 않는다.

## 보호하는 내용

- 서버에 계정별 요청 기록을 먼저 만들고, 재시도는 같은 비공개 저장 경로를 사용한다. 같은 요청 식별값에 다른 파일 내용이나 자료정보를 보내면 409로 거부한다. 동시 재시도도 하나의 원본과 메타데이터에 모인다.
- 원본 저장 직후 응답이 유실되거나 DB 저장 응답이 불확실해도 원본을 삭제하여 되돌리지 않는다. 같은 요청으로 다시 실행해 저장 상태를 확인한다. 로그인 계정이 바뀐 요청은 업로드 전에 차단한다.
- 권한을 확인한 명시적 삭제는 요청 기록에 삭제 상태를 먼저 남긴다. 오래된 업로드 재시도가 삭제된 원본과 메타데이터를 되살리지 못한다. 삭제 중 실패한 원본의 다운로드와 새 업로드 재시도도 차단하고 삭제를 다시 실행할 수 있게 한다.
- 이번 변경 이후 새 신청에 업로드한 파일은 최종 접수의 자료 목록에 실제 연결되어야 상담·AI 입력 검토 목록에 나타난다. 부분 실패 후 사용자가 제외한 첨부나 미완료 신청의 원본을 자동으로 검토 대상으로 섞지 않는다. 검토 미리보기 API도 같은 조건을 적용한다.
- 기존 파일의 계정·진행 연결과 레거시 자료 규칙을 유지한다. 기존 원본을 지우거나 담당 계정을 일괄 이관하지 않는다. AI 분석, 외부 전송과 비용 승인을 자동 실행하지 않는다.

## 검증과 운영 범위

전체 lint·타입검사·자동 테스트 137개와 격리 workerd/D1/R2 검증 71개를 통과했다. 원본 저장 직후 응답 유실, DB 저장 전 실패와 저장 후 응답 유실, 여러 파일 중 일부 실패, 동시 재시도, 타인 접근, 삭제 중 지연 업로드, 최종 접수에서 제외한 첨부의 검토 차단을 재현했다. 실제 고객 자료·계정·메일·유료 AI를 사용하지 않았으며 격리 Worker의 외부 요청은 0건이다. 브라우저 클릭 시험은 수행하지 않았다.

`0007_file_upload_requests.sql`은 요청 기록 테이블을 추가하는 마이그레이션이다. 기존 DB/R2 연결과 공개 범위를 보존한다. 삭제된 원본의 요청 기록은 늦은 재시도를 막기 위해 유지한다.

선행 운영 소스는 `77e0ea5`, 버전 40이다. 이번 운영 반영 결과는 Sites 배포 이력과 로컬 `outputs/release/` 완료 기록에 남긴다.

## 남아 있는 제한과 다음 점검

이전 버전에서 이미 중복 업로드되었거나 연결되지 않은 원본은 자동 복구·삭제하지 않는다. 요청 식별값을 보내지 않는 이전 화면의 업로드 재시도도 중복 방지를 보장하지 않는다. 업데이트 후 새로 연 화면에서 사용한다.
