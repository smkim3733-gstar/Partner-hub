# 상담 FLOW 입금 확인 효과 무결성

기준일: 2026-09-06

## 문제

`confirm_payment` 명령은 계약 뒤 입금 내역을 한 건 추가했지만, 기존 저장 경계는 추가 개수와 명령 기반 ID만 확인했다. 따라서 결제 확인자를 다른 파트너로 바꾸거나, 기록시각·컨설팅 수행 시작시각·감사문구를 정상 형식의 다른 값으로 위조해도 저장될 수 있었다. 실패 우선 검사로 확인자 위조를 재현한 뒤 애플리케이션과 D1에 같은 결제 효과 계약을 추가했다.

## 적용한 경계

- 입금 확인은 계약이 존재하는 상태에서 안정 관리자 신원 `admin:primary`만 수행할 수 있다.
- 기존 입금 배열은 길이·순서·내용을 그대로 보존하고, 이번 명령 ID에 결속된 입금 정확히 한 건만 뒤에 추가한다.
- 새 입금 객체는 `id`, `amountWon`, `receivedAt`, `reference`, `confirmedBy`, `recordedAt` 여섯 필드만 허용한다.
- 입금액은 1원 이상 1조원 이하 정수, 입금일은 정상 달력 날짜이며 서버 수정시각의 한국시간 날짜보다 미래일 수 없다.
- 입금 참조문구는 앞뒤 공백 없는 비어 있지 않은 200자 이하 정규 문자열로 고정한다.
- 확인자는 `김성민 대표`, 기록시각은 해당 revision의 서버 수정시각과 정확히 같아야 한다.
- 누적 입금액이 약정 계약금에 처음 도달하면 수행 시작시각을 서버 수정시각으로 한 번만 기록한다.
- 수행이 이미 시작된 뒤 추가 입금이 생겨도 최초 수행 시작시각은 바꿀 수 없다.
- 누적 입금액에 따라 감사문구를 `계약금 일부 입금 확인 · 잔액 대기` 또는 `약정 계약금 입금 확인 완료 · 컨설팅 수행 시작`으로 정확히 결속한다.

애플리케이션 커밋 검사와 추가형 `0090_consulting_flow_confirm_payment_effect.sql` D1 트리거가 같은 효과를 독립적으로 강제한다. 기존 저장 계약·입금 기록은 변경하지 않고 이후 revision에 새로 추가되는 입금 확인 명령만 검사한다.
