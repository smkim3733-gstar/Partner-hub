# 상담 FLOW 재시도 담당 진행 권한 회수 무결성

기준일: 2026-09-07

## 확인한 위험

파트너의 전사문·음성 2슬롯 업로드가 첫 R2 객체만 저장한 채 실패한 뒤 대표가 `ownCases` 권한을 회수하면, 기존 ChatGPT 계정 결속이나 미완료 업로드 예약만으로 남은 객체를 저장하고 상담 FLOW를 변경할 위험이 있다.

## 확인한 현재 경계

- 정상 파트너의 첫 전사문 객체 저장 성공과 두 번째 음성 저장 실패를 결정적으로 재현했다.
- `ownCases` 권한 회수와 복구를 실제 관리자 상태 저장 경로로 적용했다.
- 권한 변경은 안정 ChatGPT 사용자 ID와 파트너 회원 ID 결속을 제거하지 않는다. 결속 유지가 업무 접근 권한을 대신하지 않음을 별도로 확인했다.
- 회수 뒤 원래 명령 ID·본문·첨부의 정확한 재시도도 HTTP 403으로 거절되고 R2 `put`을 한 번도 호출하지 않는다.
- 거절 중 FLOW 본문, 기존 전사문 객체 바이트와 두 `pending` 예약의 파일 ID·R2 키·상태는 그대로 유지된다.
- `ownCases` 권한 복구 뒤에만 정확한 재시도가 기존 두 파일 ID와 R2 키를 이용해 완료된다.
- 완료 영수증의 행위자 키는 `member:<회원 ID>`를 유지한다. 로그인 이메일이나 권한 상태를 예약 소유권으로 사용하지 않는다.

기존 구현이 요구 경계를 만족해 런타임 코드는 바꾸지 않고 권한 회수 회귀 증거를 추가했다. 같은 검사에서 계정 정지와 `fileUpload` 회수도 실제 관리자 상태 저장 경로를 통과하도록 강화했다.
