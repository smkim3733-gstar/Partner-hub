# 파트너 접속 통계 D1 전이 무결성 경계

기준일: 2026-09-05

## 문제

파트너 접속 통계의 정상 애플리케이션 쓰기는 30분 비활동 기준으로 같은 세션의 최근 접속시각만 전진시키거나 새 세션 수를 정확히 1 증가시킨다. 하지만 D1 직접 SQL은 통계 행을 다른 계정 ID로 옮기고, 누적 횟수를 감소·점프시키거나, 최근 접속시각을 과거 또는 잘못된 값으로 바꿀 수 있었다. 대표 화면이 잘못된 접속 이력을 정상 통계처럼 표시할 수 있는 저장소 계약 공백이었다.

## 적용

- `0032_portal_login_stats_transition_envelope.sql`과 런타임 준비에 삽입·신원 불변·수정 전이 트리거를 추가했다.
- 신규 행은 공백 없는 계정 ID, 정상 UTC 밀리초 시각, 최초 접속 횟수 1만 허용한다.
- 기존 행의 계정 ID는 변경할 수 없다.
- 같은 접속 세션에서는 누적 횟수를 유지하면서 최근 접속시각만 같거나 이후로 전진할 수 있다.
- 새 접속 세션은 기존 시각에서 30분 이상 지난 시각과 누적 횟수의 정확한 `+1`을 함께 저장해야 한다.
- 누적 횟수는 1 이상의 JavaScript 안전 정수 범위만 허용한다.
- 통계 삭제·보존 정책은 변경하지 않았다. 애플리케이션에는 삭제 경로가 없으며, 향후 개인정보·운영 보존 정책이 확정되기 전 D1 삭제 자체를 새로 차단하지 않는다.
- 정상 쓰기는 `lib/portal-state.ts` 한 곳뿐이며 정적 회귀검사가 다른 직접 작성 경로의 추가를 차단한다.

## 검증

- D1 직접 계정 ID 재지정, 잘못된 시각, 시간 후퇴, 횟수 감소·점프, 30분 전 조기 증가가 모두 거절된다.
- 각 거절 뒤 원래 계정 ID·최근 접속시각·누적 접속 세션 수가 그대로 보존된다.
- 같은 세션의 반복 조회는 횟수 1을 유지하고, 30분 이상 지난 격리 행은 다음 정상 조회에서 정확히 2로 증가한다.
- 통계 트리거 장애가 인증된 파트너의 운영정보 조회를 막지 않는 기존 가용성 경계도 유지한다.
- 33개 추가형 마이그레이션을 기존 운영 상태가 있는 격리 D1에 두 번 적용해도 기존 상태를 교체하지 않는다.
- Node 회귀 검사 635/635 통과
- 격리 workerd/D1/R2 검사 444/444 통과
- 타입검사, 전체 lint, 변경 파일 포맷, 프로덕션 빌드 통과
- 로컬 운영 Worker `/`, `/account`, `/account/setup` HTTP 200과 CSP, `X-Frame-Options: DENY`, `nosniff`, `no-referrer` 확인
- 실제 운영 쓰기, 이메일 발송, 유료 AI 요청, 외부 요청 0건
