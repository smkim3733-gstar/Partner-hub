# 기업자료 업로드 응답 멱등 반영 안전성

> 2026-09-05 보완: 화면의 동일 업로드 응답은 계속 한 건으로 반영하지만, 서버 상태 요청 안의 중복 업무·기업자료·일정 ID를 마지막 항목으로 합치는 동작은 [포털 레코드 ID 무결성 경계](PORTAL_RECORD_ID_INTEGRITY_2026_09_05.md)에서 403 거절로 강화했다.

## 문제

기업 원본 업로드 서버는 같은 요청을 재시도하면 저장된 파일 ID를 재사용하지만, 화면은 성공 응답마다 새 자료 카드를 앞에 추가했다. 빠른 이중 실행이나 응답 유실 복구가 겹치면 같은 `storageFileId`를 가진 카드가 중복되고, 이후 파트너 상태 저장에도 동일 ID 신규 기록이 여러 건 들어갈 수 있었다.

## 변경

- 서버가 확정한 파일 ID·파일명·크기·자료종류·담당 계정을 하나의 자료 카드 변환 함수에서 사용한다.
- 자료 카드 ID를 `file-${stored.id}`로 고정하고 자료 ID와 보안 원본 ID를 함께 대조한다.
- 같은 원본의 성공 응답이 다시 도착하면 기존 카드 배열을 그대로 유지한다. 이미 `검토완료` 등으로 바뀐 화면 상태도 `제출완료`로 되돌리지 않는다.
- 자료 ID 또는 원본 ID가 서로 다른 카드와 충돌하거나 기존 중복이 발견되면 덮어쓰지 않고 최신 자료함 확인을 요구한다.
- 파트너 저장 병합은 신규 기록을 ID별로 먼저 정리해 한 요청 안의 같은 ID를 마지막 제출 1건으로 합친다. 기존 저장소의 중복 기록은 자동 이관하거나 삭제하지 않는다.

## 유지한 운영 경계

- 서버 업로드 재시도 키, 원본 R2 객체, D1 메타데이터, 자료 검토 상태 규칙과 revision/CAS 저장 경계를 유지한다.
- 기존 자료·원본·레거시 중복을 수정하거나 삭제하지 않았다.
- 인증·권한·보관 정책, 외부 발송, 유료 AI 경로를 변경하지 않았다.
- GitHub 푸시와 공개 Sites 배포는 사용자 승인 전까지 수행하지 않는다.
