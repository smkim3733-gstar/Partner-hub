# 비밀번호 설정 링크 응답 검증 안전성

2026-09-04 기준으로 대표가 파트너의 일회용 비밀번호 설정 링크를 발급한 뒤 사용하는 API 응답의 클라이언트 검증을 보강했다.

## 변경 범위

- 링크 발급 응답을 `unknown`으로 읽고 일반 JSON 객체인지 먼저 확인한다.
- HTTP 201 성공 상태를 요구한다.
- 경로는 `/account/setup#token=`으로 시작하는 동일 출처 상대 경로와 64자리 소문자 16진수 토큰만 허용한다.
- 토큰이 쿼리 문자열·외부 주소·다른 페이지로 들어가거나 대문자·잘못된 길이인 응답을 거절한다.
- 만료시각은 안전한 정수이며 응답을 읽는 현재시각보다 뒤, 최대 31분 안인지 확인한다.
- 검증된 경로와 만료시각만 새 객체로 반환한다. 이메일·계정정보 등 알 수 없는 응답 필드는 화면 상태로 전달하지 않는다.
- 실패 응답은 길이가 제한된 서버 오류만 유지한다. 비-JSON 또는 손상된 성공 응답은 계정 상태 확인 후 재시도를 안내한다.

## 유지한 안전 경계

- 서버의 대표 관리자 인증, 명시적 본인 확인, 활성 계정·이메일 검사와 발급 속도 제한은 변경하지 않았다.
- 새 링크 발급 시 이전 미사용 링크 만료, 30분 유효기간, 단일 사용, 비밀번호 설정 뒤 기존 세션 폐기를 유지한다.
- fragment 토큰을 HTTP 요청·접근 로그·Referer에 싣지 않고 자동 이메일을 보내지 않는 방식을 유지한다.
- 실제 계정, 운영 데이터, D1/R2 스키마, 권한·보관 정책과 공개 배포 상태를 변경하지 않았다.

- 자동 테스트 395개
- 격리 workerd/D1/R2 검사 129개
- TypeScript 타입검사, 전체 lint, 프로덕션 빌드
