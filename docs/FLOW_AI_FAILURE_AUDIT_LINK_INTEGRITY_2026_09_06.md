# 상담 FLOW AI 실패 증거·감사기록 결속

기준일: 2026-09-06

## 문제·적용

공급자 실패 증거에 UTC 관측시각이 있어도 해당 실패 상태를 저장한 `ai_result` 감사기록과 직접 연결되지 않았다. 직접 저장된 payload가 증거만 복제하거나 감사기록을 바꾸면 개별 실패의 처리 이력을 신뢰하기 어려웠다. 이제 서버가 실패 저장 시 감사 ID를 증거에 함께 부여하고 현재·과거 실패 증거마다 정확히 하나의 자동생성 결과 기록을 요구한다.

## 저장·검증 경계

- 공급자 응답 처리기는 외부 관측 사실만 만들고, 영속 저장 함수가 작업 ID와 실패 저장시각으로 감사 ID를 생성한다.
- 연결된 감사기록은 같은 작업 ID·감사시각으로 만든 ID, `보고서 자동생성` 실행자와 `ai_result` 동작을 모두 만족해야 한다.
- 감사시각은 공급자 관측시각 이상, FLOW 최종 수정시각 이하여야 한다.
- 한 작업의 현재 증거와 실패 이력은 같은 감사 ID를 재사용할 수 없다.
- 상세 조회의 전체 구조 검사와 대시보드의 별도 D1 검사 쿼리가 누락·동작 변조·중복 연결을 실패 폐쇄한다. D1 표현식 깊이 한계를 피하도록 증거 형식 검사와 감사 결속 검사를 분리했다.
- 파트너 응답은 추가된 감사 ID도 허용 키로 명시 선택하며 미래 중첩 필드는 노출하지 않는다.
