# Next.js 이전: 서버 전용 R2 연결

## 범위와 운영 경계

2026-09-08 서버 측 파일 읽기·메타데이터 조회·조건부 저장·삭제를 인증된 HTTP 연결로 구현했습니다. AI 원본 읽기, 신청자료 검토본 복사, 보관 현황·회수 사전 점검은 기존 업무 처리기와 원장 검증을 그대로 사용합니다. 브라우저 대용량 전송과는 별도 경로입니다.

격리된 로컬 Next 및 네이티브 Worker 검사에 이어, 명시적 원격 연결 후보에서도 HTTPS 동작을 검증했습니다. [독립 운영 연결 설정](NEXT_REMOTE_BACKEND.md)을 참고하세요. 실제 Cloudflare 계정 연결, 원본 내보내기·이관, Vercel 배포는 하지 않았습니다. 기본 미연결 Next 업무 API는 계속 `503`으로 차단하며 기존 Sites 운영 경로와 99개 SQL 이력을 보존합니다. Duet/Claude 호출도 없습니다.

## 연결과 보안

- Next의 기존 업무 처리기 → `lib/r2-http-client.next.ts` → HTTPS `POST /internal/r2/v1/object` → `infra/r2-bridge/worker.ts` → 비공개 R2.
- `server-only` 진입점은 브라우저 사용과 테스트용 fetch/HTTP 우회를 금지합니다. R2 서비스 비밀값은 D1 HTTP 비밀값 및 브라우저 전송 권한과 별개인 32바이트 난수입니다.
- Worker에는 `R2_BRIDGE_ENABLED=1`과 유효한 `R2_BRIDGE_SECRET`이 필요합니다. 배포 설정·실제 자원 ID는 아직 없습니다.
- Cookie·Origin·CORS·쿼리·리다이렉트를 사용하지 않습니다. 객체 키는 URL 대신 크기를 제한한 base64url JSON 헤더에 전달합니다. 비밀값·메타데이터·원본을 로그에 남기지 않습니다.
- **서비스 인증은 사용자 권한 검사를 대체하지 않습니다.** 기존 처리기가 최신 계정·담당·원장 상태를 먼저 확인하고 필요한 시점에 재검사합니다. 사용자 쿠키와 Sites 신원 헤더는 서비스 인증 수단이 아닙니다.
- 로컬은 명시적 개발 opt-in에서만 루프백 임시 포트와 메모리 난수를 사용합니다. Vercel 환경에서는 로컬 연결을 켤 수 없습니다. 실제 외부 주소나 자격증명은 읽지 않습니다.

## 지원 계약

현재 업무 코드가 쓰는 `get`, `head`, `put`, 단일 키 `delete`를 지원합니다. `list`, multipart API, 범위/조건부 get, 고객 관리 암호화 키와 지원하지 않는 put 옵션은 명시적으로 실패합니다. 옵션을 몰래 버리거나 다른 저장소로 우회하지 않습니다.

새 저장은 `company-source/…`와 `consulting-flow/…`에 한정합니다. 기존 평면 ASCII 키는 원래 관리자·원장 검사 아래 읽기/조회/삭제만 유지합니다. 새 평면 키 쓰기는 금지합니다. 실제 운영 전에는 전체 기존 키 형식·크기를 대조해야 합니다.

파일 최대 25MiB, 메타데이터 헤더 8KiB, 오류 본문 16KiB입니다. 입력 스트림은 크기·바이트 형식·완결성을 확인한 뒤 한 번만 저장합니다. File/Blob/ArrayBuffer/부분 TypedArray/스트림과 SHA-256·ETag 조건·HTTP/사용자 메타데이터를 지원합니다.

객체의 키·버전·크기·ETag·HTTP ETag·시각·메타데이터·체크섬을 검증해 복원합니다. 다운로드는 단일 소비 스트림이며 길이 초과/부족, SHA-256 불일치, 중단 및 최대 120초 기한을 검사합니다. `arrayBuffer`, `text`, `json`, `blob`, `bytes`, `bodyUsed`, `writeHttpMetadata`를 제공합니다. 본문 소비가 끝나기 전에는 원본 검증이 완료된 것으로 간주하지 않습니다.

실제 로컬 R2의 기본 `storageClass` 빈 문자열과 `undefined` 메타데이터 필드도 호환 처리합니다. 빈 등급을 임의로 `Standard`라고 단정하지 않습니다. [Cloudflare R2 API 계약](https://developers.cloudflare.com/r2/api/workers/workers-api-reference/)

## 실패와 데이터 보존

- 검증된 Worker의 `NOT_FOUND`만 `null`입니다. 프록시 404나 통신 오류를 원본 부재로 해석하지 않습니다.
- 조건부 put의 검증된 `PRECONDITION_FAILED`만 `null`입니다. 체크섬 오류는 성공이나 조건 실패로 바꾸지 않습니다.
- 인증 실패는 `R2_HTTP_AUTH_FAILED`, 전달 후 결과 불명은 `R2_HTTP_OUTCOME_UNKNOWN`입니다. 내부 오류 상세·객체 키·비밀값을 오류 메시지에 넣지 않습니다.
- put/delete 커밋 후 응답이 사라질 수 있습니다. 자동 재시도나 삭제 보상을 하지 않습니다. 기존 예약·멱등성 영수증으로 상태를 확인하며 저장 완료 원본의 자동 덮어쓰기를 추가하지 않습니다.

## 실행과 검사

```sh
pnpm run test:r2:http
pnpm run test:storage:http
pnpm run test:next:local:files
pnpm run dev:next:local:files
```

마지막 두 명령은 격리된 D1 HTTP·R2 HTTP·별도 파일 전송을 함께 사용합니다. 같은 `.next` 디렉터리에서 Sites/Next 빌드와 개발 서버를 동시에 실행하지 않습니다.

네이티브 R2 Worker 검사 13건이 통과했습니다. 25MiB/초과 경계, 한국어 원본, 메타데이터, 체크섬, 조건부 저장, 원본 스트림 복사, 빈 파일, 브라우저 접근 차단, 응답 유실 후 원본 보존과 삭제를 확인했습니다. 기존 업무 검사 687건도 **D1과 R2를 모두 HTTP 연결로 바꾼 상태**에서 통과했습니다. 운영 쓰기·메일·유료 AI·외부 요청은 모두 0건입니다.

실제 클라우드의 지연·부하·비용, 요청량 제한, 비밀값 회전, 기존 데이터 최대 크기/키 형식과 백업·복원은 아직 검증하지 않았습니다. 로컬 통과는 운영 완료를 뜻하지 않습니다. 운영 계정·저장소 접근, 독립 운영 인증·복구, 데이터 대조·롤백, Vercel Preview 검증이 남아 있습니다.

추가 단위 검사 14건을 포함한 전체 Node 검사 853건과 TypeScript/lint도 통과했습니다. 전송 인증·경로·비지원 옵션·프록시 오류·응답 유실·중단/잘림/변조 스트림·레거시 평면 키와 메타데이터 복원을 검증합니다. 클라우드 로그나 실제 파일을 사용하지 않았습니다.

실제 Next + D1/R2 HTTP + 별도 파일 전송 검사에서 기업자료 전송, FLOW 업로드 6종, 6MiB 초과 음성·큰 전사문, 완료 명령 재시도, 계정 전환에 따른 권한 취소와 재시작 후 보존을 통과했습니다. 관리자/파트너 로그아웃·관리자 만료·로그인 제한 `429`도 확인했습니다.

추가 집중 검사(`test:next:local:files` 명령 끝에 `--inventory-only` 전달)에서 전체 원본 목록과 기업자료/FLOW의 현재 크기·SHA-256 메타데이터 대조, 파트너의 관리자 점검 접근 거절을 확인했습니다. 기본 목록은 미연결 원본만 표시하므로 검사에서 `status=all`을 명시합니다. Windows 테스트 종료는 반환 코드만으로 판단하지 않고 테스트 소유 PID 종료와 루프백 포트 폐쇄를 확인합니다. 집중 검사의 재시작·만료·로그아웃까지 통과했고 소유 서버는 종료했습니다.

최종 반복 검증에서 기존 Sites 빌드·클라이언트 번들 한도, 공식 Next 프로덕션 빌드, 미설정 API 차단 118건, 위조 신원 차단, TypeScript/lint 및 `git diff --check`가 통과했습니다. 운영 번들에는 로컬 에뮬레이터·독립 로컬 관리자·미설정 D1/R2 연결이 포함되지 않습니다. 기존 99개 SQL과 `.openai/hosting.json`은 변경하지 않았습니다. release manifest 검사는 이전 v343 산출물의 검증이며, 이번 이전본의 배포를 뜻하지 않습니다. 커밋·GitHub 전송·운영 배포·브라우저 시각 QA는 수행하지 않았습니다.
