# AI 중단 잠금 회수 무결성 경계

기준일: 2026-09-06

## 문제

Step 0 외부 AI 요청에 명시적 타임아웃이 없었다. Worker가 응답 전에 종료되거나 공급자 연결이 끝나지 않으면 실패 처리 코드가 실행되지 않아 `생성중` 원장이 진행별 고유 잠금을 영구 점유하고, 이후 모든 명시적 새 요청이 계속 차단될 수 있었다.

## 적용

- Step 0 외부 요청에 85초 타임아웃을 적용한다.
- 생성 잠금 만료 기준은 요청 타임아웃보다 긴 5분으로 고정한다.
- 새로 승인된 요청이 들어올 때 같은 진행의 5분 이상 지난 `생성중` 행만 `생성실패`로 전환하고 원장을 보존한다.
- 만료 전 요청은 기존 잠금을 유지하며 새 외부 호출을 시작하지 않는다.
- 만료 회수 뒤에도 시스템이 요청을 스스로 만들거나 반복하지 않는다. 사용자가 새 요청 ID와 비용 동의를 제출한 경우에만 새 잠금을 만든다.
- 이전 Worker의 늦은 완료는 상태 조건부 갱신에 실패해 회수된 실패 원장을 덮어쓰지 못한다.

## 검증

- 만료 1밀리초 전 새 요청은 `pending`으로 차단된다.
- 정확히 5분 지난 새 명시 요청은 이전 행을 실패로 보존하고 새 `생성중` 행 하나를 만든다.
- 회수된 이전 실행의 늦은 완료 저장은 0건으로 끝난다.
- 외부 fetch에는 중단 가능한 타임아웃 신호가 전달된다.
- Node 회귀 검사 643/643 통과
- 격리 workerd/D1/R2 검사 451/451 통과
- 타입검사, 전체 lint, 변경 파일 포맷, 프로덕션 빌드 통과
- 로컬 운영 Worker `/`, `/account`, `/account/setup` HTTP 200과 CSP, `X-Frame-Options: DENY`, `nosniff`, `no-referrer` 확인
- 실제 운영 쓰기, 이메일 발송, 유료 AI 요청, 외부 요청 0건
