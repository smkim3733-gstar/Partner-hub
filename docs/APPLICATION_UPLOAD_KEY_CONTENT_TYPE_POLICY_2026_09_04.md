# 신청 첨부 업로드 멱등키 Content-Type 정책

## 목적

같은 신청 첨부를 다시 선택했을 때 브라우저가 MIME을 다르게 보고해도 새 업로드로 오인하지 않고, 응답 유실 뒤 기존 파일 ID를 복구한다.

## 적용 범위

- 진행 ID가 있는 협업신청 첨부의 멱등키 MIME을 공용 업로드 형식 등록표 값으로 고정한다.
- 독립 기업자료 업로드는 같은 `File` 선택 동안만 재시도 키를 유지하고 별도 등록을 구분하는 기존 의미를 유지한다.
- 서버는 공식 클라이언트가 만든 이전·신규 키 중 하나를 보낸 경우에만 정규 키를 적용한다. 임의 API 요청 키는 바꾸지 않는다.
- 이전 키의 원장이 `pending`, `ready`, `deleted`이면 같은 계정·파일·자료정보 지문을 확인한 뒤 원장 키와 지문만 조건부 갱신한다.
- 대기·완료 원장은 같은 파일 ID와 R2 원본을 재사용하고, 삭제 원장은 tombstone을 보존해 지연 재시도가 파일을 되살리지 못하게 한다.
- 파일 바이트나 기업·자료명·종류·담당·진행이 달라지면 기존처럼 HTTP 409로 거절한다.

## 유지한 경계

파일 실제 내용·확장자·크기·이름·MIME 저장 정책, 동의, 인증·권한, 담당 계정·진행 연결, R2 키, D1 스키마, 보관·삭제 정책은 변경하지 않았다. 기존 운영 자료를 일괄 조회하거나 변경하지 않았다.
