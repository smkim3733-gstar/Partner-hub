# 서버 인증·세션 입력 경계 통합

## 목적

Sites가 전달하는 ChatGPT 로그인 식별 헤더와 Cloudflare 접속 주소, 사이트 전용 비밀번호 세션 쿠키를 업무 인증에 사용하기 전에 공용 경계에서 검증한다. 과대·불완전·손상된 인증 입력이 권한 판정, 응답 표시, 로그인 시도 제한 또는 D1 세션 조회로 전달되지 않도록 한다.

## 적용 범위

- `oai-authenticated-user-id`: 공백을 제거한 뒤 비어 있지 않은 가시 ASCII 256자 이하만 허용한다.
- `oai-authenticated-user-email`: ID와 함께 있어야 하며 소문자 정규화, 이메일 형식, 254자 제한을 적용한다.
- `oai-authenticated-user-full-name`: `percent-encoded-utf-8` 표기와 유효한 퍼센트 인코딩을 요구하고, 해제한 이름은 공백 제거 후 1~80자이며 제어문자를 포함하지 않아야 한다. 조건을 만족하지 않으면 이메일 표시로 복귀한다.
- `cf-connecting-ip`: IPv4·IPv6 표기에 필요한 문자와 64자 제한만 허용하며, 없거나 잘못되면 기존 공용 제한 버킷을 사용한다. 클라이언트가 보낸 `X-Forwarded-For`는 계속 사용하지 않는다.
- 사이트 전용 세션 쿠키: 전체 Cookie 헤더를 8KiB로 제한하고 현재 프로토콜의 정확한 쿠키 이름이 한 번만 있어야 한다. 세션 토큰은 영문 소문자 16진수 64자리만 허용한다.

## 유지한 경계

Sites 전달 헤더와 사이트 전용 비밀번호 세션의 기존 이중 인증 구조를 유지한다. 유효한 비밀번호 세션을 먼저 확인하고 ChatGPT 헤더로 권한을 높이지 않으며, 공개 사이트의 익명 방문자에게는 로그인 정보를 만들지 않는다. 대표 이메일·활성 파트너 명단·계정 ID·역할·권한 판정, HTTPS·동일 출처 검사, 로그인 시도 제한 수치와 D1/R2 스키마·보관 정책에는 변경이 없다.

## 재발 방지

공용 인증 입력 단위검사와 대표 직접등록·공개 자가가입·비밀번호 인증의 실제 경로 회귀검사를 추가했다. 알려진 인증 소비처가 원시 헤더를 다시 직접 읽지 않는지 정적 검사로 고정했다.

## 검증 결과

- 대상 회귀검사 67개 통과
- 전체 자동 테스트 429개 통과
- 격리 workerd/D1/R2 검사 129개 통과
- TypeScript 타입검사, 전체 lint, 프로덕션 빌드 통과
- 로컬 Workers `/` HTTP 200 확인
- 격리검사 중 운영 쓰기, 메일, 유료 AI, 외부 요청 0건

현재 공개 운영본은 Sites 버전 80이다. 이번 인증·세션 입력 경계 변경의 GitHub 푸시와 공개 Sites 배포는 별도 운영 반영 승인 전까지 수행하지 않는다.
