# 견적·계약 진입 경로 점검

2026-09-01. 사용자의 연속 개발 요청에 따라 기존 진행 화면의 견적서·계약서 진입 경로를 점검했다. 메모리 전용 D1/R2의 가상 대표와 가상 파트너만 사용했다.

## 코드 대조와 수정

진행 화면의 견적·계약 버튼은 이미 권한을 확인한 뒤 상담 FLOW로 이동했다. 상담 FLOW에는 5차 견적서, 6차 경영자문용역계약서, 계약상담·체결·입금 확인의 단계별 조건과 서버 권한 검사가 구현돼 있다.

반면 이전 초안 모달 코드가 별도로 남아 있었다. 이 코드는 서비스 범위·금액·기간·업무 범위·상태 입력을 받지만 모두 버리고 고정된 타임라인 문구만 저장하는 구현이었다. 현재 호출하는 코드가 없어 화면에서 도달할 수는 없었지만, 다시 연결될 경우 잘못된 계약 기록을 만들 위험이 있었다.

- 호출되지 않는 견적·계약 초안 모달과 상태·저장 코드를 제거했다. 기존에 저장된 타임라인 기록은 변경하거나 삭제하지 않았다.
- 빈 견적·계약 탭에서 `작성`을 단정하던 문구를 상담 FLOW의 현재 단계 확인 안내로 변경했다.
- 빠른 업무 버튼 두 개를 `견적·계약 상태 확인` 하나로 정리하고 실제 처리 경로인 상담 FLOW로 연결했다.
- `견적·계약 확인` 권한이 없는 파트너에게는 견적·계약 요약·탭·버튼을 계속 숨기고 기존 권한 안내만 표시한다.

새 견적 생성 방식, 금액 정책, 계약 양식, 서명·입금 연동은 추가하거나 변경하지 않았다.

## 가상 화면 검증

| 조건 | 결과 |
| --- | --- |
| 대표 화면 | 견적서 탭의 빈 상태가 상담 FLOW 단계 확인을 안내했다. 빠른 업무에는 `견적·계약 상태 확인` 한 개만 표시됐다. |
| FLOW 이동 | 상태 확인 버튼을 누르면 선택한 같은 가상 진행의 상담 FLOW가 열리고 1–6차 보고서와 계약·입금 단계가 표시됐다. |
| 권한 없는 파트너 | 담당 진행은 열 수 있지만 견적·계약 요약·탭·상태 확인 버튼은 표시되지 않았고 별도 승인 또는 대표 권한 필요 안내만 보였다. |
| 외부 작업 | 실제 고객 자료, 계약, 금액, 파일, 서명, 입금, 연락, 메일, 유료 AI와 외부 요청을 사용하지 않았다. |

## 회귀 검사와 배포

- 전체 Node 검사 195개, 타입검사, lint, 빌드가 통과했다. 이번 변경은 도달 불가능 코드 제거와 기존 FLOW 연결 문구 정리이므로 구현을 복제하는 새 테스트는 만들지 않았다.
- 서버 API·DB 스키마·권한 판정은 바꾸지 않아 기존 workerd/D1/R2 저장소 검사 110개는 반복하지 않았다.
- 검사·빌드 로그는 `outputs/validation/quote-contract-route-tests.log`, `quote-contract-route-build.log`에 남겼다.
- 운영 반영 상태는 `outputs/release/quote-contract-route-deployment.json`에 기록한다. 기존 공개 사이트, D1/R2 연결, 추가형 마이그레이션 8개를 유지한다.
- 실제 계약·입금과 모든 FLOW 분기, 전체 키보드·모바일 검증을 완료한 것으로 해석하지 않는다.
