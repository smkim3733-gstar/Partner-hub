# 상담 FLOW 최초 첨부 동시성·실패 복구

기준일: 2026-09-06

## 확인한 문제

첫 FLOW 명령 두 건이 첨부파일 업로드까지 동시에 진행되면 한 요청만 revision 0→1 저장에 성공한다. 패자 배치는 파일 소유권 트리거에서 중단됐지만, 애플리케이션은 이를 일반 저장 장애 503으로 반환했다. 실제 원인은 저장소 장애가 아니라 이미 확정된 동시 수정 충돌이었다.

## 보완

- 첨부 또는 파일 목적 변경을 포함한 D1 배치가 실패하면 현재 FLOW를 다시 읽는다.
- 현재 revision이 요청 기준과 달라졌음이 확인될 때만 409 동시 수정 충돌로 반환한다.
- 현재 상태를 읽지 못하거나 revision이 그대로면 기존 503 저장 장애를 유지한다.
- 패자 요청이 올린 R2 객체는 승자 FLOW가 참조하지 않을 때만 삭제한다. 승자 객체와 파일 원장은 보존한다.
- 성공 응답을 잃은 승자 요청은 같은 명령·같은 파일 재시도에서 중복 성공으로 수렴하며 새 R2 객체를 만들지 않는다.

## 회귀 검증

- 동일 첫 명령과 서로 다른 가상 첨부를 동시에 실행해 응답이 200 한 건, 409 한 건인지 확인했다.
- D1에는 revision 1 FLOW와 파일 한 건만 남고 R2에도 승자 객체 한 건만 남는지 확인했다.
- 인위적 D1 배치 장애는 503을 유지하고 저장되지 않은 R2 객체를 제거하는지 확인했다.
- Node 701/701, 집중 FLOW 105/105, 격리 workerd+D1+R2 520/520, 타입검사, lint, 변경 파일 포맷과 프로덕션 빌드를 통과했다.
- 로컬 Worker의 `/`, `/account`, `/account/setup`은 200, 비로그인 `/api/state`는 401과 비공개 무저장 헤더를 반환했다.
- 실제 운영 데이터 쓰기, 메일 발송, 유료 AI 호출, 외부 업무 API 호출은 0건이다.
