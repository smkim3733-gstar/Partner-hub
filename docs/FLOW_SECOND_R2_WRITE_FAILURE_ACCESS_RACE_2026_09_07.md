# 상담 FLOW 두 번째 R2 저장 실패 중 접근변경 경쟁 무결성

기준일: 2026-09-07

## 확인한 경계

전사문·음성파일을 함께 저장하는 상담 FLOW 요청은 전사문 객체를 먼저 R2에 기록하고 현재 접근을 다시 확인한 뒤 음성 스트림을 기록한다. 두 번째 음성 저장 중 권한 변경과 R2 실패가 겹치면 첫 객체가 이미 존재하므로, 음성 객체 생성 여부와 두 예약·FLOW 커밋의 복구 가능성을 별도로 증명해야 한다.

## 감사 결과

- 첫 시도에서 두 번째 R2 쓰기를 실패시켜 전사문 객체 1개와 전사문·음성 두 `pending` 예약을 만들었다.
- 정확한 재시도의 두 번째 음성 스트림 소비 중 실제 관리자 상태 저장 API로 담당 파트너의 `fileUpload` 권한을 회수했다.
- 첫 회귀는 음성 객체 생성 전에 스트림 오류를 냈다. 두 번째 회귀는 음성 객체를 예약 키에 생성한 뒤 응답만 실패시켜 모호한 저장 결과를 만들었다.
- v301에서 추가한 모든 예약 객체 쓰기의 실패 후 접근 재검사가 두 경로에도 적용됐다. 두 회귀 모두 현재 권한 상실을 403으로 반환하고 FLOW·명령 영수증·파일 원장·완료 원장 D1 쓰기를 시작하지 않았다. 런타임 추가 수정은 필요하지 않았다.
- 객체 생성 전 실패는 기존 전사문 객체 1개만 보존한다. 모호한 생성 후 실패는 전사문·음성 객체 2개를 정확한 예약 키에 보존한다. 두 결과 모두 예약 상태는 `pending`이고 권한 회수도 유지된다.
- 권한 복구 뒤 정확한 재시도는 같은 파일 ID와 R2 키를 재사용해 FLOW를 한 번만 완료하고 두 예약을 `ready`로 전이한다.
