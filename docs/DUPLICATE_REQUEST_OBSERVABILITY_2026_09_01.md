# 중복 입력·중복 요청 운영 지표

## 목적

상담 FLOW 명령, 기업자료 업로드, 대표의 파트너 직접등록에서 서버가 이미 판별하고 있는 안전한 재시도와 요청번호 충돌을 개인정보 없이 집계한다. 이 지표는 운영 흐름과 재시도 보호가 실제로 작동하는지 확인하기 위한 이벤트 합계이며 사람·기업·진행의 고유 건수를 뜻하지 않는다.

## 구현 경계

- 추가형 D1 테이블에는 한국시간 날짜, 고정된 요청 경로, 고정된 결과, 이벤트 수만 저장한다.
- 사용자·이메일·회사·진행·파일·요청번호·입력 지문·본문·IP·정확한 시각은 저장하지 않는다.
- 결과는 `안전 재시도`, `요청번호 충돌`, `기존 계정 중복차단`, `식별값 없는 업로드`로 제한한다.
- 식별값 없는 업로드는 중복으로 분류하지 않는다. 서버가 실제 중복 여부를 판별할 수 없는 관측 범위 경고로만 합산한다.
- 삭제된 업로드 예약은 지문이 달라도 지표 분류에서 제외한다. 사용자가 받던 기존 삭제·변경 오류의 순서와 상태 코드는 유지한다.
- 과거 상담 FLOW 요청번호에 상세 영수증이 없는 경우는 측정 불가로 두며 충돌 수에 넣지 않는다.
- 대표 상태 API 최상위에 최근 7일 합계와 경로·결과별 합계만 제공한다. 파트너 응답과 저장 상태 원문에는 넣지 않는다.
- 지표 기록·조회 실패는 파일·FLOW·파트너 등록의 원래 성공 또는 오류 응답을 바꾸지 않는다.
- 집계 보관·삭제 정책은 정하지 않았으며 자동 삭제나 기존 자료 삭제를 추가하지 않는다.

## 동시 요청 처리

- 업로드 예약 전에 후보 파일 ID를 만들고, 예약 뒤 조회된 파일 ID와 비교해 기존 요청인지 판별한다. D1 변경 건수는 기존 여부 판정에 사용하지 않는다.
- 업로드 저장 함수의 반환 객체와 HTTP 파일 응답 필드는 바꾸지 않고 선택적 관측 콜백만 추가한다.
- 대표 파트너 직접등록의 상태 변경 콜백은 CAS 충돌로 반복될 수 있으므로 콜백 안에서는 최종 분류만 갱신하고, 상태 변경이 끝난 뒤 응답당 한 번만 집계를 예약한다.
- 관리자 상태 API의 저장 충돌·비밀번호 링크·신청 상담·중복 요청 지표는 각각 오류를 격리한 상태로 병렬 조회한다.

## 검증 결과

- Node 자동 검사 229개 통과.
- 격리 workerd + 실제 D1/R2 검사 118개 통과. 추가형 마이그레이션을 두 번 적용해 기존 상태를 보존했고, 익명 집계 열 네 개만 생성되는지 확인했다.
- 타입검사, lint, 프로덕션 빌드 통과.
- FLOW 동일 요청 재사용과 내용·계정 변경, 업로드 응답 유실과 내용 변경, 식별값 없는 업로드, 삭제 뒤 재시도, 대표 직접등록 재시도·내용 변경·동시 CAS 재시도를 가상 데이터로 확인했다.
- 격리 검증의 외부 요청, 운영 쓰기, 메일 발송, 외부 AI 호출은 0건이다.

## Duet 검수

Duet 기획 검수의 중대 의견을 모두 반영했다. 업로드 기존 예약 판정, 응답 형식 보존, 삭제 행 분류 제외, 관리자 직접등록의 CAS 중복 집계 방지, 관리자 지표 병렬 조회를 구현과 회귀 검사에 포함했다. 최종 차이 검토는 네이티브 Windows에서 고위험 실행에 필요한 샌드박스 검사를 제공할 수 없어 완료 판정을 받지 못했다. 이는 코드 실패가 아닌 실행 환경 제한이며, 샌드박스 완료 판정이 필요하면 저장소와 Duet을 WSL2에서 다시 실행해야 한다.
