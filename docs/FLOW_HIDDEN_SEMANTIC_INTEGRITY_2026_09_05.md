# 상담 FLOW 숨김 필드 의미 무결성 경계

기준일: 2026-09-05

## 확인한 문제

대시보드의 SQLite 축소 투영은 숨겨지는 FLOW 필드의 타입과 길이를 확인했지만 공백만 있는 문자열과 실제로 해석할 수 없는 날짜는 거절하지 않았다. 상세 FLOW 조회는 JavaScript의 `trim()`과 `Date.parse()` 검증으로 같은 값을 손상으로 판단하므로, 한 저장 행이 상세 조회에서는 실패하고 대시보드에서는 정상처럼 보일 수 있었다.

AI 작업의 생성·시작·완료 시각 순서도 전체 저장 검증에서만 확인했다. 축소 투영 전에 제거되는 작업 정보가 역순이어도 대시보드 경계를 통과할 가능성이 있었다.

## 적용한 경계

- ECMAScript `trim()`이 제거하는 공백 문자를 하나의 고정 SQLite 문자열 집합으로 정의했다. 일반 공백·탭·개행뿐 아니라 NBSP, 전각 공백, BOM 등 Unicode 공백만 있는 필드도 거절한다.
- 보고서 제목·작성자·파일 연결, 파일 식별자·이름·MIME·저장 키·용도·검토 메타데이터, 녹취 연결·검토자, AI 작업 연결, 감사기록, 명령 ID와 영수증 값을 축소 투영 전에 공백 검사한다.
- 보고서·파일·녹취·AI 작업·감사기록의 숨김 시각을 SQLite `julianday()`로 해석해 잘못된 날짜를 거절한다.
- AI 작업의 시작시각이 생성시각보다 이르거나 완료시각이 시작시각보다 이른 상태를 거절한다.
- 기존 대형 투영 조건과 의미 검증을 별도 SQL 문장으로 나누되 하나의 D1 `batch`에서 읽어 같은 시점의 결과를 사용한다. D1 표현식 깊이 제한 100을 넘기지 않는다.
- Node D1 모의 배치도 실제 D1처럼 SELECT 결과 행을 반환하게 해 같은 경로를 회귀 검증한다.

## 검증

- 보고서 제목·작성자, 파일 저장 키·검토자, 녹취 검토자, 감사 행위자·상세, 명령 ID와 영수증에 ASCII·Unicode 공백만 넣은 손상 9종을 대시보드 HTTP 503으로 차단했다.
- 보고서·파일·녹취·AI 작업·감사 시각의 잘못된 날짜와 AI 작업 시작 역전 손상 6종을 같은 경계로 차단했다.
- 격리 Workers+D1에서 실제 D1 행의 잘못된 숨김 감사시각을 HTTP 503과 비공개 오류 응답으로 차단했다.
- Node 자동 테스트 585/585 통과.
- 격리 workerd+D1+R2 검사 372/372 통과.
- 타입검사, 전체 lint, 포맷 검사, 프로덕션 빌드 통과.
- 로컬 프로덕션 `/`, `/account`, `/account/setup` HTTP 200과 CSP·`DENY`·`nosniff`·`no-referrer` 확인.
- 실제 운영 쓰기, 메일 발송, 유료 AI 요청, 외부 요청 0건.
