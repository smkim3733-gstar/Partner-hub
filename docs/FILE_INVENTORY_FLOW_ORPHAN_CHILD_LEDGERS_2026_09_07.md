# 파일 재고 FLOW 하위 고아 원장 가시성

## 결과

FLOW payload와 소유 원장은 없지만 메타데이터·R2 객체 무결성·SHA-256 체크섬 하위 D1 원장 중 하나 이상이 남은 파일도 관리자 재고에서 사라지지 않는다. 같은 파일 ID의 하위 원장 여러 행은 한 `inconsistent` 항목과 한 `unavailable` 건수로 격리한다. 개별 현재 R2 확인은 저장 키를 추정하거나 객체를 조회하지 않고 원장 무결성 503으로 닫는다.

안전한 메타데이터 원장이 있을 때만 경계 검증한 파일명·용도·크기를 표시한다. ETag·SHA-256·저장 키·본문·요청 지문은 응답하지 않는다. 스키마와 마이그레이션 변경은 없다.

기능 커밋은 `1fec000ef61f66926e2ab21ccfeb8a3b79ed7311`이다.

## 수정 전 재현

- payload·소유 원장·업로드 예약 없이 같은 ID의 메타데이터, 객체 무결성, 체크섬 원장만 만들었다.
- 수정 전 재고는 세 하위 원장을 후보나 증명 적용 현황의 시작점으로 사용하지 않았다.
- 따라서 세 원장이 남아도 목록에는 0건, `unavailable` 증가도 0건이었고 개별 확인은 404를 반환했다.
- 정확한 적색 회귀는 파일 재고 19건 중 18건 통과, 하위 원장 격리 1건 실패로 결함을 고정했다.

## 변경

- FLOW 메타데이터·객체 무결성·체크섬 원장의 파일 ID 합집합을 만든다.
- 소유 원장과 저장 키가 있는 payload 격리 후보가 모두 없는 ID만 하위 고아 원장 후보로 분류한다.
- 세 하위 원장이 같은 ID를 공유해도 한 후보만 만들고, 미완료 예약이 함께 있으면 손상 격리 후보를 우선해 동일 `source:id` 응답 중복을 막는다.
- 안전한 메타데이터 원장이 있으면 길이·정수 범위를 통과한 표시값만 사용하고, 신뢰할 시각이 없으면 명시적인 안전 정렬값을 사용한다.
- 전체 증명 적용 현황에서 하위 고아 원장 ID마다 `unavailable`을 한 번 센다.
- 개별 확인은 하위 원장 존재와 소유 원장 부재를 확인해 R2 접근 전 503으로 거절한다.

## 실제 D1 호환 보정

첫 구현은 payload 고아와 하위 원장 고아를 재고 후보의 별도 `UNION ALL` 분기로 추가했다. Node D1 mock 19/19는 통과했지만 격리 workerd의 실제 D1은 여섯 번째 compound SELECT 항에서 `too many terms in compound SELECT`로 거절했다.

두 고아 유형을 `flow_orphan_inventory` CTE에서 합치고 후보·증명 집계·개별 확인에 각각 하나의 분기로만 연결했다. 의미와 중복 우선순위는 유지하면서 실제 D1 제한 안으로 되돌렸고, 임시 진단 로그는 검증 직후 제거했다.
