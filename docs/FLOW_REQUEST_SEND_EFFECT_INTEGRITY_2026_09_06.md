# 상담 FLOW 서류 요청 발송 효과 무결성

기준일: 2026-09-06

## 문제

`mark_request_sent` 명령은 선택한 요청의 실제 발송 여부를 기록하지만, 기존 명령 영수증에는 선택한 요청 ID가 남지 않았다. 따라서 저장 결과가 요청 한 건의 `sentAt`만 변경하는지는 검사해도, 그 요청이 사용자가 선택한 요청인지는 독립적으로 증명할 수 없었다. 실패 우선 검사에서 첫 번째 요청을 선택한 뒤 두 번째 요청으로 발송 증거를 바꿔치기한 상태가 애플리케이션 경계를 통과했다.

## 적용한 경계

- 명령 영수증 `targetId`에 선택한 요청 ID를 보존한다.
- 과거 요청과 현재 요청에서 해당 ID가 각각 정확히 한 건이어야 한다.
- 선택한 요청은 기존 값 전체를 보존하고 `sentAt`만 해당 FLOW revision의 서버 `updatedAt`으로 기록한다.
- 다른 요청의 변경, 요청 추가·삭제·재정렬, 대상 ID 누락을 거절한다.
- 감사기록은 명령 ID·서버시각·`mark_request_sent` 동작과 기존 요청 전달 경로 기반의 `{전달 경로} 서류요청 실제 발송 기록` 문구에 결속한다.
- 행위자는 대표 또는 해당 FLOW 담당 파트너만 허용한다.

애플리케이션 커밋 검사와 D1 트리거가 같은 계약을 독립적으로 강제한다. `0086_consulting_flow_mark_request_sent_effect.sql`은 기존 명령 영수증 대상 트리거를 추가형으로 교체해 `mark_request_sent`의 `targetId`를 필수화하고, 전용 효과 트리거를 추가한다.
