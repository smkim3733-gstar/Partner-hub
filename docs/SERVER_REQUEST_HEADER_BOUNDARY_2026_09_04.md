# 서버 조건·멱등 요청 헤더 경계 통합

## 목적

운영 상태 저장과 기업자료 업로드의 재시도·동시성 제어에 쓰는 요청 헤더를 공용 경계에서 검증한다. 잘못된 조건 버전이나 업로드 요청 식별값을 업무 데이터 비교 또는 D1/R2 쓰기에 전달하지 않고 HTTP 400으로 차단한다.

## 적용 범위

- 운영 상태 저장의 `If-Match`: SHA-256 형식인 영문 소문자 16진수 64자리만 허용하며, 정확히 한 겹의 큰따옴표가 있는 형식과 없는 형식을 지원한다.
- 기업자료 업로드의 `Idempotency-Key`: 영문 대소문자·숫자·하이픈·밑줄로 된 10~128자리만 허용한다.
- 운영 상태 저장·공개 자가가입·대표 직접등록의 `X-Portal-Conflict-Receipt`: 기존 43자리 회수 영수증 검증을 요청 단위 공용 함수로 통합한다.

여러 값이 쉼표로 합쳐진 헤더, 와일드카드·약한 ETag, 대문자 또는 길이가 다른 저장 버전, 공백·구두점·과대 멱등키는 허용하지 않는다. 충돌 회수 영수증은 업무 요청의 성패를 바꾸지 않는 익명 관측값이므로 기존과 같이 잘못된 값을 조용히 무시한다.

## 유지한 경계

헤더 검증은 기존 동일 출처·로그인·역할 확인 뒤 수행한다. `If-Match`가 없는 저장 요청은 기존 동시성 충돌 또는 동일 내용 재시도 규칙을 유지하고, 업로드 멱등키 생략도 기존 관측 범위 경고와 업로드 동작을 유지한다. 충돌 영수증은 업무 요청 성공 뒤에만 회수한다. 인증 헤더·쿠키, 업무 권한, D1/R2 스키마, 원본 파일, 보관·삭제 정책에는 변경이 없다.

## 재발 방지

공용 헤더 단위검사와 실제 상태 저장·파일 업로드 회귀검사를 추가했다. 해당 소비 경로가 공용 경계를 우회하지 않는지 정적 검사로 고정했다.

- 로컬 Workers `/` HTTP 200 확인
