# 진행단계·중단 상태 변경 확인 안전성

2026-09-03 기준. 진행판의 수동 단계 변경과 진행 중단·재개가 선택 즉시 자동저장되던 경계를 보완했다.

## 문제

- 수동 진행단계 선택은 즉시 단계·다음 행동·정체일·긴급 표시를 바꾸고 상위 자동저장을 시작했다.
- 진행 중단·재개 버튼도 별도 영향 확인 없이 생명주기 상태를 바꿨다.
- 진행 중단은 서버가 해당 진행의 상담 FLOW 쓰기를 차단하므로 단순 표시 변경보다 강한 확인이 필요했다.

## 변경

- 단계 선택은 실제 진행을 바꾸지 않고 현재 단계와 변경 후 단계를 담은 초안만 만든다.
- 확인창에서 변경 후 다음 행동과 정체일·긴급 표시 초기화를 설명하고 `단계 변경 저장`을 눌러야 적용한다.
- 단계 저장 직전 진행 ID·기존 단계·FLOW 자동관리 여부·중단 상태와 허용 단계를 다시 검사한다.
- 진행 중단·재개도 현재 단계와 다음 상태를 별도 확인한 뒤 저장한다.
- 중단 확인창은 저장 후 상담 FLOW 쓰기가 차단됨을, 재개 확인창은 FLOW 입력이 다시 가능함을 명시한다.
- 중단·재개 저장 직전 진행 ID·단계·현재 생명주기 상태를 다시 검사한다.
- 모든 확인창의 `취소`와 닫기는 초안을 폐기하고 운영 상태를 바꾸지 않는다.

## 유지한 경계

- FLOW 자동관리 진행의 단계는 계속 서버 검증 결과로만 바뀐다.
- 수동 단계 변경 시 서버의 최고 도달단계 기록은 기존대로 보존된다.
- 진행 중단·재개는 기존 진행·자료·업무를 삭제하거나 자동 완료·발송하지 않는다.
- 기존 서버의 관리자 전용 중단·재개, revision/CAS, 중단 중 FLOW 쓰기 차단을 변경하지 않았다.
- DB/R2 스키마·권한·보관 정책과 기존 운영 데이터를 변경하지 않았다.
