# 신청자료 검토 응답 검증 안전성

2026-09-04 기준으로 상담 FLOW의 신청자료 목록과 미리보기 API 응답에 대한 클라이언트 검증을 보강했다.

## 변경 범위

- 성공 응답을 `unknown`으로 읽고 일반 JSON 객체인지 먼저 확인한다.
- 목록은 최대 100건, 고유 파일 ID, 파일명·자료종류·크기·생성시각과 더 보기 상태를 검증한다.
- 파일 확장자에서 계산한 본문·바이너리·음성·미지원 분류와 서버 응답 분류가 같은지 확인한다.
- 파일 형식과 크기로 계산한 차단 사유가 서버 응답과 정확히 같은지 확인한다. 응답이 차단된 파일을 임의로 검토 가능하게 만들 수 없다.
- 미리보기 응답의 파일 ID·이름·자료종류·크기·생성시각·분류·차단 사유를 사용자가 선택한 목록 항목과 모두 대조한다.
- 검토 가능한 파일만 미리보기에 허용하고 SHA-256 원본 해시 형식을 확인한다.
- Word·TXT는 최대 60,000자의 본문만 허용하고 PDF·이미지 응답에는 서버가 만든 텍스트를 허용하지 않는다.
- 검증된 공개 필드만 새 객체로 반환한다. 저장소 키 등 알 수 없는 응답 필드는 검토 상태로 전달하지 않는다.
- 실패 응답은 길이가 제한된 서버 안내만 유지한다. 비-JSON 또는 손상된 성공 응답은 목록 새로고침을 안내한다.

## 유지한 안전 경계

- 서버의 대표 관리자 인증, 진행·기업·담당 계정 연결 확인, D1 메타데이터 조회와 R2 원본 읽기는 변경하지 않았다.
- 원본 해시와 저장 직전 재검증, 검토·공유·마스킹·녹취 이용 확인, AI 외부 전송의 별도 승인을 유지한다.
- 목록·미리보기만으로 검토 사본을 저장하거나 상담·보고서 단계를 바꾸지 않는다.
- 원본, 운영 데이터, D1/R2 스키마, 권한·보관·삭제 정책과 공개 배포 상태를 변경하지 않았다.

## 검증

- 자동 테스트 386개
- 격리 workerd/D1/R2 검사 129개
- TypeScript 타입검사, 전체 lint, 프로덕션 빌드
- localhost `/` HTTP 200

모든 신규 응답 검사는 가상 파일 메타데이터와 합성 응답으로 실행했다. 실제 원본 열람·검토 사본 저장·운영 쓰기·메일·유료 AI·외부 요청은 0건이다. GitHub 푸시와 공개 Sites 배포는 사용자 승인 전까지 수행하지 않는다.
