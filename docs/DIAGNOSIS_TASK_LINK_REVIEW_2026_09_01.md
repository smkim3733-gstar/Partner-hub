# AI 진단 검토업무 진행 연결 점검

2026-09-01. 사용자의 별도 `다음 진행` 요청으로 AI 사전점검 A 판정 후 생성되는 대표 검토업무의 반복 진행 연결을 점검했다. 실제 고객 자료와 외부 AI는 사용하지 않았다.

## 재현과 수정

기존 중복 검사는 기업명과 `AI 진단 사전점검` 문구만 비교했다. 같은 기업이 두 번 신청하면 첫 진행의 미완료 업무가 두 번째 진행의 업무 생성을 막았다. 생성 업무에는 진행 ID가 없어 업무 카드에서 해당 기업 진행으로 이동할 수도 없었다.

- AI 검토업무 중복 여부를 정확한 진행 ID로 판단한다.
- 새 대표 검토업무에 사전점검의 진행 ID를 저장한다.
- 같은 진행의 미완료 업무는 중복 생성하지 않는다. 완료 업무는 후속 검토가 필요할 때 새 업무 생성을 막지 않는다.
- 기업명이 같더라도 다른 반복 신청은 별개의 검토업무를 만들 수 있다.
- 진행 ID가 없는 과거 업무는 특정 진행의 중복으로 추측하지 않는다.

업무 담당자는 기존대로 김성민 대표이며 실제 AI 전송·비용·동의·자료 보존 정책은 변경하지 않았다.

## 검증과 배포

- 동일 기업의 서로 다른 진행, 완료 업무, 진행 ID 없는 과거 업무를 가상 데이터로 대조하는 회귀 검사를 추가했다.
- 전체 Node 검사 198개, 타입검사, lint, 빌드가 통과했다.
- 서버 API·DB 스키마를 바꾸지 않아 기존 workerd/D1/R2 저장소 검사 110개는 반복하지 않았다.
- 검사·빌드 로그는 `outputs/validation/diagnosis-task-link-tests.log`, `diagnosis-task-link-build.log`에 남겼다.
- 사용자 지침에 따라 브라우저 클릭 시험과 외부 AI 호출을 수행하지 않았다.
- 운영 반영 상태는 `outputs/release/diagnosis-task-link-deployment.json`에 기록한다. 기존 공개 사이트, D1/R2 연결, 추가형 마이그레이션 8개를 유지한다.
