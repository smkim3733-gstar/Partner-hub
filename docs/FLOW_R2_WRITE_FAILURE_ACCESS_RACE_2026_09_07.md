# 상담 FLOW R2 저장 실패 중 접근변경 경쟁 무결성

기준일: 2026-09-07

## 확인한 위험

상담 FLOW가 예약된 파일을 R2에 스트리밍하는 동안 저장소 예외와 계정·권한·담당·사건 상태 변경이 함께 발생할 수 있다. R2는 객체 생성 전 실패와 객체는 생성됐지만 응답을 받지 못한 모호한 실패를 모두 만들 수 있다. 기존 라우트는 저장 예외를 즉시 503으로 바꿔 반환했기 때문에, 같은 순간 업로드 권한이 회수돼도 현재 접근 상태를 확인하지 않고 재시도를 안내했다.

## 발견·수정한 문제

- 첫 R2 객체의 스트림 소비 중 실제 관리자 상태 저장 API로 담당 파트너의 `fileUpload` 권한을 회수했다.
- 첫 회귀는 스트림을 일부 소비한 뒤 객체 생성 전에 R2 오류를 냈다. 두 번째 회귀는 객체를 원래 예약 키에 생성한 뒤 응답만 실패시켜 모호한 저장 결과를 만들었다.
- 수정 전 두 회귀 모두 현재 권한 상실을 확인하지 않고 503을 반환해 기대한 403과 다른 `503 !== 403`을 재현했다.
- 예약 객체 쓰기가 실패하면 현재 인증·안정 신원·FLOW 담당 ID·업로드 권한·사건 생명주기를 즉시 다시 확인한다. 접근이 유효할 때만 원래 저장소 503을 반환하고, 접근을 잃었으면 현재 403·404·409를 우선 반환한다.
- 객체 생성 전 실패는 새 R2 객체 0개, 모호한 생성 후 실패는 전사문 객체 1개만 남는다. 두 경우 모두 음성 객체는 없고 두 예약은 `pending`이며 FLOW·명령 영수증·파일 원장·완료 원장 D1 쓰기는 발생하지 않는다.
- 권한 회수는 유지된다. 권한 복구 뒤 정확한 재시도는 같은 파일 ID와 R2 키를 재사용해 전사문·음성 객체와 FLOW를 한 번만 완료한다.
- 접근 상태가 바뀌지 않은 기존 R2 실패는 계속 503을 반환하므로 일시 저장소 장애 복구 계약은 유지된다.
