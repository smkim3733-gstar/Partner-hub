# 기업자료 메타데이터 원장 불변 경계

기준일: 2026-09-05

## 문제

버전 169의 전체 메타데이터 원장은 원본 행의 유효값 변조를 모든 소비 경로에서 탐지하지만, 원장 테이블 자체는 SQLite의 직접 `UPDATE`와 부모 원본이 남은 상태의 직접 `DELETE`를 받아들일 수 있었다. 애플리케이션 운영 경로에는 이런 변경이 없었으나, 잘못된 유지보수 SQL이 원장 증거를 다시 쓰거나 먼저 지우면 이후 검사가 실패 폐쇄되더라도 불변 원장이라는 저장소 계약은 D1 자체에서 강제되지 않았다.

## 적용

- 전체 애플리케이션 경로를 검사해 `company_file_metadata`에는 신규 업로드의 `INSERT`만 있고 직접 `UPDATE`·`DELETE`가 없음을 확인했다.
- `0020_company_file_metadata_immutability.sql`에 `BEFORE UPDATE` 트리거를 추가해 값 변경과 무관하게 원장 행의 모든 직접 수정을 거절한다.
- 부모 원본이 존재하는 원장 직접 삭제를 별도 트리거로 거절한다.
- 정상 파일 삭제는 검증된 `company_file_objects` 부모 한 행만 조건부 삭제하고, 외래 키 `ON DELETE CASCADE`가 메타데이터 원장을 같은 SQLite 결정에서 정리한다.
- 부모가 이미 없는 고아 원장 정리는 차단하지 않아 명시적 장애 복구 가능성을 보존한다.
- 런타임 테이블 준비에도 같은 `CREATE TRIGGER IF NOT EXISTS` 정의를 넣어 새 로컬·격리 저장소와 마이그레이션 적용 저장소가 같은 계약을 가진다.
- D1 `exec`가 줄바꿈을 여러 쿼리 구분으로 취급하는 실행 계약에 맞춰 런타임 트리거 정의와 격리 마이그레이션 실행을 단일 SQL 행으로 전달한다.

## 검증

- 정상 신규 파일의 메타데이터 직접 `UPDATE`는 `immutable` 오류로 거절된다.
- 부모 원본이 존재하는 메타데이터 직접 `DELETE`는 `requires parent deletion` 오류로 거절된다.
- 같은 파일의 정상 삭제 API는 HTTP 204를 반환하고 R2 객체와 메타데이터 원장을 함께 제거한다.
- 21개 추가형 마이그레이션을 기존 행이 있는 격리 D1에서 두 번 적용해도 상태를 교체하지 않는다.
- Node 회귀 검사 618/618 통과
- 격리 workerd/D1/R2 검사 432/432 통과
- 타입검사, 전체 lint, 변경 파일 포맷, 프로덕션 빌드 통과
- 로컬 운영 Worker `/`, `/account`, `/account/setup` HTTP 200과 CSP, `X-Frame-Options: DENY`, `nosniff`, `no-referrer` 확인
- 실제 운영 쓰기, 이메일 발송, 유료 AI 요청, 외부 요청 0건
