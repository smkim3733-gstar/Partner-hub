# 파일 재고 FLOW 한쪽 완료 영수증 격리

기준일: 2026-09-08

## 확인한 상태

완료 FLOW 첨부의 소유·payload·메타데이터·객체 무결성·체크섬 원장이 정상이더라도 다음과 같은 한쪽 영수증 손상이 남을 수 있다.

- `ready` 업로드 예약은 존재하지만 완료 영수증이 없는 상태
- 완료 영수증은 존재하지만 업로드 예약이 없는 상태

버전 324에서 추가한 예약·완료 영수증 결속이 이 두 상태도 닫는지 별도 단위·격리 런타임 회귀로 감사했다. 신규 단위 회귀는 첫 실행부터 23/23을 통과해 운영 코드 수정은 필요하지 않았다.

## 확인한 경계

- 예약·완료 영수증 중 하나라도 존재하면 두 원장이 모두 있어야 증명을 인정한다.
- `ready` 예약만 남은 파일과 완료 영수증만 남은 파일은 각각 한 `inconsistent` 항목으로 유지한다.
- 두 파일 모두 기존 FLOW 연결은 표시하되 저장 증명은 제거하고 전체 적용 현황의 `unavailable`에 포함한다.
- 개별 현재 R2 확인은 `head` 호출 전에 503으로 닫는다.
- 파일 ID 외의 명령 ID·행위자 키·지문·저장 키는 응답에 노출하지 않는다.
- 격리 실제 D1에서 영수증 행을 각각 제거한 뒤 같은 결과를 확인하고, 원장을 복구하면 SHA-256 증명이 정상 복귀한다.
- 자동 복구·삭제·운영 D1/R2 읽기나 쓰기와 새 마이그레이션은 추가하지 않았다.
