# Step 0 중복 실행·응답 유실 점검

2026-09-01. 사용자의 별도 `다음 진행` 요청에 따라 가상기업 Step 0의 중복 클릭, 동시에 들어온 요청, 저장 응답 유실과 실패 재시도를 점검했다. 실제 고객 자료와 외부 AI는 사용하지 않았다.

## 재현과 수정

기존 화면은 한 탭에서 요청 중 버튼을 비활성화했지만 서버에는 생성 요청 식별값과 진행별 실행 잠금이 없었다. 두 탭이나 응답 유실 뒤 재시도에서는 같은 입력이 외부 AI를 여러 번 호출하고 결과도 중복 저장될 수 있었다.

- 화면에서 생성 요청 ID를 만들고 성공 응답을 받을 때까지 같은 ID를 유지한다.
- 서버는 요청 ID, 관리자 계정, 진행, 기업, 가상 입력의 지문을 함께 확인한다.
- 기존 진단 실행 테이블에 `생성중` 상태를 먼저 원자적으로 저장하고, 진행별 `생성중` 고유 인덱스로 동시에 하나의 외부 호출만 허용한다.
- 같은 요청이 완료된 뒤 응답이 유실되어 재시도되면 외부 호출 없이 저장된 결과를 반환한다.
- 같은 요청 ID로 다른 내용을 보내거나, 같은 진행의 생성이 처리 중일 때 들어온 다른 요청은 HTTP 409로 차단한다.
- 외부 제공자 오류나 결과 저장 오류는 `생성실패`로 남긴다. 불확실한 실패 요청을 같은 ID로 자동 재실행하지 않으며, 대표가 입력을 다시 확인한 별도 요청만 새로 실행할 수 있다.
- 진행의 최신 Step 0 조회에서는 완료 결과만 반환하고 처리 중·실패 내부 레코드는 노출하지 않는다.

새 테이블·열과 보관·삭제 정책은 추가하지 않았다. 기존 `ai_diagnosis_runs` 테이블에 조건부 고유 인덱스만 추가하며, 기존 추가형 마이그레이션 8개와 DB/R2 연결을 유지한다.

## 가상 회귀 검증

모의 외부 응답을 지연시킨 상태에서 같은 요청 ID와 다른 요청 ID를 동시에 보냈다. 첫 요청만 모의 외부 호출에 도달했고 나머지는 HTTP 409로 끝났다. 완료 응답 유실을 가정한 동일 요청 재시도는 저장 결과를 재사용했고, 입력이 달라진 요청 ID 재사용은 차단됐다. 모의 제공자 실패는 자동 재호출되지 않았으며 별도의 명시적 요청만 실행됐다.

- 전체 Node 검사 202개, 타입검사, lint, 빌드가 통과했다.
- 격리 workerd/D1/R2 검사 110개가 통과했고 실제 외부 요청·유료 AI·운영 쓰기는 0건이었다.
- 검사·빌드 로그는 `outputs/validation/step-zero-idempotency-tests.log`, `step-zero-idempotency-worker.log`, `step-zero-idempotency-build.log`에 남겼다.
- 사용자 지침에 따라 브라우저 클릭 시험과 실제 AI 호출은 수행하지 않았다.
- 운영 반영 상태는 `outputs/release/step-zero-idempotency-deployment.json`에 기록한다. 기존 공개 범위와 D1/R2 연결을 유지한다.
