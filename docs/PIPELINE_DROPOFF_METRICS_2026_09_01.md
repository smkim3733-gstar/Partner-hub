# 진행 단계별 명시적 중단 지표

검수일: 2026-09-01
범위: 가상 예시를 제외한 신규 협업신청의 진행 단계별 명시적 중단

## 측정 정의

- 기능 반영 뒤 서버가 접수한 신규 신청만 생명주기 버전 1로 추적한다. 기존 진행은 현재 단계를 근거로 과거 경로를 추정하지 않고 `기존 측정 불가`로 분리한다.
- `진행 중단`은 장기 미진행이나 화면 체류로 추정하지 않는다. 대표가 현재 단계에서 명시적으로 중단한 경우만 센다.
- 단계별 도달 건수는 해당 단계 이상에 한 번이라도 도달한 건수다. 단계별 중단 건수는 바로 그 단계에서 중단된 건수다. 중단률은 `해당 단계 중단 ÷ 해당 단계 이상 도달`로 계산한다.
- 상담 FLOW 기록으로 확인된 단계와 일반 진행판에서 보고된 단계를 별도 계열로 표시한다. 두 계열을 합친 단일 중단률은 제공하지 않는다.
- 가상 예시 고정 ID는 제외한다. 삭제된 진행의 과거 사건은 남기지 않는 현재 상태 스냅샷이다.

## 서버 보호와 권한

- 생명주기 버전·상태·최고 도달 단계·단계 출처·중단 시각·중단 단계·재개 횟수는 서버가 소유한다. 일반 저장에서 위조하거나 지울 수 없다.
- 대표만 진행을 중단하거나 다시 열 수 있다. 중단된 동안 단계 선택과 상담 FLOW 쓰기·외부 처리 실행을 409로 차단하며 조회는 허용한다.
- 중단 뒤 같은 저장을 다시 보내도 최초 중단 시각을 유지한다. 응답 유실 뒤 기존 신청 본문으로 재시도해도 현재 서버 단계와 생명주기 값을 유지한다.
- 대표가 다시 열면 중단 시각과 중단 단계를 제거하고 재개 횟수를 1 늘린다. 다시 열기 전에는 중단 당시 단계가 바뀌지 않는다.
- 저장된 생명주기 값이 손상된 경우 일반 저장으로 덮어쓰지 않고 관리자 복구가 필요한 이상 상태로 집계한다.

## 개인정보·보존 경계

- 대표 전용 응답에는 단계별 합계, 추적·진행중·중단·재개·사후관리 도달·기존 측정 불가·이상 상태 수만 포함한다.
- 기업명, 담당자, 계정, 진행번호, 정확한 시각, 중단 사유는 지표에 포함하지 않는다. 중단 사유 입력란과 자유문자 저장도 추가하지 않았다.
- 새 D1 표나 별도 사건 이력을 만들지 않는다. 기존 운영 상태에서 현재 생명주기만 보존하므로 진행 삭제 시 이력도 함께 사라진다. 기존 DB/R2 연결과 보관·삭제 정책은 바꾸지 않는다.

## 검증 결과

- Node 회귀 검사 240개 통과.
- 격리 workerd + 실제 D1/R2 검사 129개 통과. 운영 쓰기, 메일 발송, 외부 처리, 외부 통신은 0건이다.
- 타입검사, lint, 프로덕션 빌드 통과. Sites 버전 저장 전 같은 커밋을 한 번 더 빌드한다.
- 가상 신규 신청의 서버 초기화, 클라이언트 위조 제거, 파트너 중단·재개 거부, 대표 중단·재개, 최고 단계 단조 증가, 응답 유실 재시도, FLOW 단계 출처, 중단된 FLOW의 동일 요청 재시도 차단, 관리자 전용 집계, 파트너 비노출을 확인했다.
- 브라우저 클릭 시험과 실제 고객 자료 조회는 수행하지 않았다.

## Duet 검수 반영

Duet가 지적한 상담 FLOW 단계의 서버 권위, FLOW 확인 단계와 수동 보고 단계의 분리, 단계 도달 분모, 응답 유실 재시도, 관리자 화면 표시, 중단 사유 최소화를 반영했다. 별도 사건 표 제안은 진행 삭제 뒤에도 중단 사건을 남겨 기존 보존 경계를 바꾸므로 적용하지 않았다.

최종 변경분에 `duet diff-review`를 실행했으나 네이티브 Windows에서는 Duet 고위험 차이 검수에 필요한 격리 검사 실행을 제공할 수 없어 완료 판정이 차단됐다. 계획 반론과 쟁점 해결은 완료했지만 최종 차이 검수를 완전 승인으로 표시하지 않는다. 코드 판정 근거는 위의 로컬 회귀 검사와 격리 workerd/D1/R2 결과다.
