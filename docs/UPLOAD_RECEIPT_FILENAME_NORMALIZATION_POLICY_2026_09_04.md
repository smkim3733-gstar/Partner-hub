# 업로드 멱등키·영수증 파일명 정규화 정책

## 목적

같은 파일을 다시 선택했을 때 운영체제나 브라우저가 한글 파일명을 NFC 또는 NFD로 다르게 전달해도 새 요청으로 오인하지 않고, 응답 유실 뒤 기존 저장 결과를 안전하게 복구한다.

## 적용 범위

- 진행 ID가 있는 협업신청 첨부의 멱등키 파일명을 공용 안전 파일명의 NFC 값으로 고정한다.
- 상담 FLOW 첨부 명령의 저장 영수증도 같은 NFC 파일명과 공용 등록표 MIME으로 지문을 계산한다.
- 독립 기업자료 업로드는 같은 `File` 선택 동안만 키를 유지하고 별도 등록을 구분하는 기존 의미를 유지한다.
- 신규 D1 기록에는 정규 키 또는 단일 정규 영수증 지문만 저장한다. 호환 후보는 요청 처리 중에만 계산하며 저장 응답에 노출하지 않는다.

## 이전 버전 호환

- 현재 요청 파일명의 원문·NFC·NFD 형태와 공용 MIME·브라우저 MIME 조합으로 제한된 이전 키 후보를 만든다.
- 서버는 공식 클라이언트의 현재 키 또는 호환 후보가 제출된 경우에만 정규 키를 사용한다. 임의 API 요청 키는 변경하지 않는다.
- 이전 `pending`, `ready`, `deleted` 원장이 한 건이면 같은 계정·파일 바이트·자료정보 지문을 확인한 뒤 정규 키로 조건부 이동한다.
- 같은 신청 첨부와 일치할 수 있는 이전 원장이 둘 이상이면 어느 원본도 임의 병합·삭제하지 않고 HTTP 409로 보존한다. 대표는 원본 보관 현황에서 확인한다.
- 상담 FLOW는 배포 전 원문 파일명과 브라우저 MIME으로 저장된 지문도 대조한다. 계정·명령·첨부 내용이 다르면 기존 HTTP 403·409 거절을 유지한다.

## 유지한 경계

파일 실제 내용·확장자·크기·저장 파일명·MIME·R2 키, 동의, 인증·권한, 담당 계정·진행 연결, D1 스키마, 보관·삭제 정책은 변경하지 않았다. 운영 원장이나 R2 원본을 일괄 조회·이관·삭제하지 않았다.
