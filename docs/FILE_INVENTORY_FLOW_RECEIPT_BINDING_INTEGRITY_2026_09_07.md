# 파일 재고 FLOW 완료 예약·영수증 결속 무결성

기준일: 2026-09-07

## 확인한 문제

완료 FLOW 첨부의 payload·소유·메타데이터·객체 무결성·체크섬 원장이 정상이어도 `consulting_flow_upload_requests`의 `ready` 예약 메타데이터나 `consulting_flow_upload_completions`의 완료 명령 ID가 어긋날 수 있다. 기존 재고 조회는 이 두 내구성 영수증을 정상 증명 조건에 결속하지 않아 손상 파일을 계속 `linked`·증명 있음으로 표시하고 현재 R2 확인도 허용했다.

새 단위 회귀는 다음 두 손상을 각각 재현했다.

- 예약의 원본 파일명이 불변 파일 메타데이터와 다른 상태
- 완료 영수증의 명령 ID가 예약과 다른 상태

수정 전에는 21개 중 20개 통과·1개 실패했고, 두 손상 파일의 메타데이터 증명 건수가 기대한 0이 아니라 2로 남은 `2 !== 0`을 기록했다.

## 적용한 경계

- 예약과 완료 영수증이 모두 없는 기존 완료 파일은 레거시 호환 대상으로 유지한다.
- 두 영수증 중 하나라도 있으면 `ready` 예약과 완료 영수증이 모두 존재하고 파일 ID·명령 ID가 일치해야 한다.
- 예약의 사건·저장 키·파일명·고정 MIME·크기·목적·신청자료 출처 필드·생성시각을 소유·메타데이터 원장과 정확히 대조한다.
- 예약 명령 ID가 같은 FLOW payload의 `commandIds`에 정확히 한 번 존재하고, 같은 키의 `commandReceipts` 한 건이 예약 행위자 키·지문과 일치해야 한다.
- payload JSON이 손상돼도 SQLite JSON 함수가 조회 전체를 중단하지 않도록 유효 JSON만 해석한다.
- 결속 실패 파일은 `inconsistent`·증명 없음으로 격리하고 전체 적용 현황의 `unavailable`에 포함한다.
- 개별 현재 R2 확인은 저장 키를 사용하거나 `head`를 호출하기 전에 503으로 닫는다.
- 명령 ID·행위자 키·지문·저장 키는 관리자 응답에도 새로 노출하지 않는다.
- 자동 수정·삭제·운영 D1/R2 읽기나 쓰기와 새 마이그레이션은 추가하지 않는다.

후보 SQL은 실제 D1의 compound SELECT 항 제한을 유지하도록 최상위 후보 분기를 늘리지 않고 기존 FLOW 소유 후보의 결속 조건만 강화했다.
