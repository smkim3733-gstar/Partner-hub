# 기업자료 원본 메타데이터 무결성 경계

기준일: 2026-09-05

## 확인한 문제

기업자료 카드의 선택적 원본 연결값은 공통 상태 구조 검사만 통과하면 저장될 수 있었다. 원본 ID만 있고 파일명·크기가 없거나, 안전하지 않은 파일명·비정상 크기·중복 원본 ID·자료 종류와 맞지 않는 확장자도 일반 상태 저장과 손상 상태 조회 경계에서 확정적으로 거절하지 못했다. 이미 회수한 원본 카드도 회수 증적 필드 밖의 원본 연결·파일명·크기·기업·진행 연결을 일반 저장으로 제거하거나 바꿀 여지가 있었다.

실제 포털 상태가 보관하는 원본 메타데이터는 `storageFileId`, `fileName`, `fileSize`다. MIME, 업로드 시각, 보안 저장 여부는 포털 상태에 중복 저장하지 않고 D1 파일 원장과 비공개 R2가 기준이다.

## 적용한 경계

- 원본이 없는 요청 카드와 안전한 파일명만 표시하는 기존 레거시 카드는 유지한다.
- 원본 ID가 있으면 안전한 파일명과 0보다 큰 제한 이내 정수 크기가 모두 있어야 한다.
- 원본 ID는 공백 없는 제한된 영문·숫자·하이픈 형식이어야 하며 같은 상태에서 중복될 수 없다.
- 파일명은 서버 안전 파일명 정규화를 그대로 통과해야 하고 파일 형식은 기업자료 종류의 기존 허용 목록과 맞아야 한다.
- 파일 크기만 단독으로 저장하거나 빈·경로 이동·비정규화 파일명, 0·소수·과대 크기를 저장하지 못한다.
- 기존 원본 연결 카드의 문서 ID·원본 ID·파일명·크기·기업·제목·자료 종류·안정 담당 계정·진행 연결은 일반 상태 저장으로 제거하거나 바꾸지 못한다.
- 검토 상태·수정시각과 파트너 표시명 동기화는 유지한다. 표시명 변경은 안정 담당 계정 ID를 바꾸지 않는다.
- 손상 입력은 403, 이미 저장된 손상 상태는 파트너 조회 403, 관리자 조회와 일반 저장 503으로 격리한다. 기존 원본 사실 변경은 409 충돌로 거절하고 익명 충돌 집계에 별도 분류한다.
- 운영 데이터 자동 수정·이동·삭제, D1/R2 스키마와 보관 정책 변경은 수행하지 않았다.

## 검증

- 수정 전 재현: 불완전·중복·비정상 원본 메타데이터와 기존 원본 사실 변경이 공용 경계에서 차단되지 않았다.
- 수정 후: 파일 없는 요청과 안전한 레거시는 유지하며 손상 조합과 기존 원본 사실 변경은 저장 전 실패하고 상태를 보존한다.
- 관리자와 파트너의 검토 상태 변경, 파트너 표시명 변경 뒤 계정 ID 기반 업무 저장은 계속 성공한다.
- Node 자동 테스트 550/550 통과.
- 격리 workerd+D1+R2 검사 336/336 통과.
- 타입검사, 전체 lint, 프로덕션 빌드 통과.
- 로컬 프로덕션 `/`, `/account`, `/account/setup` HTTP 200 확인.
- 실제 운영 쓰기, 메일 발송, 유료 AI 요청, 외부 요청 0건.

## 다음 감사

새로 추가되는 완전한 원본 연결이 D1 파일 원장의 실제 파일 ID·파일명·크기·기업·자료 종류·담당 계정·진행과 일치하는지 저장 직전에 확인한다. 삭제·업로드 대기·미완료 원본은 일반 상태 저장으로 연결하지 못하게 하되, 파일 없는 요청 카드와 검증된 기존 원본은 보존하고 실제 원본을 자동 변경하지 않는다.
