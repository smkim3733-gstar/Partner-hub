# 파트너 접속 통계 무결성·가용성 경계

기준일: 2026-09-05

## 점검 목적

파트너가 포털 운영정보를 새로 불러올 때마다 `login_count`가 증가해 한 번의 접속 중 발생한 새로고침과 자동 재조회까지 별도 로그인으로 집계됐다. 접속 통계 D1 쓰기 실패도 인증과 운영정보 조회가 성공한 요청 전체를 HTTP 500으로 바꿀 수 있었다. 대표 화면의 접속 기록을 실제 의미에 맞게 보정하고, 비핵심 통계 장애가 파트너 업무를 막지 않게 한다.

## 반영 내용

- 동일 파트너가 30분 안에 다시 운영정보를 조회하면 최근 접속시각만 갱신하고 누적 접속 세션 수는 유지한다.
- 마지막 접속 뒤 30분 이상 비활동 상태에서 다시 조회할 때만 누적 접속 세션을 1회 증가시킨다.
- D1의 단일 `INSERT ... ON CONFLICT DO UPDATE` 문장에서 현재 저장시각을 비교하므로 동시에 도착한 새로고침도 한 세션으로 집계한다.
- Worker 시계가 일시적으로 뒤로 움직여도 저장된 최근 접속시각이 과거로 후퇴하지 않게 했다.
- 접속 통계 테이블 쓰기가 실패해도 인증된 파트너의 포털 조회는 계속한다. 서버 로그에는 고정 작업 문맥과 `Error.name`만 남기며 요청·계정·예외 메시지는 기록하지 않는다.
- 대표 화면의 `누적` 문구를 `누적 접속 세션`으로 바꿔 값의 의미를 명확히 했다.

기존 통계 행을 삭제하거나 다시 계산하지 않는다. 과거에 이미 누적된 수치는 유지하고 새 배포 이후 증가 규칙만 교정한다. 인증·권한, 회원 상태, 운영 D1/R2 연결, 보관·삭제 정책은 변경하지 않는다.
