# 1차 보고서 사전점검 응답 검증 안전성

2026-09-04 기준으로 유료 AI 1차 보고서 생성 전에 표시하는 사전점검 API 응답의 클라이언트 검증을 보강했다.

## 변경 범위

- 사전점검 응답을 `unknown`으로 읽고 일반 JSON 객체인지 먼저 확인한다.
- 응답 진행 ID와 revision이 현재 화면의 진행·revision과 같은지 확인한다.
- 점검시각·모델·기존 보고서 여부와 요약 글자 수·선택 파일 수·제외 파일 수·전체 바이트를 범위 안에서 검증한다.
- 파일 ID·이름·크기·MIME·신청자료 검토본 여부를 검증하고 중복 ID를 차단한다.
- 응답 파일 수와 실제 파일 배열 길이, 전체 바이트와 각 파일 크기 합계가 정확히 같은지 확인한다.
- 분석자료 구성·저장 파일/텍스트·외부 AI/비용 승인·API 키·진행 단계의 5개 필수 검사가 모두 한 번씩 존재하고 고정 라벨·이동 대상·통과값을 갖는지 확인한다.
- `canGenerate`는 5개 검사 전체 통과와 같아야 하며, 자료 구성 통과값은 요약 또는 파일 존재·파일 8개 이하·합계 8MB 이하 계산과 같아야 한다.
- 대표가 확인해야 할 5개 고정 안내를 서버와 클라이언트가 공용 상수로 사용한다. 누락·교체된 안내로 유료 생성 확인을 활성화하지 않는다.
- 검증된 공개 필드만 새 객체로 반환한다. 저장소 키·API 키 등 알 수 없는 필드는 화면 상태로 전달하지 않는다.
- 실패 응답은 길이가 제한된 서버 오류만 유지한다. 비-JSON 또는 손상된 성공 응답은 진행 새로고침 후 재점검을 안내한다.

## 유지한 안전 경계

- 사전점검은 대표 관리자 전용 읽기이며 파일 본문 저장·상담 완료·AI 호출을 하지 않는다.
- 실제 생성 전 브라우저 확인, 기업별 외부 처리·마스킹·비용 동의와 서버의 최신 자료·권한·진행 상태 재검증을 유지한다.
- API 키 유효성·잔액·정확한 요금은 점검으로 보장하지 않으며 보고서 최종 승인·고객 전달은 자동 처리하지 않는다.
- 실제 자료, 운영 데이터, D1/R2 스키마, 권한·보관 정책과 공개 배포 상태를 변경하지 않았다.

## 검증

- 자동 테스트 404개
- 격리 workerd/D1/R2 검사 129개
- TypeScript 타입검사, 전체 lint, 프로덕션 빌드
- localhost `/` HTTP 200

모든 신규 응답 검사는 가상 자료 메타데이터와 합성 응답으로 실행했다. 실제 자료 열람·운영 쓰기·메일·유료 AI·외부 요청은 0건이다. GitHub 푸시와 공개 Sites 배포는 사용자 승인 전까지 수행하지 않는다.
