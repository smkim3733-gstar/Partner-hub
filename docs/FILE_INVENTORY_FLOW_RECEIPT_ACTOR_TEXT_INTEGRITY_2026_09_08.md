# 파일 재고 FLOW 영수증 행위자 텍스트 무결성

기준일: 2026-09-08

## 문제

완료 FLOW 업로드 재고는 현대 영수증과 연결 감사기록의 `actor`가 정확히 같은지는 확인했지만, 두 값을 함께 바꾸면 텍스트 자체의 의미는 검사하지 않았다. 실패 우선 회귀에서 ECMAScript 공백 집합만 있는 두 값은 정상 증명을 유지하고 개별 확인이 R2 `head`까지 한 번 진행했다. 공유 상한보다 긴 값과 짝 없는 UTF-16 서로게이트도 같은 경계를 통과했다.

## 적용

- 현대 영수증 `actor`를 필수 JSON 텍스트와 공유 `FLOW_FIELD_LIMITS.actor` 상한인 Unicode 코드포인트 200자로 결속한다.
- ECMAScript `trim`과 같은 탭·개행·일반 공백·NBSP·Unicode 공백·BOM 집합을 제거한 뒤 내용이 하나 이상 남는지 확인한다.
- JSON1이 짝 없는 서로게이트를 변환한 잘못된 UTF-8 바이트 `ED A0..BF 80..BF`를 `hex` 패턴으로 탐지해 거절한다.
- 감사기록 `actor`가 영수증 값과 정확히 같아야 하는 기존 결속을 유지해 두 원장의 공동 변조도 같은 텍스트 경계에서 차단한다.
- 손상 값은 한 `inconsistent`·증명 없음 항목으로 격리하고 `unavailable`에 포함하며 R2 `head` 전에 503으로 닫는다.
- 기존 D1/R2 데이터, 스키마, 마이그레이션은 자동 수정·삭제하지 않는다.

## D1 깊이 안전성

현대 영수증 분기에 추가한 `actor` 조건은 필수 텍스트·길이·공백·Unicode 검사를 하나의 `CASE` 잎으로 묶는다. 버전 342에서 실제 D1 표현식 깊이 100 제한을 통과하도록 만든 균형 괄호 트리를 보존하며 전역 CTE나 전체 물질화는 추가하지 않았다.
