# AI 진단 완료 결과 envelope 무결성 경계

기준일: 2026-09-05

## 문제

Step 0 AI 응답 파서는 잘못된 배열 항목을 제거하고 초과 항목을 잘라 정상 결과처럼 저장했다. D1 완료 전이도 필수 컨테이너 종류만 확인해 숫자 배열 항목, 예상 밖 키, 과도한 문자열과 대용량 결과를 직접 저장할 수 있었다. 이 경우 대표 검토 화면에는 공급자 원문과 다른 불완전한 진단이 표시되거나 원장 용량이 비정상적으로 커질 수 있었다.

## 적용

- 파서는 5개 문자열 배열과 해결안 배열을 모두 필수로 요구하고 잘못되거나 초과한 항목을 조용히 버리지 않는다.
- 기업 현황·다음 행동은 각각 12,000자, 배열은 각각 20개, 해결안은 10개, 개별 문자열은 4,000자 이하로 제한한다.
- 해결안은 정확한 `solution`, `basis`, `condition` 키만 허용하며 앞뒤 공백을 제거한 정규 결과만 저장한다.
- 요청 지문을 포함한 저장 envelope는 320,000 UTF-8 바이트 이하로 제한한다.
- `0034_ai_diagnosis_result_envelope.sql`과 런타임 준비 트리거는 완료 결과의 정확한 9개 루트 키, 배열·해결안 구조, 문자열 길이와 저장 바이트를 D1에서도 같은 계약으로 강제한다.
- 기존 완료 원장은 바꾸지 않고 이후 `생성중 → 대표 검토 대기` 저장만 보호한다.

## 검증

- 누락 배열, 숫자·공백 배열 항목, 배열·문자열 개수 초과, 잘못된 해결안과 320,000바이트 초과 응답이 모두 거절된다.
- D1 직접 완료에서 숫자 항목과 예상 밖 루트 키가 거절되고 원래 생성중 행이 그대로 남는다.
- 정상 결과는 공백 정규화 뒤 정확한 계약으로 저장·재조회된다.
- 35개 추가형 마이그레이션을 기존 상태가 있는 격리 D1에 반복 적용해도 기존 상태를 교체하지 않는다.
- Node 회귀 검사 640/640 통과
- 격리 workerd/D1/R2 검사 446/446 통과
- 타입검사, 전체 lint, 변경 파일 포맷, 프로덕션 빌드 통과
- 로컬 운영 Worker `/`, `/account`, `/account/setup` HTTP 200과 CSP, `X-Frame-Options: DENY`, `nosniff`, `no-referrer` 확인
- 실제 운영 쓰기, 이메일 발송, 유료 AI 요청, 외부 요청 0건
