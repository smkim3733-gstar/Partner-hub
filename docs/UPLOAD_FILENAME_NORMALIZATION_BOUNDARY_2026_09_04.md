# 업로드 파일명 정규화 보안 경계

## 목적

기업자료와 상담 FLOW가 저장하는 파일명에 서로 다른 정리 규칙을 적용하지 않도록 하고, 제어문자·경로 구분자·손상된 유니코드와 코드 포인트 절단을 공용 경계에서 처리한다.

## 적용 범위

- 파일명은 NFC 유니코드로 정규화한다.
- `/`, `\\`, ASCII 제어문자, DEL, 단독 서로게이트를 `_`로 중화한다.
- UTF-16 코드 단위가 아닌 유니코드 코드 포인트 기준 180자로 제한해 이모지·보조 평면 문자를 중간에서 자르지 않고 허용 확장자는 보존한다.
- 기업자료 원본 이름, 상담 FLOW 첨부 이름, 신청자료 검토본 이름이 같은 `safeFileName` 경계를 사용한다.

## 유지한 경계

파일 내용·확장자·크기·MIME·R2 키, 업로드 동의·인증·권한 재확인, D1/R2 스키마와 보관 정책은 변경하지 않았다. 다운로드 시 파일명은 기존 RFC 5987 경계에서 다시 보호한다.

## 재발 방지

조합형 유니코드·제어문자·경로 구분자·단독 서로게이트, 180개 이모지 경계와 긴 이름의 확장자 보존을 자동 테스트로 고정하고, 상담 FLOW가 별도 파일명 정리 구현 대신 공용 함수를 사용하도록 했다.

## 검증 결과

- 관련 파일명·상담 FLOW 회귀검사 31개 통과
- 전체 자동 테스트 445개 통과
- 격리 workerd/D1/R2 검사 129개 통과
- TypeScript 타입검사, 전체 lint, 프로덕션 빌드 통과
- 격리검사 중 운영 쓰기, 메일, 유료 AI, 외부 요청 0건

자동 운영 승인 원칙에 따라 검증한 커밋을 GitHub `main`과 기존 공개 Sites에 순차 반영하고 배포 결과를 별도 기록한다.
