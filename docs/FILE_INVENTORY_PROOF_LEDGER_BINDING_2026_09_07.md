# 관리자 파일 재고 증명 원장 결속 무결성

## 결과

대표 파일 재고의 체크섬 적용 현황은 체크섬 행의 형식만으로 증명을 인정하지 않는다. 기업자료는 부모 파일, 불변 메타데이터, 저장 키, 객체 무결성 원장이 모두 정확히 일치해야 한다. FLOW 첨부는 소유 원장과 실제 FLOW payload의 파일 항목까지 정확히 한 건으로 결속돼야 한다. 하나라도 누락되거나 어긋나면 SHA-256·ETag·메타데이터 증명으로 과대 분류하지 않고 `증명 불가`로 집계한다.

기능 커밋은 `87ff1158226bb4857c3040f447f82a7a3c8ea44b`이다.

## 재현과 수정

- 수정 전에는 유효한 SHA-256 파일 1건과 MIME이 어긋난 기업자료, 잘못된 저장 키를 가진 기업자료, 실제 FLOW payload가 없는 고아 FLOW 원장을 함께 조회하면 네 건 모두 SHA-256 증명으로 집계됐다.
- 기업자료 증명은 `company-source/{fileId}` 저장 키, 부모와 메타데이터 원장의 10개 불변 필드, 저장 키 원장, 객체 무결성 원장과 MIME 일치를 모두 요구한다.
- FLOW 증명은 `consulting-flow/{fileId}` 저장 키, 메타데이터·객체 무결성 원장, MIME 일치와 함께 같은 사건의 실제 `consulting_flows.payload.files`에 ID·키·생성시각·이름·MIME·크기·목적·신청자료 출처 필드가 정확히 한 건 존재해야 한다.
- 손상되거나 유효하지 않은 FLOW JSON은 빈 파일 배열로 취급해 증명을 인정하지 않는다.
- 증명 분류는 기존 단일 SQLite 문장과 읽기 스냅샷 안에서 수행한다. 별도 R2 본문 읽기나 스키마 변경은 없다.

## 검증

- 수정 전 회귀에서 SHA-256 4건 과대 집계 재현
- 수정 후 유효한 1건만 SHA-256, 손상된 3건은 증명 불가로 집계
- 손상된 기업자료 개별 항목도 `inconsistent`와 증명 없음으로 유지
- Node 회귀 테스트 766/766
- 격리 workerd·D1·R2 527개 검사와 98개 추가형 마이그레이션 2회 적용 통과
- 타입검사, 전체 lint, 변경 파일 포맷, 프로덕션 빌드 통과
- 로컬 Worker 공개 화면 3곳 200, 비인증 보호 API 3곳 401, CSP·프레임 차단·`nosniff`·`no-referrer`·API `private, no-store` 확인
- 검증 중 운영 데이터 쓰기, 메일 발송, 유료 AI 요청, 외부 업무 요청 0건

## 운영 경계와 다음 감사

GitHub `main`에는 반영했다. Sites 소스 전송과 공개 운영 배포는 별도 외부 변경이므로 버전 316 명시 승인 전에는 수행하지 않는다. 현황 집계는 의도적으로 D1 불변 원장만 검증하므로 현재 R2 객체의 실재·크기·MIME·ETag·SHA-256을 실시간 확인한 결과와는 구분된다. 다음 감사는 화면의 증명 용어와 R2 존재 확인 결과가 이 경계를 오해 없이 전달하는지 검토한다.
