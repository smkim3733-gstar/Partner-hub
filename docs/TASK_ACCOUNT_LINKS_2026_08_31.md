# 진행판·업무목록의 담당 계정 정리 — 2026-08-31

## 변경 범위

서버가 계정 ID로 허용한 진행과 업무를 화면에서 이름으로 다시 거르지 않는다. 이름이 변경된 계정의 기존 진행·업무와 진행 ID만 연결된 후속업무도 목록과 알림 집계에 남는다. 이는 화면 표시 정비이며 서버의 접근 권한 검사를 제거한 것이 아니다.

대표의 진행판 담당자 필터는 이름·이메일·계정 상태로 구분한다. 동명이인을 따로 선택할 수 있고, ‘대표 전용’과 ‘담당 계정 확인 필요’를 분리해 볼 수 있다. 정지·승인대기 계정은 과거 진행 필터에서 확인할 수 있지만 새 업무의 담당자로 지정할 수 없다.

직접 등록한 업무에는 선택한 담당 계정 ID를 저장한다. 파트너는 로그인한 본인 계정에만 등록하며, 대표는 담당 계정 또는 대표 전용을 선택한다. 상담 후속업무와 요청서류 확인 업무에는 진행 ID도 함께 저장한다. 진행판·업무 카드의 담당자 이름은 연결된 계정의 현재 이름을 사용한다.

진행 ID만 있고 과거 담당 이름이 없는 후속업무의 완료 저장도 처리한다. 서버에서 해당 진행이 본인에게 배정되어 있는지 먼저 확인하고, 기존 업무의 소유권 확인은 그대로 유지한다. 다른 계정의 진행 ID나 담당 ID를 제출해 업무를 가져갈 수 없다.

## 확인

이름 변경 전후의 상태 API 왕복, 업무 완료 처리, 동명이인 구분, 미확정 과거 자료, 대표 전용, 정지·승인대기·중복 계정 선택 거부를 자동 검증한다. 진행에만 연결된 업무의 완료 저장 실패는 수정 전 재현했다.

격리 workerd/D1/R2 검증은 총 46개다. 실제 파트너 계정·고객 데이터·운영 쓰기·메일 발송·유료 AI는 검증에 사용하지 않는다. 브라우저 클릭 검증이나 서비스 전체 보안감사는 포함하지 않는다. 이번 변경은 DB 스키마를 추가하거나 과거 담당자를 일괄 이관하지 않는다.

선행 파일 연결 변경은 공개 버전 35에서 완료됐으며 소스는 `32d4cd8`이다. 본 변경의 최종 배포 결과는 배포 이력과 로컬 `outputs/release/` 완료 기록으로 구분한다.

## 후속 점검 후보

- 같은 기업으로 협업신청을 다시 할 때 신규 진행·타임라인·첨부의 연결이 유지되는지 확인.
- 기존 이름 기반 요청서류와 일정의 화면 연결 정리. 담당자가 모호한 과거 자료는 자동 재배정하지 않음.
- 대상 파트너를 정한 뒤 실제 로그인·업무 처리 파일럿. 실제 계정 승인·연락·자료 제출은 범위를 정한 후 수행.
