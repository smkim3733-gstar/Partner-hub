# 상담 FLOW 응답 검증 안전성

## 문제

상담 FLOW 화면은 조회·저장·AI 대기 실행의 JSON을 타입 단언만으로 사용했다. 서버나 중간 연결이 HTTP 200과 함께 비어 있거나 손상된 JSON을 반환하면 `flow`를 잘못된 값으로 바꾼 뒤 화면 오류를 낼 수 있었다. AI 실행의 비-JSON 응답은 브라우저 기본 영문 오류로 표시될 수도 있었다.

## 변경

- FLOW 조회 성공 응답은 FLOW 핵심 구조, 역할, 업로드 권한과 AI 준비상태를 공용 검증기로 확인한다.
- FLOW 저장·안전 재시도·AI 대기 실행 성공 응답은 더 좁은 저장 응답 계약과 FLOW 핵심 구조를 확인한다.
- FLOW의 스키마 버전·진행·기업·담당·revision과 필수 배열, 공동분석·AI 설정 구조가 없거나 잘못되면 화면 상태를 바꾸기 전에 차단한다.
- HTTP 오류의 상태와 안전한 서버 안내를 보존한다. 409 저장 충돌은 기존 최신 FLOW 재조회 절차를 유지한다.
- 읽을 수 없는 조회·저장·AI 실행 응답과 잘못된 성공 응답은 각각 한국어 복구 안내로 구분한다.

## 유지한 운영 경계

- 서버 FLOW 명령·권한·요청 영수증·중복 방지·AI 실행 규칙과 공개 투영 내용을 변경하지 않았다.
- 잘못된 응답을 자동 재전송하거나 저장 결과로 추정하지 않는다.
- 운영 데이터·DB/R2 스키마·인증·권한·보관 정책, 외부 발송·유료 AI 설정을 변경하지 않았다.
- GitHub 푸시와 공개 Sites 배포는 사용자 승인 전까지 수행하지 않는다.

## 검증

- 자동 테스트: 344개 통과
- 격리 workerd/D1/R2 스모크: 129개 통과
- TypeScript `--noEmit`, 전체 lint, 프로덕션 빌드 통과
- 기존 개발 서버 `/` 응답: HTTP 200
- 검증 중 운영 쓰기·메일 발송·유료 AI·외부 요청: 각 0건
