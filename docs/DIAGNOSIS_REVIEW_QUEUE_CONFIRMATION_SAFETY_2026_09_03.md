# 가상 진단 검토대기 등록 확인 안전성

## 문제

AI 진단 화면의 `1차 초안 검토대기 등록`은 한 번 누르면 `diagnosisAssessments`, `timeline`, `tasks`를 즉시 바꾸고 상위 자동저장으로 이어졌다. 생성 업무는 현재 시각 기반 ID를 사용하고 명시적인 관리자 전용 담당 계정도 없어서, 가상 진단에서 파생된 업무가 운영 알림·지표 후보에 섞일 수 있었다.

## 변경

- 등록 버튼은 원본 상태를 바꾸지 않고 확인 초안만 만든다.
- 확인창에서 가상 기업·진행, 최신 A 판정, 오늘 마감 대표 검토업무와 저장 영향을 확인해야 적용할 수 있다.
- 취소하거나 확인창을 닫으면 초안을 폐기하고 기존 진단·타임라인·업무를 유지한다.
- 적용 직전 관리자 역할, 진단·진행 ID, 기업명, 최신 A 판정, 근거·동의 상태를 다시 검사한다.
- 고정 가상 진단과 정확히 연결된 고정 가상 진행만 허용하고, 같은 진행의 열린 검토업무나 고정 ID 충돌은 거절한다.
- 파생 업무는 진단별 결정적 예약 ID와 빈 `partnerMemberId`를 사용해 관리자 전용 가상 기록임을 명시한다.
- 타임라인도 진단별 결정적 ID를 사용하고, 진단·전체 업무·전체 타임라인을 하나의 계산 결과로 함께 반영해 같은 확인의 빠른 이중 실행을 중복 적용하지 않는다.
- 동일 진행의 기존 ID 없는 검토대기 타임라인은 유지하고 중복 생성하지 않는다. 안정 ID가 다른 진행과 충돌하면 전체 적용을 차단한다.
- 파생 업무 ID를 정확한 가상 시드 목록에 포함해 운영 알림·지표에서 제외하고, 파트너가 같은 ID로 운영 업무를 만드는 것도 차단한다.

## 유지한 운영 경계

- 가상 시드 진단 전용이다. 운영 진단·진행에는 적용하지 않는다.
- 실제 AI 호출·외부 전송·메일·유료 API를 실행하거나 추가하지 않았다.
- 기존 진단 판정 규칙, 운영 업무, 서버 API, 인증·권한, revision/CAS, DB/R2 스키마·보관 정책을 변경하지 않았다.
- 과거에 이미 저장된 시각 기반 가상 파생 업무 ID는 운영 데이터 변경 위험 때문에 자동 이관하지 않았다. 이후 생성분부터 고정 가상 ID를 사용한다.
- GitHub 푸시와 공개 Sites 배포는 사용자 승인 전까지 수행하지 않는다.
