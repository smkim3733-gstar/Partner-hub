# Step 0 응답 저장 직전 상태 재검증

2026-09-01. 사용자의 별도 `다음` 요청에 따라 외부 AI 응답 대기 중 동의나 근거 원본이 변경되는 경우를 점검했다. 실제 고객 자료와 외부 AI는 사용하지 않았다.

## 재현과 수정

기존 서버는 외부 요청 직전에 현재 진행·담당·동의와 D1/R2 원본을 확인했지만, 외부 응답을 받은 뒤 결과를 저장할 때는 같은 검사를 반복하지 않았다. 따라서 요청을 시작한 뒤 녹취 활용 동의가 철회되거나 필수 R2 원본이 사라져도 결과가 `대표 검토 대기`로 저장될 수 있었다.

- 외부 응답을 파싱한 뒤 결과 저장 직전에 포털 상태와 실행 계정 권한을 다시 읽는다.
- 같은 관리자 계정인지, 현재 진행·기업·담당 연결이 유지되는지 다시 확인한다.
- A 판정과 개인정보·제3자 AI·녹취 활용 동의가 계속 유효한지 확인한다.
- 필수 사업자등록증 및 재무·신용 자료의 D1 연결과 R2 원본 존재·크기를 다시 확인한다.
- 하나라도 바뀌었으면 완료 결과를 저장하지 않고 실행 레코드를 `생성실패`로 격리한다.
- 상태가 바뀐 요청은 같은 요청 ID로 자동 재실행하지 않는다. 대표가 조건을 다시 확인한 별도 요청만 가능하다.

이미 유효한 동의 아래 시작된 외부 전송 자체는 사후에 되돌릴 수 없다. 이번 보완은 변경된 조건의 응답이 운영 화면과 완료 이력에 남는 것을 차단한다. AI 제공자·비용·파일 보관 정책과 DB/R2 구조는 변경하지 않았다.

## 가상 회귀 검증

모의 외부 응답 함수 안에서 포털의 녹취 활용 동의를 철회한 경우와 재무자료 R2 원본을 제거한 경우를 각각 재현했다. 두 요청 모두 모의 응답은 반환됐지만 HTTP 409로 끝났고 완료 결과가 저장되지 않았으며, 실행 레코드는 `생성실패`로 남았다. 같은 요청 ID 재시도도 외부 호출 없이 차단됐다.

- 전체 Node 검사 202개, 타입검사, lint, 빌드가 통과했다.
- 격리 workerd/D1/R2 검사 110개가 통과했고 실제 외부 요청·유료 AI·운영 쓰기는 0건이었다.
- 검사·빌드 로그는 `outputs/validation/step-zero-final-state-tests.log`, `step-zero-final-state-worker.log`, `step-zero-final-state-build.log`에 남겼다.
- 사용자 지침에 따라 브라우저 클릭 시험과 실제 AI 호출은 수행하지 않았다.
- 운영 반영 상태는 `outputs/release/step-zero-final-state-deployment.json`에 기록한다. 기존 공개 범위와 D1/R2 연결, 추가형 마이그레이션 8개를 유지한다.
