# 상담 FLOW 재시도 접근권한 회수 무결성

기준일: 2026-09-07

## 확인한 위험

파트너의 2슬롯 업로드가 첫 객체만 저장한 채 실패한 뒤 계정이 정지되거나 업로드 권한이 회수되면, 이전 요청의 예약을 이용한 재시도가 남은 R2 객체를 쓰거나 FLOW를 완료할 위험이 있다.

## 확인한 현재 경계

- 활성·업로드 허용 파트너의 첫 전사문 객체 저장 성공과 두 번째 음성 저장 실패를 결정적으로 재현했다.
- 실패 뒤 파트너 계정을 정지한 경우와 계정은 유지하되 업로드 권한만 회수한 경우를 각각 재현했다.
- 두 재시도 모두 HTTP 403으로 거절되고 R2 `put`을 한 번도 호출하지 않는다.
- 거절된 요청은 FLOW 본문, 기존 전사문 객체 바이트와 두 `pending` 예약의 파일 ID·R2 키·상태를 그대로 보존한다.
- 계정을 다시 활성화하고 업로드 권한을 복구한 뒤 원래 명령 ID·본문·첨부를 보내면 같은 두 파일 ID·R2 키로 완료되고 예약과 완료 원장이 원래 파트너 명령에 결속된다.

기존 구현이 요구 경계를 만족해 런타임 코드는 바꾸지 않고 권한 회수 우회 방지 회귀 증거를 추가했다.
