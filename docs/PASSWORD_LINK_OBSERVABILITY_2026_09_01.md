# 비밀번호 설정 링크 운영 지표

2026-09-01. 사용자의 Duet 검수·구현 승인에 따라 파일럿에서 비밀번호 설정 링크의 발급·재발급·완료 흐름을 확인할 수 있는 개인정보 최소 집계를 추가했다. 실제 계정 생성, 실제 고객 명단 조회, 메일 발송, 운영 데이터 삭제는 수행하지 않았다.

## 구현 범위

- 링크 발급, 아직 유효한 링크의 교체, 만료된 미사용 링크 뒤 재발급, 설정 완료, 서버에 남은 만료 링크의 제시를 한국시간 기준 날짜별 건수로 합산한다.
- 사용자 ID·이름·이메일·관리자·토큰·토큰 해시·IP·요청 ID·정확한 이벤트 시각·요청 본문을 집계 테이블에 저장하지 않는다.
- 관리자 상태 API에는 최근 7일의 합계만 최상위 `passwordLinks`로 제공한다. 일별 원시 행은 보내지 않으며 `PortalState`와 파트너 응답에는 포함하지 않는다.
- 파트너 계정관리 화면에서 발급, 활성 링크 교체, 만료 후 재발급, 설정 완료, 관측된 만료 시도를 함께 표시한다.
- 이미 사용된 링크를 다시 제시한 경우는 만료 시도에 포함하지 않는다.

## 인증과 장애 경계

- 기존 30분 만료, 일회용 링크, 관리자 본인 확인, URL fragment 전달, 메일 자동발송 없음, 비밀번호 변경 뒤 기존 세션 폐기를 바꾸지 않는다.
- 링크 조회는 토큰 해시로 한 번 수행하고 만료 여부를 코드에서 판정한다. 실제 상환은 기존 D1 조건과 변경 행 수 검사로 다시 보호한다.
- 집계 테이블 DDL은 `portalPasswordSchemaSql`에 넣지 않는다. 인증 경로가 관측용 테이블 준비 상태에 의존하지 않도록 기록·관리자 요약 함수 안에서만 준비한다.
- 지표 쓰기는 `waitUntil` 작업으로 분리하며 예약·DDL·쓰기 실패가 링크 발급, 일반화된 오류, 설정 완료 응답을 바꾸지 않는다.
- 관리자 요약 읽기도 실패 시 `null`로 격리하여 운영 상태 전체 조회를 실패시키지 않는다.

## 지표 해석 경계

- `관측된 만료 시도`는 만료된 미사용 행이 서버에 남아 있을 때 사용자가 제시한 경우만 센다.
- 기존 발급 로직은 새 링크를 만들 때 해당 회원의 이전 행과 전체 만료 행을 삭제한다. 따라서 이미 정리된 링크의 제시는 알 수 없으며 만료 관련 수치는 실제 만료의 하한값이다.
- `만료 후 재발급`도 재발급 직전 해당 회원의 만료 행이 남아 있을 때만 센다. 다른 발급 과정에서 전역 정리된 행은 복원하거나 추정하지 않는다.
- 집계는 운영 병목과 안내 개선을 판단하는 보조 지표이며 개인 평가 자료로 사용하지 않는다.
- 일별 집계의 보존 기간과 정리 담당은 아직 확정하지 않았다. 이번 변경은 자동 삭제나 고객 자료 보관 정책을 추가·변경하지 않는다.

## Duet 검수 반영

Duet은 관측 테이블 DDL을 인증 스키마에 넣으면 지표 장애가 로그인·가입·설정을 막을 수 있다는 점과, 기존 만료 행 전역 삭제로 만료 건수가 과소 계상된다는 점을 지적했다. DDL을 지표 경로에만 두고, 발급 전 기존 행을 활성·만료 미사용으로 분류해 `활성 링크 교체`와 `만료 후 재발급`을 나눴다. 관리자 읽기 실패도 격리하고, 만료 관련 수치가 하한값이라는 설명을 화면과 문서에 표시했다. 토큰 존재에 따른 추가 조회는 만들지 않았다.

## 검증

- Node 회귀검사 221개 통과
- 격리 workerd/D1/R2 검사 116개 통과
- 추가형 마이그레이션 11개를 두 번 적용하고 기존 상태 보존 확인
- 최초 발급, 활성 링크 교체, 만료 후 재발급, 만료 제시, 설정 완료의 가상 데이터 집계 확인
- 만료·존재하지 않는 토큰의 동일 오류 응답, 사용 링크 재시도 거부, 동시 상환 1회 성공 확인
- 지표 DDL·예약 실패 시 링크 발급 유지, 관리자 요약 실패 시 상태 응답 유지 확인
- 관리자 최상위 합계, 파트너 응답과 `PortalState` 비노출, 집계 테이블의 비식별 열 구성 확인
- 한국시간 날짜 경계, 타입검사, lint, 빌드, `git diff --check` 통과

격리 검사는 실제 운영 DB·R2·계정·메일·외부 AI를 사용하지 않았고 외부 요청도 발생시키지 않았다. 네이티브 Windows에서는 Duet 고위험 결정론 검사 샌드박스를 사용할 수 없으므로 최종 차이 검토 결과를 완전한 고위험 승인으로 표시하지 않는다. 공개 운영 반영은 기존 Sites 프로젝트의 공개 범위와 DB/R2 연결을 유지하고 사용자의 구체적인 배포 승인 뒤에만 수행한다.
