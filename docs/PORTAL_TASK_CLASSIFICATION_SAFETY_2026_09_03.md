# 새 업무 분류 명시 선택 안전성

2026-09-03 기준. 업무·알림 관리의 직접 등록에서 업무유형과 지원 요청 유형을 실제 목적에 맞게 직접 선택하도록 보완한 기록이다.

## 확인한 문제

- 새 업무가 항상 `내부업무` 유형으로 시작했다.
- `지원요청`으로 바꾸면 세부분류가 `로그인·계정`으로 이미 선택되어 있었다.
- 공용 업무 초안 검증은 업무유형과 지원 세부분류를 허용 목록으로 확인하지 않고 화면의 타입 단언에 의존했다.
- 잘못된 분류는 업무 범위·표시뿐 아니라 지원 요청 유형별 운영 지표에도 영향을 줄 수 있었다.

## 적용한 동작

- 새 업무의 업무유형과 지원 요청 유형을 빈 값으로 시작한다.
- 업무유형은 7개 공용 허용 목록에서 직접 선택해야 한다.
- `지원요청`을 선택한 경우에만 5개 지원 요청 유형 중 하나를 추가로 선택해야 한다.
- 업무유형을 바꾸면 이전 기업명과 지원 세부분류를 지워 다른 분류의 입력을 이어받지 않는다.
- 새 등록창을 열거나 취소·저장한 뒤에는 제목·기업·분류·담당·기한 입력을 같은 빈 초안으로 초기화한다.
- 공용 준비 함수가 업무유형·조건부 지원분류·마감 구분을 허용 목록으로 검증한다.
- 실제 업무에는 화면 원문이 아니라 공용 검증이 반환한 유형과 지원분류만 사용한다.

## 운영 경계

- 기존 업무와 지원 요청 기록을 일괄 수정하거나 재분류하지 않는다.
- 업무유형·지원분류의 종류와 의미, 고정 업무 범위, 알림·지원 지표 기준은 변경하지 않았다.
- 서버 API, DB/R2 스키마, 인증·권한·보관 정책은 변경하지 않았다.
- 실제 운영 데이터 쓰기, 메일 발송, 유료 AI 호출, 외부 요청은 검증 중 모두 0건이다.

## 검증 결과

- 빈 초기 분류, 임의 업무유형, 빈·임의 지원분류 거절 회귀검사 추가.
- 관련 업무·지원·계정 연결 테스트 12개 통과.
- 전체 자동 테스트 287개 통과.
- 격리 workerd/D1/R2 검사 129개 통과.
- 타입검사, 전체 lint, `git diff --check`, 프로덕션 빌드 통과.
- 실행 중인 localhost `/` 응답 HTTP 200 확인.

GitHub `main` 푸시와 공개 Sites 배포는 사용자 승인 전까지 수행하지 않는다.
