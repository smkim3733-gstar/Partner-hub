# 파트너 감사 필드 무결성 경계

기준일: 2026-09-05

## 확인한 문제

파트너의 가입 출처 `registration`과 로그인 통계 `lastLoginAt`, `loginCount`는 전용 가입·로그인 서버 경로가 확정해야 한다. 그러나 수정 전 관리자 일반 상태 저장은 이 값을 클라이언트 입력 그대로 운영 상태에 기록했다. 실제 `/api/state` 요청으로 가입 방식·요청번호·가입시각·등록자를 바꾸고 임의 로그인 횟수와 최근 접속시각을 넣을 수 있었다. 가입 출처 변경은 회원 명단 revision까지 증가시켰고, 로그인 통계 입력은 별도 통계 테이블과 다른 값을 상태 원문에 남겼다.

## 적용한 경계

- 초기화된 운영 상태의 기존 회원은 일반 상태 저장에서 `registration`, `lastLoginAt`, `loginCount`를 현재 서버 저장값 그대로 유지한다.
- 현재 저장값에 없는 감사 필드는 클라이언트가 새로 넣어도 제거한다.
- 가입 출처는 ChatGPT·비밀번호 자가가입과 관리자 직접등록 전용 경로만 기록한다.
- 로그인 통계는 별도 D1 통계 경로만 기록하고 관리자 조회 때 서버가 합성한다.
- 기존 회원은 안정 ID로 대조한다. 레거시 중복 ID가 있으면 정규화 이메일로 정확히 한 회원을 식별할 수 있을 때만 보존값을 적용하며, 모호하면 HTTP 403으로 실패한다.
- 운영 상태가 없는 최초 기준자료 선택 흐름은 기존 동작을 유지한다.
- 차단·보존 처리에는 D1 스키마, R2 연결, 공개 범위, 보관·삭제 정책 변경이 없다.

## 검증

- 수정 전: 일반 상태 저장으로 가입 출처와 로그인 통계 위조가 HTTP 200으로 저장되는 것을 재현했다.
- 수정 후: 같은 저장은 일반 업무 변경만 반영하고 가입 출처를 원본 그대로 유지하며 임의 로그인 통계를 원문에 남기지 않는다.
- 표적 Node 테스트 76/76, 전체 Node 회귀 테스트 495/495 통과.
- 격리 workerd+D1+R2 검사 190/190 통과. 운영 쓰기·이메일·유료 AI·외부 요청은 모두 0건이다.
- 타입검사, 전체 lint, 프로덕션 빌드 통과.
- 로컬 운영 Worker의 `/`, `/account`, `/account/setup` 모두 HTTP 200.
