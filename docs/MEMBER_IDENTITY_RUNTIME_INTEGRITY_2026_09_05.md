# 파트너 식별정보 실행 무결성 경계

기준일: 2026-09-05

## 확인한 문제

관리자 일반 상태 저장은 이메일 형식을 검사했지만 런타임 값이 문자열이라고 가정했다. 조작 요청이 회원 이메일에 `null`을 넣으면 검증 함수 내부에서 예외가 발생해 HTTP 403 대신 500을 반환했다. 과거 이관·손상 상태에서 활성 회원 이름이 비문자열인 경우에도 비밀번호·ChatGPT 포털 조회가 이름 정규화 중 500으로 중단됐다. 안정 ID에 이미 결속된 ChatGPT 계정은 저장 회원 이메일이 비문자열이어도 접근을 계속할 수 있었다.

## 적용한 경계

- 이메일 정규화·형식·대표 예약·중복 검사는 모든 런타임 입력을 안전하게 처리한다. 비문자열 값은 빈 정규화값 또는 형식 오류로 판단한다.
- 관리자 일반 저장의 비문자열 회원 이메일은 내부 예외 없이 HTTP 403으로 거절하고 상태를 변경하지 않는다.
- 회원 이름 정규화는 비문자열 값에서 예외를 만들지 않는다.
- 비밀번호·ChatGPT 파트너 인증은 현재 활성 회원의 표시 이름이 비어 있지 않은 문자열인지 확인한다.
- 안정 ID에 이미 결속된 ChatGPT 파트너도 현재 저장 회원 이메일이 유효한 문자열인지 다시 확인한다. 제공자 이메일 변경을 허용하는 기존 결속 규칙은 유지한다.
- 회원·기업 데이터, 인증수단, D1 스키마, R2, 공개 범위는 변경하지 않았다.

## 검증

- 수정 전: 관리자 `null` 이메일 저장과 비밀번호·ChatGPT의 비문자 이름 조회가 모두 HTTP 500임을 재현했다.
- 수정 후: 비문자 이메일 저장, 비문자 이름의 두 인증 경로, 결속 회원의 비문자 이메일을 모두 HTTP 403으로 실패 폐쇄했다.
- 전체 Node 회귀 테스트 506/506 통과.
- 격리 workerd+D1+R2 검사 206/206 통과. 운영 쓰기·이메일·유료 AI·외부 요청은 모두 0건이다.
- 타입검사, 전체 lint, 프로덕션 빌드 통과.
- 로컬 운영 Worker의 `/`, `/account`, `/account/setup` 모두 HTTP 200.

## 저장 상태

기능 커밋 `2dada7c89ce8eec73dc13525c63707b3049e856e`를 GitHub `main`과 Sites 소스 저장소에 반영했다. 같은 커밋의 검증된 빌드 산출물을 Sites 버전 127 (`appgprj_6a92514801988191b79eb9bd314e3fcd~appgver_ed7ba737f8808191a841350b5fca2293`)로 저장했다. 저장 산출물은 160개 파일, 4,382,720바이트, 해시 `sha256:17ef9d14c9ee1fe501554d5cbae2cc83ec521862c8660980f6739ae6e7c0e48c`이다.

현재 공개 운영본은 버전 107이다. 버전 108~126은 버전 127로 대체하며 공개 배포하지 않는다. 버전 127도 정확한 운영 배포 승인 전까지 저장 상태로 유지한다.
