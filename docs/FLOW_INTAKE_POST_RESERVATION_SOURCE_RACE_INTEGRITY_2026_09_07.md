# 상담 FLOW 신청자료 예약 후 원본 경쟁 무결성

기준일: 2026-09-07

## 확인한 경계

대표가 검토한 기업자료 원본을 상담 FLOW 근거자료로 가져올 때 원본 검증 뒤 안정 파일 ID와 R2 키를 가진 `pending` 업로드 예약을 먼저 만든다. 예약 생성 중 원본이 삭제 처리되거나 같은 R2 키의 객체가 교체돼도 이미 읽어 둔 바이트를 목적지 R2에 복사하거나 FLOW를 생성하면 안 된다.

## 발견·수정

- 버전 305는 FLOW 접근 재검사 뒤, 업로드 예약을 시작하기 직전에 원본 스냅샷을 확인했다. 예약 D1 배치가 끝난 뒤에는 FLOW 접근만 다시 확인하고 신청자료 원본은 다시 확인하지 않았다.
- 예약 배치 직후 원본 삭제 tombstone을 만들고 목적지 R2 쓰기를 차단한 수정 전 회귀는 현재 원본 부재 404 대신 저장소 오류 503을 반환했다. 이는 삭제 뒤에도 목적지 쓰기가 시작됐음을 증명한다.
- 예약 생성·조회 뒤 FLOW 접근과 생명주기를 확인한 직후 준비된 신청자료의 기업자료 행, 표시 상태, 기업·사건·담당 결속, 최신 무결성 원장과 R2 `head`를 다시 대조한다.
- 원본 삭제 tombstone 경쟁은 404로 끝난다. 같은 키·MIME·크기의 R2 객체 교체 경쟁은 네이티브 ETag 불일치를 409로 반환한다.
- 두 경쟁 모두 목적지 R2 쓰기 0회, FLOW 0건이다. 각 요청의 불변 파일 ID·키를 가진 예약 1건은 `pending`으로 보존해 현재 상태 조사와 정확 재시도에 사용한다.
- 이 보강은 예약 완료부터 첫 목적지 R2 쓰기 직전까지의 경계를 닫는다. 목적지 쓰기 자체와 최종 FLOW D1 커밋 사이의 원본 변경은 다음 감사 대상으로 분리한다.
