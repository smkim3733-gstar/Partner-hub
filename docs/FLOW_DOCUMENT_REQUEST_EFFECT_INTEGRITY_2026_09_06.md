# 상담 FLOW 서류 요청 등록 효과 무결성

기준일: 2026-09-06

`request_document` 명령을 대표 행위자와 명령 ID 기반 새 서류 요청 정확히 한 건에 결속했다. 애플리케이션 커밋 검사와 추가형 `0085` D1 트리거는 계약 체결 전 대표만 요청을 등록하도록 하고, 기존 요청 이력과 별개인 여분 요청 또는 담당 파트너 명의의 직접 저장을 거절한다.

새 요청은 `id`, `title`, `required`, `channel`, `recipient`, `dueDate`, `status`, `note`, `createdAt` 아홉 필드만 갖는다. 제목은 공백을 제거한 1~~150자, 수신자는 1~~100자, 필수 여부는 명시적 불리언, 전달 경로는 카카오톡·이메일·기타 중 하나여야 한다. 제출기한은 빈 값 또는 실제 달력 날짜만 허용한다. 초기 상태는 `requested`, 메모는 빈 문자열, 생성시각은 해당 FLOW revision의 서버시각으로 고정하며 파일·발송·수령·검토·확인 증거의 선행 주입을 차단한다.

검증은 방어 전 담당 파트너 행위자, 과거 생성시각과 이미 보완한 메모를 조합한 저장이 수락되는 실패를 먼저 재현했다. 보완 후 정상 등록과 회원 행위자, 위조 초기 증거, 발송 증거 선행 주입, 존재하지 않는 달력 날짜를 앱과 D1 양쪽에서 확인했다. Node 690/690, 관련 FLOW 검사 138/138, 집중 검사 96/96, 격리 workerd+D1+R2 512/512, 타입검사, lint, 포맷, 프로덕션 빌드, 로컬 Worker 화면 3곳 200·보호 API 3곳 401과 비공개 무저장 헤더를 통과했다. 검증 중 운영 데이터 쓰기·메일·유료 AI·외부 업무 API 호출은 0건이다.
