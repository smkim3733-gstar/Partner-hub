# 업무·기업자료·일정 연결 무결성 경계

기준일: 2026-09-05

## 확인한 문제

업무·기업자료·일정은 고유 ID만 확인했다. 제공된 `caseId`가 현재 진행에 없거나 `partnerMemberId`가 현재 명단에 없더라도 관리자 일반 저장을 통과했다. 두 값이 각각 존재하지만 서로 다른 파트너를 가리키는 기록도 구조상 유효했다. 파트너 권한 판정은 연결 진행과 직접 담당이 모두 같은 계정을 가리켜야 하므로 이런 기록은 어느 파트너에게도 보이지 않는 운영 고아 데이터가 됐다.

## 적용한 경계

- 업무·기업자료·일정에 `caseId`가 있으면 앞뒤 공백 없는 문자열이며 현재 진행 하나에 정확히 연결되어야 한다.
- `partnerMemberId`가 있으면 앞뒤 공백 없는 문자열이어야 한다. 비어 있지 않은 값은 현재 회원 명단의 계정 하나에 정확히 연결되어야 한다.
- 진행과 직접 담당 계정이 함께 있으면 두 연결이 같은 파트너를 가리켜야 한다. 진행이 이름 기반 레거시라면 이름이 현재 명단에서 하나로 결정될 때만 직접 담당 ID와 함께 사용할 수 있다.
- `partnerMemberId: ''`인 대표 전용 기록, 담당 ID가 없는 이름 기반 레거시 기록, 직접 담당 없이 진행 담당을 상속하는 기록은 기존 의미를 유지한다.
- 공용 순수 검증기를 서버 저장·조회, 클라이언트 최초 상태 응답, 상담 FLOW 투영 뒤 재검증에 함께 적용한다.
- 조작 저장은 403, 이미 저장된 손상 상태는 파트너 조회 403, 관리자 조회와 일반 저장 503으로 격리한다.
- 운영 데이터 자동 수정, 기존 기록 재배정, D1/R2 스키마 변경은 수행하지 않았다.

## 검증

- 수정 전 재현: 미존재 진행, 미존재·중복 담당 ID, 진행 담당과 직접 담당의 충돌이 구조 검사를 통과했다.
- 수정 후: 세 컬렉션 모두 미존재·상충 연결을 거절하고 저장 상태는 바뀌지 않는다.
- 대표 전용 기록, 진행 담당 상속, 이름 기반 레거시와 정지 계정의 기존 연결은 유지한다.
- Node 자동 테스트 530/530 통과.
- 격리 workerd+D1+R2 검사 290/290 통과.
- 타입검사, 전체 lint, 프로덕션 빌드 통과.
- 로컬 프로덕션 `/`, `/account`, `/account/setup` HTTP 200 확인.
- 실제 운영 쓰기, 메일 발송, 유료 AI 요청, 외부 요청 0건.

## 다음 감사

진행 타임라인의 제공된 `caseId`, 선택적 안정 ID와 필수 표시 필드가 손상됐을 때 다른 진행 기록으로 합쳐지거나 파트너 화면에서 잘못 노출되는지 점검한다. `caseId`가 없는 기존 레거시 타임라인의 호환은 유지하고, 자동 배정·삭제는 하지 않는다.
