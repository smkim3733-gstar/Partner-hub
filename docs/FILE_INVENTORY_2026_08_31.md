# 대표 전용 원본 보관 현황 — 2026-08-31

이 문서는 버전 42의 조회 기능 기록이다. 후속 단계로 대표가 원본과 기존 신청을 직접 대조한 뒤 연결하는 기능과 미완료 상담 FLOW 첨부 예약 조회를 추가했다. 현재 사용 방법과 제한은 [원본 회수 안내](FILE_RECOVERY_2026_08_31.md)와 [FLOW 첨부 예약·복구 무결성](FLOW_UPLOAD_RESERVATION_RECOVERY_INTEGRITY_2026_09_06.md)을 참고한다. 목록·존재 확인 API 자체는 계속 조회 전용이다.

## 사용하는 순서

대표 계정으로 **기업별 자료함 → 원본 보관 현황 → 미연결 원본 확인**을 연다. 기본 목록은 `연결 확인 필요`이며, 상태 필터에서 업로드 대기·메타데이터 확인·삭제 기록·연결된 자료를 따로 볼 수 있다. 페이지당 최대 25건을 표시하고 `다음 25건`으로 이어서 조회한다. `처음부터 새로 조회`는 현재 서버 기록을 다시 확인한다.

목록은 파일명·기업·자료명·업로드 계정·보관시각·파일 ID와 직접 참조 여부를 보여 준다. 업로드 요청만 남고 파일 메타데이터가 없는 항목은 파일명·기업·크기를 추정하지 않고 미확인으로 표시한다. 미완료 FLOW 예약은 예약에 기록된 파일명·용도·크기와 진행 배정만 표시한다.

`원본 존재 확인`은 서버가 보관 경로를 찾아 R2의 메타데이터만 조회한다. 원본 존재 여부·실제 크기·DB 기록과의 크기 일치 여부·확인시각을 표시하며 파일 본문을 다운로드하거나 분석하지 않는다. 저장소 연결 오류는 `원본 없음`으로 바꾸지 않고 확인 실패로 안내한다.

## 상태를 읽는 방법

| 상태 | 의미 |
|---|---|
| 연결 확인 필요 | 자료 목록의 `storageFileId`와 상담 파일의 `intakeFileId`에서 직접 참조를 찾지 못했다. 작성 중·제출 제외·연결 누락일 수 있으며 삭제 가능 판정이 아니다. |
| 업로드 확인 대기 | 기업자료 업로드 요청 또는 상담 FLOW 첨부 예약이 아직 `pending` 상태다. 원본은 이미 저장됐을 수도 있으므로 존재 확인과 같은 신청·명령·파일 재시도를 먼저 검토한다. |
| 메타데이터 확인 필요 | 완료 요청은 있지만 파일 메타데이터가 없다. 자동 복구나 삭제를 실행하지 않는다. |
| 삭제 기록 확인 | 삭제 상태에 파일 메타데이터 또는 자료·상담 참조가 남아 있다. 원본 존재와 연결 기록을 각각 확인한다. |
| 자료·상담 연결 | 저장된 자료 목록이나 상담 파일에서 직접 참조하고 있다. 원본 존재·정상 내용·사용 승인을 의미하지 않는다. |

신청 업로드 때 먼저 부여한 진행 연결값만으로 접수 완료로 분류하지 않는다. 완료된 삭제 요청 중 파일 메타데이터와 직접 참조가 모두 없는 항목은 목록에서 제외하되, 재시도 방지용 삭제 기록은 DB에 그대로 둔다. 이름으로 담당자를 추측하여 자료를 연결하지 않는다.

## 보안과 확인 범위

- 목록과 존재 확인 API는 서버에서 매번 대표 관리자 권한을 확인한다. 파일 업로드 권한이 있는 일반 파트너도 접근할 수 없다. 응답은 `private, no-store`다.
- 업로드 요청 키·내용 지문·저장소 경로·파일 본문·전사문·보고서 내용은 화면 응답에 포함하지 않는다. 계정별 파일명과 보관 메타데이터는 대표 화면에서만 제공한다.
- UI와 새 API는 조회 전용이다. 삭제·자동 연결·다운로드·AI 분석·알림 전송·자동 만료를 실행하지 않는다. 기존 파일 삭제 API와 자료 연결 규칙도 바꾸지 않는다.
- 최초 조회 기능은 새 DB 마이그레이션 없이 동작했다. 후속 `0093` 마이그레이션은 R2 쓰기 전 FLOW 첨부 예약만 추가하며 기존 D1/R2 연결과 공개 범위를 보존한다.
- 이 화면은 DB에 기록된 기업 원본·업로드 요청과 미완료 FLOW 첨부 예약을 확인한다. DB 기록 없이 저장소에만 있는 객체, 완료된 모든 상담 산출물, 외부 백업과 파일 내용의 정상 여부를 전수 조사하지 않는다.
- 목록 조회와 원본 존재 확인은 서로 다른 시점이다. 다른 창에서 변경하면 다음 페이지의 분류도 달라질 수 있다. 목록이 비었다는 이유만으로 보관 원본이 전혀 없다고 판단하지 않는다.

## 검증과 운영 기록

전체 lint·타입검사·자동 테스트 143개와 격리 workerd/D1/R2 검증 77개를 통과했다. 비로그인·일반 파트너 접근 거부, 실제 자료·상담 참조 분류, 같은 시각 기록의 페이지 이동, 삭제 잔여 기록, 업로드 대기 기록, 원본 존재·크기 불일치·연결 오류 구분을 확인했다. 조회 중 원본 읽기·쓰기·삭제가 일어나지 않는지와 민감한 내부 필드가 응답에 없는지도 검증했다.

실제 운영 고객 목록·파일 본문·계정은 조회하거나 수정하지 않았다. 메일 전송·유료 AI 호출·격리 Worker의 외부 요청은 0건이다. 브라우저 클릭 시험은 수행하지 않았다.

선행 운영 소스는 `5c95482`, 버전 41이다. 이번 배포 결과는 Sites 이력과 로컬 `outputs/release/` 완료 기록에 남긴다. 남은 작업은 확인한 원본을 담당 신청과 대조하여 안전하게 회수하는 절차다. 보관 기간 결정과 운영 자료 삭제는 이번 조회 기능에 포함하지 않는다.
