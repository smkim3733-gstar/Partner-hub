# 상담 FLOW 첨부 다운로드 원본 크기 무결성 경계

기준일: 2026-09-05

## 확인한 문제

상담 FLOW 첨부 다운로드 API는 현재 진행·계정 권한과 R2 객체 존재를 확인하고 R2 조회 뒤 권한을 다시 확인했다. 그러나 FLOW에 저장된 파일 `size`와 실제 R2 객체 크기를 대조하지 않았고, 재조회한 FLOW에서도 파일 ID와 저장 키만 비교했다.

같은 R2 키의 객체가 손상되거나 다른 크기로 교체된 경우와 R2 조회 중 FLOW 파일 크기가 바뀐 경우 모두 기존 구현은 미리 읽은 본문을 HTTP 200으로 제공했다.

## 적용한 경계

- R2 본문을 가져온 직후 실제 객체 크기와 최초 FLOW 파일 크기를 대조한다.
- R2 조회 뒤 현재 진행·계정 권한을 다시 확인하고 같은 파일 ID의 저장 키·파일명·크기가 최초 값과 모두 같은지 확인한다.
- 실제 R2 크기도 재조회한 FLOW 크기와 다시 대조한다.
- 불일치 시 미리 가져온 R2 본문 스트림을 폐기하고 비공개 보안 헤더가 적용된 HTTP 409로 거절한다.
- 기존 권한·진행 연결·파일명·MIME·R2 키 정책을 유지한다. FLOW payload, R2 객체, 스키마와 보관·삭제 정책은 자동 변경하지 않았다.

## 검증

- 수정 전 재현: 저장 크기와 다른 R2 객체 및 R2 조회 중 바뀐 FLOW 크기가 모두 HTTP 200 본문으로 제공됐다.
- 수정 후: 두 경우 모두 HTTP 409로 실패하고 미리 읽은 본문을 반환하지 않는다.
- 거절 뒤 저장된 FLOW 파일 크기와 R2 객체를 자동 수정·삭제하지 않는다.
- 격리 Worker에서 잘못된 R2 크기를 거절하고 FLOW 파일 크기를 보존한 뒤 정상 크기 복구 시 다운로드가 다시 HTTP 200으로 성공한다.
- 기존 정지·담당·권한 변경 재검사, 정상 첨부 다운로드와 AI 입력 크기 검사가 계속 통과한다.
- Node 자동 테스트 562/562 통과.
- 격리 workerd+D1+R2 검사 353/353 통과.
- 타입검사, 전체 lint, 프로덕션 빌드 통과.
- 로컬 프로덕션 `/`, `/account`, `/account/setup` HTTP 200과 CSP·`nosniff`·`no-referrer` 확인.
- 실제 운영 쓰기, 메일 발송, 유료 AI 요청, 외부 요청 0건.
