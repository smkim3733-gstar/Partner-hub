# 서버 인증 응답·세션 쿠키 보안 속성 감사

## 목적

사이트 전용 비밀번호 인증, ChatGPT 로그인 기반 자가등록·대표 직접등록, 포털 상태 응답이 브라우저·중간 캐시에 남거나 콘텐츠 형식 오인으로 해석되지 않도록 공통 응답 경계를 적용한다. 세션 쿠키의 호스트 고정과 브라우저 전송 제한도 실제 라우트와 격리 Workers에서 다시 검증한다.

## 적용 범위

- 인증·계정·포털 상태 JSON 응답에 `Cache-Control: private, no-store, max-age=0`, `Pragma: no-cache`, `Expires: 0`을 공통 적용한다.
- 같은 응답에 `Referrer-Policy: no-referrer`, `X-Content-Type-Options: nosniff`를 적용한다.
- 성공·입력 오류·권한 거절·충돌·서버 오류가 같은 보안 헤더 경계를 사용한다.
- 로그인 시도 제한의 `Retry-After`와 로그인·로그아웃의 `Set-Cookie`는 공통 경계와 함께 유지한다.

## 쿠키 감사 결과

운영 HTTPS 세션 쿠키는 `__Host-keve_session` 이름, `Secure`, `HttpOnly`, `SameSite=Strict`, `Path=/`, 12시간 `Max-Age`를 사용하고 `Domain` 속성을 두지 않는다. 로그아웃도 같은 호스트 전용 속성과 `Max-Age=0`으로 삭제한다. localhost HTTP 개발에서만 별도 `keve_local_session` 이름을 사용한다. 쿠키 동작 변경은 필요하지 않아 기존 계약을 유지하고 회귀검사만 강화했다.

## 유지한 경계

인증 방식·대표 이메일·파트너 역할과 권한·세션 수명·로그인 시도 제한·HTTPS와 동일 출처 검사·D1/R2 스키마·자료 보관 정책은 변경하지 않았다. 인증 실패 응답은 기존 한국어 안내와 HTTP 상태만 제공하며 비밀번호, 세션 토큰, 원시 공급자 응답이나 내부 오류 내용을 추가로 노출하지 않는다.
