# 상담 FLOW 업로드 예약 중 접근변경 경쟁 무결성

기준일: 2026-09-07

## 확인한 위험

상담 FLOW는 첨부파일 실제 형식·서명 검사 뒤 접근을 다시 확인하지만, 안정 파일 ID와 R2 키를 조회하거나 생성하는 업로드 예약도 별도 비동기 D1 작업을 수행한다. 그 예약 작업 중 사건·담당 계정·업로드 권한이 바뀌면 기존 구현은 최종 접근 재검사에서 FLOW D1 커밋을 막더라도 변경 뒤 새 R2 객체를 기록할 수 있었다.

## 발견·수정한 문제

- 첫 전사문 객체와 두 `pending` 예약이 남은 정확한 multipart 재시도의 기존 예약 조회가 끝난 직후 실제 관리자 상태 저장 API를 두 번 실행했다. 첫 저장은 사건 삭제·담당 계정 정지, 두 번째 저장은 배정 없는 정지 계정 삭제를 수행했다.
- 수정 전 기존 예약 조회 경쟁은 사건·회원 삭제와 안정 ChatGPT 결속 폐기 뒤에도 두 예약 키에 R2 쓰기 2회를 수행했음을 `2 !== 0`으로 증명했다.
- 예약이 없는 첫 multipart 요청에서는 두 예약의 D1 삽입 배치가 끝난 직후 실제 관리자 상태 저장 API로 담당 파트너의 업로드 권한을 회수했다. 수정 전 권한 회수 뒤에도 R2 쓰기 2회가 발생했다.
- 업로드 예약 조회 또는 생성이 끝난 직후 인증·안정 신원·FLOW 담당 ID·업로드 권한·사건 생명주기를 다시 확인하도록 상담 FLOW 라우트를 보강했다.
- 수정 후 두 경쟁 모두 403으로 끝나며 새 R2 쓰기와 FLOW·명령 영수증·파일 원장·완료 원장 D1 쓰기를 시작하지 않는다.
- 기존 예약 조회 경쟁에서는 사건·회원 삭제와 결속 폐기가 유지되고 기존 FLOW·영수증·전사문 객체·두 `pending` 예약은 그대로 보존된다. 사건·회원 원본 복구 뒤 정확한 재시도가 다시 결속해 한 번만 완료된다.
- 첫 예약 생성 경쟁에서는 권한 회수가 유지되고 새 두 `pending` 예약은 안정 파일 ID·R2 키 복구를 위해 보존되며 객체는 생성되지 않는다. 권한 복구 뒤 정확한 재시도가 같은 예약을 재사용해 한 번만 완료한다.
