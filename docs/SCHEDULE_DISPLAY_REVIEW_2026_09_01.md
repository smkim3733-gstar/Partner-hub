# 일정 날짜 표시·외부 등록 안내 점검

2026-09-01. 사용자의 「다음진행」 요청으로 기존 대표·파트너 일정 화면을 점검했다. 실제 일정이나 외부 캘린더를 읽거나 변경하지 않았다. 자동 후속 실행은 일시 중지 상태를 유지한다.

## 재현과 수정

메모리 전용 D1/R2에 가상 일정 6건을 준비했다. 2026년 9월 15일, 연말을 넘기는 일정, 다음 해 같은 월·일, 연도 없는 옛 일정과 두 공개범위 예제를 넣었다. 기존 큰 화면은 9월 1~7일의 고정 칸만 보여 주어 준비한 일정이 모두 누락됐다. 일정이 없다는 근거만으로 각 칸에 예약 가능이라고 표시했다.

- 고정 주간 칸과 모바일 전용 목록을 하나의 날짜별 목록으로 통합했다. 필터·공개범위 적용 후의 저장된 일정을 날짜·시간순으로 표시하며, 다른 연도의 같은 월·일을 섞지 않는다.
- 연도가 없거나 유효하지 않은 날짜는 추측하거나 누락하지 않고 확인 필요 그룹에 표시한다. 원래 저장 자료는 수정하지 않는다.
- 기존 외부 캘린더 링크는 누락된 연도를 2026년으로 가정했다. 이제 유효한 시작·종료 날짜와 시간이 있을 때만 등록 화면 링크를 만들며, 역전·동일 시각과 불가능한 날짜는 차단한다. 종료일이 다르면 화면에도 종료일을 표시한다.
- 실제 자동 동기화 구현 없이 연결 확인·지금 동기화·양방향 반영을 안내하던 문구를 바로잡았다. 버튼은 연동 상태 안내만 보여 준다. 외부 링크는 직접 등록 화면을 여는 기능이며 실제 Google 저장 성공은 확인하지 않았다.
- 빈 일정은 예약 가능으로 단정하지 않고 별도 확인이 필요하다고 안내한다.

서버 권한·공개범위·예약 저장·DB/R2·보존 정책은 변경하지 않았다. 새로운 외부 연결이나 주간 이동·예약 가능시간 계산 기능은 추가하지 않았다.

## 수정본의 가상 화면 검증

| 조건 | 관찰 결과 |
| --- | --- |
| 빈 상태 | 저장된 일정 0건과 별도 예약 가능 여부 확인 안내가 표시됐다. |
| 대표 전체 일정 | 준비한 6건이 모두 표시됐다. 2026.09.15와 2027.09.15가 분리되고 연도 미상 항목도 남았다. |
| 연말 일정 | 2026.12.31 23:30~2027.01.01 00:30과 종료일 표시를 확인했다. 링크의 날짜 범위도 일치했다. 링크를 열거나 Google에 저장하지 않았다. |
| 연도 미상 | 연도 확인 필요·외부 등록 전 날짜·시간 확인 필요를 표시하고 등록 링크는 없었다. |
| 출처 필터 | Google 출처는 1건, 상담 출처는 5건이 표시됐다. |
| 파트너 공개범위 | 5건만 표시됐다. 비공개 항목은 빠지고 시간 공유 항목의 기업명·목적·장소는 숨겨졌다. 담당 상담은 상세를 볼 수 있었다. |
| 연동 상태 안내 | 자동 동기화 미연결과 변경·취소 별도 확인 안내만 표시했다. 외부 요청은 발생하지 않았다. |
| 화면 폭 | 1280px 창에서 문서 폭 1265px이었다. 이번에는 별도 모바일 크기·기본 Tab/Enter 조작을 검증하지 않았다. |

가상 TXT/PDF 등 고객 자료는 필요하지 않았으며 가상 일정만 사용했다. 실제 가입·연락·메일·외부 일정 등록·삭제·유료 AI 호출을 수행하지 않았다. 로컬 런타임의 외부 요청은 0건이다.

## 회귀 검사와 배포

- 날짜별 그룹의 연도 분리·정렬·원본 불변, 윤년과 잘못된 날짜, 연말 종료일, 잘못된 시간과 연도 미상의 등록 차단을 4개 회귀 테스트로 추가했다.
- 전체 Node 검사 187개, 타입검사, lint, 빌드 통과. 서버 변경이 없어 기존 workerd 저장소 검사 110개는 반복하지 않았다.
- 가상 상태와 화면 결과: `outputs/validation/schedule-before.json`, `schedule-seed.json`, `schedule-runtime.json`, `schedule-results.json`. 검사와 빌드 로그는 `schedule-tests.log`, `schedule-build.log`다.
- 확정 운영 반영 상태는 `outputs/release/schedule-display-deployment.json`에 기록한다. 기존 공개 사이트·DB/R2·마이그레이션 8개를 유지한다.
- 실제 외부 캘린더의 연결·등록 성공·동기화, 실제 파트너 실사용과 전체 화면 접근성 검증 완료로 해석하지 않는다.
