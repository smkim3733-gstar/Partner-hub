# 서버 API 요청 경계 최종 감사

## 목적

서버 API가 JSON 요청 본문 전체를 제한 없이 메모리에 읽는 경로를 점검하고, 과대·비정상 요청을 운영 상태 저장이나 외부 AI 호출 전에 차단한다.

## 점검 결과

- `app/api/**/route.ts` 전체에서 직접 `request.json()` 또는 `request.text()`를 호출하는 경로를 제거했다.
- 대표 파트너 등록, ChatGPT 자가가입, 포털 상태 저장, Step 0 생성 요청에 공용 스트림 기반 JSON 요청 경계를 적용했다.
- `Content-Type`이 JSON이 아닌 요청은 `415`, 비어 있거나 손상된 JSON과 객체가 아닌 JSON은 `400`, 선언 크기 또는 실제 스트림 크기가 한도를 넘으면 `413`으로 차단한다.
- `Content-Length`가 실제보다 작아도 읽는 도중 한도를 넘으면 즉시 중단한다.
- 대표 파트너 등록과 ChatGPT 자가가입은 12,000바이트, 포털 상태 저장은 기존 상태 한도 900,000바이트, Step 0은 40,000바이트를 적용했다.
- Step 0의 요청·진행·기업 식별값은 초과 문자열을 잘라 비교하지 않고 잘못된 요청으로 거절한다. 긴 접두사가 같은 서로 다른 식별값의 충돌 가능성을 없앴다.
- 정적 회귀검사로 API 라우트의 직접 본문 파싱 재도입을 차단한다.

## 유지한 경계

- 기존 인증·역할·담당 계정 권한과 revision/CAS 처리를 바꾸지 않았다.
- D1 스키마, R2 원본 저장, 보관·삭제 정책을 바꾸지 않았다.
- 기존 정상 JSON 요청과 응답 계약을 유지했다.
- 실제 운영 저장, 계정 등록, 메일, 유료 AI, 외부 요청을 검증에 사용하지 않았다.

## 검증

- Node 자동 테스트 410개 통과
- 격리 workerd/D1/R2 검사 129개 통과
- 격리 검사 중 운영 쓰기·메일·유료 AI·외부 요청 각 0건
- TypeScript 타입검사, 전체 lint, 프로덕션 빌드 통과
- 로컬 Workers 실행 후 `/` HTTP 200 확인

## 배포 경계

코드와 문서는 로컬 커밋까지 준비한다. GitHub 푸시와 기존 공개 Sites 반영은 사용자 운영 승인 뒤 수행한다. 현재 공개 Sites 버전 73의 D1 `DB`, R2 `AI_SOURCE_FILES`, 공개 범위는 변경하지 않았다.
