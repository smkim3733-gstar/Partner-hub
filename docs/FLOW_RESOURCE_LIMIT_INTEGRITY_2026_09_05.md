# 상담 FLOW 리소스 상한 무결성 경계

기준일: 2026-09-05

## 확인한 문제

FLOW 전체 payload가 서버 요청 크기 제한보다 작더라도 다수의 짧은 항목이나 일부 지나치게 긴 필드가 반복되면 상세 조회 검증과 SQLite JSON 투영 비용이 불필요하게 증가할 수 있었다. 저장된 데이터가 외부 요인으로 변형된 경우에는 일반 명령 생성 경계만으로 이 문제를 차단할 수 없었다.

## 적용한 경계

- 명령 ID·수신증 2,000개, 상담·녹취·서류요청·입금·AI 작업 2,000개, 보고서·파일·감사기록 4,000개로 저장 컬렉션 상한을 고정했다.
- 보고서 본문 80,000자, 녹취 본문 60,000자, AI 원문 80,000자와 함께 제목·이름·메모·사유·참조 ID별 상한을 적용했다.
- 문서 생성 키는 현재 계약서·견적서 결과물을 보존할 수 있도록 300,000자로 제한했다.
- 솔루션은 최대 12개, 항목당 80자로 제한했다.
- 명령 적용 전 명령 ID와 감사기록 용량을 함께 확인한다.
- 저장 payload 전체 검증과 D1 쓰기 직전 검증에서 같은 상한을 적용한다.
- 대시보드는 숨겨질 컬렉션을 JSON 투영하기 전에 SQLite `json_array_length`와 `json_each`로 개수를 확인한다.

## 검증

- 한도 초과 명령 ID 컬렉션과 80,000자를 초과한 보고서 본문을 상세 조회 전에 HTTP 503으로 차단한다.
- 한도 초과 본문을 D1 쓰기 직전에 차단하고 새 행을 남기지 않는다.
- 대시보드 투영에서 숨겨질 과다 명령 ID 컬렉션도 SQLite 단계에서 차단한다.
- 격리 Worker의 실제 D1 경로에서 과다 컬렉션을 상세·대시보드 모두 차단하고 원본 복구 뒤 정상 조회가 재개된다.
- Node 자동 테스트 581/581 통과.
- 격리 workerd+D1+R2 검사 369/369 통과.
- 타입검사, 전체 lint, 포맷 검사, 프로덕션 빌드 통과.
- 로컬 프로덕션 `/`, `/account`, `/account/setup` HTTP 200과 CSP·`DENY`·`nosniff`·`no-referrer` 확인.
- 실제 운영 쓰기, 메일 발송, 유료 AI 요청, 외부 요청 0건.

## 다음 감사

FLOW와 일반 포털 상태에서 서버가 생성하는 문자열이 모든 저장 경계와 동일한 상한을 사용하는지 비교한다. 정상 명령이 한도를 초과하는 값을 만든 뒤 저장 단계에서 뒤늦게 실패하는 경로가 없는지 확인하고, 필요한 경우 명령 입력 경계에서 더 일찍 거절한다.
