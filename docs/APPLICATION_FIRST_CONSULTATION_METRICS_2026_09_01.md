# 협업신청 → 첫 상담 FLOW 운영 지표

검수일: 2026-09-01
범위: 신규 협업신청의 서버 접수시각과 상담 FLOW 초회상담 완료기록을 사용한 관리자 전용 파일럿 지표

## 구현 결과

- 최종 신청 저장이 승인된 정확한 `case-draft-*` 진행에만 서버 ISO 접수시각과 추적 버전 1을 기록한다.
- 클라이언트가 보내는 접수시각·추적 버전은 관리자와 파트너 저장 모두에서 제거한다. 이미 서버가 기록한 값은 변경·삭제할 수 없고, 응답 유실 뒤 같은 저장을 재시도해도 최초 시각을 보존한다.
- 대표 대시보드에 추적 신청, FLOW 개시, 첫 상담 완료, FLOW 완료대기, FLOW 미개시를 집계한다. 완료율은 `첫 상담 완료 / FLOW 개시`로 계산한다.
- 기존 상담 입력만 있는 진행은 정확한 완료시각이 없으므로 `레거시 상담 기록·측정 불가`로 분리하며 완료율 분모에 넣지 않는다.
- 소요시간은 신청 접수부터 FLOW의 초회상담 완료기록까지다. 공동분석과 2·3차 자료 준비가 FLOW의 선행 조건이므로 순수한 상담 일정 대기시간과 같지 않다.

## 개인정보와 운영 경계

- API는 관리자에게만 집계 결과를 최상위 응답으로 제공한다. 파트너 응답과 저장 상태에는 지표 객체를 넣지 않는다.
- 집계 SQL은 진행 ID와 가장 이른 초회상담 완료시각만 읽으며 회사명, 파트너명, 보고서, 녹취, 원본을 조회하지 않는다. 응답에는 진행 ID나 정확한 시각도 포함하지 않는다.
- 접수시각보다 빠르지 않은 유효 완료 소요시간이 5건 미만이면 구간을 숨긴다. 5건 이상일 때도 1일 미만, 1~~3일, 3~~7일, 7일 이상의 거친 구간만 표시한다.
- 기존 가상 시드 ID, 배포 전 신청, 서버 추적표식이 없는 레거시 신청은 제외한다. 완료시각이 접수시각보다 이른 비정상 기록은 별도 건수로 표시하고 소요시간에서 제외한다.
- 값은 현재 저장 상태와 FLOW의 실시간 스냅샷이다. 원본 신청이 제거되면 집계도 줄 수 있으며, 이 구현은 보관·삭제 정책이나 실제 고객 자료를 변경하지 않는다.
- 지표 조회 실패는 관리자 상태 조회를 막지 않고 `불러오지 못함`으로 격리한다.

## 검증

- Node 자동 테스트 225개 통과.
- 격리 workerd + 실제 D1/R2 검증 117개 통과. 외부 요청, 실제 데이터 쓰기, 메일 발송, 외부 AI 호출은 0건이다.
- 타입검사, lint, 프로덕션 빌드 통과.
- 서버 필드 위조 차단, 정확한 신청에만 최초 시각 부여, 응답 유실 재시도, 관리자 전용 응답, FLOW 분모 분리, 레거시 측정 불가, 비정상 시각 제외, 5건 미만 소요시간 비공개를 가상 데이터로 확인했다.

## Duet 검수 반영

Duet의 중요 의견에 따라 레거시 상담을 FLOW 완료율에서 분리하고, 모든 클라이언트 입력에서 추적 필드를 제거한 뒤 현재 임시저장 검사를 통과한 정확한 신규 진행에만 서버 시각을 부여했다. 네이티브 Windows에서는 Duet의 결정론적 샌드박스 검사를 실행할 수 없으므로 최종 차이 검토를 고위험 운영 배포의 완전 승인으로 해석하지 않는다.
