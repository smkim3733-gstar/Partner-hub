# 파일 재고 FLOW payload 전역 소유 결속

## 결과

완료 상담 FLOW 파일은 전체 FLOW payload에서 파일 ID가 정확히 한 번만 나타나고, 그 한 건의 사건·저장 키·생성시각·전체 메타데이터가 D1 소유·메타데이터 원장과 일치할 때만 정상 재고와 무결성 증명으로 인정한다.

소유 원장의 사건 귀속 불일치, 소유 원장은 있지만 payload 파일 항목이 없는 상태, 같은 파일 ID가 다른 FLOW payload에도 복제된 상태는 모두 `inconsistent`·증명 없음으로 격리한다. 개별 현재 R2 확인도 전역 payload 출현 수가 1이 아니면 객체 조회 전에 503으로 닫는다. 스키마와 마이그레이션 변경은 없다.

기능 커밋은 `3e6531f1a6189629336992ee7baa0a57b08593cb`이다.

## 수정 전 재현

- 소유 원장 사건 불일치와 payload 파일 누락은 기존 목록·현재 R2 확인 경계가 이미 닫힌 실패로 처리했다.
- 정상 완료 FLOW 파일을 소유 사건 외의 다른 FLOW payload에도 같은 ID와 메타데이터로 복제했다.
- 수정 전 재고는 소유 사건 안의 일치 항목만 세어 복제된 파일을 계속 `linked`·증명 있음으로 표시했다.
- 수정 전 개별 확인도 소유 사건만 읽어 현재 R2 확인을 200으로 허용할 수 있었다.
- 정확한 적색 회귀는 파일 재고 17건 중 16건 통과, 전역 중복 격리 1건 실패로 결함을 고정했다.

## 변경

- 모든 FLOW payload 파일을 목록 조회의 공통 CTE에서 한 번 투영한다.
- 각 소유 원장 파일 ID의 전역 payload 출현 수와 사건·키·생성시각·전체 메타데이터 정확 일치 수를 계산한다.
- 정상 재고 분류와 전체 체크섬 적용 현황이 모두 `전역 출현 1건 + 정확 결속 1건`을 요구한다.
- 동일 파일 ID가 같은 FLOW 안에서 중복되거나 다른 FLOW에 복제돼도 증명 불가로 전환한다.
- 개별 현재 R2 확인 쿼리도 모든 FLOW payload의 파일 ID 출현 수를 계산해 정확히 1건이 아니면 `head` 전에 거절한다.
- 목록과 응답에는 내부 저장 키·본문·다이제스트를 추가하지 않았다.
