# 신청 저장 확인·재시도 보완 — 2026-08-31

## 변경

협업신청은 첨부 업로드와 진행·타임라인·자료 연결의 서버 저장 응답을 확인한 뒤에만 완료 안내를 표시하고 진행판으로 이동한다. 저장 응답이 실패하거나 유실되면 신청 화면과 준비한 진행 ID·파일 ID를 유지한다. 사용자가 `같은 신청 다시 저장`을 누르면 해당 연결을 재사용한다. 이미 준비한 신청은 저장 확인 전까지 입력 수정·다른 메뉴 이동·로그아웃을 막는다. 파일 업로드 단계에서 실패하면 기존의 부분 업로드 정리 처리를 유지한다.

일반 자동저장도 한 창에서 하나씩 실행한다. 요청 중 추가 변경은 최신 내용으로 모아서 앞선 요청 완료 후 저장한다. 오래된 요청의 성공 응답만으로 최신 변경까지 저장됐다고 표시하지 않는다. 실패하면 반복 전송을 멈추고 현재 입력을 유지하며, 사용자가 다시 저장할 수 있다. 서버가 반환한 파트너 명단 버전 갱신만으로 불필요한 후속 저장을 시작하지 않는다.

저장 중·저장 실패·신청 입력 중 새로고침이나 창 닫기를 시도하면 브라우저 이탈 경고를 요청한다. 제출 전 신청 입력이 있는 상태에서 내부 메뉴로 이동하면 폐기 여부를 확인한다. 실제 저장 기능이 없었던 `임시저장` 버튼·배지를 제거하고 제출 전 입력의 보관 범위를 안내한다.

저장 권한 오류가 나도 신청 폼을 로그인 화면으로 바꾸어 입력을 지우지 않는다. 같은 계정으로 새 탭에서 다시 로그인하는 경로를 제공한다. 저장 요청은 처음 불러온 사용자 ID를 포함하며, 서버는 현재 인증한 계정과 다르면 거부한다. 이 값은 권한을 부여하지 않으며 서버의 기존 인증·Origin·담당 계정 검사를 유지한다.

## 검증

- 자동 테스트 110개: 요청 순서·최신 변경 병합·저장 중 원래 값으로 되돌리기·응답 유실·명시적 재시도·준비된 첨부 ID 재사용·동시 제출·서버 확인 없는 HTTP 200 거부 등을 포함한다.
- 실제 저장 핸들러와 격리 SQLite에서 서버 저장 직후 응답이 유실된 상황을 만들고, 재시도 후 진행·타임라인·서류가 각각 한 건만 남는지 확인한다.
- 격리 workerd/D1/R2 점검 55개: 동일 신청 재저장 시 파일 연결을 보존하고 다른 인증 계정으로 재시도하면 저장 전 거부하는 것을 확인한다.
- 운영 고객 데이터·실제 계정 생성·메일 전송·유료 AI 호출·브라우저 클릭 시험은 수행하지 않았다. 데이터 구조와 운영 접근 설정은 변경하지 않는다.

## 제한과 후속 점검

이번 재시도 보관은 **열린 신청 화면의 메모리**에 한정된다. 브라우저 이탈 경고를 무시하거나 브라우저·기기가 종료되면 서버에 저장되지 않은 입력을 복원하지 못한다. 브라우저가 이탈 경고를 표시하지 않는 경우도 있다. 제출 전 신청의 서버 임시저장, 새로고침 후 첨부 복구, 업로드 응답 유실 시 미연결 원본 회수는 별도 구현이 필요하다. 입력 중인 모든 신청 항목의 영구 저장을 보장하지 않는다.

한 창의 저장 순서만 보장하며, 서로 다른 창·여러 사용자의 일반 운영 데이터 수정에 대한 전체 충돌 해소를 추가하지 않았다. 기존 명단 충돌 검사를 유지하고 자동 덮어쓰기나 강제 재저장을 하지 않는다. 네트워크 요청이 아직 끝나지 않은 동안은 추가 쓰기를 시작하지 않는다.

선행 운영 소스는 `1ce9ad0`, 버전 37이다. 이번 배포 결과는 운영 배포 이력과 로컬 `outputs/release/` 완료 기록에 남긴다. 다음 점검은 제출 전 신청 항목의 실제 저장 범위, 서버 임시저장·재접속 복구, 여러 창의 변경 충돌 순으로 진행한다.
