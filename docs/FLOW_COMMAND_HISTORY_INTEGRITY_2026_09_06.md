# 상담 FLOW 명령 이력 무결성

기준일: 2026-09-06

## 문제·적용

감사기록과 AI 작업은 보존됐지만, 후속 저장에서 기존 `commandIds` 또는 명령 영수증을 제거·교체해 처리된 요청을 다시 실행 가능한 상태로 만들 수 있었다. 새 AI 작업도 작업·감사 ID만 맞추고 실제 멱등 명령 원장에는 기록하지 않을 수 있었다. 이제 애플리케이션과 추가형 `0050` D1 트리거가 명령 ID의 순서 보존 접두부, 기존 영수증과 AI 작업 생성 명령 연결을 강제한다.

## 감사·보존 경계

- 기존 `commandIds`는 순서와 값이 유지된 접두부로 보존한다.
- 기존 `commandReceipts`의 행위자 키와 요청 지문은 수정·삭제할 수 없다.
- 새 AI 작업은 같은 revision에 추가된 정확히 하나의 명령 ID에서 파생돼야 한다.
- 작업 ID·감사 ID가 맞아도 멱등 명령 ID가 빠졌거나 과거 ID를 재사용하면 저장을 거절한다.
- 기존 레거시 명령 ID의 영수증 부재는 읽기 호환하며 운영 자료를 다시 쓰지 않는다.
