# 포털 자동저장 응답 검증 안전성

## 문제

포털 자동저장 클라이언트는 `/api/state` 저장 응답을 타입 단언으로 읽었다. `ok`만 참이면 명단 버전·상태 버전·저장용량 구조를 확인하지 않은 채 저장 완료로 취급할 수 있었고, 비-JSON 오류는 기술 오류 문구로 노출될 수 있었다.

## 변경

- 저장 응답 JSON을 안전하게 읽고 객체 여부를 확인한다.
- 성공 응답은 명시적 `ok`, 0 이상의 명단 버전, 비어 있지 않은 상태 버전을 모두 요구한다.
- 대표에게 제공되는 선택적 저장용량 지표는 공용 구조 검증을 통과한 경우에만 반영한다.
- 성공 응답은 검증한 필드만 새 객체로 반환한다.
- 실패 응답은 안전한 서버 오류와 형식이 유효한 충돌 복구 영수증만 유지한다.
- 비-JSON·손상된 성공 응답은 현재 화면을 유지하고 동일 내용을 다시 저장하도록 안내한다.

## 유지한 운영 경계

- `/api/state` 서버 계약·저장·인증·권한·CAS·충돌 복구 동작을 변경하지 않았다.
- 실패한 저장은 기존 큐 정책대로 자동 재시도하지 않고 사용자 확인 후 같은 최신 화면을 다시 저장한다.
- 운영 데이터·DB/R2 스키마·보관 정책, 외부 발송·유료 AI 설정을 변경하지 않았다.
- GitHub 푸시와 공개 Sites 배포는 사용자 승인 전까지 수행하지 않는다.

## 검증

- 자동 테스트: 360개 통과
- 격리 workerd/D1/R2 스모크: 129개 통과
- TypeScript `--noEmit`, 전체 lint, 프로덕션 빌드 통과
- 기존 개발 서버 `/` 응답: HTTP 200
- 검증 중 운영 쓰기·메일 발송·유료 AI·외부 요청: 각 0건
