# 진행 타임라인 기록 무결성 경계

기준일: 2026-09-05

## 확인한 문제

진행 타임라인은 배열 항목이 객체인지만 확인했다. 빈 날짜·제목·상세·유형·색상 값, 현재 진행에 없는 `caseId`, 공백 ID와 같은 안정 ID의 중복 기록도 저장될 수 있었다. 파트너 병합 키가 `caseId`와 ID를 함께 사용해 같은 안정 ID를 다른 진행으로 옮기는 조작도 새 기록처럼 합쳐질 수 있었다.

## 적용한 경계

- `date`, `title`, `detail`, `type`, `tone`은 앞뒤 공백 없는 비어 있지 않은 문자열이어야 한다.
- 선택적 `id`가 있으면 앞뒤 공백 없는 문자열이며 전체 타임라인에서 고유해야 한다.
- 선택적 `caseId`가 있으면 앞뒤 공백 없는 문자열이며 현재 진행 하나에 정확히 연결되어야 한다.
- 안정 ID가 있는 기존 타임라인을 파트너가 저장할 때 그 ID의 진행 연결을 다른 `caseId`로 바꾸지 못한다.
- 파트너 병합에서 안정 ID는 진행 ID와 무관한 전역 키로 취급해 다른 진행에 같은 ID를 새 기록처럼 추가하지 못한다.
- ID가 없는 기존 타임라인과 `caseId`가 없는 레거시 기록은 기존 표시·병합 의미를 유지한다.
- 공용 순수 검증기를 서버 저장·조회와 클라이언트 최초 상태 응답에 함께 적용한다.
- 조작 저장은 403, 이미 저장된 손상 상태는 파트너 조회 403, 관리자 조회와 일반 저장 503으로 격리한다.
- 운영 데이터 자동 수정, 기존 타임라인 재배정·삭제, D1/R2 스키마 변경은 수행하지 않았다.

## 검증

- 수정 전 재현: 미존재 진행, 공백·중복 안정 ID, 필수 표시값 누락과 안정 ID의 진행 이동이 저장·병합 경계를 통과했다.
- 수정 후: 손상 타임라인은 서버·클라이언트·격리 Worker 경계에서 거절하고 저장 상태는 바뀌지 않는다.
- ID 없는 타임라인과 `caseId` 없는 레거시 기록은 유지한다.
- Node 자동 테스트 535/535 통과.
- 격리 workerd+D1+R2 검사 303/303 통과.
- 타입검사, 전체 lint, 프로덕션 빌드 통과.
- 로컬 프로덕션 `/`, `/account`, `/account/setup` HTTP 200 확인.
- 실제 운영 쓰기, 메일 발송, 유료 AI 요청, 외부 요청 0건.
