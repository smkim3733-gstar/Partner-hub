## 2026-10-12 후속 개발 — 상담 FLOW 첨부·중복 명령·권한 경합

운영과 분리된 PostgreSQL **17.11**의 독립 연결 **4개**와 가상 Storage를 사용했다. 전체 실제 마이그레이션을 적용하고, 가상 관리자·파트너의 기존 로그인/API 경로를 통해 첨부를 처리했다. 각 요청의 DB와 Storage 원장은 동일 연결에 묶었다. 같은 테이블 잠금에서 두 쓰기 연결의 실제 대기를 관찰한 뒤 경합을 해제했다. 고객 자료·운영 연결값·유료 AI는 사용하지 않았다.

- **제품 수정 1건:** 동일 첨부의 Storage 원장 등록에서 확정된 PostgreSQL **40001**이 `writeReservedFlowUpload`를 거치며 일반 장애 **503**으로 바뀌었다. `lib/consulting-flow-handlers.ts`에서 이미 분류된 `SupabaseTransactionConflict`만 **409**로 안내한다. 원본은 보존하고 저장 결과 확인 후 같은 자료로 재시도하도록 한다.
- 업로드 실패 후 최신 권한을 재검사하는 기존 경로는 유지했다. 권한 해제는 **403**, 응답 유실·결과 불명은 기존 **503**이며 자동 재시도하지 않는다. 합성 Storage 응답 유실에서는 물리 업로드 시도 **1회**만 있었다.

2. 운영과 분리된 Next.js + Supabase 검증 배포에서 테스트 기업 1곳으로 가입 → 승인 → 신청 → 배정 → 업로드·다운로드 → 상담 FLOW → 계약·입금 기록 → 사후관리·권한 검증을 수행한다. 운영 대상 확인은 기존 자료 이전 계획과 데이터 보존 범위를 확정한 뒤 제한적으로 수행한다.
3. 기존 Sites의 완전한 원본·파일 목록을 확보해 이전 계획을 보완한다. 현재 포털 초기 상태와 이전 도구의 빈 대상 조건을 대조하고, 조건을 우회하거나 기존 행을 임의 삭제하지 않는다.
4. 암호화 백업과 복구 키의 별도 외부 보관 위치를 정하고 전달·복호화를 검증한다.
5. 실패 알림 수신과 실제 파일을 포함한 새 Supabase 환경 복구를 검증한다. 임시 업로드 정리 도구 O3는 완료했으므로 반복 구현하지 않는다. 실제 정리 실행은 별도 승인과 버전 API 호환 검증을 요구한다. AI 자동화는 별도 선택 기능으로 진행한다.

기존 Sites 접근에 대한 자동 승인 거절은 해제된 것으로 간주하지 않는다. 원본 확보가 필요하면 해당 접근의 승인 상태부터 확인한다. 실제 고객 자료를 테스트에 사용하거나 외부 발송·유료 AI를 실행하는 작업은 별도 범위를 확인한다.
