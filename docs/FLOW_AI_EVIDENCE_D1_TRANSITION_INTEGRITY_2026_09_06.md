# 상담 FLOW AI 증거·감사 D1 전이 무결성

기준일: 2026-09-06

## 문제·적용

애플리케이션 커밋은 기존 AI 증거와 감사기록을 보존하지만 D1에 직접 쓰는 경로는 revision·행 envelope만 맞추면 구조상 정상인 증거와 이력을 함께 바꿀 수 있었다. 이제 추가형 `0043` 마이그레이션과 런타임 준비 트리거가 같은 불변 전이를 D1에서 독립적으로 강제한다.

## 네이티브 저장 경계

- 기존 감사기록은 배열 위치와 전체 JSON 값이 같은 접두부로 남아야 하며 뒤쪽 추가만 허용한다.
- 기존 작업 ID는 후속 revision에서 제거할 수 없다.
- 새 작업은 시작·완료·보고서·성공·실패·실패이력 증거가 없는 `queued` 또는 `blocked` 상태로만 추가할 수 있다.
- 성공 증거는 기존 작업의 `processing` → `complete` 전이에서만 처음 추가하며 이후 전체 값을 고정한다.
- 현재 실패 증거는 `processing` → `failed`에서만 처음 추가하고, 이후 그대로 보존하거나 재시도 때 실패 이력 끝으로 정확히 한 번 이동한다.
- 실패 이력의 기존 항목은 위치와 전체 값을 고정하며 임의 추가·변경·삭제를 거절한다.
- 정상 실패 → 재시도 → 처리 중 → 재실패 수명주기는 그대로 허용한다.
- 기존 행과 운영 자료를 변경하지 않는 추가형 트리거만 설치한다.
