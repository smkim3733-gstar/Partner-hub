# 파트너 계정 설정 저장 안전성

2026-09-03 기준. 대표의 계정·권한 설정창에서 저장 전 변경이 운영 상태에 먼저 반영되던 경계를 보완했다.

## 문제

- 이메일과 파트너 유형은 화면 안 임시값이었지만 로그인 상태와 개별 권한은 선택 즉시 `members` 상태를 바꿨다.
- 상위 자동저장이 `members` 변경을 감지하므로 `계정·권한 저장`을 누르기 전에도 변경이 저장될 수 있었다.
- 사용자가 취소하거나 창을 닫아도 이미 바뀐 상태·권한은 되돌아가지 않았다.

## 변경

- 이메일·파트너 유형·로그인 상태·개별 권한을 하나의 계정 설정 초안으로 복사한다.
- 권한 스위치와 상태 선택은 초안만 바꾸며 실제 파트너 명단을 수정하지 않는다.
- `계정·권한 저장`은 검증된 초안을 한 번에 적용하고, `취소`와 닫기는 초안을 폐기한다.
- 승인대기 계정도 검토한 유형·이메일·권한을 승인 동작과 함께 원자적으로 적용한다.
- 저장하지 않은 변경이 있으면 기존 계정 기준의 비밀번호 설정 링크 발급을 잠시 막는다.
- 변경이 없을 때 저장 버튼을 비활성화하고, 화면에 저장 전 상태임을 표시한다.

## 유지한 경계

- 기존 파트너 유형·기본 권한·리더 역할 유지 규칙을 바꾸지 않았다.
- 계정 정지는 저장을 눌러야 반영되며, 삭제는 실제 저장된 정지 상태와 기존 2단계 확인을 계속 요구한다.
- 기존 계정이나 운영 데이터를 일괄 변경하지 않았다.
- 서버의 인증·권한·저장 revision/CAS, DB/R2 스키마와 보관 정책을 변경하지 않았다.

- 격리 workerd/D1/R2 스모크 검사 129개 통과
- 타입검사·전체 lint·프로덕션 빌드 통과
- `git diff --check` 통과
- localhost `/` HTTP 200 확인
- 실제 운영 쓰기·메일·유료 AI·외부 요청 0건

GitHub 푸시와 공개 Sites 배포는 사용자 승인 전까지 수행하지 않는다.
