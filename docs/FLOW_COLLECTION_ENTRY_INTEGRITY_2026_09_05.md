# 상담 FLOW 컬렉션 항목 무결성 경계

기준일: 2026-09-05

## 확인한 문제

기존 v144 경계는 FLOW의 필수 배열과 객체가 존재하는지 확인했지만 배열 내부 항목의 필드 형식과 허용값까지 검증하지 않았다. 따라서 배열 껍데기는 정상이면서 보고서 단계, 파일 크기, 상담 상태, 요청 필수 여부, 결제 금액 등이 손상된 payload가 진행단계·다운로드·대시보드 계산으로 전달될 수 있었다.

대시보드는 SQLite에서 파일·감사기록·AI 작업 등 민감 컬렉션을 제거한다. 제거 전에 내부 항목이 일반 객체인지 확인하지 않으면 숨겨진 손상 컬렉션이 정상 투영 결과처럼 보일 수 있었다.

## 적용한 경계

- 보고서·파일·상담·녹취·서류요청·결제·AI 작업·감사기록의 모든 항목이 일반 객체이고 비어 있지 않은 고유 ID를 갖도록 검증한다.
- 보고서 단계·버전·출처, 파일명·MIME·크기·저장 키·생성시각, 상담 종류·참석자·상태·시각 순서, 녹취 동의·검토시각을 검증한다.
- 서류요청 채널·상태·필수 여부, 결제의 양수 정수 금액, AI 작업 단계·상태, 감사기록의 행위자·행위·상세를 검증한다.
- analysis·ai·decision·contract·aftercare·commandReceipts의 필수 필드와 값 형식도 함께 검증한다.
- 배열 ID와 command ID 중복을 거절한다. 저장된 파일은 비어 있지 않은 비공개 저장 키를 요구하고, 브라우저용 공개 FLOW에서 의도적으로 제거한 키는 허용한다.
- 대시보드는 SQLite 투영 전에 원본의 모든 필수 컬렉션 항목 형식을 확인한다. 이후 축소된 보고서·녹취 항목도 전용 projected 검증기를 통과해야 한다.
- 구조 손상은 상세 조회와 대시보드 모두 HTTP 503 관리자 복구 상태로 격리한다. 정상 명령, 권한, CAS, D1/R2 보관 정책은 변경하지 않았다.

## 검증

- 잘못된 보고서 단계, 음수 파일 크기, 허용되지 않은 상담 상태, 문자열형 요청 필수 값, 음수 결제 금액을 상세 조회 전에 모두 거절한다.
- 대시보드가 투영에서 제거할 `files` 컬렉션에 숫자 항목이 들어간 경우 SQLite 선검증에서 차단한다.
- 격리 Worker의 실제 D1 경로에서 보고서 단계 손상을 상세·대시보드 모두 HTTP 503으로 차단하고 원본 복구 뒤 정상 조회가 재개된다.
- Node 자동 테스트 572/572 통과.
- 격리 workerd+D1+R2 검사 363/363 통과.
- 타입검사, 전체 lint, 포맷 검사, 프로덕션 빌드 통과.
- 로컬 프로덕션 `/`, `/account`, `/account/setup` HTTP 200과 CSP·`nosniff`·`no-referrer` 확인.
- 실제 운영 쓰기, 메일 발송, 유료 AI 요청, 외부 요청 0건.

## 다음 감사

각 컬렉션 내부 참조의 연결 무결성을 검증한다. 보고서의 파일·원본 보고서·녹취·결정 참조, 녹취의 상담·파일 참조, 요청의 파일 참조, 분석·결정·계약·AI 작업의 보고서·상담·서명 파일 참조가 같은 FLOW 안의 실제 대상과 일치하는지 확인한다. 형식은 정상이지만 존재하지 않거나 다른 종류를 가리키는 고아 참조를 차단한다.
