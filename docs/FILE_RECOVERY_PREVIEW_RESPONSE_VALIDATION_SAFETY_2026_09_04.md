# 원본 회수 미리보기 응답 검증 안전성

2026-09-04 기준으로 대표가 미연결 원본의 회수 조건을 확인할 때 사용하는 미리보기 API 응답의 클라이언트 검증을 보강했다.

## 변경 범위

- 회수 조건 응답을 `unknown`으로 읽고 일반 JSON 객체인지 먼저 확인한다.
- 응답 파일 ID가 사용자가 보관 목록에서 선택한 원본 ID와 같은지 확인한다.
- 파일명·기업명·자료종류·자료명·서비스·담당자명·담당 이메일을 형식과 길이 범위 안에서 검증한다.
- 진행 ID와 담당 계정 ID는 서버가 허용하는 식별값 형식인지 확인한다.
- 원본 크기는 0보다 크고 업로드 상한인 25MB 이하인 안전한 정수만 허용한다.
- 운영 상태 revision과 원본 revision은 각각 64자리 소문자 16진수 SHA-256 형식인지 확인한다.
- 검증된 공개 필드만 새 객체로 반환한다. 저장소 키·업로드 요청정보 등 알 수 없는 응답 필드는 확인 폼과 회수 요청에 전달하지 않는다.
- 실패 응답은 길이가 제한된 서버 오류만 유지한다. 비-JSON 또는 손상된 성공 응답은 보관 목록 새로고침 후 재확인을 안내한다.

## 유지한 안전 경계

- 서버의 대표 관리자 인증, 원본·진행·기업·담당 계정 연결 확인, D1 기록과 R2 `head` 재검증은 변경하지 않았다.
- 미리보기 뒤 확인 사유·명시 동의·고정 요청번호·편집 잠금과 저장 직전 revision 재검증을 유지한다.
- 미리보기만으로 자료 카드·회수 이력·상담 FLOW를 만들거나 원본을 이동·삭제하지 않는다.
- 운영 데이터, 실제 원본, D1/R2 스키마, 권한·보관·삭제 정책과 공개 배포 상태를 변경하지 않았다.

## 검증

- 자동 테스트 399개
- 격리 workerd/D1/R2 검사 129개
- TypeScript 타입검사, 전체 lint, 프로덕션 빌드
- localhost `/` HTTP 200

모든 신규 응답 검사는 가상 원본 메타데이터와 합성 응답으로 실행했다. 실제 원본 조회·회수 저장·운영 쓰기·메일·유료 AI·외부 요청은 0건이다. GitHub 푸시와 공개 Sites 배포는 사용자 승인 전까지 수행하지 않는다.
