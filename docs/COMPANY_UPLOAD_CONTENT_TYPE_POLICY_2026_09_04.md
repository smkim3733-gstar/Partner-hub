# 기업자료 업로드 Content-Type 저장 정책

## 목적

기업자료 업로드에서 브라우저가 전달한 MIME 값을 신뢰하지 않고, 검증한 파일 확장자의 공용 등록표 MIME만 응답·D1·R2 메타데이터에 저장한다.

## 적용 범위

- 파일명 정규화와 실제 내용 검사를 통과한 뒤 공용 업로드 형식 등록표에서 고정 MIME을 결정한다.
- 새 기업자료의 API 응답, D1 `content_type`, R2 `httpMetadata.contentType`에 같은 고정값을 사용한다.
- 클라이언트는 배포 전후 응답 유실 재시도를 위해 이전 서버의 브라우저 MIME 응답도 한시적으로 검증하되, 화면 상태에는 등록표 MIME만 반영한다.
- 배포 직전 이전 서버가 `pending`으로 예약한 요청은 이전·신규 지문을 함께 대조해 동일 파일의 안전한 재시도를 이어간다. 파일이나 업무 메타정보가 달라진 요청은 기존처럼 HTTP 409로 거절한다.

## 유지한 경계

허용 확장자, 실제 파일 내용 검사, 크기·개수, 파일명, 동의, 인증·권한, 담당 계정·진행 연결, R2 키, D1 스키마와 보관·삭제 정책은 변경하지 않았다. 기존 운영 자료의 저장값을 일괄 변경하거나 읽지 않았다. 다운로드는 기존과 같이 등록표 MIME을 사용한다.

## 재발 방지

- 브라우저가 TXT를 `text/html`로 제출해도 응답·D1·R2가 모두 `text/plain`인지 검사한다.
- 이전 릴리스가 브라우저 MIME으로 예약한 대기 요청이 같은 파일로 완료되는지 검사한다.
- 새 클라이언트가 이전·신규 서버 응답을 모두 안전하게 받되 반환 MIME은 고정값인지 검사한다.
