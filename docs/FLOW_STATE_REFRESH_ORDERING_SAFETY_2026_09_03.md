# 상담 FLOW 상태 새로고침 순서 안전성

## 문제

상담 FLOW 화면의 초기 조회, 수동 새로고침과 409 충돌 후 재조회는 각각 도착 즉시 상태를 적용했다. 새로고침 버튼을 빠르게 반복하거나 연결 지연으로 응답 순서가 바뀌면, 더 늦게 도착한 과거 성공 응답이 최신 FLOW를 되돌리거나 과거 실패가 최신 성공 뒤 오류를 표시할 수 있었다.

## 변경

- FLOW 상태 조회마다 증가하는 요청 버전을 부여한다.
- 초기 조회·수동 새로고침·409 충돌 후 재조회가 같은 최신 요청 판정을 사용한다.
- 가장 최근 요청의 검증된 성공 응답만 FLOW·역할·업로드 권한·AI 준비상태에 적용한다.
- 최신 성공 이후 도착한 과거 성공·실패 응답은 상태와 오류 안내를 바꾸지 않는다.
- 진행 화면을 닫거나 다른 진행으로 이동하면 대기 중 조회를 취소하고 요청 버전을 무효화한다.

## 유지한 운영 경계

- 서버 FLOW 저장·AI 실행·권한·중복 요청·409 충돌 의미와 응답 검증 규칙을 변경하지 않았다.
- 새로고침 실패를 자동 재시도하거나 저장 결과를 추정하지 않는다.
- 운영 데이터·DB/R2 스키마·인증·권한·보관 정책, 외부 발송·유료 AI 설정을 변경하지 않았다.
- GitHub 푸시와 공개 Sites 배포는 사용자 승인 전까지 수행하지 않는다.

## 검증

- 자동 테스트: 346개 통과
- 격리 workerd/D1/R2 스모크: 129개 통과
- TypeScript `--noEmit`, 전체 lint, 프로덕션 빌드 통과
- 기존 개발 서버 `/` 응답: HTTP 200
- 검증 중 운영 쓰기·메일 발송·유료 AI·외부 요청: 각 0건
