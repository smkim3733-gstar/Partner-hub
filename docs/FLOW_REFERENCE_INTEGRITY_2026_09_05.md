# 상담 FLOW 내부 참조 무결성 경계

기준일: 2026-09-05

## 확인한 문제

각 FLOW 항목의 필드 형식이 정상이어도 파일·보고서·상담·녹취 ID가 같은 FLOW 안의 실제 대상을 가리킨다는 보장은 없었다. 고아 참조가 남으면 보고서 다운로드, 공동분석, 심화보고서, 계약, 서류 검토, AI 작업과 대시보드 단계 계산이 서로 다른 근거를 사용할 수 있었다.

또한 정상 명령 경로는 참조를 올바르게 만들지만 내부 저장 함수가 최종 payload의 전체 구조와 참조를 쓰기 전에 다시 확인하지 않아 잘못된 서버 호출이 손상 상태를 기록할 여지가 있었다.

## 적용한 경계

- 분석 보고서는 실제 1차 보고서, 보고서의 원본 보고서는 실제 1차 보고서, 원본 녹취는 실제 녹취, 결정 ID는 실제 결정만 가리키도록 검증한다.
- 보고서 첨부, 녹취 원본·전사문·음성, 서류요청 첨부와 계약 서명본은 같은 FLOW의 실제 파일만 참조하도록 검증한다.
- 녹취는 실제 상담, 결정은 실제 4차 보고서, 계약은 실제 계약상담과 6차 보고서를 가리키도록 검증한다.
- AI 작업의 원본 녹취·1차 보고서·결과 보고서가 존재하고 결과 차수가 작업 차수와 일치하도록 검증한다.
- 명령 영수증은 실제 command ID에만 연결할 수 있다.
- 브라우저 공개 응답과 SQLite 대시보드 축소본에도 남아 있는 보고서·녹취·결정·계약 참조를 같은 규칙으로 검사한다.
- 대시보드 투영에서 제거되는 파일·AI 작업·명령 영수증 참조는 SQLite 내부 `json_each` 검사로 확인한 뒤에만 민감 필드를 제거한다.
- `commitFlow`가 D1 쓰기 전에 저장본 전체 구조와 참조를 다시 확인한다. 손상 payload는 HTTP 503 복구 상태로 거절하며 새 행도 만들지 않는다.

## 검증

- 존재하지 않는 보고서 파일·원본 보고서·분석 보고서·녹취 상담·요청 파일·결정 보고서·AI 원본 녹취와 고아 명령 영수증을 상세 조회 전에 모두 거절한다.
- 저장 함수가 존재하지 않는 파일을 가리키는 보고서를 D1 쓰기 전에 거절하고 행을 남기지 않는다.
- SQLite 대시보드가 투영에서 제거할 파일을 가리키는 서류요청도 고아 참조로 차단한다.
- 격리 Worker의 실제 D1 경로에서 고아 보고서 참조를 상세·대시보드 모두 HTTP 503으로 차단하고 복구 뒤 정상 조회가 재개된다.
- Node 자동 테스트 575/575 통과.
- 격리 workerd+D1+R2 검사 365/365 통과.
- 타입검사, 전체 lint, 포맷 검사, 프로덕션 빌드 통과.
- 로컬 프로덕션 `/`, `/account`, `/account/setup` HTTP 200과 CSP·`nosniff`·`no-referrer` 확인.
- 실제 운영 쓰기, 메일 발송, 유료 AI 요청, 외부 요청 0건.
