# 상담 FLOW 진행판 새로고침 안전성

## 문제

상담 FLOW 명령이 서버에 저장된 뒤 허브 진행·일정 화면을 갱신하는 요청은 비정상 HTTP 응답이나 손상된 성공 응답을 조용히 무시했다. 연속 명령의 새로고침 응답이 역순으로 도착하면 늦게 도착한 과거 응답이 더 최신 진행판을 덮을 수도 있었다.

## 변경

- 진행판 새로고침 응답은 HTTP 성공 여부와 전체 포털 상태 형식을 모두 확인한다.
- 401·500 등 서버 오류, 읽을 수 없는 JSON, 상태가 없거나 잘못된 성공 응답은 저장된 FLOW 명령과 구분해 수동 새로고침 안내를 표시한다.
- 새로고침마다 증가하는 요청 버전을 부여하고 가장 최근 요청의 검증된 응답만 화면에 적용한다.
- 최신 요청 이후 도착한 과거 성공·실패 응답은 진행·일정·오류 안내를 바꾸지 않는다.
- 화면 해제 시 대기 중 응답을 무효화해 이후 상태 변경을 막는다.

## 유지한 운영 경계

- FLOW 명령의 서버 저장, 요청 ID·영수증·권한 재검증과 진행·일정 투영 규칙을 변경하지 않았다.
- 실패한 화면 갱신을 자동 재실행하거나 서버 데이터를 되돌리지 않는다. 저장 결과는 최신 화면을 다시 불러와 확인한다.
- 운영 데이터·DB/R2 스키마·인증·권한·보관 정책, 외부 발송·유료 AI 경로를 변경하지 않았다.
- GitHub 푸시와 공개 Sites 배포는 사용자 승인 전까지 수행하지 않는다.

## 검증

- 자동 테스트: 340개 통과
- 격리 workerd/D1/R2 스모크: 129개 통과
- TypeScript `--noEmit`, 전체 lint, 프로덕션 빌드 통과
- 기존 개발 서버 `/` 응답: HTTP 200
- 검증 중 운영 쓰기·메일 발송·유료 AI·외부 요청: 각 0건
