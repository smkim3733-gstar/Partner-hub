# 개발 현황 — 2026-08-31

## 포함한 구현

기존 파트너 허브의 전체 코드, 35개 선행 개발 커밋, 최신 이메일·비밀번호 인증 개발본, 기획·입출력 명세·검증 문서를 함께 보관한다. 실제 고객 자료와 운영 DB는 보관 범위가 아니다.

### 계정

가입 항목은 이름, 핸드폰번호, 소속, 이메일 아이디, 사이트 전용 비밀번호다. 신규 가입은 승인대기로 등록하고 대표가 네 가지 파트너 유형 중 하나를 지정해 승인한다. 이메일은 메일 서비스 계정의 ID가 아니라 전체 이메일 주소를 사이트 로그인 ID로 사용하는 의미다. 메일 비밀번호를 수집하지 않는다.

기존에 등록된 이메일은 공개 가입으로 다시 가져갈 수 없다. 대표 본인 확인 후 30분 유효 일회용 설정 링크를 전달한다. 설정 완료 시 기존 사이트 비밀번호 세션을 무효화한다. 자동 발송은 없으며 관리자 및 기존 ChatGPT 로그인도 남아 있다.

### 업무

협업신청 → 근거자료 검토 → 1차 보고서 등록·공유 → 대표/파트너 각각 분석 완료 → 초회상담 예약 → 2차 보고서·3차 PPT 준비 → 동반 상담 → 녹취자료 등록·4차 심화분석 → 대표의 솔루션 확정 → 추가서류 요청·수령·확인 → 5차 견적·6차 계약서 준비 → 계약상담·서명본 등록 → 계약금 확인 → 수행·사후관리 흐름이다.

상담·서류요청은 필요한 횟수만큼 반복한다. 서명과 입금 확인은 별개이고, 상담 횟수나 자료 제출만으로 계약·입금·성공을 확정하지 않는다. 공유 일정은 다른 기업의 상세정보를 가린다. 신규 상담 FLOW는 담당 계정 ID에 연결된다.

### 자료와 AI

초기 신청 시 기업자료와 전화통화 녹취자료를 함께 등록한다. 상담 후에는 DOCX/TXT 또는 검토한 전사 본문을 중심으로 입력하고, 음성은 보조 파일로 보관한다. 전사문·식별정보·기업·상담일·금액을 확인해야 하며 자동 OCR·마스킹이나 원음 자동 전사를 완료된 기능으로 표시하지 않는다.

AI 1차/4차는 기업별 외부 처리·마스킹·비용 확인 후 서버 API로 요청한다. 키 존재 확인과 실제 키 인증/잔액/모델 이용 가능 확인은 다르다. 2차/3차/5차/6차는 대표가 준비한 실제 문서 등록 방식이다. 최종 검토와 고객 전달은 대표 판단을 유지한다.

## 별도 운영 확인이 필요한 부분

- 이메일/휴대폰 소유권 자동 인증, 자동 초대메일, MFA는 이번 기능에 포함되지 않는다. 대표 본인 확인 절차를 유지한다.
- Google Calendar 양방향 연동, 음성 전사 서비스, 카카오톡·이메일 발송, 전자서명, 은행 입금 자동조회는 미연결이다.
- 이메일·비밀번호 개발본의 공개 사이트 배포와 실제 파트너 로그인 파일럿은 GitHub 업로드와 별개다.
- 기존 이름 기반 레거시 업무자료까지 계정 ID로 전면 이관하는 작업이나 서비스 전체 침투시험은 이번 인증 검증 범위가 아니다.
- UI 공통 컴포넌트의 기존 lint 오류 19건은 후속 로컬 정비를 완료했다. 전체 lint, 테스트 81개, 타입검사와 빌드가 통과했으며, 이 변경의 운영 배포는 아직 수행하지 않았다.

## 후속 로컬 정비

모바일 화면 감지와 캐러셀 버튼 상태를 외부 상태 구독 방식으로 변경했다. 캐러셀 재초기화 이벤트도 정리 시 구독을 해제한다. 버튼·입력 그룹, 현재 위치 표시, 페이지 링크, 로딩 표시의 HTML 의미를 정리하고, 차트가 함수형 데이터 접근자를 문자열 키로 잘못 사용하는 문제를 수정했다. 차트 회귀 테스트 4개를 추가했다.

슬라이드·폼 필드·다형 목록의 유효한 ARIA 역할과 입력 장식의 보조 클릭 동작은 유지한다. 이 네 위치의 검사 오탐에만 사유를 명시한 줄 단위 예외를 적용했으며, 전체 lint 설정과 인증·업무·DB 코드는 변경하지 않았다. UI 정적 검사 통과가 브라우저 접근성 전체 검증을 의미하지는 않는다.

## 다음 작업

가입·승인 파일럿을 위한 후속 로컬 점검에서 동명이인 자료 노출·수정 문제를 재현하고 보완했다. 조회·저장 시 서버의 계정 ID를 우선 사용하며, 이름이 여러 계정에 연결된 과거 자료는 파트너 접근을 허용하지 않는다. 공유 일정의 추가 비공개 필드도 차단한다. 테스트 87개, 격리 workerd/D1/R2 검증 31개, 전체 lint·타입검사·빌드를 통과했다. 실제 운영 데이터는 확인하거나 이관하지 않았다.

기존 사이트가 공개 상태인 것을 읽기 전용으로 확인했으며, 이번 수정은 아직 배포하지 않았다. [운영 반영 준비사항](../RELEASE_READINESS.md)에 반영 내용·승인 후 순서·실사용 제한을 정리했다.

운영 반영을 승인받은 후 기존 사이트의 DB/R2 연결과 권한을 보존해 추가형 마이그레이션을 포함하여 배포한다. 실제 대상과 연락처를 확인한 파트너 한 명으로 가입 또는 비밀번호 설정 → 대표 승인 → 로그인 → 본인 배정 진행 확인을 순서대로 검증한다. 실제 계정 생성·링크 발송·고객 자료 제출은 별도 사용자 요청 범위에서만 수행한다.
