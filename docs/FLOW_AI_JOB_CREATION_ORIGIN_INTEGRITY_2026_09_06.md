# 상담 FLOW AI 작업 생성 원본 무결성

기준일: 2026-09-06

## 문제·적용

기존 작업의 수명주기와 감사기록은 보호됐지만, 새 작업을 과거 시각으로 만들거나 1차 작업에 기존 보고서를 원본으로 붙이고 4차 작업에 최신 녹취·1차 보고서가 아닌 원본을 지정할 수 있었다. 생성 명령 감사 없이 새 작업만 추가하는 직접 D1 수정도 가능했다. 이제 애플리케이션과 추가형 `0048` D1 트리거가 새 작업의 생성 revision, 단계별 원본과 생성 감사기록을 원자 결속한다.

## 감사·보존 경계

- 새 작업의 `createdAt`은 해당 FLOW revision의 권위 `updatedAt`과 정확히 같아야 한다.
- 1차 작업은 녹취·보고서 원본 참조를 갖지 않는다. 기존 생성 코드가 1차 작업에 최신 1차 보고서를 잘못 상속하던 동작도 제거했다.
- 4차 작업은 같은 payload의 최신 녹취와 최신 1차 보고서를 모두 정확히 참조해야 한다.
- 새 1차 작업 수와 같은 revision의 새 `queue_report1` 감사기록 수, 새 4차 작업 수와 새 `save_recording` 감사기록 수가 각각 같아야 한다.
- 과거 감사기록 재사용, 감사 없는 작업 추가, 과거 생성시각, 오래되거나 다른 단계의 원본 참조를 앱 저장과 D1 직접 수정에서 모두 거절한다.
- 최초 D1 행도 생성시각과 단계별 원본 규칙을 적용한다. 기존 행과 운영 자료를 변경하지 않는 추가형 트리거만 설치한다.
