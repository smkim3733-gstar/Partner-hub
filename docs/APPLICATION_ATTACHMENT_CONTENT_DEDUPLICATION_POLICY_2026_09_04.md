# 협업신청 첨부 실제 내용 중복 판정 정책

## 목적

협업신청 화면에서 실제 내용이 다른 첨부가 파일명·크기·수정시각 우연한 일치 때문에 중복으로 누락되지 않게 한다. 같은 파일을 Unicode 정규형이나 브라우저 MIME 차이와 함께 다시 선택한 경우에는 한 항목만 유지한다.

## 변경 전 위험

화면은 파일명·크기·수정시각을 이어 붙인 값으로 중복을 판정하고 React 목록 키에도 같은 값을 사용했다. 내용이 다른 두 파일의 메타정보가 같으면 뒤 파일을 사용자 안내와 함께 중복으로 제외했고, 목록 키도 충돌할 수 있었다. 반대로 실제 내용이 같은 파일을 다시 선택할 때 수정시각이나 NFC/NFD 파일명이 달라지면 중복으로 판정하지 못했다.

## 적용 내용

- 첨부 선택 시 공용 NFC 안전 파일명·확장자별 고정 MIME·파일 크기·실제 바이트 SHA-256으로 화면 지문을 계산한다.
- 같은 정규 파일명과 실제 바이트를 가진 재선택만 중복 처리한다.
- 파일명과 크기가 같아도 실제 바이트가 다르면 별도 첨부로 유지한다.
- 계산한 지문을 첨부 항목에 보관해 React 목록 키에도 사용한다.
- 파일 내용을 확인하는 동안 두 파일 입력을 잠그고 동시 선택 경합을 차단한다.
- SHA-256 공용 구현을 독립 모듈로 이동해 업로드 멱등키와 같은 계산 구현을 재사용한다.
- 파일 검증 또는 판독 실패 시 기존 선택은 그대로 유지하고 입력 잠금을 해제한다.

## 유지한 경계

화면 지문 계산은 사용자가 선택한 로컬 파일에서만 수행한다. 제출 전 서버·D1·R2로 전송하지 않으며 운영 고객 파일을 읽지 않았다. 제출 시 서버의 파일 형식·크기·개수·권한·출처·멱등키 검증, 원본 보관과 삭제 정책은 변경하지 않았다.
