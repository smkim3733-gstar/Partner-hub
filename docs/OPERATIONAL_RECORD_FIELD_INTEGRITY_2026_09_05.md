# 업무·기업자료·일정 필드 무결성 경계

기준일: 2026-09-05

## 확인한 문제

업무·기업자료·일정은 배열 구조와 고유 ID·담당 연결만 공통 확인했다. 화면과 운영 집계가 직접 사용하는 필수 표시값이 비어 있거나 앞뒤 공백을 포함해도 저장될 수 있었고, 업무 상태·우선순위, 기업자료 종류·상태, 일정 출처·공개범위 같은 허용값도 손상된 문자열을 통과시킬 수 있었다. 이런 기록은 업무 알림·완료 처리·자료 검토·일정 마스킹에서 누락되거나 잘못 표시될 수 있었다.

## 적용한 경계

- 업무의 기업·제목·담당자·마감·관련 정보는 앞뒤 공백 없는 비어 있지 않은 문자열이어야 한다.
- 업무 유형·마감 구분·상태·우선순위와 선택적 지원 요청 유형은 기존 공용 허용 목록만 사용한다.
- 기업자료의 기업·제목·담당자·제출자·수정시각·버전은 앞뒤 공백 없는 비어 있지 않은 문자열이어야 한다.
- 기업자료 종류·검토 상태는 기존 공용 허용 목록만 사용하고 민감자료 표시는 정확한 boolean이어야 한다.
- 일정의 날짜·요일·시작·종료·기업·서비스·방식·상태·색상은 앞뒤 공백 없는 비어 있지 않은 문자열이어야 한다.
- 일정 출처·상태·공개범위는 기존 저장·파트너 마스킹 표현만 허용하고 선택적 비공개 표시는 정확한 boolean이어야 한다.
- 연도를 알 수 없는 기존 월·일 일정과 파트너 화면의 `예약됨` 마스킹 표현은 유지한다. 날짜 형식이나 연도를 임의 생성하지 않는다.
- 공용 순수 검증기를 서버 저장·조회와 클라이언트 최초 상태 응답에 함께 적용한다.
- 조작 저장은 403, 이미 저장된 손상 상태는 파트너 조회 403, 관리자 조회와 일반 저장 503으로 격리한다.
- 운영 데이터 자동 수정, 기존 기록 변환·삭제, D1/R2 스키마 변경은 수행하지 않았다.

## 검증

- 수정 전 재현: 빈 필수 표시값과 허용되지 않은 상태·분류·공개값이 공통 상태 구조 검사를 통과했다.
- 수정 후: 세 컬렉션의 손상값은 서버·클라이언트·격리 Worker 경계에서 거절하고 저장 상태는 바뀌지 않는다.
- 연결 무결성 검사는 완전한 운영 레코드를 사용해 별도로 계속 검증한다.
- Node 자동 테스트 543/543 통과.
- 격리 workerd+D1+R2 검사 318/318 통과.
- 타입검사, 전체 lint, 프로덕션 빌드 통과.
- 로컬 프로덕션 `/`, `/account`, `/account/setup` HTTP 200 확인.
- 실제 운영 쓰기, 메일 발송, 유료 AI 요청, 외부 요청 0건.
