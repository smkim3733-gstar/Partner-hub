# 새 업무 입력 안전성

2026-09-03. 사용자의 연속 개발 요청으로 새 업무 창에 남아 있던 가상 회사명·특정 날짜 기본값과 필수 입력 표시의 불일치를 보완했다.

## 변경

- 새 업무 창은 업무명·기업명·마감일을 빈 상태로 시작한다. 가상 회사명이나 과거 예시 날짜를 운영 업무로 저장하지 않는다.
- 일반 업무는 공백을 정리한 업무명·기업명·마감일이 모두 있어야 생성한다. `지원요청`은 기업명 입력 대신 기존 고정 지원 범위를 사용한다.
- 업무명 120자, 기업명 120자, 마감일 60자로 제한한다. 화면 제한과 등록 직전 검증을 함께 적용한다.
- 등록 성공 뒤 업무명·기업명·유형·지원유형·담당·마감일·마감 구분을 안전한 초기값으로 되돌린다. 실패하면 사용자가 입력한 값은 유지한다.

## 검증 경계

- 자동 테스트 259개, 타입검사, lint, 프로덕션 빌드 통과.
- 공백 정리, 일반 업무의 필수값, 지원 요청 고정 범위, 세 입력 길이 제한을 회귀검증한다.
- 격리 workerd/D1/R2 검사 129개 통과. 실제 쓰기·메일·유료 AI·외부 요청은 0건이다.
- localhost `/` 응답은 HTTP 200이다.
- 기존 업무와 운영 데이터는 다시 쓰지 않는다. 서버 API, DB/R2 스키마, 권한·보관 정책도 변경하지 않는다. GitHub 푸시와 공개 Sites 배포는 사용자 승인 전까지 수행하지 않는다. 반영 뒤 결과는 `outputs/release/portal-task-entry-safety-deployment.json`을 기준으로 한다.
