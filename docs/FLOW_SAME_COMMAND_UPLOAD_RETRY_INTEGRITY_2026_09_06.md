# 상담 FLOW 동일 명령 첨부 재시도 무결성

기준일: 2026-09-06

## 확인한 위험

전사문과 보조 음성 업로드 중 두 번째 R2 쓰기가 실패한 뒤 같은 브라우저가 원래 명령 ID를 재사용할 수 있다. 이 경로가 새 명령 재시도와 다르게 처리되면 기존 예약을 잃거나 중복 키·완료 원장을 만들 수 있다.

## 확인한 현재 경계

- 첫 객체 저장 성공과 두 번째 객체 저장 실패를 결정적으로 재현했다.
- 기존 FLOW 본문은 바뀌지 않고 첫 객체와 두 `pending` 예약을 유지한다.
- 원래 명령 ID와 같은 전사문·음성으로 재시도하면 정확한 두 기존 파일 ID·R2 키를 재사용한다.
- 완료 FLOW는 원래 명령 ID를 한 번만 기록하고 두 예약을 `ready`로 바꾼다.
- 두 완료 원장은 모두 실제 성공한 원래 명령 ID에 결속된다.

기존 구현이 요구 경계를 만족해 런타임 코드는 바꾸지 않고 동일 명령 회귀 증거를 추가했다.
