# ChatGPT 중복 이메일 결속 무결성

기준일: 2026-09-05

## 확인한 문제

기존 관리 화면은 신규 중복 이메일 저장을 차단하지만, 과거 자료 이관·손상 상태처럼 이미 회원 명단에 같은 정규화 이메일이 둘 이상 존재할 수 있다. 안정 사용자 ID가 아직 결속되지 않은 ChatGPT 사용자가 이 이메일로 접속하면 기존 구현은 명단의 첫 회원을 임의 선택해 접근을 허용하고 그 회원에게 사용자 ID 결속을 만들었다. 수정 전 회귀 재현에서 중복 활성 회원 2명의 이메일을 제시한 미결속 사용자가 HTTP 200을 받았다.

## 적용한 경계

- 안정 사용자 ID가 아직 결속되지 않은 ChatGPT 파트너는 정규화 이메일과 일치하는 회원이 정확히 1명일 때만 기존 활성 회원 결속을 시도한다.
- 활성·비활성 여부와 관계없이 같은 이메일 회원이 둘 이상이면 계정을 추정하지 않고 HTTP 403으로 거절한다.
- 거절된 요청은 `portal_chatgpt_identity_bindings`에 결속을 만들지 않는다.
- 이미 결속된 사용자는 공급자 이메일이 바뀌거나 레거시 명단에 중복 이메일이 생겨도 기존 회원 ID로 찾는다.
- 신규 중복 이메일 차단, 회원 상태 확인, 안정 ID 해시 저장, D1 고유 제약, 관리자·비밀번호 인증 경계는 유지한다.

## 검증

- 수정 전: 중복 활성 회원 이메일을 제시한 미결속 ChatGPT 사용자가 HTTP 200을 받고 첫 회원으로 결속됐다.
- 수정 후: 같은 요청은 HTTP 403이며 결속 행은 0건이다.
- Node 회귀 테스트 486/486 통과.
- 격리 workerd+D1+R2 검사 180/180 통과. 운영 쓰기·이메일·유료 AI·외부 요청은 모두 0건이다.
- 타입검사, 전체 lint, 프로덕션 빌드 통과.
- 로컬 운영 Worker의 `/`, `/account`, `/account/setup` 모두 HTTP 200.

## 저장 상태

기능 커밋 `07c84a1a2afc2d8e1de9be1c386dd0ce589b4d34`를 GitHub `main`과 Sites 소스 저장소에 반영했다. 같은 커밋의 검증된 빌드 산출물을 Sites 버전 119 (`appgprj_6a92514801988191b79eb9bd314e3fcd~appgver_7ebe2d570d3c8191b0cfff7f5f30b24a`)로 저장했다.

현재 공개 운영본은 버전 107이다. 버전 108~118은 버전 119로 대체하며 공개 배포하지 않는다. 버전 119도 정확한 운영 배포 승인 전까지 저장 상태로 유지한다. D1 스키마, R2 연결, 공개 범위, 데이터 보관·삭제 정책은 변경하지 않았다.
