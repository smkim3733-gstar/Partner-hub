# 회수 확인 기록 보호 — 2026-08-31

## 문제와 수정

기존 원본 회수 API는 대표 확인·동일 신청·중복 요청을 검사했지만, 일반 상태 저장 API는 자료에 포함된 회수 사유·확인자와 진행 이력을 다시 검증하지 않았다. 가상 데이터의 회수 완료 기록을 일반 저장 요청으로 수정하는 회귀 테스트가 수정 전 실패했다. 운영 자료가 실제로 바뀌었는지는 조사하지 않았다.

일반 상태 저장은 권한별 병합과 상담 상태 반영 후, DB에 저장된 회수 증빙과 최종 저장할 내용을 비교한다. 회수 자료의 ID·원본 ID·기업·진행번호·담당 계정·원본 파일명·크기·확인 기록, 회수 진행 이력을 보호한다. 위조·교체·누락·중복은 충돌 응답으로 거부하며, 다른 업무 변경과 함께 일부만 저장하지 않는다. 대표 계정도 이 경로에서 증빙을 수정할 수 없다.

회수 자료의 검토 상태와 정상 업무 메모는 계속 저장할 수 있다. JSON 필드 순서 변경만으로 차단하지 않는다. 담당 파트너의 화면은 기존 권한대로 필터링하며 타인 자료를 내려받지 않는다. 회수 API의 같은 요청 재시도는 그대로 동작한다.

자료 카드에는 회수 확인 사유와 시각을 한국시간으로 표시한다. 표시된 회수 사실이 원본 내용 검토나 최종 분석 승인을 의미하지 않는다는 안내를 함께 둔다.

## 제한

회수 기록의 정정·삭제·다른 신청 이관 UI를 새로 만들지 않았다. DB 운영자의 직접 수정까지 막는 불변 감사 저장소가 아니며 별도 보관 기간 정책도 추가하지 않았다. 기존 파일 다운로드·삭제 API 권한과 원본 보관 방식은 변경하지 않는다. 원본이 이후 별도로 삭제되어도 확인 이력은 원본 존재를 보증하지 않는다.

새 DB 마이그레이션은 없다. 기존 8개 추가형 마이그레이션과 공개 범위·DB/R2·외부 서비스 설정을 보존한다. 실제 고객 자료를 검사하거나 복구·삭제하지 않는다.
