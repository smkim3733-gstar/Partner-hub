# 비밀번호 자격 이메일 예약 무결성 경계

기준일: 2026-09-05

## 해결한 문제

과거 버전에서 회원 명단과 분리된 비밀번호 자격이 남았을 때 대표 직접등록이나 기존 회원 이메일 변경이 같은 이메일을 명단에 먼저 저장할 수 있었다. 명단 저장은 성공하지만 이후 비밀번호 설정에서 `portal_password_accounts.email` 고유 제약과 충돌해 새 계정을 사용할 수 없는 불완전 상태가 될 수 있었다.

## 적용 경계

- 대표 직접등록은 대상 이메일이 다른 비밀번호 자격에 예약돼 있으면 명단을 쓰기 전에 HTTP 409로 거절한다.
- 대표의 회원 이메일 변경과 상태 저장도 새 이메일이 다른 회원·삭제된 회원의 비밀번호 자격에 예약돼 있으면 전체 저장을 거절한다.
- 일반 상태 변경처럼 이메일을 바꾸지 않는 저장은 자격 저장소 조회를 추가하지 않는다.
- 같은 회원 ID가 이미 새 이메일 자격을 가진 복구형 불일치는 허용한다. 이메일 저장과 함께 기존 자격을 폐기해 새 설정 링크로 다시 설정하도록 정합화한다.
- 대표 직접등록의 동일 요청 재시도는 먼저 기존 등록을 확인하므로, 등록 뒤 해당 회원이 정상 비밀번호 자격을 만든 경우에도 같은 계정을 안전하게 반환한다.
- 동시 자가가입은 비밀번호 자격과 명단을 함께 커밋하고, 대표 저장은 명단 CAS 재시도에서 최신 이메일 예약을 다시 확인한다.

## 의도적으로 하지 않은 일

- 분리된 기존 자격을 자동 삭제·이전·재사용하지 않는다.
- 어떤 회원이 과거 자격의 소유자인지 화면이나 응답에 노출하지 않는다.
- 운영 D1/R2, 실제 회원, 실제 고객자료를 읽거나 변경하지 않는다.
- DB 스키마, 비밀번호 해시, 쿠키, 권한, 보관·삭제 정책을 변경하지 않는다.

과거 자격 정리는 운영 데이터 변경이므로 별도 범위와 승인이 필요하다. 이번 변경은 새 불완전 상태 생성을 막고 대표에게 이메일 확인 또는 기존 자격 정리를 안내한다.

## 검증

- Node 회귀 테스트 477개 통과
- 격리 workerd/D1/R2 검사 159개 통과, 외부 요청·운영 쓰기 0건
- 분리된 자격 이메일의 대표 직접등록·이메일 변경·삭제 회원 ID 재생성 차단 확인
- 충돌 때 명단과 기존 자격이 모두 그대로 유지되는지 확인
- 동일 회원 소유 자격의 복구형 이메일 정합화와 원자적 자격 폐기 확인
- 정상 직접등록 동일 요청 재시도가 자체 비밀번호 자격에 막히지 않는지 확인
