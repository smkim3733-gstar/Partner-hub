# 파트너 안정 ID 생성 경계

기준일: 2026-09-05

## 확인한 문제

파트너 안정 ID는 계정·진행·업무·원본 권한의 기준이지만, 관리자 일반 상태 저장이 새 ID 삽입과 기존 ID 교체를 허용했다. 수정 전 실제 `/api/state` 요청에서 두 경우 모두 HTTP 200이었고 회원 명단이 변경됐다. 이 경로는 직접등록의 입력·유형·중복·요청번호 검사를 우회하거나 기존 ID에 연결된 자료를 고아 상태로 만들 수 있었다.

## 적용한 경계

- 운영 상태가 초기화된 뒤 관리자 일반 저장은 현재 회원 명단에 없는 안정 ID를 HTTP 403으로 거절한다.
- 새 계정과 새 안정 ID는 ChatGPT·비밀번호 자가가입 또는 관리자 직접등록 전용 API에서만 생성한다.
- 기존 회원의 이름·이메일·유형·상태·권한 편집과 명시적 삭제는 유지한다.
- 아직 운영 상태가 없는 최초 기준자료 선택은 기존 초기화 흐름을 유지한다.
- 삭제된 ID를 일반 상태 저장으로 되살리는 요청도 전용 등록 경로 요구 단계에서 먼저 거절해 분리된 비밀번호 자격 존재 여부를 노출하지 않는다.
- 거절된 요청은 회원 명단, `membersRevision`, 비밀번호 자격과 ChatGPT 결속을 변경하지 않는다.

## 검증

- 수정 전: 일반 상태 저장의 신규 ID 삽입과 기존 ID 교체가 각각 HTTP 200으로 재현됐다.
- 수정 후: 두 요청 모두 HTTP 403이며 D1 상태가 바뀌지 않는다.
- Node 회귀 테스트 495/495 통과.
- 격리 workerd+D1+R2 검사 189/189 통과. 운영 쓰기·이메일·유료 AI·외부 요청은 모두 0건이다.
- 타입검사, 전체 lint, 프로덕션 빌드 통과.
- 로컬 운영 Worker의 `/`, `/account`, `/account/setup` 모두 HTTP 200.

## 저장 상태

기능 커밋 `b029af366ac5220534e23410e0a6d3eaebc4fd36`을 GitHub `main`과 Sites 소스 저장소에 반영했다. 같은 커밋의 검증된 빌드 산출물을 Sites 버전 122 (`appgprj_6a92514801988191b79eb9bd314e3fcd~appgver_9f58bf6597588191b2d907dbbb5d9b59`)로 저장했다.

현재 공개 운영본은 버전 107이다. 버전 108~121은 버전 122로 대체하며 공개 배포하지 않는다. 버전 122도 정확한 운영 배포 승인 전까지 저장 상태로 유지한다. D1 스키마, R2 연결, 공개 범위, 데이터 보관·삭제 정책은 변경하지 않았다.
