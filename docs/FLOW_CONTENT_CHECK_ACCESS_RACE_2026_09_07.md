# 상담 FLOW 파일 서명 검사 중 접근변경 경쟁 무결성

기준일: 2026-09-07

## 확인한 위험

상담 FLOW는 multipart 본문 처리 뒤 접근을 다시 확인하지만, DOCX 같은 압축문서나 큰 텍스트의 실제 형식·서명 검사는 별도 비동기 파일 읽기를 수행한다. 그 검사 중 사건과 담당 계정이 삭제되면 기존 구현은 최종 재검사에서 FLOW D1 커밋을 막더라도 삭제 뒤 새 R2 객체를 기록할 수 있었다.

## 발견·수정한 문제

- 첫 전사문 객체 저장 성공과 두 번째 음성 저장 실패로 기존 전사문 객체와 두 `pending` 예약이 남은 정확한 재시도를 구성했다.
- 파일·음성 명령 지문 계산과 본문 뒤 접근 재검사를 마친 다음, 전사문 실제 내용의 세 번째 `File.arrayBuffer()` 호출 중 지원되는 관리자 상태 저장 API를 두 번 실행했다. 첫 저장은 사건 삭제·담당 계정 정지, 두 번째 저장은 배정 없는 정지 계정 삭제를 수행했다.
- 수정 전 실패 회귀는 계정·사건 삭제와 안정 ChatGPT 결속 폐기 뒤에도 두 예약 키에 R2 쓰기 2회를 수행했음을 `2 !== 0`으로 증명했다.
- 모든 첨부의 실제 형식·서명 검사가 끝난 직후 인증·안정 신원·FLOW 담당 ID·업로드 권한·사건 생명주기를 다시 확인하도록 상담 FLOW 라우트를 보강했다.
- 수정 후 같은 경쟁은 403으로 끝나며 새 R2 쓰기, 업로드 예약 확인·생성, FLOW·명령 영수증·파일 원장·완료 원장 D1 쓰기를 모두 시작하지 않는다.
- 사건·회원 삭제와 결속 폐기는 유지된다. 기존 FLOW·영수증은 변하지 않고 기존 전사문 객체와 두 `pending` 예약은 같은 파일 ID·R2 키로 복구 가능하게 보존되며 음성 객체는 새로 생성되지 않는다.
- 사건·회원 원본을 복구해도 결속은 자동 복원되지 않는다. 같은 안정 사용자 ID·명령 ID·본문·첨부의 정확한 재시도는 다시 회원 ID에 결속하고 같은 예약을 재사용해 한 번만 완료된다.
