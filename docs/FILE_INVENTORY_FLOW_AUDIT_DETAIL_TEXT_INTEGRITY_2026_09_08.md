# 파일 재고 FLOW 감사기록 detail 텍스트 무결성

기준일: 2026-09-08

## 문제

완료 FLOW 업로드 재고는 연결 감사기록 `detail`의 필수 텍스트·1~2,000자 봉투를 확인했지만 공백 전용 문자열과 짝 없는 UTF-16 서로게이트는 정상으로 인정했다. 실패 우선 회귀에서 ECMAScript 공백 집합만 있는 값은 정상 증명을 유지하고 개별 확인이 R2 `head`까지 한 번 진행했다. 잘못된 유니코드도 같은 경계를 통과했다.

## 적용

- ECMAScript `trim`과 같은 탭·개행·일반 공백·NBSP·Unicode 공백·BOM 집합을 SQLite `trim` 문자 목록으로 공유해 내용이 하나 이상 남는지 확인한다.
- JSON1이 짝 없는 서로게이트를 변환한 잘못된 UTF-8 바이트 `ED A0..BF 80..BF`를 `hex` 패턴으로 탐지해 거절한다.
- 기존 필수 텍스트·Unicode 코드포인트 기준 2,000자 상한·허용 키·영수증 결속을 그대로 유지한다.
- 손상 값은 한 `inconsistent`·증명 없음 항목으로 격리하고 `unavailable`에 포함하며 R2 `head` 전에 503으로 닫는다.
- 기존 D1/R2 데이터, 스키마, 마이그레이션은 자동 수정·삭제하지 않는다.

## D1 깊이 안전성

실패 회귀 수정 직후 단위 모의 D1은 통과했지만 실제 workerd D1 목록 조회가 `Expression tree is too large (maximum depth 100)`으로 실패했다. 전역 감사 CTE는 기능을 통과했지만 불필요한 전체 물질화를 만들었다. 최종 구현은 감사 조건과 현대 영수증 조건의 좌측 결합 `AND` 사슬을 균형 괄호 트리로 바꿔 의미와 단일 조회 스냅샷을 유지하면서 실제 D1 깊이 제한을 통과한다. 임시 진단 로그와 전역 CTE는 최종 코드에 남기지 않았다.
