# 상담 FLOW 후반 단계 가상 화면 점검

2026-09-01. 사용자의 「다음 진행」 요청에 따라 이전 기록에서 미완료로 남긴 후반 FLOW 화면을 확인했다. 기존 자동 점검 3항목은 다시 실행하지 않으며 자동 실행은 일시 중지 상태를 유지한다.

## 범위와 환경

- 현재 운영 소스의 빌드를 새 메모리 전용 D1/R2에서 실행했다. 실제 고객·운영 계정·운영 DB/R2는 읽거나 복사하지 않았다.
- 1~4차 보고서, 공동분석, 초회상담과 전사문은 가상 API 준비 자료로 구성했다. 이번 브라우저 검증 범위는 솔루션 확정부터 사후관리까지의 한 가지 대표 경로이며, 모든 분기·모든 역할 조합의 전수 검증은 아니다.
- 가상 TXT와 `SYNTHETIC UI TEST ONLY`라고 표시한 PDF를 사용했다. 화면의 계약·입금 확인 체크는 격리된 가상 흐름에서만 조작했다. 실제 서명·계약·거래 사실을 확인하거나 수행한 것이 아니다.
- 외부 요청을 차단했다. AI 자동생성은 꺼져 있고, 전사문 등록에 따라 생기는 승인 대기 작업은 실행하지 않았다. 카톡·이메일 발송, 문안 복사, 실제 발송 완료 기록과 유료 AI 호출은 수행하지 않았다.

## 화면에서 확인한 경로

| 항목 | 관찰 결과 |
| --- | --- |
| 솔루션 확정 | 대표 확정 후 추가서류 단계로 이동했다. 파트너는 확정 내용을 조회하지만 확정 입력 버튼이 없었다. |
| 필수 서류 요청 | 대표가 요청을 등록했다. 발송 전으로 남았으며 외부 발송은 없었다. |
| 수령·보완·재수령 | 파트너가 TXT를 제출하고 대표가 보완 사유를 기록했다. 파트너 새로고침 후 보완 필요와 사유가 표시됐다. 가상 보완본을 다시 제출했다. |
| 검토 권한·다음 단계 제한 | 파트너에 대표 검토 버튼이 없었다. 보완 중에는 5·6차 등록이 제한되고, 대표 검토 완료 후 등록이 열렸다. |
| 5·6차 보고서 | 대표가 각각 80자 이상의 가상 본문을 등록했다. 각 보고서는 V1로 담당 파트너에게 표시됐다. |
| 계약상담·체결 | 파트너 단독 가상 계약상담을 예약하고 가상 PDF·약정금 1,000원을 등록했다. 계약금 확인 단계로 이동했으며 바로 수행 단계가 되지 않았다. |
| 일부 입금·응답 유실 | 대표의 가상 400원 저장 응답에 15초 지연과 HTML 503을 주입했다. 처리 중 입력·저장이 잠겼고 오류 후 입력이 유지됐다. 같은 저장 버튼으로 재시도하자 400원 한 건과 잔액 600원이 표시됐다. |
| 잔액 확인·권한 | 파트너에게 입금 확인 폼이 없었다. 잔액이 있을 때 사후관리 입력이 막혔고, 대표가 가상 600원을 추가 기록한 뒤 합계 1,000원·잔액 0원으로 수행 단계가 됐다. |
| 사후관리 | 대표가 가상 수행 결과와 다음 점검일을 저장했다. 파트너는 같은 결과를 조회하고 수정 폼은 보이지 않았다. |
| 계약 근거 보호 | 계약 체결 후 대표의 기존 보고서 새 버전 등록 버튼이 사라졌다. |

격리 API의 후반 상태 대조에서 보고서 1~6차 각 1건, 검토 완료 요청 1건, 보존된 수령 첨부 2개, 입금액 `[400, 600]` 및 입금 이력 2건을 확인했다. 외부 요청은 0건이다. 초기 보조 검사에서 AI 작업 수를 0으로 예상한 것은 잘못된 가정이었다. 기존 코드는 자동생성을 꺼도 `blocked` 승인 대기 항목을 만들며 실제 실행 여부는 상태와 외부 요청으로 구분한다. 서버 동작은 변경하지 않았다.

## 재현한 화면 오류와 수정

1. FLOW 조회·새로고침에서 HTML 오류 응답이 오면 `Unexpected token` 파싱 오류가 그대로 나타났다. 최초 조회와 새로고침에 같은 한국어 재시도 안내를 적용했다. 기존 JSON 오류 응답의 업무별 안내는 유지한다.
2. 최초 조회 실패 후 「다시 불러오기」로 정상 복구해도 이전 오류 안내가 남았다. 최신 진행을 정상 수신한 뒤에는 오래된 오류를 지우도록 수정했다.

수정은 `components/consulting-workflow.tsx`의 조회 응답 처리와 화면 오류 상태에만 적용했다. 저장 요청 식별값, 입금 처리, 역할 권한, 서류 보존, DB/R2 연결과 마이그레이션은 바꾸지 않았다.

최종 빌드에서 최초 조회·새로고침에 각각 HTML 503을 주입했다. 두 경로 모두 한국어 안내가 표시됐고 정상 재시도 후 오류 알림은 0개였다. 새로고침 오류 전 입력한 미저장 메모도 실패·복구 양쪽에서 유지됐다.

## 검증과 반영 경계

- Node 자동 검사 183개, 타입검사·lint·빌드 결과는 `outputs/validation/flow-late-node-tests.log`, `flow-late-build.log`와 실행 결과에 남긴다. 서버 변경이 없어 기존 110개 workerd 저장소 검증은 반복하지 않았다.
- 첫 화면 시험의 요청 기록은 `outputs/validation/flow-late-first-pass.json`, 수정본 재검증은 `flow-late-pilot-runtime.json` 및 `flow-late-browser-results.json`에 구분한다.
- 확정된 운영 반영 상태는 `outputs/release/flow-late-deployment.json`을 기준으로 한다. 기존 공개 사이트만 사용하고 가상 자료·보조 스크립트는 배포하지 않는다.
- 실제 파트너 실사용, 실제 대표 SSO, Tab·Enter 기본 조작과 전체 접근성 검증은 여전히 미완료다. 실제 발송·계약·입금·AI 연결의 운영 검증을 이번 결과로 대신하지 않는다.
