# 상담 FLOW 서류 수령 효과 무결성

기준일: 2026-09-06

## 문제

`receive_document` 명령은 선택한 서류 요청에 수령 파일과 검토 대기 상태를 기록하지만, 기존 명령 영수증에는 선택한 요청 ID가 남지 않았다. 상태 검사도 요청 한 건이 수령 상태가 되었는지만 확인해, 명령이 선택하지 않은 다른 요청으로 수령 증거를 옮겨도 독립적으로 식별할 수 없었다. 실패 우선 검사에서 첫 번째 요청을 선택한 명령에 두 번째 요청의 수령 증거를 결합한 상태가 애플리케이션 경계를 통과했다.

## 적용한 경계

- 명령 영수증 `targetId`에 사용자가 선택한 요청 ID를 보존한다.
- 과거 요청과 현재 요청에서 해당 ID가 각각 정확히 한 건이어야 한다.
- 수령 파일은 `requested_document` 용도여야 하며 선택 요청의 `fileId`와 정확히 일치해야 한다.
- 새 파일 업로드는 기존 파일 이력을 그대로 보존하고, 서버 수정시각으로 생성된 요청서류 한 건만 배열 마지막에 추가한다.
- 이미 연결된 같은 요청서류를 다시 선택하는 안전한 재시도는 기존 파일과 최초 `receivedAt`을 보존한다.
- 새 파일 또는 다른 파일로 수령 증거가 바뀌면 `receivedAt`을 서버 수정시각으로 기록하고 과거 `reviewedAt`·`verifiedAt`은 제거해 다시 검토 대기로 전환한다.
- 다른 요청·파일의 변경, 파일 추가·삭제·재정렬, 신청자료 유입 메타데이터 주입, 대상 ID 누락을 거절한다.
- 행위자는 대표 또는 해당 FLOW 담당 파트너만 허용하며, 계약 체결 뒤 수령 변경은 거절한다.
- 메모는 JavaScript `trim()`과 같은 유니코드 공백 정규형이어야 한다.
- 감사기록은 명령 ID·서버시각·`receive_document` 동작과 `요청 서류 수령 · 대표 검토 대기` 문구에 결속한다.

애플리케이션 커밋 검사와 D1 트리거가 같은 계약을 독립적으로 강제한다. `0087_consulting_flow_receive_document_effect.sql`은 기존 명령 영수증 대상 트리거를 추가형으로 교체해 `receive_document`의 `targetId`를 필수화하고 전용 효과 트리거를 추가한다. 기존 저장 영수증은 변경하지 않고 이후 revision에 새로 추가되는 명령만 검사한다.
