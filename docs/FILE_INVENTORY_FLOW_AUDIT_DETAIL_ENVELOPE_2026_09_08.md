# 파일 재고 FLOW 감사기록 detail 봉투

기준일: 2026-09-08

## 문제

완료 FLOW 업로드 파일의 재고 증명은 연결된 감사기록의 ID·시각·행위자·동작과 허용 필드를 확인했지만 `detail` 자체의 타입과 길이는 검사하지 않았다. 실제 D1 payload에서 `detail`을 제거하거나 빈 문자열·객체로 바꿔도 정상 `linked` 증명이 유지되고 현재 R2 확인이 `head`까지 한 번 진행되는 실패 회귀를 고정했다.

## 적용

- 연결 감사기록의 `detail`을 필수 JSON 텍스트로 제한한다.
- SQLite `length`가 1자 이상이고 공유 `FLOW_TEXT_LIMITS.auditDetail` 상한인 2,000자 이하일 때만 정상 증명을 인정한다.
- 누락·빈 문자열·비텍스트·상한 초과는 한 `inconsistent`·증명 없음 항목으로 격리하고 전체 적용 현황에서 `unavailable`로 센다.
- 손상 값은 응답에 노출하지 않으며 개별 현재 R2 확인은 `head` 전에 503으로 닫는다.
- 기존 D1/R2 데이터, 스키마, 마이그레이션은 자동 수정·삭제하지 않는다.

- 로컬 Worker 공개 화면 3곳 HTTP 200, 비인증 보호 API 3곳 HTTP 401, CSP·`nosniff`·`no-referrer` 확인
