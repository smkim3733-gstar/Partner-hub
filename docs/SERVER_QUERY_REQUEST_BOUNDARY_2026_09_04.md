# 서버 URL 쿼리 요청 경계 통합

## 목적

서버 조회 API가 URL 쿼리의 첫 번째 값만 임의로 사용하거나 값의 존재만으로 동작을 바꾸지 않도록 공용 단일값 경계를 적용했다. 중복·과대·모호한 값은 저장소 조회 또는 파일 응답 동작을 선택하기 전에 HTTP 400으로 차단한다.

## 적용 범위

- 대표 원본 보관 목록: `status` 최대 20자, `cursor` 최대 600자
- Step 0 최신 결과 조회: `caseId` 최대 120자
- 신청자료 미리보기: `fileId` 최대 120자
- 상담 FLOW 보고서 내려받기: `download=1`만 명시적으로 허용

같은 키가 두 번 이상 전달되면 첫 값이나 마지막 값을 임의로 선택하지 않는다. `download=false`, 빈 값, 중복 플래그는 내려받기로 해석하지 않는다. 허용하지 않는 값은 각 API의 기존 비공개 오류 응답 형식으로 반환한다.

## 유지한 경계

인증과 역할 확인은 기존 순서를 유지해 익명 요청에 내부 입력 규칙을 먼저 노출하지 않는다. 원본 목록 커서의 필터 결속, 파일 ID 형식·소유권, FLOW 보고서 접근권한, Step 0 관리자 권한과 D1/R2 조회 범위는 변경하지 않았다. DB/R2 스키마와 보관·삭제 정책에도 변경이 없다.
