# 파트너 안정 ID 무결성

기준일: 2026-09-05

## 확인한 문제

파트너의 안정 ID는 로그인, ChatGPT 결속, 담당 진행과 원본 접근의 권한 기준이다. 관리 화면은 중복 이메일은 막았지만, 중복되거나 비어 있는 회원 ID는 별도로 검증하지 않았다. 과거 이관·손상 상태에 같은 ID가 둘 이상이면 서로 다른 이메일 계정이 같은 권한 주체로 해석될 수 있었다.

수정 전 실제 라우트 재현에서는 중복 ID 명단 저장, 미결속·기결속 ChatGPT 접근, 비밀번호 로그인, ChatGPT 자가등록이 각각 HTTP 200을 반환했다. 빈 ID 레거시 회원의 ChatGPT 결속 가능성도 코드 경계에서 확인했다.

## 적용한 경계

- 대표의 회원 명단 저장은 비어 있거나 공백 정규화가 필요하거나 중복된 안정 ID를 HTTP 403으로 거절한다.
- 비밀번호 로그인·기존 세션·설정 링크 발급·설정 완료는 대상 ID가 현재 명단에 정확히 1개일 때만 진행한다.
- 미결속·기결속 ChatGPT 접근은 후보 안정 ID가 없거나 현재 명단에서 고유하지 않으면 HTTP 403으로 실패한다.
- ChatGPT 자가등록은 일치 회원의 안정 ID가 없거나 중복이면 회원·자격·결속 처리 전에 HTTP 409로 실패한다.
- ChatGPT 결속 D1 쓰기도 현재 회원 ID 고유성을 SQL 조건으로 다시 확인한다.
- 거절 경로는 회원 명단, 세션, 설정 링크와 `portal_chatgpt_identity_bindings`를 변경하지 않는다.

## 검증

- 수정 전: 중복 ID 관련 관리자 저장·ChatGPT 접근·비밀번호 로그인·자가등록 5개 경로가 HTTP 200으로 재현됐다.
- 수정 후: 같은 경로와 빈 ID 레거시 접근이 HTTP 403 또는 409로 실패하고 결속을 만들지 않는다.
- Node 회귀 테스트 493/493 통과.
- 격리 workerd+D1+R2 검사 187/187 통과. 운영 쓰기·이메일·유료 AI·외부 요청은 모두 0건이다.
- 타입검사, 전체 lint, 프로덕션 빌드 통과.
- 로컬 운영 Worker의 `/`, `/account`, `/account/setup` 모두 HTTP 200.
- DOCX 업로드 회귀 테스트의 ZIP 수정시각을 고정해 분 경계에서 발생하던 비결정적 바이트 비교 실패도 제거했다.

## 저장 상태

기능 커밋 `d03e54539027f5cb040b55086d674db24eb05214`를 GitHub `main`과 Sites 소스 저장소에 반영했다. 같은 커밋의 검증된 빌드 산출물을 Sites 버전 121 (`appgprj_6a92514801988191b79eb9bd314e3fcd~appgver_3c641c41a0288191ac35982394793a07`)로 저장했다.

현재 공개 운영본은 버전 107이다. 버전 108~120은 버전 121로 대체하며 공개 배포하지 않는다. 버전 121도 정확한 운영 배포 승인 전까지 저장 상태로 유지한다. D1 스키마, R2 연결, 공개 범위, 데이터 보관·삭제 정책은 변경하지 않았다.
