# 대표 직접등록 응답 검증 안전성

2026-09-04 기준으로 관리자 파트너 직접등록 뒤 화면 명단에 적용하는 API 응답 검증을 보강했다.

## 변경 범위

- 성공 응답을 `unknown`으로 읽고 등록 계정, 전체 명단, 명단 버전, 재시도 여부를 검증한다.
- 등록 계정의 이름·연락처·소속·이메일·파트너 유형을 현재 제출값과 대조한다.
- 등록 계정이 활성 일반 파트너, 기업 수 0, 기존 최소 권한, 관리자 등록 출처와 동일 요청번호를 갖는지 확인한다.
- 전체 명단의 계정 구조와 권한을 검증하고 중복 계정 ID·중복 이메일·등록 계정 누락 또는 불일치를 차단한다.
- 신규 등록은 HTTP 201, 안전 재시도는 HTTP 200과 일치할 때만 완료로 표시한다.
- 검증된 공개 필드만 반환한다. 알 수 없는 필드는 화면 상태나 다음 자동저장으로 전달하지 않는다.
- 실패 응답은 허용된 입력 필드 오류와 형식이 유효한 충돌 복구 영수증만 유지한다.
- 비-JSON 또는 손상된 성공 응답에서는 입력과 고정 요청번호를 유지하고 명단 확인 후 같은 요청으로 재시도하도록 안내한다.

## 유지한 안전 경계

- 서버의 관리자 인증, 동일 출처, 입력 검증, 최소 권한, 이메일 중복 차단, 멱등 요청번호와 CAS 처리는 변경하지 않았다.
- 응답이 손상돼도 자동으로 다른 요청번호를 만들거나 완료로 표시하지 않는다.
- 등록 성공이 서버에 반영됐는지 불확실할 때 같은 요청번호 재시도가 기존 계정을 재사용하는 방식을 유지한다.
- 운영 데이터, 실제 계정, D1/R2 스키마, 충돌 지표와 보관·삭제 정책은 변경하지 않았다.

## 검증

- 자동 테스트 377개
- 격리 workerd/D1/R2 검사 129개
- TypeScript 타입검사, 전체 lint, 프로덕션 빌드
- localhost `/` HTTP 200

모든 신규 응답 검사는 가상 계정과 합성 응답으로 실행했다. 실제 계정 등록·운영 쓰기·메일·유료 AI·외부 요청은 0건이다. GitHub 푸시와 공개 Sites 배포는 사용자 승인 전까지 수행하지 않는다.
