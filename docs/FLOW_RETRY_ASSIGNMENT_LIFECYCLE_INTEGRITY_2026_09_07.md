# 상담 FLOW 재시도 담당·진행상태 무결성

기준일: 2026-09-07

## 확인한 위험

파트너의 전사문·음성 2슬롯 업로드가 첫 R2 객체만 저장한 채 실패한 뒤 포털 사건 담당 계정이 상담 FLOW의 저장 담당자와 달라지거나 대표가 진행을 중단하면, 이전 파트너의 재시도가 남은 객체를 저장하고 FLOW를 완료할 위험이 있다.

## 발견과 보완

- 기존 진행은 저장된 불변 파트너 ID를 접근제어 기준으로 사용했지만, 포털 사건에 명시된 `partnerMemberId`가 다른 계정으로 바뀐 비정상 상태는 비교하지 않았다.
- 이 상태에서는 이전 파트너가 저장된 FLOW 담당자와 일치하므로 접근 검사를 통과할 수 있었다.
- 기존 파트너 접근 검사를 먼저 수행한 뒤 포털의 명시적 담당 계정과 FLOW 담당 계정이 다르면 HTTP 409로 실패하도록 보완했다. 권한 없는 다른 계정에는 기존 403 경계를 유지한다.
- `partnerMemberId`가 없는 레거시 사건은 이미 결속된 불변 FLOW 파트너 ID를 계속 사용하므로 과거 자료 호환성을 유지한다.
- 진행 중단 상태는 기존 구현이 명령 본문·예약·R2 처리 전에 HTTP 409로 차단하고 있었다.

## 확인한 복구 경계

- 정상 파트너의 첫 전사문 객체 저장 성공과 두 번째 음성 저장 실패를 결정적으로 재현했다.
- 실패 뒤 포털 사건 담당 ID를 다른 계정으로 바꾼 상태와 `pipelineLifecycleStatus`를 `discontinued`로 바꾼 상태를 각각 재현했다.
- 두 재시도 모두 R2 `put`을 한 번도 호출하지 않고 HTTP 409로 거절한다.
- 거절 뒤 FLOW 본문, 기존 전사문 객체 바이트와 두 `pending` 예약의 파일 ID·R2 키·상태가 그대로 유지된다.
- 담당·진행 상태를 원상복구한 뒤 원래 명령 ID·본문·첨부를 보내면 같은 두 파일 ID·R2 키로 완료되고 예약과 완료 원장이 원래 파트너 명령에 결속된다.
