# AI 진단 실행 메타데이터 무결성 경계

기준일: 2026-09-05

## 문제

AI 진단 실행 원장의 시각은 24자 UTC 모양과 SQLite 날짜 해석만 검사해 `2026-02-30`처럼 존재하지 않는 달력 날짜도 저장할 수 있었다. 완료행을 다시 읽을 때 서버는 신원·토큰 수·정확한 시각을 재검증하지 않았고, 같은 요청 ID의 모델이나 지침 버전이 달라도 기존 결과를 재사용할 수 있었다.

## 적용

- 공용 UTC 밀리초 검증기는 문자열을 다시 ISO 직렬화한 값과 원문이 정확히 같을 때만 허용한다.
- `0038_ai_diagnosis_timestamp_envelope.sql`과 런타임 D1 트리거가 신규 실행 삽입과 완료 시각 변경에 실제 달력상 존재하는 정확한 UTC 밀리초 시각을 강제한다.
- 실행 잠금과 완료 저장은 D1 접근 전에 요청 지문, 신원, 안전한 토큰 정수와 정확한 시각을 검사한다.
- 저장 완료 결과를 읽을 때도 단계·상태·신원·요청 지문·토큰·시각·결과 구조를 모두 재검증하고 손상행을 화면에서 격리한다.
- 같은 요청 ID라도 지침 버전이나 모델이 달라지면 기존 결과를 재사용하지 않고 충돌로 처리한다.
- 기존 실행 행의 내용을 자동 변경하지 않는다.

## 검증

- 존재하지 않는 달력 날짜는 애플리케이션 잠금·완료 저장과 D1 직접 삽입·완료 전이에서 거절된다.
- 음수·소수·JavaScript 안전 정수 범위 밖 토큰 수는 완료 저장과 조회 경계에서 거절된다.
- 모델이 달라진 동일 요청 ID는 기존 결과를 반환하지 않는다.
- 39개 추가형 마이그레이션을 기존 상태가 있는 격리 D1에 반복 적용해도 기존 상태를 교체하지 않는다.
- Node 회귀 검사 642/642 통과
- 격리 workerd/D1/R2 검사 450/450 통과
- 타입검사, 전체 lint, 변경 파일 포맷, 프로덕션 빌드 통과
- 로컬 운영 Worker `/`, `/account`, `/account/setup` HTTP 200과 CSP, `X-Frame-Options: DENY`, `nosniff`, `no-referrer` 확인
- 실제 운영 쓰기, 이메일 발송, 유료 AI 요청, 외부 요청 0건
