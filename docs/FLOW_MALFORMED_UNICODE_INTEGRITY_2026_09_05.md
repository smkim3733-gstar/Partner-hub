# 상담 FLOW 잘못 구성된 Unicode 무결성 경계

기준일: 2026-09-05

## 확인한 문제

JavaScript 문자열은 짝이 없는 UTF-16 high·low surrogate를 가질 수 있다. `JSON.stringify()`는 이 값을 `\ud800` 또는 `\udc00` 형태로 저장하지만 SQLite JSON1은 추출할 때 이를 잘못된 UTF-8 바이트로 만들고 D1 응답 계층에서 대체문자로 바꿀 수 있다. 같은 저장값이 JavaScript 상세 조회와 SQLite 축소 대시보드에서 서로 다른 문자로 해석될 수 있었다.

## 적용한 경계

- high surrogate는 바로 뒤의 low surrogate와 정확히 한 쌍이어야 하고, 독립된 low surrogate도 거절하는 공용 검증을 추가했다.
- FLOW 전체 JSON의 모든 문자열 값과 객체 키를 순회한다. 현재 알려진 필드뿐 아니라 추가 필드에 들어온 잘못 구성된 Unicode도 저장 구조 검증에서 거절한다.
- 수동 명령 입력, 진행솔루션, AI 입력·응답·작업 결과, 1차 보고서 사전점검도 같은 검증을 사용한다.
- SQLite 축소 전 의미 검증은 JSON1이 드러내는 surrogate 범위의 잘못된 UTF-8 바이트를 찾아 손상 행을 HTTP 503으로 격리한다. 정상 행은 원문에 surrogate escape 후보가 있을 때만 전체 JSON 트리를 검사한다.
- 정상 한국어·이모지와 v152의 Unicode 코드 포인트 길이 계약은 유지한다.
- D1 스키마, R2 파일, 인증·권한, 보관·삭제 정책은 변경하지 않았다.

## 검증

- 정상 한국어·이모지는 허용하고 짝이 없는 high·low surrogate는 거절한다.
- 잘못된 문자가 들어간 수동 보고서 명령과 AI 성공·실패 결과를 유효한 상태로 반환하지 않는다.
- 숨김 감사 상세의 잘못된 surrogate와 추가 JSON 객체 키의 잘못된 surrogate를 상세 조회와 축소 대시보드가 모두 HTTP 503으로 격리한다.
- 실제 workerd+D1에서도 JSON1 문자 변형 전에 상세 조회와 대시보드가 동일하게 차단한다.
- Node 자동 테스트 588/588 통과.
- 격리 workerd+D1+R2 검사 378/378 통과.
- 타입검사, 전체 lint, 변경 파일 포맷 검사, 프로덕션 빌드 통과.
- 로컬 프로덕션 `/`, `/account`, `/account/setup` HTTP 200과 CSP·`DENY`·`nosniff`·`no-referrer` 확인.
- 실제 운영 쓰기, 메일 발송, 유료 AI 요청, 외부 요청 0건.

- Sites 저장 산출물: 157개 파일, 4,464,640바이트, `sha256:51794a94e493525e5bde16e5c13c581a3458017dc5ecea976a53b0533e1c0189`
- GitHub `main`과 Sites 소스: 동일 기능 커밋 반영

버전 108~152는 버전 153으로 대체하며 공개 배포하지 않는다. 버전 153 공개 배포는 플랫폼이 요구하는 정확한 `버전 153 운영 배포 승인` 뒤 진행한다.

## 다음 감사

FLOW 구조 검증이 정의되지 않은 추가 속성을 허용하고 상세 응답의 객체 펼치기가 이를 그대로 반환하는지 확인한다. 저장 객체·중첩 항목별 허용 키 계약과 공개 응답의 명시적 투영을 마련해, 추가된 비공개 필드가 상세 또는 대시보드 응답으로 노출되지 않게 한다.
