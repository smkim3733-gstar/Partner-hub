# 신청 항목 저장과 접수 내용 확인 — 2026-08-31

## 변경

신청 폼에 보이지만 저장되지 않던 기업과의 관계, 공동 협업자 메모, 대표 전달사항, 사업자등록번호, 대표자명, 법인·개인 구분, 업종·주요사업, 소재지, 기업 담당자, 연락처, 희망 진행시기, 긴급도, 요청 배경을 신청별 `applicationDetails`에 저장한다. 입력값을 React 상태로 관리하므로 앞뒤 단계로 이동해도 유지된다. 기업명은 가상 기본값 대신 빈칸에서 시작한다. 서비스와 기존 계정 ID·첨부 연결은 유지한다.

단계별 필수값과 길이를 검사한다. 사업자등록번호는 10자리 또는 3-2-5 하이픈 형식을 받아 숫자 10자리로 저장한다. 날짜·선택값·항목 형식도 서버에서 재검증하며 잘못된 새 입력은 전체 저장 전에 거부한다. 기업명은 첨부 저장 경로와 동일한 100자 이내로 제한한다. 주민등록번호 등 불필요한 개인정보를 추가 수집하지 않는다.

진행 상세와 상담 FLOW에 접을 수 있는 `접수한 신청 내용`을 제공한다. 담당 계정과 대표에게 허용된 진행에서만 표시하며 입력한 문구는 HTML이 아닌 텍스트로 표시한다. 긴급도는 신규 접수 카드의 기존 긴급 표시에도 반영한다. 공동 협업자 항목은 참고용 메모이며 계정 검색·초대·접근 권한 부여 기능이 아니다.

작동하지 않던 사업자번호 중복확인 버튼과 서비스별 과업 자동생성 안내를 제거했다. 실등록·중복 조회, 자동 과업 생성, 외부 전송을 수행하지 않는다.

## 기존 기록과 검증

기존 진행에 상세를 추정하여 채우거나 DB 테이블을 변경하지 않는다. 상세 항목을 모르는 이전 화면이 기존 진행을 저장해도 이미 저장된 상세 필드는 유지한다. 별도 신청 재시도 흐름과 파일 ID 연결은 그대로 사용한다.

자동 테스트 116개와 격리 workerd/D1/R2 점검 57개를 통과했다. 필드별 형식·필수값·길이·날짜 검증, 단계별 입력 컴포넌트 재렌더링, 텍스트 이스케이프, 제출 후 재조회·재시도·상담 FLOW 반영, 기존 화면 저장 시 보존, 다른 계정의 열람·변조 차단을 확인했다. 브라우저 클릭 시험·실제 고객 자료 조회·실제 계정 생성·메일 전송·유료 AI 호출은 수행하지 않았다.

이번 변경은 **제출한 신청의 상세 저장**이다. 제출 전 입력의 서버 임시저장이나 새로고침 후 복원은 아직 지원하지 않는다. 서버 임시저장·재접속 복구와 여러 창의 변경 충돌은 후속 작업이다. 과거 저장되지 않았던 입력은 자동 복구할 수 없다.

선행 운영 소스는 `35a5e63`, 버전 38이다. 이번 결과는 운영 배포 이력과 로컬 `outputs/release/` 완료 기록에 남긴다.
