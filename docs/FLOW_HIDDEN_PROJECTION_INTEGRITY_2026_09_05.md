# 상담 FLOW 숨김 투영 필드 무결성 경계

기준일: 2026-09-05

## 확인한 문제

대시보드 조회는 모든 기업의 보고서 본문·파일 목록·녹취·AI 작업·감사기록·명령 영수증을 메모리에 올리지 않도록 SQLite 안에서 축소 투영한다. 그러나 투영 전에 숨겨지는 필드는 이후 JavaScript 구조 검증에서 보이지 않으므로, 과도하게 긴 문자열이나 잘못된 형식과 숨겨진 중복 ID가 대시보드 무결성 검사를 우회할 수 있었다.

상세 FLOW 조회는 전체 저장 구조를 검사해 해당 손상을 거절했지만, 같은 저장 행의 대시보드 조회가 축소된 정상 객체처럼 보일 수 있어 조회 경계가 일치하지 않았다.

## 적용한 경계

- FLOW 식별자·표시값·타임스탬프·파일 메타데이터·결정·사후관리·명령 영수증 길이 상한을 공용 상수로 통합했다.
- SQLite 축소 투영 전에 AI 원문과 보고서 본문·제목·작성자·출처·파일 연결을 검증한다.
- 제거되는 파일의 ID·이름·MIME·크기·저장 키·용도·검토 메타데이터를 검증한다.
- 제거되는 녹취의 회의·파일 연결, 본문 상한, 동의·생성·검토 시각 필드를 검증한다.
- 제거되는 AI 작업의 단계·사유·보고서와 녹취 연결·처리 시각 필드를 검증한다.
- 제거되는 감사기록과 명령 ID·명령 영수증의 키·행위자·지문 필드를 검증한다.
- 파일·AI 작업·감사기록·명령 ID의 숨겨진 중복을 투영 전에 거절한다.
- 손상 행은 부분적으로 표시하지 않고 기존과 같은 HTTP 503 복구 경계로 실패 폐쇄한다.

## 검증

- 보고서 본문, AI 원문, 감사 상세, AI 작업 사유, 파일 저장 키, 녹취 본문, 명령 ID와 영수증 행위자 키의 상한 초과를 각각 재현해 대시보드가 HTTP 503으로 거절함을 확인했다.
- 숨겨진 AI 작업 단계와 파일·감사·명령의 중복 ID 손상을 각각 재현해 같은 경계로 거절함을 확인했다.
- 격리 Workers+D1에서 실제 D1 행의 과도한 감사 상세를 대시보드가 HTTP 503과 비공개 오류 응답으로 차단함을 확인했다.
- Node 자동 테스트 584/584 통과.
- 격리 workerd+D1+R2 검사 371/371 통과.
- 타입검사, 전체 lint, 포맷 검사, 프로덕션 빌드 통과.
- 로컬 프로덕션 `/`, `/account`, `/account/setup` HTTP 200과 CSP·`DENY`·`nosniff`·`no-referrer` 확인.
- 실제 운영 쓰기, 메일 발송, 유료 AI 요청, 외부 요청 0건.

## 다음 감사

SQLite 축소 투영에서 제거되는 숨김 문자열의 공백 전용 값과 타임스탬프의 실제 날짜 형식을 투영 전에 검증한다. 현재 길이·타입 검사를 통과하더라도 전체 저장 검증에서는 거절되는 의미상 잘못된 숨김 값을 대시보드가 정상 행으로 보지 않게 한다.
