# 파트너 파일럿 준비 고도화

2026-09-01. Duet 기획 검수에서 확인한 데이터 기준선, 저장 용량·동시편집, 파트너 자격증명 전달 문제 중 코드로 안전하게 개선할 수 있는 범위를 구현했다. 실제 고객 자료 조회·계정 생성·연락·메일 발송·외부 AI 호출·데이터 삭제·보관 정책 변경은 수행하지 않았다.

## 구현 결과

### 운영 데이터 기준선

- 저장된 `portal_state`가 없는 새 환경에서는 가상 예시가 자동 저장되지 않는다.
- 대표 관리자가 `빈 운영 데이터로 시작` 또는 `가상 예시 데이터로 시작`을 직접 선택해야 저장이 시작된다.
- 기존 Sites의 저장 상태가 있으면 선택 화면을 표시하지 않고 기존 상태를 그대로 불러온다.
- 빈 상태에서 진행이 없으면 상담·서류요청 화면이 고정 가상 진행을 대신 사용하지 않는다.

### 가상 예시와 실사용 지표 분리

- 코드에 포함된 고정 시드 ID만 가상 예시로 분류한다. 회사명이나 파트너가 제출한 임의 값은 분류 근거로 사용하지 않는다.
- 파트너가 새 운영 레코드에 예약된 시드 ID를 사용하려 하면 서버에서 거부한다.
- 대표 대시보드의 접수·자료보완·상담·계약·긴급·장기 미진행 지표는 가상 예시를 제외한 파생 계산을 사용한다.
- 원본 상태 배열과 자동저장 페이로드는 필터링하지 않으므로 기존 가상 예시나 운영 레코드를 삭제하지 않는다.
- 대표 화면에는 지표에서 제외된 가상 진행·자료·업무·일정·파트너 건수를 함께 표시한다.

### 저장 용량 가시화

- 저장된 D1 원문 바이트와 다음 저장 요청의 JSON 래퍼 바이트를 별도로 계산한다.
- 두 값 중 큰 값을 기준으로 사용률과 남은 여유를 계산해 대표에게만 표시한다.
- 텔레메트리는 API 응답의 최상위 필드이며 `PortalState`에 병합하거나 다시 저장하지 않는다.
- 파트너 응답에는 저장 용량 텔레메트리를 포함하지 않는다.
- 70% 경보는 측정 전 잠정 기준으로 표시한다. 자동 분할·아카이브·삭제는 수행하지 않는다.

### 가입·저장 충돌 경계

- 기존 본인확인 체크, 30분 유효 일회용 링크, 이전 미사용 링크 무효화, 수동 전달 안내를 유지했다.
- 이메일 소유권 인증이나 MFA가 완료됐다고 표시하지 않는다.
- 전체 상태 비교·교체와 HTTP 409 충돌 방식은 유지한다. 저장 실패 스냅샷도 현재 화면 메모리에 보존하며 명시적 재시도 경로를 그대로 사용한다.

## 검증

- 타입검사 통과
- lint 통과
- Node 회귀검사 209개 통과
- 격리 workerd/D1/R2 검사 110개 통과
- Vinext 배포 빌드 통과
- `git diff --check` 통과

격리 검사는 실제 운영 DB·R2·회원·메일·외부 AI를 사용하지 않았고 외부 요청도 발생시키지 않았다. 별도 브라우저 클릭·화면 검증은 수행하지 않았다.

## 남은 운영 결정

- 기존 운영 상태에 포함된 가상 예시를 계속 유지할지, 별도 승인 후 정리할지 결정해야 한다.
- 잠정 70% 경보는 실제 파일럿의 상태 증가량과 충돌 기록을 측정한 뒤 확정해야 한다.
- 단일 상태를 도메인별·레코드별 저장으로 분리하는 작업은 측정 결과를 근거로 별도 설계한다.
- 공개 자가가입 유지 여부, 이메일 소유권 인증, MFA, 링크 전달 담당·대응시간은 파일럿 운영 절차로 확정해야 한다.
- 네이티브 Windows에서는 Duet의 고위험 결정론적 샌드박스 검사를 수행할 수 없다. 실제 배포는 검증 결과와 이 제한을 확인한 뒤 별도 단계로 진행한다.
