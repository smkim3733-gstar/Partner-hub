# 서버 URL 경로 식별값 경계 통합

## 목적

동적 API 경로의 진행·기업자료·원본·첨부·보고서 식별값을 저장소 조회 전에 공용 경계로 검증한다. 경로마다 달랐던 형식 검사를 하나로 합치고, 잘못된 문자나 과대한 값을 D1/R2 조회 키로 전달하지 않는다.

## 적용 범위

- 상담 FLOW의 `caseId`
- 상담 FLOW 첨부파일의 `fileId`
- 상담 FLOW 보고서의 `reportId`
- 기업자료 내려받기·삭제의 `id`
- 대표 원본 보관 현황·회수의 `id`

식별값은 영문 대소문자·숫자·하이픈·밑줄만 허용하고 최대 120자로 제한한다. 빈 값, 점·슬래시 등 경로 유사 문자, 한글을 포함한 임의 표시문자와 과대한 값은 HTTP 400으로 거절한다.

## 유지한 경계

각 경로의 로그인·대표/파트너 역할·담당 계정·진행 연결 확인을 유지한다. 첨부와 보고서 식별값은 진행 접근권한을 확인한 뒤 검증하며, 기업자료와 원본도 기존 인증·관리자 확인 순서를 바꾸지 않는다. D1/R2 스키마, 파일 본문, 보관·삭제 정책에는 변경이 없다.

## 재발 방지

공용 경계 단위검사와 동적 경로 소비처 정적 검사를 추가했다. 기업자료·상담 FLOW 통합검사에는 잘못된 문자와 120자 초과 경로가 HTTP 400으로 끝나는 회귀 사례를 포함했다.
