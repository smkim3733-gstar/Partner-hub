# 기업자료 상태 변경 확인 안전성

## 문제

기업자료 카드의 상태 선택은 즉시 `companyDocuments`를 바꾸고 상위 자동저장으로 이어졌다. 잘못 선택해도 저장 전 취소할 기회가 없었고, 특히 `검토완료`는 대시보드 집계와 진단·후속 업무의 사용 가능 자료 판단에 영향을 줄 수 있었다.

## 변경

- 상태 목록과 상태별 영향을 공용 모듈에 정의했다.
- 상태 선택은 원본 자료를 바꾸지 않고 현재 상태·변경 후 상태·원본 연결을 담은 확인 초안만 만든다.
- 확인창에서 기업·자료명·현재 상태·변경 후 상태와 운영 영향을 대조한 뒤 `상태 변경 저장`을 눌러야 반영한다.
- 취소하거나 확인창을 닫으면 초안을 폐기하고 기존 상태를 유지한다.
- 저장 직전 자료 ID, 현재 상태와 `storageFileId`가 초안 작성 시점과 같은지 다시 검사한다.
- 임의 상태값과 실제 보안 저장 파일이 없는 `제출완료`·`검토완료` 변경을 공용 검증에서 거절한다.
- `보완필요` 선택은 사이트 상태만 변경하며 실제 보완 요청을 자동 발송하지 않는다고 표시한다.

## 유지한 운영 경계

- 관리자와 담당 파트너의 기존 자료 상태 변경 권한은 바꾸지 않았다.
- 기존 자료, 회수 증빙, 진단 판정 규칙, 서버 인증, revision/CAS, DB/R2 스키마와 보관 정책은 변경하지 않았다.
- 메일·메신저·고객 통지, 외부 AI 호출과 파일 전송을 추가하지 않았다.
- GitHub 푸시와 공개 Sites 배포는 사용자 승인 전까지 수행하지 않는다.
