# 비밀번호 자격 생명주기 무결성 경계

기준일: 2026-09-05

## 해결한 문제

대표가 사이트 비밀번호 계정의 로그인 이메일을 변경하거나 회원을 삭제해도 `portal_password_accounts`의 기존 비밀번호 해시가 남을 수 있었다. 남은 자격은 이전 이메일의 재등록을 막고, 회원 명단과 인증 저장소의 생명주기를 다르게 만들었다.

## 적용 경계

- 대표가 회원 이메일을 변경하면 기존 비밀번호 자격·세션·설정 링크를 모두 폐기한다. 새 이메일에는 새 비밀번호 설정 링크를 발급해야 한다.
- 대표가 회원을 삭제하면 해당 회원의 비밀번호 자격·세션·설정 링크를 모두 폐기한다. 삭제된 이메일은 새 가입에 다시 사용할 수 있다.
- 정지와 재활성화는 세션·설정 링크만 폐기하고 비밀번호 자격은 유지한다. 재활성화 뒤 기존 비밀번호를 다시 사용할 수 있다.
- 회원 상태 저장과 인증수단 폐기는 하나의 D1 배치 트랜잭션으로 실행한다. 각 삭제문은 방금 커밋하려는 포털 상태 payload가 현재 값일 때만 작동한다.
- 자격 삭제가 실패하면 회원 이메일·삭제·명단 revision과 세션·설정 링크 삭제도 함께 롤백한다.
- 화면은 이메일 변경과 회원 삭제가 비밀번호 자격을 폐기한다는 영향을 저장 전에 안내한다.

## 의도적으로 하지 않은 일

- 기존 운영 데이터에서 과거 버전이 남긴 고아 자격을 일괄 탐색하거나 삭제하지 않는다.
- 운영 D1/R2, 실제 회원, 실제 고객자료를 읽거나 변경하지 않는다.
- 비밀번호 해시 형식, 쿠키 정책, 권한, DB 스키마, 보관 정책을 변경하지 않는다.

과거 고아 자격의 일괄 정리는 실제 운영 데이터 변경이므로 별도 범위와 승인이 필요하다.

- Node 회귀 테스트 474개 통과
- 격리 workerd/D1/R2 검사 155개 통과, 외부 요청·운영 쓰기 0건
- 이메일 변경·회원 삭제의 자격 폐기와 삭제 이메일 재가입 확인
- 정지·재활성화의 비밀번호 자격 보존 확인
- 자격 삭제 실패 때 회원 상태·revision·세션·링크·자격 전체 롤백 확인
- 타입검사, 전체 lint, 변경 파일 형식검사, 프로덕션 빌드와 로컬 운영 응답 확인
