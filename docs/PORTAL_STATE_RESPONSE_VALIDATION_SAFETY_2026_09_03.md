# 포털 최초 상태 응답 검증 안전성

## 문제

포털 최초 로딩은 `/api/state` 응답을 타입 단언으로 읽고 핵심 상태와 여러 운영 지표를 화면에 적용했다. 비-JSON 응답은 기술 오류 문구를 노출할 수 있었고, 손상된 성공 응답은 사용자·저장 버전·운영 상태를 일부만 적용하거나 잘못된 부가 지표로 화면 오류를 만들 수 있었다.

## 변경

- HTTP 상태와 JSON 읽기를 공용 응답 경계에서 처리한다.
- 운영 상태는 명시적 `null` 또는 현재 포털 상태 검증을 통과한 값만 허용한다.
- 로그인 사용자의 역할·계정 연결·권한과 비어 있지 않은 저장 버전을 검증한 뒤 상태를 적용한다.
- 비-JSON·손상된 성공 응답은 한국어 복구 안내로 차단한다.
- 저장용량과 대표용 익명 운영 지표는 각각 구조를 검증하고, 손상된 부가 지표만 숨겨 핵심 포털 접근을 막지 않는다.
- 401·403과 안전한 서버 오류 문구는 기존 로그인 안내 경로에 유지한다.

## 유지한 운영 경계

- `/api/state` 서버 응답·저장·인증·권한·지표 계산과 운영 데이터 형식을 변경하지 않았다.
- 부가 지표 손상을 추정값이나 기본 통계로 대체하지 않는다.
- 운영 데이터·DB/R2 스키마·보관 정책, 외부 발송·유료 AI 설정을 변경하지 않았다.
- GitHub 푸시와 공개 Sites 배포는 사용자 승인 전까지 수행하지 않는다.

## 검증

- 자동 테스트: 354개 통과
- 격리 workerd/D1/R2 스모크: 129개 통과
- TypeScript `--noEmit`, 전체 lint, 프로덕션 빌드 통과
- 기존 개발 서버 `/` 응답: HTTP 200
- 검증 중 운영 쓰기·메일 발송·유료 AI·외부 요청: 각 0건
