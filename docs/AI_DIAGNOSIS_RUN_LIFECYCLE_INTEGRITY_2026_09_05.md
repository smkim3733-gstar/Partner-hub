# AI 진단 실행 원장 수명주기 무결성 경계

기준일: 2026-09-05

## 문제

`ai_diagnosis_runs`는 유료 외부 AI 요청의 멱등 잠금, 진행·기업·실행자, 모델·지침, 결과와 토큰 사용량을 보관한다. 애플리케이션은 생성중 행을 먼저 확보한 뒤 성공 또는 실패로 한 번만 전환하지만 D1 직접 SQL은 요청 신원을 바꾸고, 생성중 행을 빈 결과로 완료하거나, 완료·실패 행을 다시 전환·삭제할 수 있었다. 이 경우 같은 요청의 유료 재실행 차단과 대표 검토 근거가 사라질 수 있었다.

## 적용

- `0033_ai_diagnosis_run_lifecycle.sql`에 테이블·인덱스의 깨끗한 DB 생성 호환과 삽입·신원 불변·전이·삭제 방지 트리거를 추가했다.
- 신규 행은 공백 없는 요청 ID·진행 ID·기업·지침·모델·실행자, `Step 0`, `생성중`, 정상 UTC 시각, 0 토큰과 64자 소문자 SHA-256 요청 지문만 허용한다.
- 요청 ID·진행·기업·단계·지침·모델·실행자는 생성 뒤 바꿀 수 없다.
- `생성중 → 생성실패`는 결과·토큰·시각을 바꾸지 않는 상태 전이만 허용한다.
- `생성중 → 대표 검토 대기`는 같은 요청 지문, 필수 결과 컨테이너, 비어 있지 않은 기업 현황·다음 행동, 안전 정수 토큰과 전진한 완료시각을 함께 저장해야 한다.
- 완료·실패 행의 재작성과 모든 실행 원장 삭제를 차단해 멱등 잠금과 실행 증거를 보존한다.
- 애플리케이션 쓰기는 `lib/ai-diagnosis.ts` 한 곳뿐이며 정적 회귀검사가 다른 작성·삭제 경로를 차단한다.

## 검증

- 잘못된 단계 삽입, 진행 재지정, 결과 없는 완료, 완료 뒤 실패 전환, 실패 뒤 재개와 직접 삭제가 모두 거절된다.
- 거절 뒤 원래 요청 신원·상태·결과·토큰·시각이 보존된다.
- 정상 완료는 저장·재조회되고 정상 실패는 terminal 상태로 남으며 같은 요청을 재실행하지 않는다.
- 기존 Step 0의 동시 요청, 공급자 실패, 동의 철회, 원본 소실, 응답 유실 멱등 흐름을 함께 회귀 검증했다.
- 34개 추가형 마이그레이션을 기존 상태가 있는 격리 D1에 두 번 적용해도 기존 상태를 교체하지 않는다.
- Node 회귀 검사 637/637 통과
- 격리 workerd/D1/R2 검사 445/445 통과
- 타입검사, 전체 lint, 변경 파일 포맷, 프로덕션 빌드 통과
- 로컬 운영 Worker `/`, `/account`, `/account/setup` HTTP 200과 CSP, `X-Frame-Options: DENY`, `nosniff`, `no-referrer` 확인
- 실제 운영 쓰기, 이메일 발송, 유료 AI 요청, 외부 요청 0건
