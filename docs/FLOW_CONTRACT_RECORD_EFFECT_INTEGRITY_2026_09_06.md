# 상담 FLOW 계약 체결 기록 효과 무결성

기준일: 2026-09-06

## 문제

`record_contract` 명령은 사용자가 선택한 계약상담과 새 서명본을 기준으로 계약 체결을 기록하지만, 기존 명령 영수증에는 선택한 상담 ID가 남지 않았다. 상태 검사도 변경된 상담이 계약 결과의 상담 ID와 같은지만 확인해, 첫 번째 계약상담을 선택한 명령의 완료·계약 증거를 두 번째 상담으로 옮겨도 애플리케이션 경계를 통과할 수 있었다. 실패 우선 검사로 대상 바꿔치기를 재현한 뒤 앱과 D1에 같은 효과 계약을 추가했다.

## 적용한 경계

- 명령 영수증 `targetId`에 사용자가 선택한 계약상담 ID를 보존한다.
- 계약은 처음 한 번만 기록하며, 5차 견적서·최신 6차 계약서·필수 서류 검토가 현재 결정과 일치해야 한다.
- 선택 상담은 이전·현재 상태에 각각 정확히 한 건 존재해야 하며, 종류는 `contract`, 상태는 예정 또는 완료, 시작시각은 서버 수정시각 이하여야 한다.
- 대표 또는 실제 상담 참석 파트너만 기록할 수 있다. 예정 상담은 서버 수정시각으로 완료하고 이미 완료된 상담은 그대로 보존한다.
- 선택하지 않은 상담과 기존 파일 이력은 추가·삭제·재정렬·수정할 수 없다.
- 계약은 선택 상담, 최신 6차 계약서, 새 서명본, 정상 계약일, 1원 이상 1조원 이하 약정 계약금과 실제 행위자 이름에 정확히 결속한다.
- 계약일은 정상 달력 날짜여야 하고 서버 수정시각의 한국시간 날짜보다 미래일 수 없다.
- 서명본은 이번 명령에서 새로 받은 파일 정확히 한 건이어야 하며 용도는 `signed_contract`, 생성시각은 서버 수정시각과 같아야 한다. 신청자료 유입 증빙 필드는 허용하지 않는다.
- 기존 서명본 파일 ID를 재사용하는 명령을 거절해 사용자가 확인한 새 업로드만 계약 증거로 사용한다.
- 감사기록은 `서명본과 약정 계약금 등록 · 입금 확인 대기` 문구에 정확히 결속한다.

애플리케이션 커밋 검사와 D1 트리거가 같은 계약을 독립적으로 강제한다. `0089_consulting_flow_record_contract_effect.sql`은 기존 명령 영수증 대상 트리거를 추가형으로 교체해 `record_contract`의 `targetId`를 필수화한다. D1 효과 검사는 SQLite 표현식 깊이 제한을 넘지 않도록 상담·선행조건과 계약·서명증빙 두 트리거로 분리했다. 기존 저장 영수증과 계약 기록은 변경하지 않고 이후 revision에 새로 추가되는 명령만 검사한다.
