# 상담 FLOW 신청자료 R2 복사 실패·접근변경 재시도 무결성

기준일: 2026-09-07

## 확인한 경계

대표가 신청자료 원본을 검토해 상담 FLOW 근거자료로 반영하면 원본은 그대로 보존하고 검토본만 새 R2 키로 복사한다. 목적지 R2 쓰기 실패와 사건 삭제가 겹칠 때 접근 상실을 우선 반환하면서도, 저장 결과가 불확실한 객체와 `pending` 예약을 같은 명령으로 안전하게 복구해야 한다.

## 발견·수정

- 목적지 객체 생성 전 R2 실패와 사건 삭제가 겹치면 현재 접근 재검사가 404를 반환한다. 새 객체와 FLOW·명령 영수증·파일 원장·완료 원장 D1 쓰기는 없고 단일 `pending` 예약만 남는다.
- 사건 복구 뒤 같은 명령의 목적지 객체가 생성됐지만 R2 응답만 실패하고 사건이 다시 삭제된 모호한 결과도 404를 반환한다. 객체 1개는 예약 키에 보존하고 FLOW D1은 커밋하지 않는다.
- 수정 전에는 사건을 복구해 같은 명령을 다시 실행하면 최초 예약의 검토시각과 재시도 FLOW 전이시각이 달라 `503 저장된 상담 FLOW 무결성` 오류가 발생했다.
- 신청자료 검토는 하나의 불변 출처 사건이므로 재사용 예약은 최초 `createdAt`·`sourceReviewedAt`을 함께 보존한다. 최종 FLOW 명령·감사·파일 원장도 그 시각에 결속한다. 일반 첨부 재시도의 현재 명령시각 규칙은 유지한다.
- 마지막 정확 재시도는 최초 예약의 파일 ID와 R2 키를 그대로 사용해 FLOW를 한 번만 커밋하고 예약을 `ready`로 전이한다. 별도 객체나 명령 영수증은 생기지 않는다.
