# AI 토큰 사용량 증거 무결성 경계

기준일: 2026-09-06

## 문제

Anthropic 성공 응답에서 `usage` 객체나 입력·출력 토큰 필드가 없어도 공용 파서가 각각 0으로 보정했다. 실제 유료 생성이 끝났는데 사용량 증거가 없는 완료 원장이 정상 결과처럼 저장될 수 있었고, Step 0 출력 토큰 수와 요청 상한 4,000의 저장소 결속도 없었다.

## 적용

- HTTP 성공 응답은 `usage.input_tokens`와 `usage.output_tokens`를 모두 필수 양의 안전 정수로 요구한다.
- HTTP 오류 응답은 사용량이 없어도 기존 401·429·공급자 오류 안내를 유지하고 완료 결과로 저장하지 않는다.
- Step 0 최대 출력 토큰 4,000을 공용 상수로 정의해 외부 요청과 완료 저장 검증이 같은 값을 사용한다.
- 애플리케이션 완료 저장, 서버 완료행 조회와 클라이언트 응답 경계가 입력·출력 토큰 양수를 강제하고 Step 0 출력은 4,000 이하만 허용한다.
- `0039_ai_diagnosis_usage_envelope.sql`과 런타임 D1 트리거가 직접 완료 전이에도 같은 사용량 계약을 강제한다.
- 기존 완료 원장의 값을 자동 변경하지 않는다.

## 검증

- 성공 응답의 사용량 객체·입력 토큰·출력 토큰 누락과 0·음수·소수 값을 거절한다.
- 오류 응답은 사용량 누락을 허용하되 완료 저장 경로에 들어가지 않는다.
- Step 0 출력 토큰 4,001은 애플리케이션·D1·클라이언트 경계에서 모두 거절된다.
- 상담 FLOW와 Step 0의 정상 AI 모의응답은 명시적 사용량 증거로 통과한다.
- 40개 추가형 마이그레이션을 기존 상태가 있는 격리 D1에 반복 적용해도 기존 상태를 교체하지 않는다.
- Node 회귀 검사 642/642 통과
- 격리 workerd/D1/R2 검사 451/451 통과
- 타입검사, 전체 lint, 변경 파일 포맷, 프로덕션 빌드 통과
- 로컬 운영 Worker `/`, `/account`, `/account/setup` HTTP 200과 CSP, `X-Frame-Options: DENY`, `nosniff`, `no-referrer` 확인
- 실제 운영 쓰기, 이메일 발송, 유료 AI 요청, 외부 요청 0건
