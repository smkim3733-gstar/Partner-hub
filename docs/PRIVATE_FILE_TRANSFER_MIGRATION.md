# Next.js 이전: 비공개 기업자료·FLOW 직접 전송

## 완료 범위와 운영 경계

2026-09-08, 기업자료와 상담 진행(FLOW)의 업로드·내려받기를 별도 전송 서버로 연결했습니다. 기존 기업자료 카드, 신청 첨부, 원본 검토·회수 화면과 FLOW 첨부에 같은 연결을 적용했습니다. 격리 로컬 Next 검증에 이어 [명시적 독립 원격 후보](NEXT_REMOTE_BACKEND.md)에서도 합성 HTTPS 통합 검사를 통과했습니다. 실제 Vercel/Cloudflare 계정 연결, 원본 이관, 운영 배포는 하지 않았습니다. Duet/Claude 호출도 없습니다.

AI와 신청자료 불러오기 등에 필요한 [서버 전용 R2 연결](R2_HTTP_MIGRATION.md)은 후속 구현해 격리 검증했습니다. 운영 인증·복구, 실제 저장소 및 백업·복원 연결은 남아 있습니다. 기본/프로덕션 Next API의 `503` 차단과 Git 자동 배포 차단을 유지합니다.

Vercel Functions의 요청/응답 본문 한도는 4.5MB입니다. 파일 바이트가 Next API를 통과하지 않도록 분리했습니다. [Vercel 공식 제한](https://vercel.com/docs/functions/limitations)

## 전송 과정

1. 브라우저가 현재 선택한 파일의 이름·MIME·크기·SHA-256과 자료정보, 기존 멱등성 키를 구성합니다.
2. Next의 `POST /api/file-transfers`는 파일 바이트가 없는 JSON을 받습니다. HTTP 본문 상한은 1MiB이며, 기업자료 및 다운로드 명세는 별도로 16KiB, FLOW 명령 본문은 UTF-8 400,000바이트로 제한합니다. 고정 앱 Origin, 현재 비밀번호 세션, 자료 권한·담당 계정·연결 신청·동의를 확인합니다. FLOW는 명령·revision·대상·업무 단계까지 사전 검증하고, 다운로드는 현재 사건·파일 조회 권한을 확인합니다.
3. AES-256-GCM으로 암호화·인증한 120초 전송 권한을 발급합니다. 전송 서버와 앱 Origin, 세션, 안정 사용자 ID, 작업 종류, 파일/자료정보를 결속합니다. 기업자료는 기존 요청 키와 바이트 해시에, FLOW는 사건·명령 ID·revision·명령 본문 해시와 두 첨부 슬롯에 한정됩니다. 전사문·보고서 본문은 전송 권한에 넣지 않습니다. 실제 파일 ID는 기존 D1 업로드 예약이 한 번만 배정합니다.
4. 브라우저는 별도 서버의 고정 경로 `/v1/files/transfer`에 `Authorization: Bearer …`로 접근합니다. 쿠키를 보내지 않고 리다이렉트를 따르지 않습니다. 전송 권한은 URL·영구 링크·브라우저 저장소에 넣지 않습니다.
5. 전송 서버는 권한을 복호화하고 DB의 **현재 세션과 계정 상태**를 다시 확인합니다. 요청자가 붙인 Cookie·Sites 신원·경로·멱등성 키는 사용하지 않습니다. 복호화한 세션으로 정해진 기업자료/FLOW 파일 처리기만 실행합니다. 계정 정지, 업로드 권한 회수, 로그아웃, 세션/자격증명 교체는 이미 발급된 권한에도 적용됩니다.
6. 기존 자료 저장/다운로드 처리기가 실제 파일 형식과 동의, 최신 담당 권한, D1 예약·완료 영수증, 원본 ETag·MIME·크기·체크섬 및 불변 원장을 검증합니다. 업로드 본문을 읽은 뒤에도 전송 만료와 해시·자료정보 일치를 확인합니다.

이 구현은 브라우저에 R2 PUT 권한을 주지 않습니다. 따라서 별도 staging 객체를 만들고 복사하는 방식 대신, 기존 서버 측 검증을 통과한 바이트만 기존 예약된 원본 경로에 기록합니다. 공개 버킷과 재사용 가능한 원본 덮어쓰기 URL이 없습니다. 이미 완료된 같은 요청은 파일 ID를 재사용하며 원본을 다시 쓰지 않습니다. 이전 D1 문서의 staging 계획을 기업자료와 FLOW 경로에서 이 방식으로 구체화했습니다.

## FLOW 명령·재시도 경계

- 직접 업로드는 `save_source`, `save_report`, `save_recording`, `save_transcript`, `receive_document`, `record_contract` 6종입니다. 첨부 없는 일반 명령은 기존 Next API를 사용합니다. `import_intake_source`나 AI 실행 명령을 전송 권한으로 호출할 수 없습니다.
- 기본 `file` 슬롯과 `save_recording`의 보조 `audio` 슬롯만 허용합니다. 최대치는 기존 규칙대로 근거 8MiB, 전사문 5MiB, 음성·일반 첨부 25MiB이며 합계 30MiB입니다. 명세 외 필드·중복 슬롯, 동의 누락, 명령/대상/본문/파일 변조를 거절합니다.
- 발급 시 파일 메타데이터로 업무 명령을 검증하되 예약·원본 저장·AI 실행은 하지 않습니다. Worker가 실제 바이트를 받은 뒤 원래 명령 처리기를 실행하며 형식·현재 권한·D1/R2 무결성을 다시 검증합니다.
- 이미 완료된 명령은 이후 revision이나 단계가 바뀌어도 원래 영수증 검사에 도달할 수 있습니다. 같은 행위자·본문·첨부일 때만 기존 결과를 반환합니다. 새 전송 권한을 발급받아도 명령 ID의 기존 영수증을 변경할 수 없습니다.
- 발급 단계의 `409`도 기존 FLOW 응답 계약을 유지합니다. 화면은 최신 진행을 다시 읽고 미완료 명령 ID·첨부 재시도 기록을 보존합니다. 자동 재업로드·저장소 우회는 하지 않습니다.
- 기업자료와 FLOW의 기존 SQL 마이그레이션·트리거·원본 원장을 변경하지 않았습니다.

## 보안·실패 처리

- 전송 비밀값은 D1 HTTP 서비스 비밀값과 **별도로 생성하는 32바이트 난수**입니다. 테스트에서는 메모리에만 생성했습니다. 실제 값은 Git·URL·브라우저·로그에 기록하지 않습니다.
- 암호화된 권한 자체도 유효기간 동안 지정 파일 작업을 허용하는 민감한 bearer 값입니다. 공유하면 안 됩니다. 원래 세션은 암호문에서 읽을 수 없으며 Next 쿠키의 HttpOnly 속성을 바꾸지 않습니다.
- 운영용 Worker는 `FILE_TRANSFER_ENABLED=1`, 별도 `FILE_TRANSFER_SECRET`, 정확한 `FILE_TRANSFER_APP_ORIGIN`/`FILE_TRANSFER_ORIGIN`이 모두 유효해야 동작합니다. 두 Origin은 서로 다른 HTTPS 주소여야 합니다. 배포 설정·자원 ID는 아직 없습니다.
- CORS는 설정한 앱 Origin 하나와 GET/POST, Authorization/Content-Type만 허용합니다. Cookie와 Origin 누락, 임의 Origin, URL 쿼리, 다른 경로·메서드·Content-Encoding은 거절합니다. 사용자 입력이나 Host 헤더에서 신뢰 주소를 만들지 않습니다.
- 응답은 `private, no-store`, `no-referrer`, `nosniff`이며 Set-Cookie를 노출하지 않습니다. 서버에서 원본 권한을 검사한 뒤 다운로드를 스트리밍합니다. 브라우저는 최대 25MiB를 검사하고 일시적인 Blob 다운로드를 만들며 이후 URL을 해제합니다.
- 본문 읽기에는 전송 만료 기한을 적용합니다. 업로드가 커밋된 뒤 응답이 사라지거나 만료될 수도 있습니다. 서버 예외 및 커밋 후 만료는 `FILE_TRANSFER_OUTCOME_UNKNOWN`으로 취급하며 자동 재시도·R2 삭제 보상·다른 저장소로 우회하지 않습니다. 사용자가 같은 파일과 자료정보로 재시도하면 기존 멱등성 원장이 결과를 확인합니다.
- 전송 전 권한이 취소되어 서버가 큰 요청을 일찍 거절하면 클라이언트가 HTTP 응답 대신 연결 중단을 볼 수도 있습니다. 이를 저장 성공으로 해석하지 않습니다.
- 실제 배포 전에는 고정 Origin/CORS, 비밀값 회전, 서비스 접근·요청량 제한, 로그 마스킹, 동시 대용량 전송 메모리·지연을 추가 검증해야 합니다. 로컬 최대 크기 검사는 실제 클라우드 부하검사를 대체하지 않습니다.

## 구현 위치와 실행

- `lib/file-transfer-contract.ts`, `file-transfer-ticket.ts`: 제한된 작업 명세와 암호화 권한.
- `lib/file-transfer-issuer.ts`: 기존 로그인·업무 권한에 따른 발급.
- `lib/file-transfer-gateway.ts`, `file-transfer-dispatch.ts`: CORS·전송 경계와 기존 처리기로의 제한된 위임.
- `lib/company-file-post.ts`: 원래 Sites 업로드 로직을 공유 처리기로 이동. Sites 라우트는 동일 Request를 위임하며 기존 검증은 유지합니다.
- `lib/consulting-flow-handlers.ts`, `flow-transfer-preflight.ts`: 원래 FLOW GET/POST 공유 처리기와 발급 전 업무 검증. Sites 라우트도 같은 Request와 context를 위임합니다.
- `infra/file-transfer/worker.ts`: 네이티브 D1/R2를 사용하는 전송 Worker. 전용 빌드 별칭은 Sites 헤더 신뢰를 끄고 독립 관리자 세션 검증을 선택합니다.
- `dev/next-local/file-http.ts`: 같은 전송 경계·처리기를 쓰는 별도 루프백 서버. 앱 주소는 명시적인 로컬 설정이며 네트워크 요청에서 정하지 않습니다. 별도 실서비스 연결을 받지 않습니다.
- `dev/next-local/r2-proxy.ts`: Node File 스트림이 Wrangler 로컬 RPC에서 길이 정보를 잃는 문제를 보완합니다. 로컬에서만 최대 25MiB를 확인해 바이트로 바꾼 뒤 **한 번만** 저장하며 체크섬·조건부 쓰기 옵션을 그대로 전달합니다. 스트림 오류/초과 크기는 저장 전 거절합니다. 네이티브 Worker와 운영 번들에는 이 어댑터를 적용하지 않습니다. [Wrangler 개발 프록시](https://developers.cloudflare.com/workers/wrangler/api/), [R2 쓰기 API](https://developers.cloudflare.com/r2/api/workers/workers-api-reference/).
- `lib/file-transfer-client.ts`, `components/company-file-download.tsx`: 브라우저 업로드와 비공개 다운로드 연결. 직접 전송을 켜지 않은 기존 Sites/Next 로컬 모드는 원래 경로를 유지합니다.

```sh
pnpm run dev:next:local:files
pnpm run test:files:worker
pnpm run test:next:local:files
pnpm run test:next:local:r2
```

개발 명령은 기존 격리 로컬 저장소에 D1·R2 HTTP 연결과 파일 직접 전송을 함께 켭니다. 같은 저장소 이름으로 다른 개발 모드를 동시에 실행하지 않습니다. 개발 서버 재시작 시 전송 비밀값과 포트가 새로 생성되어 이전 전송 권한은 무효화됩니다. 기존 DB 계정·세션·원본 파일은 보존됩니다.

## 기업자료 단계 검사 기록

- 전송 명세·암호화·주소·만료·CORS·응답 불확실성·공유 처리기 연결 검사 9건 통과.
- 실제 Worker + 격리 D1/R2 검사 24건 통과. 최대 25MiB 업로드/다운로드 체크섬, 동일·동시 재시도, 중단 후 재개, 자료정보/내용/MIME 변경 거절, 한글 파일명·빈 MIME 호환성, 실제 형식 검사, 만료·정지·로그아웃, 독립 관리자, 원본 변조 차단을 포함합니다.
- 실제 Next 서버에서 작은 JSON 발급 요청과 별도 6MB 초과 파일 전송, 동일 원본 재사용, 익명/Origin 거절, 로그인 계정 전환 후 이미 발급된 전송 권한 취소를 확인했습니다. 기존 관리자·파트너 인증/저장소 재시작 검사도 통과했습니다.
- 원래 네이티브 Worker 업무 검사 687건 통과. 운영 쓰기·메일·유료 AI·외부 요청은 0건입니다.
- 전체 Node 검사 830건, Next 프로덕션 빌드·HTTP 118건, TypeScript·lint, 기존 Sites 빌드·클라이언트 번들 검사, 기존 release manifest 검사를 통과했습니다. manifest는 기존 릴리스 산출물 검증이며 이번 이전본을 배포했다는 뜻이 아닙니다. 추가된 CI는 아직 원격에서 실행하지 않았습니다.
- 브라우저 DOM·클릭·시각 QA는 수행하지 않았습니다. 실제 GitHub CI 실행이나 클라우드 배포를 의미하지 않습니다.

## FLOW 후속 검사

네이티브 Worker + 격리 D1/R2의 기업자료/FLOW 검사 40건을 통과했습니다. FLOW에서는 5MiB 전사문과 25MiB 음성의 동시 저장, 두 원본 다운로드 체크섬, 큰 전사문과 작은 전송 권한, 명령/음성 변조 거절, 후속 revision 이후 같은 명령 재시도, 권한 회수·정지·교차 사건·원본 변조 차단을 확인했습니다. 외부 요청·운영 쓰기·유료 AI·발송은 모두 0건입니다.

실제 Next 서버와 독립 관리자·파트너 세션에서 근거자료, 1~6차 수동 보고서, 공동분석·상담 일정, 두 첨부 녹취, 전사문 갱신, 요청 서류·검토, 서명본 등록까지 연결했습니다. 6종 직접 업로드 명령 전체, 6MiB 초과 음성, 큰 한글 전사문, 발급 전 권한·본문·revision·확장자 거절, 이후 단계의 정확한 재시도와 비공개 다운로드가 통과했습니다. JSON 발급 13회와 별도 업로드 12회를 구분해 검사했습니다.

로컬 R2 전용 검사에서 Node 스트림 저장·읽기, 체크섬 보존, 기존 객체의 조건부 덮어쓰기 거절과 ETag 조건 저장도 통과했습니다. 전체 Node 검사 839건, 인증 D1 HTTP 경로의 기존 업무 회귀검사 687건이 통과했습니다.

최종 반복 검증에서 Next 재시작 후 DB·관리자/파트너 세션·원본 보존, 만료·로그아웃·로그인 시도 제한 `429`까지 확인했습니다.
