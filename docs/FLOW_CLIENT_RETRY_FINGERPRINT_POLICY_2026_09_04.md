# 상담 FLOW 화면 재시도 지문 정책

## 목적

상담 FLOW 저장 응답을 확인하지 못한 뒤 같은 명령과 첨부를 다시 제출할 때 같은 명령 ID를 유지한다. 파일 시스템 메타정보가 우연히 같아도 실제 바이트가 다르면 새 명령 ID를 사용해 서버가 정상 처리 기회를 갖게 한다.

## 변경 전 위험

화면은 명령 JSON과 첨부의 원본 파일명·크기·수정시각만으로 대기 중인 명령을 구분했다. 같은 파일을 다시 선택하면서 Unicode 정규형이나 수정시각이 달라지면 새 명령 ID가 생겨 응답 유실 뒤 중복 명령이 될 수 있었다. 반대로 다른 바이트가 같은 파일명·크기·수정시각을 가지면 이전 명령 ID가 유지되어 서버가 변경 내용 충돌로 거절한 뒤 현재 화면에서 새 제출로 전환하기 어려웠다.

## 적용 내용

- 화면 재시도 키와 서버 영수증이 같은 공용 계산 경로를 사용한다.
- 명령 객체는 키 순서를 정규화한다.
- 첨부 파일명은 공용 NFC 안전 파일명, MIME은 허용 확장자의 공용 등록표 값으로 계산한다.
- 파일·음성 첨부는 실제 SHA-256 바이트 지문과 크기를 포함하고 `lastModified`는 사용하지 않는다.
- 브라우저 재시도 키는 현재 정규 지문만 계산한다. 서버만 배포 전 기록 호환을 위한 제한된 이전 지문 후보를 추가 계산한다.
- 파일 판독 실패도 기존 제출 잠금을 `finally`에서 해제해 화면이 영구 잠기지 않는다.

## 유지한 경계

서버의 계정·명령 ID·내용·첨부 지문 검증, HTTP 403·409 충돌, 저장된 영수증 구조, D1/R2 스키마, 파일 저장·보관·삭제와 외부 AI 승인 조건은 변경하지 않았다. 운영 FLOW나 원본 파일을 읽거나 변경하지 않았다.
