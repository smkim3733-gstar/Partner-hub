# 업로드 실제 형식 미등록 기본 거절

## 목적

향후 업로드 허용 확장자가 추가되더라도 실제 형식 검사기에 함께 등록되지 않은 파일이 검사 누락으로 통과하지 않도록 한다.

## 적용 범위

- PDF, PNG, JPEG, 구형 XLS, DOCX, XLSX, PPTX, MP3, M4A, WAV만 등록된 바이너리 형식으로 판정한다.
- TXT와 Markdown은 기존 텍스트 검증 경계로 보낸다.
- 그 밖의 미등록 확장자와 확장자 없는 파일은 실제 형식 경계에서 기본 거절한다.
- 새 확장자를 지원하려면 허용 정책과 실제 형식 판정 양쪽을 명시적으로 추가해야 한다.

## 유지한 경계

현재 허용 형식·파일 내용·크기·MIME·파일명·R2 키, 인증·권한·동의, D1/R2 스키마와 보관 정책은 변경하지 않았다. 기존 정상 파일의 판정 결과도 동일하다.

## 재발 방지

등록된 모든 바이너리 형식의 정상 표식, 위장 파일, TXT·Markdown, 미등록 확장자와 무확장 파일의 결과를 자동 테스트로 고정했다.

## 검증 결과

- 관련 실제 형식 회귀검사 6개 통과
- 전체 자동 테스트 446개 통과
- 격리 workerd/D1/R2 검사 129개 통과
- TypeScript 타입검사, 전체 lint, 프로덕션 빌드 통과
- 격리검사 중 운영 쓰기, 메일, 유료 AI, 외부 요청 0건

2026-09-04 자동 운영 승인 원칙에 따라 커밋 `7866eae`를 GitHub `main`과 공개 Sites 버전 89에 반영했다. 공개 범위와 D1 `DB`, R2 `AI_SOURCE_FILES` 연결을 유지했으며 운영 화면 3곳의 HTTP 200, 기업자료·상담 FLOW API의 익명 HTTP 401과 비공개 보안 헤더를 확인했다. 실제 업로드는 운영 자료를 만들지 않고 격리 workerd/R2와 API 테스트에서 확인했다. 배포 결과는 `outputs/release/upload-signature-fail-closed-deployment.json`을 기준으로 삼는다.
