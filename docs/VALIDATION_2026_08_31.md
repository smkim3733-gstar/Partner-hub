# 검증 기록 — 2026-08-31

## 파트너 권한·가입 승인 후속 검증 — 현재 로컬 작업본

전체 lint·타입검사·테스트 87개·빌드가 통과했다. `portal-ownership.test.ts`의 6개 검사는 동명이인, 담당 ID 위조, 관련 진행 ID 충돌, 정지된 동명이인, 신규 기록의 계정 연결, 유일한 이름 연결의 유지 및 기존 파일의 권한을 검증한다. 수정 전에는 최초 5개 중 4개가 실패해 문제를 재현했다.

확장한 `password-worker-smoke.mjs`는 실제 workerd와 격리 D1/R2에서 31개를 통과했다. 승인 전 로그인 거부, 대표 API를 통한 승인·담당 배정, 오래된 명단 저장 거부, 쿠키만으로 본인 진행 열기, 타인 진행·동명이인 파일의 읽기/삭제 거부, 원본 보존, 정지 계정 차단, 비밀번호 설정·기존 세션 폐기를 포함한다. 마이그레이션 4개 반복 적용 시 기존 상태를 보존했다. Worker 외부 통신은 차단하고 요청 0건을 확인했다.

이는 격리된 핸들러 실행 검증이며, 실제 브라우저·공개 호스팅 라우터·운영 사용자·운영 DB 검증이 아니다. 현재 공개 사이트는 읽기 전용으로 연결 상태만 확인했다. 운영 반영과 실사용 검증은 [운영 반영 준비사항](../RELEASE_READINESS.md)에 별도로 남겼다. 아래 표들은 이전 단계의 기록이다.

| `pnpm test` | 81개 통과: 기존 77개 + 차트 회귀 검사 4개 |

모바일 감지는 `matchMedia`를 `useSyncExternalStore`로 구독하고 서버 렌더링의 초기값을 유지한다. 캐러셀은 이전·다음 이동 가능 상태를 구독하며 `select`와 `reInit`을 모두 해제한다. 폼 그룹·링크·로딩 표시의 HTML 의미를 정리했다.

차트 회귀 검사는 함수형 `dataKey`를 실행하거나 함수 본문으로 표시하지 않는지, 숫자 0 키와 명시적 제목·계열 키를 보존하는지, 범례 기본값과 사용자 formatter가 유지되는지 확인한다.

전체 검사 규칙은 변경하지 않았다. 캐러셀 슬라이드, Label 안에서도 사용하는 Field, 다형 ItemGroup의 ARIA 역할에는 해당 줄의 `prefer-tag-over-role` 예외를 적용했다. InputGroupAddon의 클릭은 이미 키보드로 접근할 수 있는 입력칸에 포커스를 주는 보조 동작이므로 해당 클릭 줄의 두 검사만 예외 처리하고, 내부 버튼·링크·입력칸의 동작은 가로채지 않는다. 이 예외는 전체 접근성 준수를 보증하지 않는다.

실제 고객 데이터, 원격 DB/R2, 회원 승인, API 키와 외부 서비스는 변경하지 않았다. 브라우저 클릭·화면 크기 변경·시각 검증 및 운영 배포는 수행하지 않았다. 아래 인증 검증 표는 이 정비 이전의 검증 기록을 보존한 것이다.

## 인증 검증 범위

- ChatGPT 헤더 없는 가입과 승인대기 저장, 대표 승인 전 접근 차단
- 승인 후 이메일·비밀번호 및 쿠키만으로 접속, 최소 파트너 권한 유지
- 기존 이메일/정지 계정/대표 이메일 공개 가입 차단, 중복·동시 가입 보호
- 무작위 salt의 scrypt 해시, 세션·설정 토큰 해시 저장, 평문 비밀번호 미저장
- 서버의 현재 승인·이메일·회원 ID·자격정보 버전 확인
- 잘못된/만료 쿠키가 관리자 ChatGPT 헤더로 자동 승격되지 않는지 확인
- 비밀번호 재설정 시 이전 세션·비밀번호 차단, 일회용 토큰 만료/재사용/동시 사용 방지
- Origin/HTTPS/요청 크기/형식 검증과 로그인 시도 제한
- 신규 명단/자격정보의 원자적 D1 저장, 기존 자료와 동시 변경 보존
- 기존 파일·상담 FLOW 접근 및 다수 업무 회귀 시나리오

## 한계

정적 화면 렌더, HTTP 및 API/서버 자동 테스트다. 브라우저 클릭·스크린샷 시각 검증이나 서비스 전체 보안감사를 수행한 것은 아니다. 공개 호스팅 도메인의 실제 쿠키 왕복과 외부 파트너 실로그인은 운영 배포 후 별도 확인해야 한다. 이메일·휴대폰 소유권 자동 검증이 없으므로 대표 승인과 비밀번호 링크 발급 전 본인 확인을 유지해야 한다.
