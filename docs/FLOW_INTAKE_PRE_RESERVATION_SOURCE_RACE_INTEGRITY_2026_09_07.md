# 상담 FLOW 신청자료 예약 직전 원본 경쟁 무결성

기준일: 2026-09-07

## 확인한 경계

대표가 검토한 기업자료 원본을 상담 FLOW 근거자료로 가져올 때 원본 읽기·해시 검증이 끝난 뒤 현재 FLOW 접근과 생명주기를 다시 확인한다. 이 비동기 D1 확인 중 원본이 삭제 처리되거나 같은 R2 키의 객체가 교체돼도 오래된 원본 사실로 새 업로드 예약이나 목적지 객체를 만들면 안 된다.

## 발견·수정

- 버전 304는 원본 읽기·해시 뒤 현재 기업자료 행, 표시 상태, 담당 결속, 불변 무결성 원장과 R2 객체를 다시 확인했다. 이후 FLOW 접근 재검사가 끝나면 원본을 다시 확인하지 않고 업로드 예약을 시작했다.
- FLOW 접근 재검사 중 원본 삭제 tombstone을 만들면 수정 전 회귀가 기대한 404 대신 합성 예약 쓰기 오류 503을 반환했다. 이는 현재 원본 부재보다 예약 D1 쓰기가 먼저 시작됐음을 증명한다.
- 원본 준비 결과에 검증 당시 기업자료 행과 객체 무결성 원장을 `sourceSnapshot`으로 보존한다.
- FLOW 접근·생명주기 재검사가 끝난 직후 현재 기업자료 행, 표시 가능 상태, 기업·사건·담당 결속, 전체 원본 사실, 최신 객체 무결성 원장과 R2 `head`를 스냅샷에 다시 대조한다.
- 원본 삭제 tombstone 경쟁은 404로 끝난다. 같은 키·MIME·크기의 R2 객체 교체 경쟁은 네이티브 ETag 불일치를 409로 반환한다.
- 두 경쟁 모두 FLOW 업로드 예약 배치 0회, 해당 명령의 예약 행 0건, 새 목적지 R2 객체 0개, FLOW 0건을 확인했다.
- 이 보강은 예약 시작 직전 검증 경계를 닫는다. 검증 완료 뒤 예약 D1 생성과 R2 복사 사이의 더 작은 경쟁은 다음 감사 대상으로 분리한다.
