# 파트너 계정 삭제 무결성 경계

기준일: 2026-09-05

## 확인한 문제

계정관리 화면은 활성 파트너 또는 담당 기업이 남은 파트너의 삭제 버튼을 막았지만 서버의 일반 상태 저장은 이 조건을 확인하지 않았다. 수정 전 실제 `/api/state` 요청으로 담당 기록이 없는 활성 계정과 진행·업무가 연결된 정지 계정을 명단에서 제거해도 HTTP 200이었다. 화면을 우회한 요청이나 손상된 클라이언트 상태가 계정·진행·업무·원본 권한 연결을 고아 상태로 만들 수 있었다.

## 적용한 경계

- 현재 서버 상태에서 `활성`인 파트너 계정은 일반 상태 저장으로 삭제할 수 없다. 먼저 별도 저장으로 계정을 정지해야 한다.
- 정지·승인대기 계정도 진행, 업무, 기업자료, 일정 중 하나가 연결돼 있으면 삭제할 수 없다.
- 새 기록의 `partnerMemberId` 연결과 ID가 없는 레거시 담당자명 연결을 모두 확인한다. 레거시 이름 연결은 오삭제보다 보존을 우선한다.
- 연결 기록은 먼저 다른 계정으로 이전하거나 명시적으로 정리하고 저장해야 한다. 계정 삭제와 연결 기록 제거를 한 요청으로 묶어 검사를 우회할 수 없다.
- 정지·승인대기 상태이며 연결 기록이 없는 계정의 기존 삭제와 비밀번호 자격·세션·설정 링크·ChatGPT 결속의 원자적 폐기는 유지한다.
- 오래된 명단 revision 요청은 삭제 오류보다 기존 409 충돌을 먼저 유지해 최신 명단 재확인 절차를 깨지 않는다.
- 실제 운영 회원·고객 데이터, D1 스키마, R2 연결, 공개 범위, 보관·삭제 정책은 변경하지 않았다.

## 검증

- 수정 전: 활성 미배정 계정과 연결 기록이 남은 정지 계정 삭제가 각각 HTTP 200으로 재현됐다.
- 수정 후: 두 요청은 HTTP 403이고 기존 상태가 유지된다. 정지·미배정 계정 삭제는 HTTP 200으로 유지된다.
- 진행·업무·기업자료·일정 네 연결 유형과 직접 회원 ID·레거시 담당자명 경로를 모두 확인했다.
- 표적 Node 테스트 79/79, 전체 Node 회귀 테스트 498/498 통과.
- 격리 workerd+D1+R2 검사 193/193 통과. 운영 쓰기·이메일·유료 AI·외부 요청은 모두 0건이다.
- 타입검사, 전체 lint, 프로덕션 빌드 통과.
- 로컬 운영 Worker의 `/`, `/account`, `/account/setup` 모두 HTTP 200.
