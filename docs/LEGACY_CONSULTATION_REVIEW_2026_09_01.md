# 기존 상담 등록 화면 점검

2026-09-01. 사용자의 연속 개발 요청에 따라 상담 FLOW와 별도로 남아 있던 기존 `상담 등록` 화면을 가상 데이터로 점검했다. 실제 고객 자료·계정·외부 캘린더는 사용하지 않았고 자동 후속 실행은 일시 중지 상태를 유지한다.

## 재현과 수정

기존 화면에서 취소 상태를 저장해도 기본 선택된 서류요청 업무가 생성됐다. 상담 제목·일시·방식·상태는 타임라인에 남지 않고, 필수 표시된 상담내용과 내부·공유 메모 등 5개 입력란은 저장 코드에 연결되지 않았다. 상담 일시는 2026-09-04로 고정됐고 후속 업무 기한도 09.05로 고정됐다. 실제 Google Calendar 연결 없이 자동 등록되는 것처럼 표시했다.

- 제목과 실제로 존재하는 한국시간 일시를 저장 전 검사한다. 고정 날짜를 제거하고 잘못된 날짜·시각과 연말 연산 실패를 차단한다.
- 제목·날짜·방식·상태를 타임라인 상세에 남긴다. 저장되지 않던 참석자·상담내용·공유 및 내부 메모 입력란은 제거하고, 상세 기록은 권한 경계가 구현된 상담 FLOW를 이용하도록 안내한다. 새로운 메모 공개 정책이나 저장소는 만들지 않았다.
- 후속 업무는 `상담 완료` 상태에서만 생성하고 중복 선택을 한 번으로 정리한다. 기한을 임의로 정하지 않고 `기한 확인`으로 생성한다. 취소·일정 요청·고객 회신 대기·일정 확정은 후속 업무를 만들지 않는다.
- 허브 일정은 `일정 확정`일 때만 선택적으로 만든다. 시작·종료 연도와 날짜, 기업 진행 ID·담당 계정 ID를 보존한다. 한국시간 23:30 상담의 다음 날·다음 해 종료도 정확히 저장한다.
- 자동 Google Calendar 연동 문구를 제거했다. 허브 일정 화면에서 사용자가 직접 외부 등록 초안을 여는 기존 기능과 구분한다. 취소 기록이 이미 등록된 일정을 자동 변경하지 않는 점도 표시한다.
- 빈 저장소의 첫 상담 번호가 0으로 표시되지 않도록 1부터 시작한다. 화면의 완료 상담 횟수와 취소·예약을 포함한 상담 기록 건수를 구분한다.
- 저장 버튼 직후 서버 저장 확정을 단정하지 않고, 저장 요청과 상단 `DB 저장됨` 표시 확인을 안내한다.

## 가상 검증

| 조건 | 결과 |
| --- | --- |
| 수정 전 취소 저장 | 취소인데도 서류요청 업무 1건이 생성됐고, 입력한 본문·내부 메모와 제목·일시는 타임라인에서 유실됐다. |
| 필수 일시 누락 | 타임라인·업무·일정을 만들지 않고 한국시간 입력 오류를 표시하며 일시 입력으로 초점을 옮겼다. |
| 잘못된 일시 | 평년 2월 29일, 4월 31일, 24시, 잘못된 분, 시각대가 포함된 값과 범위를 넘는 연말 시각을 차단했다. 윤년 2월 29일은 허용했다. |
| 취소·대기 상태 | 일정과 후속 업무 계획을 만들지 않으며 제목·한국시간·방식·상태는 상담 기록에 포함했다. |
| 일정 확정 | 연말을 넘는 1시간 일정의 시작일 2026-12-31, 종료일 2027-01-01과 `Asia/Seoul` 외부 등록 초안 값을 확인했다. 외부 링크는 열지 않았다. |
| 상담 완료 | 선택한 중복 후속조치를 한 번씩만 남기고 임의 기한 없이 준비했다. 일정은 생성하지 않았다. |
| 브라우저 점검 범위 | 큰 화면에서 빈 일시 오류, 첫 상담번호, 비기능 입력 제거, 상태별 일정·후속조치 비활성 문구를 확인했다. 자동 도구가 `datetime-local`의 React 변경 이벤트를 재현하지 못해 유효 날짜의 브라우저 저장 클릭은 완료로 간주하지 않았다. |

가상 런타임은 메모리 전용 D1/R2와 `example.invalid` 계정만 사용했고 외부 요청은 0건이었다. 실제 계정 등록·고객 자료 조회·연락·메일·외부 일정 저장·유료 AI·삭제는 수행하지 않았다.

## 회귀 검사와 배포

- 제목·한국시간 날짜·윤년·연말 종료·상태별 일정 및 후속조치·중복 선택·원본 불변을 5개 회귀 검사로 추가했다.
- 전체 Node 검사 192개, 타입검사, lint, 빌드가 통과했다. 서버 API와 DB 스키마를 변경하지 않아 기존 workerd/D1/R2 110개 저장소 검사는 반복하지 않았다.
- 가상 실행 기록은 `outputs/validation/consultation-before-runtime.json`, `consultation-after-invalid-runtime.json`, `consultation-runtime.json`에, 검사·빌드는 `consultation-tests.log`, `consultation-build.log`에 남겼다.
- 운영 반영 상태는 `outputs/release/legacy-consultation-deployment.json`에 기록한다. 기존 공개 사이트와 D1/R2 연결, 추가형 마이그레이션 8개를 유지한다.
- 실제 브라우저의 모든 입력 방식·모바일·전체 키보드 조작과 Google Calendar 실제 저장을 완료한 것으로 해석하지 않는다.
