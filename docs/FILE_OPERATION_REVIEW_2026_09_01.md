# 순차 점검 2 — 파일 동시 요청·계정 정지 시점

## 재현 결과

2026-08-31 밤 시작한 두 번째 점검을 2026-09-01에 검증했다. 기존 코드와 격리 가상 자료로 요청 본문 읽기, R2 저장·조회, D1 저장 직전에 지연을 넣었다. 최초 회귀 검증 8개는 수정 전 모두 실패했다.

- 요청 시작 때 활성 계정이면 본문 수신 중 정지되거나 R2 저장 중 정지되어도 업로드가 완료됐다. 메타데이터 트랜잭션 직전에 정지되는 경우도 재현했다.
- R2 조회 중 정지되거나 다른 요청에서 삭제를 완료한 원본을 다운로드 응답으로 반환했다.
- 최초 인증 후 계정이 정지되어도 삭제가 실행됐다.
- 아직 메타데이터가 없는 업로드에 삭제 성공을 반환했지만 뒤늦은 업로드가 파일을 생성했다. 삭제 조회 직후 업로드가 완료되는 경로도 별도 회귀 검증으로 확인했다.
- 업로드 요청 원장이 없는 레거시 원본은 명시적인 삭제 요청의 R2 처리가 실패한 뒤에도 다운로드할 수 있었다.

실제 고객 원본이나 운영 명단으로 재현하지 않았다.

## 수정한 동작

- 업로드 본문 수신·해시 계산 뒤, R2 저장 전후, 기존 요청 결과를 돌려주기 전에 계정과 업로드 권한·담당 배정·진행 연결을 재확인한다.
- 권한을 확인한 운영 상태 원문과 D1에 남은 상태가 일치할 때만 업로드 예약 및 메타데이터 확정을 허용한다. 동시 명단 변경은 같은 D1 문장의 조건으로 차단한다.
- R2 저장 뒤 계정이 정지되거나 권한이 회수되면 원본을 자동 삭제하지 않는다. 미확정 업로드를 유지하고, 권한이 다시 허용된 상태의 동일 요청 재시도는 같은 원본 ID로 이어진다.
- 다운로드는 R2 조회 후 현재 계정·배정·원본 존재·삭제 기록·운영 상태를 다시 확인한다. 거부 시 아직 반환하지 않은 스트림을 취소한다. 파일 API의 오류 응답에도 `private, no-store`를 적용한다.
- 삭제는 현재 계정과 같은 운영 상태에 대한 조건부 삭제 기록을 먼저 남긴다. 레거시 원본에도 기존 요청 원장을 사용해 삭제 기록을 남기므로 R2 처리 실패 뒤 다운로드와 재생성을 차단하고 명시적 삭제 재시도를 허용한다.
- 메타데이터가 아직 없거나 조회 직후 확정된 업로드는 삭제 성공 대신 충돌을 반환한다. 같은 원본에 대한 동시 삭제와 기존 업로드 재시도·삭제 경합 보호는 유지한다.

새 DB 마이그레이션·외부 연동·기능 화면·보관 기간 정책은 추가하지 않았다. 정지만을 이유로 원본을 삭제하지 않는다. 삭제 완료 전에 불확실한 R2 쓰기가 남더라도 이전에 명시적으로 승인된 삭제 기록이 있는 경우에만 기존 재생성 방지 정리를 수행한다.

## 검증과 한계

전체 자동 테스트 172개, 격리 workerd/D1/R2 검증 102개를 통과했다. 파일 경합 회귀 12개는 지연 중 정지·업로드 권한 회수, 메타데이터 확정 및 삭제 결정 직전 정지, 원본 보존·동일 요청 복구, 다운로드·삭제 경합, 처리 중 업로드, 동시 삭제, 레거시 삭제 실패를 포함한다. 네이티브 런타임에는 실제 D1 조건부 저장·레거시 삭제 기록과 정지된 가상 비밀번호 세션의 파일 요청 거부·원본 보존 등 9개 확인을 추가했다.

업로드 메타데이터 확정과 삭제 기록 작성은 D1의 조건부 문장을 경계로 한다. 다운로드는 응답 스트림 반환 직전에 재확인한다. 이미 전송을 시작한 바이트를 회수하거나, 이미 승인된 삭제 결정을 사후 정지로 취소하는 보장은 아니다. D1과 R2가 하나의 트랜잭션인 것으로 취급하지 않는다. 다른 운영 저장과 충돌하면 재시도가 필요할 수 있다.

브라우저 클릭·실제 고객 파일 조회·운영 자료 변경·실제 계정 생성·메일·유료 AI는 수행하지 않았다. 다음 미완료 점검은 상담 FLOW의 단계별 권한·중복 요청이다.

선행 운영 버전은 45, 소스는 `2d26620ed435380b773318c2b87c9bdd0b9040d1`이다. lint·타입검사·빌드를 수행하며, 정확한 소스 커밋·최종 검증·운영 반영 결과와 공개 경로 확인은 `outputs/release/file-operations-deployment.json` 및 Sites 배포 이력에 기록한다. 이 문서의 코드 점검 완료를 운영 배포 성공으로 대신하지 않는다.
