# 상담 FLOW 재시도 명령 불일치 무결성

기준일: 2026-09-07

## 확인한 위험

2슬롯 업로드가 첫 객체만 저장한 채 실패한 뒤, 같은 명령 ID와 원래 첨부를 유지하면서 명령 본문만 바꿔 재시도하면 기존 예약 객체와 다른 상담 내용이 결합될 위험이 있다.

## 확인한 현재 경계

- 첫 전사문 객체 저장 성공과 두 번째 음성 저장 실패를 결정적으로 재현했다.
- 원래 첨부는 그대로 두고 같은 명령 ID의 `transcript` 명령 필드만 바꿔 재시도했다.
- 서버는 예약의 명령 SHA-256 지문 불일치를 R2 쓰기 전에 409로 거절한다.
- 거절된 요청은 R2 `put`을 한 번도 호출하지 않고 기존 전사문 객체 바이트·FLOW 본문·두 `pending` 예약을 그대로 보존한다.
- 원래 명령 본문과 첨부로 다시 시도하면 같은 명령 ID·두 파일 ID·두 R2 키로 정상 완료된다.

기존 구현이 요구 경계를 만족해 런타임 코드는 바꾸지 않고 잘못된 명령 결합 방지 회귀 증거를 추가했다.
