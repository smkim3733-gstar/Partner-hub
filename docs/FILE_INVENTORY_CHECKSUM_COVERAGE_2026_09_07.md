# 관리자 파일 재고 체크섬 적용 현황

## 결과

대표 전용 파일 재고 화면에서 기업자료와 상담 FLOW 파일 원장의 무결성 증명 적용 범위를 건수로 확인할 수 있다. 새 SHA-256 증명, 레거시 ETag 증명, 레거시 메타데이터 증명, 증명 불가 상태를 구분하며 목록의 각 기업자료에도 현재 적용 증명을 표시한다. 원본 존재 확인을 실행한 경우에는 R2 `head` 결과와 대조한 증명 종류를 별도로 안내한다.

기능 커밋은 `1f9edb176ab225f07c3a2c82fcf784fb8e257086`이다.

## 구현

- 재고 응답에 `integrityCoverage`를 추가해 네 증명 유형의 안전한 0 이상 정수 건수를 제공한다.
- 기업자료 목록 항목에 `integrityProof`를 추가한다. 유효한 D1 원장 조합만 `sha256`, `etag`, `metadata`로 분류하고 불완전하거나 모순된 조합은 적용 증명으로 인정하지 않는다.
- 원본 존재 확인 응답에도 증명 유형을 포함하고 검증 모드와 일치하지 않는 응답은 클라이언트 경계에서 거절한다.
- SHA-256 적용 파일은 유효한 64자리 소문자 D1 체크섬 원장이 있을 때만 집계한다. 체크섬이 없는 신규 ETag 모드는 레거시 ETag로, 더 오래된 메타데이터 모드는 레거시 메타데이터로 분리한다.
- 미완료 예약은 개별 적용 증명을 갖지 않는다. 완료 FLOW 첨부는 전체 D1 원장 집계에 포함한다.

## 정보 보호와 성능 경계

적용 현황 집계는 D1 원장만 읽는다. R2 본문이나 객체 메타데이터를 대량 조회하지 않으며 SHA-256 값, ETag, R2 저장 키, 원문을 API 응답과 화면에 노출하지 않는다. 기존 객체에 체크섬을 추정하거나 백필하지 않고 현재 검증 경계를 사실대로 집계한다. 원본 존재 확인을 사용자가 명시적으로 실행할 때만 해당 파일의 R2 `head`를 한 번 수행한다.

## 검증

- Node 회귀 테스트 764/764
- 격리 workerd·D1·R2 전체 검사와 98개 추가형 마이그레이션 2회 적용 통과
- SHA-256·ETag·메타데이터·증명 불가 각 1건의 집계와 목록 분류 확인
- 재고 응답에 SHA-256 값·ETag·R2 저장 키가 없고 집계 중 R2 `head`·`get` 호출이 0건임을 확인
- 손상된 적용 유형·음수 또는 비정수 집계·검증 모드와 모순된 존재 확인 응답 거절 확인
- 타입검사, 전체 lint, 변경 파일 포맷, 프로덕션 빌드 통과
- 로컬 Worker 공개 화면 3곳 200, 비인증 보호 API 3곳 401, CSP·프레임 차단·`nosniff`·`no-referrer`·API `private, no-store` 확인
- 검증 중 운영 데이터 쓰기, 메일 발송, 유료 AI 요청, 외부 업무 요청 0건

## 운영 경계와 다음 감사

GitHub `main`에는 반영했다. Sites 소스 전송과 공개 운영 배포는 별도 외부 변경이므로 버전 314 명시 승인 전에는 수행하지 않는다. 재고 목록과 전체 적용 현황은 현재 두 번의 읽기로 수집한다. 다음 감사는 동시 원장 추가 시 두 결과가 서로 다른 시점을 나타낼 수 있는지와 화면의 단일 점검시각 안내를 더 엄격히 해야 하는지 검토한다.
