# 상담 FLOW 재시도 사건·계정 삭제 무결성

기준일: 2026-09-07

## 확인한 위험

파트너의 전사문·음성 2슬롯 업로드가 첫 R2 객체만 저장한 채 실패한 뒤 포털 사건이나 담당 파트너 계정이 삭제되면, 이전 요청의 예약을 이용한 재시도가 남은 객체를 저장하거나 고아 FLOW를 완료할 위험이 있다.

## 확인한 현재 경계

- 정상 파트너의 첫 전사문 객체 저장 성공과 두 번째 음성 저장 실패를 결정적으로 재현했다.
- 실패 뒤 포털 사건만 삭제한 상태와 사건·담당 파트너 계정을 함께 삭제한 상태를 각각 재현했다.
- 사건만 삭제한 재시도는 HTTP 404, 담당 계정까지 삭제한 재시도는 HTTP 403으로 거절한다.
- 두 재시도 모두 명령 파싱·예약 재개·R2 처리보다 앞선 인증·사건 접근 단계에서 중단되어 R2 `put`을 한 번도 호출하지 않는다.
- 거절 뒤 FLOW 본문, 기존 전사문 객체 바이트와 두 `pending` 예약의 파일 ID·R2 키·상태가 그대로 유지된다.
- 사건과 계정을 원상복구한 뒤 원래 명령 ID·본문·첨부를 보내면 같은 두 파일 ID·R2 키로 완료되고 예약과 완료 원장이 원래 파트너 명령에 결속된다.

기존 구현이 요구 경계를 만족해 런타임 코드는 바꾸지 않고 사건·계정 삭제 우회 방지 회귀 증거를 추가했다. 보존된 미완료 객체와 예약은 자동 삭제하지 않으며 관리자 보관 진단과 명시적 복구 판단 대상으로 남긴다.
