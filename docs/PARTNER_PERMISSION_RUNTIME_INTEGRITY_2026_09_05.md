# 파트너 권한 실행 무결성 경계

기준일: 2026-09-05

## 확인한 문제

버전 125는 관리자 일반 저장으로 새 손상 권한을 만들지 못하게 했지만, 과거 이관·손상 상태에 남은 비-boolean 권한값은 무관한 저장에서 보존했다. 수정 전 인증 경계는 이 값을 그대로 사용자 권한으로 반환했다. 따라서 문자열 `"false"`, 숫자, 객체처럼 JavaScript에서 참으로 평가되는 값이 권한 검사에서 허용으로 오인될 수 있었다.

## 적용한 경계

- 비밀번호와 ChatGPT 파트너 인증은 저장된 각 권한이 정확히 boolean `true`일 때만 허용한다.
- 누락값, 문자열, 숫자, 배열, 객체, `null`과 알 수 없는 구조는 모두 `false`로 정규화한다.
- 파트너가 받는 자기 회원 정보도 같은 유효 권한만 포함해 화면의 오인 표시를 막는다.
- 관리자 응답과 원본 저장 상태는 바꾸지 않아 손상 데이터를 확인하고 별도 정상 저장으로 복구할 수 있다.
- 기존의 유효한 다섯 boolean 권한, 인증 방식, 회원·기업 데이터, D1 스키마, R2, 공개 범위는 변경하지 않았다.

## 검증

- 수정 전: 비밀번호와 ChatGPT 인증 모두 다섯 개의 truthy 비-boolean 값을 그대로 반환하는 실패를 재현했다.
- 수정 후: 두 인증 경로의 `currentUser.permissions`와 파트너 회원 응답이 다섯 항목 모두 `false`로 실패 폐쇄됨을 확인했다.
- 전체 Node 회귀 테스트 502/502 통과.
- 격리 workerd+D1+R2 검사 200/200 통과. 운영 쓰기·이메일·유료 AI·외부 요청은 모두 0건이다.
- 타입검사, 전체 lint, 프로덕션 빌드 통과.
- 로컬 운영 Worker의 `/`, `/account`, `/account/setup` 모두 HTTP 200.

## 저장 상태

기능 커밋 `01b871b3756195d4b89d2422a316d0136d4ae7de`를 GitHub `main`과 Sites 소스 저장소에 반영했다. 같은 커밋의 검증된 빌드 산출물을 Sites 버전 126 (`appgprj_6a92514801988191b79eb9bd314e3fcd~appgver_994a9d8b4f508191869dced41ba83cc0`)으로 저장했다. 저장 산출물은 160개 파일, 4,382,720바이트, 해시 `sha256:73640eddc7de19098ca9bdc515c7d109064b2228607b0375c2b5218b9455f8b6`이다.

현재 공개 운영본은 버전 107이다. 버전 108~125는 버전 126으로 대체하며 공개 배포하지 않는다. 버전 126도 정확한 운영 배포 승인 전까지 저장 상태로 유지한다.
