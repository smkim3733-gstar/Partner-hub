# 상담 FLOW 파일 진행 소유권 무결성 경계

기준일: 2026-09-05

## 확인한 문제

FLOW 파일 키를 `consulting-flow/{파일 ID}` 형식에 결속해도 손상된 D1 payload가 다른 진행의 파일 ID와 키 쌍을 함께 복제하면 형식 검사를 통과할 수 있었다. 이 상태에서는 대상 진행을 볼 수 있는 계정이 다른 진행의 R2 객체를 다운로드할 가능성이 있었다.

## 적용한 경계

- `consulting_flow_file_owners` D1 원장을 추가해 파일 ID를 진행 ID와 저장 키에 전역 결속한다. 파일 ID는 기본키, 저장 키는 고유값이다.
- 새 파일의 FLOW 저장과 소유권 등록을 같은 D1 batch에서 처리한다. FLOW CAS가 실패하거나 파일 ID·키가 다른 진행에 이미 결속됐으면 전체 batch를 롤백하고 HTTP 503으로 실패 폐쇄한다.
- 기존 파일 ID의 저장 키는 이후 FLOW 전이에서 변경하거나 제거할 수 없다. 용도 변경과 정상적인 파일 상태 전이는 유지한다.
- 상세 조회, 파일 다운로드와 SQLite 대시보드 축소 전에 모든 파일의 원장 진행·키를 대조한다. 미등록·불일치 참조는 HTTP 503으로 격리한다.
- 기존 데이터 백필은 같은 파일 ID 또는 저장 키가 여러 진행에 나타나면 어느 한쪽을 추정하지 않는다. 충돌 항목을 원장에 등록하지 않아 관련 진행을 모두 복구 전 상태로 격리한다.
- 손상 참조가 가리키는 R2 객체는 읽거나 삭제하지 않고 그대로 보존한다.
- 기존 FLOW·R2 객체를 자동 수정하거나 삭제하지 않았다. 인증·권한과 보관·삭제 정책도 변경하지 않았다.

## 검증

- 다른 진행의 파일 ID·키 쌍을 정상 명령에 복제했을 때 FLOW 쓰기와 소유권 등록이 함께 롤백되는지 확인했다.
- 손상 payload를 직접 주입하고 충돌 안전 백필을 실행한 뒤 상세·대시보드·다운로드가 모두 HTTP 503으로 실패하는지 확인했다.
- 실제 workerd+D1+R2에서 다른 진행 소유 원장을 만든 뒤 같은 세 경로가 차단되고 외부 진행의 객체가 보존되는지 확인했다.
- 전체 Node 자동 테스트 594/594 통과.
- 격리 workerd+D1+R2 검사 402/402 통과.
- 타입검사, 전체 lint, 변경 파일 포맷 검사, `git diff --check`, 프로덕션 빌드 통과.
- 로컬 프로덕션 `/`, `/account`, `/account/setup` HTTP 200과 CSP·`DENY`·`nosniff`·`no-referrer` 확인.
- 실제 운영 쓰기, 메일 발송, 유료 AI 요청, 외부 요청 0건.

## 다음 감사

FLOW payload의 파일명·MIME·크기·용도·생성시각이 최초 저장 뒤 다른 유효값으로 바뀌어도 현재 소유권 원장은 진행과 키만 확인한다. 최초 파일 메타데이터를 권위 원장에 결속하고 상세·다운로드·대시보드·저장 전이에서 같은 사실을 검증할지 감사한다.
