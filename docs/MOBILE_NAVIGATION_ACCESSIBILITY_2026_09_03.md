# 모바일 메뉴 접근성 보완

2026-09-03. 사용자의 「다음 진행」 요청으로 실제 계정·고객자료·외부 서비스를 사용하지 않고 공통 모바일 메뉴의 키보드·화면 읽기 경계를 점검했다.

## 확인한 문제

- 기존 모바일 메뉴는 화면 위에 직접 배치한 `aside`와 배경 버튼이었다. 열린 메뉴를 대화상자로 알리는 이름·설명이 없고, 메뉴 안 초점 유지·Escape 닫기·닫은 뒤 실행 버튼 초점 복원을 공통 오버레이 동작으로 보장하지 않았다.
- 현재 화면은 배경색으로만 구분했다. 주요 메뉴와 모바일 메뉴 모두 화면 읽기 프로그램에 현재 메뉴를 전달하는 `aria-current`가 없었다.

## 변경

- 설치된 `components/ui/sheet` 기반 왼쪽 모달 메뉴로 교체했다. 제목·설명 연결, 초기 초점, 메뉴 내부 초점 유지, Escape 닫기, 닫은 뒤 초점 복원을 Base UI 동작으로 통일했다.
- 메뉴 열기 버튼에 대화상자 열림 상태와 제어 대상을 연결했다. 닫기 버튼은 Sheet 닫기 동작을 사용한다.
- 공통 메뉴 버튼을 분리하고 선택한 화면에만 `aria-current="page"`를 제공한다. 기존 권한별 메뉴 필터·저장 중 이동 차단·화면 이동 로직은 유지한다.

## 검증 경계

- 자동 테스트 241개, 타입검사, lint, 프로덕션 빌드 통과.
- 격리 workerd/D1/R2 검사 129개 통과. 실제 쓰기·메일·유료 AI·외부 요청은 0건이다.
- localhost `/` 응답은 HTTP 200이다. 사용자가 브라우저 조작 검증을 요청하지 않아 실제 Tab 순환·Escape 입력을 완료 판정하지 않았으며, 공통 Sheet의 접근성 계약과 코드 회귀검증을 확인했다.
- 서버 API, DB/R2 스키마, 공개범위, 보관·삭제 정책은 변경하지 않았다. 운영 반영 결과는 `outputs/release/mobile-navigation-accessibility-deployment.json`을 기준으로 한다.
