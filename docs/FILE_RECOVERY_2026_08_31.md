# 기존 신청으로 보관 원본 회수 — 2026-08-31

## 사용 순서

대표 계정에서 **기업별 자료함 → 원본 보관 현황 → 미연결 원본 확인 → 기존 신청 회수 조건 확인**을 연다. 파일에 이미 기록된 진행번호와 담당 계정만 확인 대상으로 제시한다. 다른 신청을 고르거나 이름으로 계정을 추정하지 않는다.

1. 표시된 기업·담당 계정 이메일·진행번호·원본 파일명을 실제 신청과 대조한다.
2. `권한 확인 후 원본 내려받기`로 기존 다운로드 경로에서 파일을 확인한다. 원본 내용의 적합성은 존재·크기 검사만으로 판단할 수 없다.
3. 확인 사유를 5~500자로 기록하고, 해당 신청과 기존 담당 파트너에게 자료를 연결한다는 확인란을 선택한다.
4. `확인한 원본 연결 회수`를 누른다. 저장 중에는 다른 자료 편집·메뉴 이동·로그아웃을 막는다.
5. 성공 안내의 `최신 운영 화면 불러오기`를 누른 뒤 자료함이나 해당 진행 기록을 확인한다. 이 단계 전에는 기존 화면으로 편집을 계속하지 않는다.

응답을 확인하지 못한 경우 현재 창의 `같은 회수 요청 다시 확인`을 사용한다. 같은 요청 ID·확인 사유·대표 계정의 재시도는 이미 저장한 결과를 반환하고 자료·이력을 추가로 만들지 않는다. 재시도 도중 사유·확인 대상을 바꾸지 않는다. 다른 창의 변경 때문에 거부되면 미저장 입력을 먼저 확인한 뒤 최신 화면에서 다시 대조한다.

## 회수 가능한 범위

- 파일 메타데이터에 기존 진행번호와 명시적 담당 계정 ID가 모두 있어야 한다.
- 실제 저장된 신청이 하나이고 그 기업명·담당 계정이 원본과 정확히 일치해야 한다. 담당 계정은 활성 상태여야 한다.
- 상담 FLOW가 있으면 기업·담당 계정도 일치해야 한다. 자료 목록이나 상담에서 이미 참조 중인 원본은 신규 회수 대상이 아니다.
- 업로드 요청이 완료 상태이거나 요청 원장 도입 전 원본이어야 한다. 대기·삭제 상태, 원본 없음·크기 불일치, 이전 회수 이력과 충돌하는 자료는 거부한다.
- 다른 신청으로 이동, 신규 신청 자동 생성, 이름에 의한 배정, DB 기록 없는 객체 복구는 지원하지 않는다. 연결값 없는 원본을 임의로 배정하지 않는다.

## 저장과 권한 보호

대표 권한과 동일 출처·확인 계정을 서버에서 검사한다. 미리보기 이후 운영 상태·원본 메타데이터·업로드 상태·상담 버전이 달라지면 저장을 거부한다. 최종 저장은 기존 상태, 파일·계정·신청 연결, 업로드 상태와 상담 참조를 다시 비교하는 D1 조건부 UPDATE 한 번으로 처리한다. 자료 목록과 확인 이력은 함께 저장되며 일부만 저장하지 않는다.

원본 파일의 재업로드·이동·삭제와 담당 계정 변경은 없다. 확인 사유·회수 시각·대표 ID·요청 ID를 자료 기록에 남기고 해당 신청의 진행 이력에도 추가한다. 이는 운영 상태에 보관되는 이력이며 별도 불변 감사 저장소는 아니다. 기존 파트너의 자료 권한 규칙은 유지한다.

원본 검사는 R2 HEAD의 존재·크기·ETag를 사용하며 본문을 분석하지 않는다. 서버의 DB 저장과 R2는 단일 트랜잭션이 아니므로 이후 별도 삭제나 저장소 장애까지 영구적으로 방지한다는 의미는 아니다. 원본 내용 확인은 대표의 수동 대조가 필요하다.

새 DB 마이그레이션 없이 기존 8개 마이그레이션과 DB/R2 바인딩을 유지한다. 공개 범위, 보관 기간, 자동 삭제 정책, AI 분석 승인과 알림 전송 규칙은 변경하지 않는다.

## 검증 기록

lint·타입검사, 자동 테스트 150개, 격리 workerd/D1/R2 검증 87개를 통과했다. 비로그인·파트너 거부, 명시적 확인, 다른 신청 연결 금지, 정상 저장과 재시도, 응답 유실 후 중복 방지, 동시 회수, 오래된 화면 저장 차단, 원본 보존, 업로드 상태·계정·상담 변경 시 조건부 저장 거부를 확인했다.

실제 운영 고객 자료·파일 본문을 조회하거나 회수하지 않았다. 이메일 전송·유료 AI 호출·격리 Worker 외부 요청은 0건이다. 브라우저 클릭 시험은 수행하지 않았다. 실제 이용 시 화면 동작과 원본 내용은 대표가 확인해야 한다.

선행 운영 버전은 42, 소스는 `8d98e9e`다. 배포 결과는 Sites 버전 이력과 로컬 `outputs/release/file-recovery-deployment.json`에 기록한다. 연결값 없는 원본의 수동 배정이나 보관 기간·삭제 정책 결정은 이번 범위에 포함하지 않는다.
