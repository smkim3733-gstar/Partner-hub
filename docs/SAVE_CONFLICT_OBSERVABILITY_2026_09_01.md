# 저장 충돌 운영 지표 고도화

2026-09-01. 사용자의 Duet 검수·구현 승인에 따라 파일럿 운영에서 저장 충돌 횟수를 확인할 수 있도록 익명 집계를 추가했다. 실제 고객 자료, 계정, 파일 원본, 요청 본문은 읽거나 기록하지 않았다.

## 구현 범위

- 운영 상태 자동저장, 공개 자가가입, 대표의 파트너 직접등록에서 발생한 `PortalStateConflict`를 모두 계측한다.
- 서버가 판정한 경로·충돌 종류·역할과 한국시간 기준 날짜, 건수, 마지막 발생 시각만 D1에 일별 집계한다.
- 사용자 ID·이메일·기업명·진행번호·요청 본문·상태 리비전·저장 페이로드는 충돌 지표에 넣지 않는다.
- 저장 용량 한도 오류는 동시편집 충돌 건수에서 제외한다.
- 지표 기록은 Worker의 `waitUntil`로 분리하고, 예약 또는 D1 쓰기가 실패해도 원래 409 응답과 화면의 입력 보존·수동 재시도 방식을 바꾸지 않는다.
- 최근 7일 집계는 대표 관리자에게만 API 최상위 필드와 대시보드 카드로 제공한다. 파트너 응답과 `PortalState`에는 포함하지 않는다.

## Duet 검수 반영

Duet은 자동저장 경로만 집계하면 자가가입·대표 직접등록 충돌이 빠진다고 지적했다. 세 경로를 모두 공용 기록 방식으로 연결하고 경로 구분을 추가했다. 실제 예외 발생 지점에 맞춰 명단 버전, 화면 버전, 회수 증적 보호, 동시 저장 반복, 미분류로 충돌 종류를 부여했다. `waitUntil` 부재나 실패가 409를 500으로 바꾸지 않도록 실패 격리와 테스트 런타임 수집기를 추가했다.

## 지표 해석 경계

- 최근 7일 건수는 충돌 발생량만 보여 준다. 복구 성공률과 재입력 시간은 아직 측정하지 않는다.
- 대표가 한 명인 현재 파일럿에서는 `admin` 역할 집계가 한 사람의 활동과 가까울 수 있다. 지표는 운영 병목 확인에만 사용하며 개인 평가 자료로 해석하지 않는다.
- 일별 집계 테이블의 보존 기간과 정리 담당은 아직 확정하지 않았다. 이 변경에서는 자동 삭제를 추가하지 않는다.
- 지표는 단일 상태 저장을 분리할지 판단하는 근거 중 하나이며, 충돌 건수만으로 자동 분할·아카이브를 수행하지 않는다.

격리 검사는 실제 운영 DB·R2·계정·메일·외부 AI를 사용하지 않았고 외부 요청도 발생시키지 않았다. Duet 최종 차이 검토는 네이티브 Windows의 고위험 샌드박스 제한으로 완료되지 않았으며 차단·중대 의견은 모두 반영했다. 사용자 승인 후 GitHub `main`과 기존 공개 Sites 버전 63에 반영했으며, DB/R2 연결과 공개 범위는 변경하지 않았다. 배포 증적은 `outputs/release/save-conflict-observability-deployment.json`에 기록한다.
