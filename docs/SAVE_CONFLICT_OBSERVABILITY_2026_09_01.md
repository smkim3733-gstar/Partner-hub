# 저장 충돌 운영 지표 고도화

2026-09-01. 사용자의 Duet 검수·구현 승인에 따라 파일럿 운영에서 저장 충돌 횟수를 확인할 수 있도록 익명 집계를 추가했다. 실제 고객 자료, 계정, 파일 원본, 요청 본문은 읽거나 기록하지 않았다.

## 구현 범위

- 운영 상태 자동저장, 공개 자가가입, 대표의 파트너 직접등록에서 발생한 `PortalStateConflict`를 모두 계측한다.
- 서버가 판정한 경로·충돌 종류·역할과 한국시간 기준 날짜, 건수, 마지막 발생 시각만 D1에 일별 집계한다.
- 사용자 ID·이메일·기업명·진행번호·요청 본문·상태 리비전·저장 페이로드는 충돌 지표에 넣지 않는다.
- 저장 용량 한도 오류는 동시편집 충돌 건수에서 제외한다.
- 지표 기록은 Worker의 `waitUntil`로 분리하고, 예약 또는 D1 쓰기가 실패해도 원래 409 응답과 화면의 입력 보존·수동 재시도 방식을 바꾸지 않는다.
- 최근 7일 집계는 대표 관리자에게만 API 최상위 필드와 대시보드 카드로 제공한다. 파트너 응답과 `PortalState`에는 포함하지 않는다.

## 24시간 익명 회수 영수증

- `PortalStateConflict`가 발생하면 32바이트 무작위 bearer 영수증을 만들고, SHA-256 해시와 서버가 판정한 경로·충돌 종류·역할·시작 시각·만료 시각만 D1에 저장한다. 평문 영수증, 계정, 이메일, 기업, 진행, 요청번호, 본문, 리비전은 저장하지 않는다.
- 영수증 행과 발급 집계가 같은 D1 batch로 성공한 경우에만 409 JSON 본문에 평문 영수증을 한 번 전달한다. 쓰기 실패 시 기존 오류 문구와 409만 반환하며 사용할 수 없는 영수증은 발급하지 않는다.
- 영수증은 24시간 동안 같은 서버 경로와 같은 서버 역할의 다음 성공 요청에서 한 번만 회수할 수 있다. 브라우저 세션 식별자는 저장하지 않으므로 영수증 자체를 가진 요청만 사용할 수 있다.
- 운영 상태 저장과 대표 직접등록 화면은 영수증을 열린 화면 메모리에만 보관하고 재시도 헤더로 보낸 뒤 성공 시 지운다. 공개 자가가입 API도 같은 응답·헤더 계약을 지원하지만 현재 저장소에는 이를 사용하는 자가가입 화면이 없어 `API 응답만`으로 표시한다.
- 응답이 유실됐지만 실제 저장은 완료된 운영 상태를 같은 내용으로 다시 확인하는 200 응답도 회수 성공으로 센다. 이때 사용자가 요청한 내용이 이미 저장돼 있기 때문이다.
- 회수 기록은 성공 응답과 분리된 `waitUntil` 작업으로 실행한다. 영수증 점유, 회수 집계, 사용된 영수증 삭제, 만료 영수증 정리가 실패해도 정상 저장·등록 응답을 바꾸지 않는다.
- 자동 삭제는 사용되었거나 24시간이 지난 익명 영수증 행에만 적용한다. 충돌·발급·회수 집계와 고객 자료의 보관 정책은 변경하지 않는다.

## Duet 검수 반영

첫 검수에서는 자동저장 경로만 집계하면 자가가입·대표 직접등록 충돌이 빠진다는 지적을 받아 세 경로를 모두 연결했다. 회수 영수증 추가 검수에서는 응답보다 늦게 영수증을 저장하면 사용할 수 없는 토큰이 생기고 성공률이 왜곡된다는 지적을 받아, DB 기록 성공 뒤에만 토큰을 반환하도록 바꿨다. 성공률은 경로를 섞지 않고 경로별 발급·회수 분모로 계산한다. 소수의 정확한 시간값이 대표 개인 활동을 드러내지 않도록 일별 평균을 만들지 않고, 경로·충돌 종류·역할별 7일 회수가 5건 이상일 때만 거친 시간 구간을 표시한다. 회수 쓰기와 관리자 읽기도 기존 지표와 같은 실패 격리를 적용했다.

## 지표 해석 경계

- 최근 7일 회수율은 DB에 정상 발급된 영수증 중 같은 경로·역할의 다음 성공 요청에서 관측된 비율이다. 브라우저 종료, 409 응답 유실, 영수증 전달 뒤 재시도하지 않은 경우는 미회수로 남으므로 실제 사용자 복구율보다 낮게 보일 수 있다.
- 시간 구간은 충돌 응답 시각부터 같은 경로의 다음 성공 요청까지다. 키보드 재입력 시간이나 업무 처리시간을 직접 측정하지 않는다.
- 대표가 한 명인 현재 파일럿에서는 `admin` 역할 집계가 한 사람의 활동과 가까울 수 있다. 정확한 개별 시간과 일별 평균은 제공하지 않고, 회수 5건 미만의 시간 구간도 숨긴다. 지표는 운영 병목 확인에만 사용하며 개인 평가 자료로 해석하지 않는다.
- 일별 충돌·발급·회수 집계 테이블의 보존 기간과 정리 담당은 아직 확정하지 않았다. 집계 자동 삭제는 추가하지 않으며, 24시간 정리는 익명 영수증 행에만 적용한다.
- 지표는 단일 상태 저장을 분리할지 판단하는 근거 중 하나이며, 충돌 건수만으로 자동 분할·아카이브를 수행하지 않는다.

격리 검사는 실제 운영 DB·R2·계정·메일·외부 AI를 사용하지 않았고 외부 요청도 발생시키지 않았다. Duet 차단·중대 의견은 모두 반영했다. 네이티브 Windows에서는 고위험 결정론 검사 샌드박스를 사용할 수 없으므로 최종 차이 검토 결과를 완전한 고위험 승인으로 표시하지 않는다. 사용자의 구체적인 공개 배포 승인 후 커밋 `9b0d4c9`를 기존 공개 범위와 DB/R2 연결을 유지한 Sites 버전 64에 반영했다. 배포 증적은 `outputs/release/conflict-recovery-receipt-deployment.json`에 기록한다.
