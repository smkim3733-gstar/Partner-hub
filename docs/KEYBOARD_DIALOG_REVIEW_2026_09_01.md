# 키보드·대화상자 후속 점검

2026-09-01. 이전 가상 화면 점검에서 남긴 키보드 조작 항목을 사용자의 「다음 진행」 요청으로 이어서 확인했다. 기존 Sites 공개 범위, DB/R2 연결, 보관 정책과 일시 중지된 자동 실행은 변경하지 않는다.

## 점검 환경 및 도구 한계

현재 빌드를 localhost의 새 메모리 전용 D1/R2에서 실행했다. 이전 운영·로컬 DB는 사용하지 않았다. 가상 이메일 계정·가상 업무·TXT 파일만 사용하고 외부 요청을 차단했다.

사이트와 별개의 최소 HTML 입력·버튼 페이지로 키보드 도구를 대조했다. Tab·Enter의 keydown/keyup 이벤트는 화면의 이벤트 기록에 나타났지만, 브라우저 기본 Tab 이동과 기본 버튼 실행은 발생하지 않았다. 같은 표준 버튼을 클릭했을 때만 실행 횟수가 0에서 1로 증가했다. 따라서 이 도구의 Enter 결과를 사이트 오류로 간주하거나, 정상 버튼에 임의의 Enter 처리 코드를 추가하지 않았다.

## 재현한 문제와 변경

- 자료 등록창과 업무 추가창을 열었을 때 초점이 창 밖의 실행 버튼에 남았다. 기존 요소는 `dialog open`이었고, DOM 확인에서 열린 상태이지만 실제 모달이 아니며 `focusInDialog: false`였다.
- 두 창을 설치된 `components/ui/dialog`를 사용하는 공통 `PortalDialog`로 연결했다. 열 때 초점 이동, 배경 접근 차단, Escape 닫기, 닫은 뒤 원래 버튼으로 초점 복원을 적용했다. 창 밖 클릭으로 닫히지 않는 기존 방식은 유지한다.
- 업로드 중에는 Escape와 닫기 버튼으로 창을 닫지 못하도록 하여 기존 취소 버튼의 저장 중 잠금과 맞췄다. 업로드·권한·저장소의 서버 로직은 바꾸지 않았다.
- 390×640 화면에서 창 상단이 -21px, 하단이 661px로 잘리는 것을 확인했다. 창 높이를 화면 높이에서 32px을 뺀 값으로 제한하고 창 내부 스크롤을 허용했다.

## 수정본에서 확인한 결과

| 동작 | 확인 결과 |
| --- | --- |
| 업무 추가창 열기 | 초점이 `업무 추가 닫기` 버튼으로 이동했다. |
| 업무 추가창 Escape | 창이 닫히고 `업무 추가` 버튼으로 초점이 복원됐다. |
| 자료 등록창 열기 | 초점이 창 안으로 이동하고 배경 콘텐츠가 접근성 트리에서 숨겨졌다. |
| 자료 등록창 Escape | 창이 닫히고 `자료 등록` 버튼으로 초점이 복원됐다. |
| 업로드 응답 15초 지연 | Escape 후에도 창이 1개 유지되고 닫기 버튼은 비활성이었다. |
| 가상 파일 저장 완료 | 창이 정상적으로 닫히고 자료 카드가 1개 표시됐다. |
| 가상 업무 저장 완료 | 업무 카드가 1개 표시되고 `업무 추가` 버튼으로 초점이 돌아왔다. |
| 390×640 창 크기 | 상단 16px, 하단 624px, 표시 높이 608px로 화면 안에 들어왔다. |
| 아래쪽 취소 버튼 접근 | 초점을 보냈을 때 창 스크롤이 74px 이동하여 취소 버튼이 564~608px 범위에 표시됐다. |

Tab·Shift+Tab 이벤트 뒤 초점이 창 안에 있는 것은 확인했지만 표준 Tab 순환 자체는 도구의 기본 동작 한계 때문에 검증 완료로 표시하지 않는다. 일반 버튼의 Enter 실행·전체 메뉴·신청 단계의 키보드 전용 왕복과 모든 대화상자의 접근성 전수 검증도 완료로 표시하지 않는다. 이번 수정 범위는 재현한 자료 등록창과 업무 추가창이다.

## 검증 및 운영 반영

- Node 테스트 183개, 타입검사, lint, 최종 빌드 통과. 서버 로직과 DB 스키마 변경은 없으므로 기존 110개 저장소 회귀검증을 이번 화면 변경 때문에 반복 실행하지 않았다.
- `outputs/validation/keyboard-first-pass.json`, `keyboard-pilot-runtime.json`, `keyboard-node-tests.log`, `keyboard-build.log`에 가상 런타임·검사 결과를 기록한다. 외부 요청 0건이며 실제 고객 자료·계정·메일·유료 AI는 사용하지 않았다.
- 확정된 운영 반영 상태는 `outputs/release/keyboard-dialog-deployment.json`을 기준으로 한다. 기존 사이트만 사용하고 가상 계정·자료·점검 보조 페이지는 배포하지 않는다.
