# 원본 보관 현황 객체 무결성 진단

기준일: 2026-09-05

## 확인한 문제

버전 163의 대표 전용 원본 보관 현황은 R2 `head`로 존재와 크기만 확인했다. 신규 기업자료에 ETag·고정 MIME 원장이 생겼어도 같은 크기 바이트 교체, 객체 MIME 교체, 무결성 원장 누락을 화면에서 정상 존재와 같은 방식으로 표시했다. 실제 다운로드와 AI 입력은 차단됐지만 대표의 복구 판단 화면이 원인을 충분히 설명하지 못했다.

## 적용한 진단

- 원본 확인 응답에 `integrityMode`와 `integrityMatches`를 추가했다. 허용값·존재·크기 관계를 클라이언트 응답 경계에서 함께 검증한다.
- 기업 원본 메타데이터가 있는 경우 R2 본문을 읽지 않고 저장 키·크기·고정 MIME·ETag 원장을 `head` 결과와 대조한다.
- 신규 `etag` 원본은 ETag·MIME 확인, 기존 `metadata` 원본은 크기·MIME만 확인됐음을 구분해 표시한다.
- 원장 누락·잘못된 원장·동일 크기 바이트 교체·객체 MIME 교체는 `객체 무결성 원장 불일치`와 사용 중지·복구 필요 안내로 표시한다.
- R2 객체 자체가 없으면 기존처럼 원본 없음으로 표시한다. 아직 기업 원본 메타데이터가 없는 업로드 대기 요청은 무결성을 추정하지 않는다.
- 관리자 전용 권한, 페이지당 25건 제한, 비공개 응답 헤더, 저장 키·원문·R2 본문 비노출, 자동 삭제·자동 복구 금지는 유지한다.

## 검증

- 정상 기존 원본은 `metadata` 확인, 정상 신규 원본은 실제 workerd R2 ETag 확인으로 표시되는지 확인했다.
- 같은 크기 바이트 교체는 크기 일치와 별개로 ETag 불일치가 표시되는지 확인했다.
- 객체 MIME 교체와 무결성 원장 누락이 불일치로 표시되는지 확인했다.
- 크기 불일치·원본 없음·업로드 대기 요청의 기존 의미와 응답 관계가 유지되는지 확인했다.
- 확인 과정이 R2 `get`·`put`·`delete`, 포털 상태 쓰기, 기업 원본 원장 쓰기를 수행하지 않는지 확인했다.
- 전체 Node 자동 테스트 607/607 통과.
- 격리 workerd+D1+R2 검사 417/417 통과. 실제 운영 쓰기, 메일 발송, 유료 AI 요청, 외부 요청 0건.
- 타입검사, 전체 lint, 변경 파일 포맷 검사, `git diff --check`, 프로덕션 빌드 통과.
- 로컬 프로덕션 `/`, `/account`, `/account/setup` HTTP 200과 CSP·`DENY`·`nosniff`·`no-referrer` 확인.

## 남은 경계

기존 `metadata` 원본은 ETag가 결속되지 않아 같은 크기 바이트 교체를 식별할 수 없다. 화면은 이 제한을 `기존 원본: 크기·MIME만 확인`으로 명시한다. 실제 객체를 읽어 기존 원본의 ETag나 해시를 결속하는 운영 이관은 별도 승인·백업·복구 계획 없이 자동 실행하지 않는다.

다음 자동 감사는 보관 목록의 DB 분류 단계에서도 기업 원본 무결성 원장 누락·구조 불일치를 `메타데이터 확인 필요`로 드러내는지 확인한다.
