# AI 진단 실행 신원 필드 envelope 무결성 경계

기준일: 2026-09-05

## 문제

Step 0 API는 요청 ID·진행 ID·기업을 제한하고 클라이언트 응답도 지침·모델 길이를 검사하지만, 실행 원장 저장 함수와 D1 직접 삽입은 비어 있지 않은 문자열만 요구했다. 과도하게 긴 진행·기업·모델·실행자 값이나 API에서 허용하지 않는 요청 ID가 원장에 들어오면 조회 응답이 거절되고 멱등 잠금과 감사 신원의 의미가 흐려질 수 있었다.

## 적용

- 공용 실행 필드 상한을 요청 ID 100자, 진행 ID 120자, 기업 100자, 지침 100자, 모델 200자, 실행자 256자로 정의했다.
- 요청 ID는 API와 동일한 영문·숫자·밑줄·하이픈 16~100자만 허용한다.
- 실행 잠금 저장 함수가 D1 접근 전에 모든 신원 필드를 검증한다.
- AI 준비상태와 생성 API는 200자를 초과한 모델 환경값을 미설정 상태로 취급하고 외부 AI 요청을 보내지 않는다.
- `0036_ai_diagnosis_run_field_envelope.sql`과 런타임 준비 트리거가 신규 D1 직접 삽입에도 같은 길이·요청 ID 계약을 강제한다.
- 기존 실행 원장은 바꾸지 않고 이후 신규 실행만 보호한다.

## 검증

- 저장 함수는 안전하지 않은 요청 ID와 여섯 필드의 상한 초과를 D1 쓰기 전에 모두 거절한다.
- D1 직접 삽입도 동일한 여섯 경계를 모두 거절한다.
- 200자 초과 모델 설정은 원본 검증 뒤에도 외부 AI 호출 전에 HTTP 503으로 종료된다.
- 37개 추가형 마이그레이션을 기존 상태가 있는 격리 D1에 반복 적용해도 기존 상태를 교체하지 않는다.
- Node 회귀 검사 642/642 통과
- 격리 workerd/D1/R2 검사 448/448 통과
- 타입검사, 전체 lint, 변경 파일 포맷, 프로덕션 빌드 통과
- 로컬 운영 Worker `/`, `/account`, `/account/setup` HTTP 200과 CSP, `X-Frame-Options: DENY`, `nosniff`, `no-referrer` 확인
- 실제 운영 쓰기, 이메일 발송, 유료 AI 요청, 외부 요청 0건
