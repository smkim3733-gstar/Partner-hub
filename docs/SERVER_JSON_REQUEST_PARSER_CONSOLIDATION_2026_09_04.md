# 서버 JSON 요청 파서 통합

## 목적

서버의 남은 JSON 요청 처리 경로를 기존 공용 스트림 경계로 통합했다. 비슷해 보이지만 JSON이 아닌 미디어 유형, 잘못된 `Content-Length`, 선언 크기와 실제 수신 크기를 벗어난 본문, JSON 객체가 아닌 값이 인증 이후의 업무 처리나 저장으로 넘어가지 않도록 한다.

## 적용 범위

- 협업신청 임시저장: 최대 40,000바이트
- 원본 회수 확정: 최대 5,000바이트
- 상담 FLOW JSON 명령: 최대 400,000바이트
- 사이트 비밀번호 인증 요청: 최대 12,000바이트
- 상담 FLOW와 기업자료의 멀티파트 업로드: 별도 스트림 크기 경계 유지

`application/json`과 매개변수가 붙은 정상 JSON 미디어 유형만 허용한다. `application/jsonx`, JSON 문자열이 매개변수에 들어간 일반 텍스트, 멀티파트를 JSON으로 오인하지 않는다. `Content-Length`는 숫자로 선언된 경우에만 인정하고 선언값과 실제 스트림을 각각 제한한다.

## 호환성과 운영 경계

공용 JSON 오류를 각 경로의 기존 오류 형식과 HTTP 상태로 변환한다. 비밀번호 입력의 사용자 안내 문구, 상담 FLOW 오류 응답, 기존 인증·권한·동일 출처 검사는 유지한다. D1/R2 스키마, 데이터 보관·삭제 정책, 운영 계정과 파일에는 변경이 없다.
