# 상담 FLOW 정확 객체 구조·공개 투영 무결성 경계

기준일: 2026-09-05

## 확인한 문제

FLOW 구조 검증은 필수 필드의 값과 타입을 확인했지만 정의되지 않은 추가 속성을 거절하지 않았다. 상세 응답은 저장 객체를 펼쳐 공개 객체를 만들었기 때문에, 향후 내부 전용 필드가 추가되거나 손상된 D1 payload에 미정의 필드가 들어오면 그대로 응답에 포함될 수 있었다. 대시보드는 SQLite에서 보고서·녹취·감사·작업 등 큰 내부 필드를 제거한 뒤 축소 구조만 검사해, 제거된 중첩 객체의 추가 속성을 발견하지 못했다.

## 적용한 경계

- FLOW 최상위 객체와 보고서·파일·분석·상담·녹취·서류요청·결정·계약·입금·사후관리·AI·작업·감사·명령 영수증에 허용 키 목록을 고정했다.
- 저장 원문, 공개 상세 응답, SQLite 축소 대시보드 각각의 실제 구조에 맞는 정확 키 계약을 사용한다.
- 공개 상세 응답은 원본 객체 펼치기를 중단하고 허용된 키만 새 객체로 복사한다. 파일 저장 키와 내부 명령 ID·영수증 비공개 처리도 유지한다.
- SQLite 축소 전에 제거되는 보고서·파일·녹취·작업·감사·명령 영수증은 별도 의미 검사에서 미정의 키를 찾는다.
- 미정의 속성이 있는 손상 행은 상세 조회와 대시보드 모두 HTTP 503 관리자 복구 상태로 격리한다.
- D1 스키마, R2 파일, 인증·권한, 보관·삭제 정책은 변경하지 않았다.

## 검증

- 최상위, 보고서, 감사 객체의 추가 속성을 상세 조회와 대시보드가 모두 거절한다.
- 원본 FLOW 객체에 최상위·보고서·파일·AI 추가 필드를 주입해도 공개 응답 투영에서 모두 제거한다.
- 실제 workerd+D1에서 SQLite 축소로 사라지는 보고서·감사 추가 필드를 상세 조회와 대시보드가 동일하게 차단한다.
- Node 자동 테스트 589/589 통과.
- 격리 workerd+D1+R2 검사 381/381 통과.
- 타입검사, 전체 lint, 변경 파일 포맷 검사, 프로덕션 빌드 통과.
- 로컬 프로덕션 `/`, `/account`, `/account/setup` HTTP 200과 CSP·`DENY`·`nosniff`·`no-referrer` 확인.
- 실제 운영 쓰기, 메일 발송, 유료 AI 요청, 외부 요청 0건.

## 다음 감사

FLOW 파일 메타데이터의 저장 크기가 실제 업로드 정책 상한을 초과해도 구조 검증을 통과하는지 확인한다. 목적별 허용 크기와 D1/R2 원본 대조 경계를 재사용해, 손상되거나 비현실적인 크기가 상세 응답·다운로드 판단·대시보드 계산으로 전달되지 않게 한다.
