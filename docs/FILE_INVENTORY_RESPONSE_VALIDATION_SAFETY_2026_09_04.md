# 원본 보관 현황 응답 검증 안전성

2026-09-04 기준으로 대표 전용 원본 보관 목록과 원본 존재 확인 API 응답의 클라이언트 검증을 보강했다.

## 변경 범위

- 성공 응답을 `unknown`으로 읽고 일반 JSON 객체인지 먼저 확인한다.
- 보관 목록은 페이지당 최대 25건, 고유 파일 ID, 허용된 보관 상태, 요청한 필터와 각 항목 상태의 일치를 검증한다.
- 파일명·기업명·자료명·자료종류·업로더·담당·진행 연결값의 형식과 길이, 파일 크기·생성시각·직접 연결 표시를 검증한다.
- 다음 페이지 커서는 최대 길이와 base64url 문자 범위를 확인한다.
- 원본 존재 확인은 응답 파일 ID가 사용자가 누른 파일 ID와 같은지 확인한다.
- 원본 존재 여부, 실제·기록 크기와 크기 일치값의 관계를 검증한다. 원본이 없는데 크기나 일치 판정이 있거나 비교할 기록 크기가 없는데 일치 판정이 있으면 차단한다.
- 검증된 공개 필드만 새 객체로 반환한다. 저장소 키 등 알 수 없는 응답 필드는 화면 상태로 전달하지 않는다.
- 실패 응답은 길이가 제한된 서버 안내만 유지한다. 비-JSON 또는 손상된 성공 응답은 처음부터 다시 조회하도록 안내한다.

## 유지한 안전 경계

- 서버의 대표 관리자 인증, 목록 필터·키셋 페이지네이션, D1 조회와 R2 `head` 기반 메타데이터 확인은 변경하지 않았다.
- 원본 본문을 읽거나 R2 객체·D1 기록·포털 상태를 수정하지 않는다.
- 기존 원본 회수 절차, 복구 확인, 보관·삭제 판단과 권한 정책은 변경하지 않았다.
- 운영 데이터, 실제 계정, D1/R2 스키마와 공개 배포 상태를 변경하지 않았다.

## 검증

- 자동 테스트 381개
- 격리 workerd/D1/R2 검사 129개
- TypeScript 타입검사, 전체 lint, 프로덕션 빌드
- localhost `/` HTTP 200

모든 신규 응답 검사는 가상 메타데이터와 합성 응답으로 실행했다. 실제 원본 조회·운영 쓰기·메일·유료 AI·외부 요청은 0건이다. GitHub 푸시와 공개 Sites 배포는 사용자 승인 전까지 수행하지 않는다.
