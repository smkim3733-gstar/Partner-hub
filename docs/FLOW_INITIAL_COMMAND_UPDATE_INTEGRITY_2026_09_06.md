# 상담 FLOW 최초 명령 전이 무결성

기준일: 2026-09-06

## 문제

상담 FLOW가 아직 저장되지 않은 상태에서 첫 사용자 명령을 처리하면 애플리케이션은 빈 revision 0에서 명령 결과 revision 1을 만든 뒤 그 결과를 D1에 직접 삽입했다. 애플리케이션 커밋 검사는 21개 명령의 정확한 효과를 확인했지만, D1의 명령별 정밀 효과 트리거는 모두 `BEFORE UPDATE`에 적용돼 첫 명령의 직접 `INSERT`에는 실행되지 않았다. 기존 D1 삽입 트리거가 명령 개수·영수증·행위자·변경 범위를 검사했으나, 각 명령의 생성자·서버시각·정규 필드·감사문구까지 확인하는 후속 revision과 방어 깊이가 달랐다.

실패 우선 검사로 정상 형식의 첫 `save_report` 명령이 포함된 revision 1 루트를 D1에 직접 삽입할 수 있음을 재현했다.

## 적용한 경계

- 추가형 `0092_consulting_flow_initial_command_update.sql` 트리거는 `commandIds`가 하나 이상인 FLOW 루트의 직접 `INSERT`를 모두 거절한다.
- 첫 명령 저장은 빈 revision 0 기준선을 먼저 삽입하고, 같은 D1 `batch` 안에서 revision 1로 갱신한다.
- 갱신에는 기존 revision과 포털 상태 스냅샷 조건을 그대로 적용한다. 동시 요청에서 먼저 저장된 명령을 나중 요청이 덮어쓰지 않는다.
- 기준선 삽입과 명령 갱신, 신규 첨부 소유권·메타데이터·R2 객체 증거 원장은 한 배치에서 처리한다. 어느 단계든 실패하면 기준선도 남지 않는다.
- 첫 명령도 후속 명령과 동일한 21개 전용 D1 효과 트리거를 통과한다.
- 명령 없는 기존 초기 저장과 이미 저장된 FLOW의 후속 revision 동작은 바꾸지 않는다.

## 누락 재발 방지

21개 지원 명령을 `FLOW_COMMAND_EXACT_EFFECT_TRIGGERS`에 타입으로 완전 매핑했다. 런타임 D1 초기화도 이 매핑에서 전용 트리거를 등록한다. 새 회귀검사는 다음 네 집합이 정확히 일치하는지 확인한다.

1. 명령별 핵심 효과 경로
2. 애플리케이션의 명령별 정밀 커밋 검사
3. D1의 명령별 전용 효과 트리거
4. `0071`~`0091` 추가형 마이그레이션

새 명령을 효과 경로에 추가하면서 앱 검사, D1 트리거 또는 마이그레이션을 빠뜨리면 자동 테스트나 타입검사가 실패한다.
