# AI 진단 사전점검 자료 연결 점검

2026-09-01. 사용자의 별도 `다음 진행` 요청에 따라 AI 진단 사전점검의 자료 선택과 대기열 등록 경계를 점검했다. 완료된 자동 점검 3항목은 재개하지 않았고 실제 고객 자료·외부 AI 호출은 사용하지 않았다.

## 재현과 수정

기존 판정은 기업명이 같은 제출완료·검토완료 자료를 모두 근거로 포함했다. 같은 기업이 여러 번 신청했거나 담당 계정이 다른 경우에도 자료의 진행 ID·담당 계정을 확인하지 않아, 다른 진행 자료로 사업자등록증·재무 근거가 통과할 수 있었다. 또한 화면에 저장된 A 판정 뒤 자료가 바뀌어도 `1차 초안 검토대기 등록` 시 최신 자료로 재판정하지 않았다.

- 판정 근거 자료를 저장된 진행 ID와 담당 계정 ID로 선택한다. 같은 기업명의 반복 신청과 다른 담당 계정 자료를 섞지 않는다.
- 진행 ID가 없는 과거 자료는 같은 기업·담당 계정의 진행이 하나로 확정되는 경우에만 사용한다. 모호한 자료를 임의 배정하지 않는다.
- `제출완료`·`검토완료` 자료만 판정 근거로 인정한다. `요청중`·`보완필요`는 제외한다.
- 1차 초안 검토대기 등록 직전에 현재 자료로 다시 판정한다. 최신 결과가 A가 아니면 대기열·타임라인·업무를 만들지 않고 화면 판정을 갱신한다.

AI 제공자·모델·비용·동의 정책, 실제 외부 전송, DB/R2 구조와 보관 정책은 변경하지 않았다.

## 가상 회귀 검증

같은 이름의 가상 기업에 동일 담당자의 반복 진행 2건과 다른 담당자의 진행 1건을 만들었다. 대상 진행의 연결 자료 1건만 판정 근거로 선택됐고, 다른 반복 진행·다른 담당·모호한 과거 자료는 제외됐다. 진행이 하나뿐인 경우에는 같은 담당 계정의 과거 자료를 사용할 수 있었으며 요청중·보완필요 자료는 제외됐다. 입력 배열은 변경되지 않았다.

- 전체 Node 검사 197개, 타입검사, lint, 빌드가 통과했다.
- 서버 API·DB 스키마를 바꾸지 않아 기존 workerd/D1/R2 저장소 검사 110개는 반복하지 않았다.
- 검사·빌드 로그는 `outputs/validation/diagnosis-preflight-tests.log`, `diagnosis-preflight-build.log`에 남겼다.
- 사용자 지침에 따라 브라우저 클릭 시험과 외부 AI 호출은 수행하지 않았다.
- 운영 반영 상태는 `outputs/release/diagnosis-preflight-deployment.json`에 기록한다. 기존 공개 사이트, D1/R2 연결, 추가형 마이그레이션 8개를 유지한다.
