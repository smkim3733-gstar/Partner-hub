# 상담 FLOW R2 쓰기 중 표시명 변경 경쟁 무결성

기준일: 2026-09-07

## 확인한 위험

파트너의 전사문·음성 2슬롯 업로드가 첫 R2 객체만 저장한 채 실패한 뒤 정확한 재시도를 시작했을 때, 재시도의 R2 객체 쓰기 사이에 대표가 파트너 표시명을 변경하면 현재 프로필 표시와 기존 상담 이력의 행위자 표시를 혼동하거나 같은 예약의 안전한 완료를 잘못 차단할 위험이 있다.

## 확인한 현재 경계

- 첫 전사문 객체 저장 성공과 두 번째 음성 저장 실패로 두 `pending` 예약이 남은 상태를 결정적으로 재현했다.
- 같은 명령 ID·본문·첨부의 정확한 multipart 재시도에서 첫 전사문 R2 쓰기가 완료된 직후 실제 관리자 상태 저장 경로로 파트너 표시명을 변경했다.
- 표시명은 권위 신원 키가 아니다. ChatGPT 안정 사용자 ID와 회원 ID 결속은 유지되고 두 번째 음성 객체가 기존 예약 키에 기록된 뒤 최종 인증·담당 접근·업로드 권한 및 생명주기 재검사를 통과한다.
- 정확한 재시도는 FLOW, 명령 영수증, 두 `ready` 예약과 완료 원장을 같은 파일 ID·R2 키로 한 번만 커밋한다.
- 현재 회원 프로필은 변경된 표시명을 유지한다. 완료 명령의 `actorKey`는 안정 회원 ID이고 FLOW 불변 담당자, 명령 영수증과 감사 행위자 표시는 기존 상담 시작 당시 표시명을 보존한다.
- 프로필 변경은 동일 인물의 현재 표시만 갱신하며 기존 상담의 책임 주체와 감사 이력을 소급 변경하지 않는다.

기존 구현이 안정 회원 ID 결속, R2 객체 쓰기 뒤 최종 접근 재검사와 기존 상담 표시 보존 경계를 갖춰 요구 조건을 만족한다. 런타임 코드는 바꾸지 않고 R2 쓰기 도중 실제 표시명 변경 경쟁 회귀 증거를 추가했다.
