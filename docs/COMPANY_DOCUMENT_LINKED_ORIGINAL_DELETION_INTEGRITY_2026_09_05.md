# 기업자료 연결 원본 삭제 무결성 경계

기준일: 2026-09-05

## 확인한 문제

기업자료 원본 삭제 API는 현재 계정 권한과 최신 포털 상태를 다시 확인했지만, 원본 ID가 이미 `companyDocuments` 카드에 연결되어 있는지는 삭제 조건으로 사용하지 않았다. 화면 밖 직접 요청은 포털 카드를 남긴 채 D1 파일 메타데이터·담당·진행 연결과 R2 원본을 삭제할 수 있었다.

일반 상태 저장은 기존 카드의 원본 연결 제거를 막으므로, 파일 삭제 API도 같은 보존 경계를 사용해야 카드와 원본 사이의 단방향 단절을 막을 수 있다.

## 적용한 경계

- 삭제 권한을 확인한 뒤 최신 포털 상태의 기업자료 카드가 해당 `storageFileId`를 참조하면 HTTP 409로 거절한다.
- 같은 참조 부재 조건을 D1 삭제 결정문 안에도 넣었다. 조회 뒤 다른 요청이 카드를 연결하면 기존 전체 상태 CAS와 결합해 삭제 결정을 확정하지 않는다.
- 삭제 결정이 먼저 원장에 기록되면 새 카드 연결의 D1 커밋 조건이 `deleted` 상태를 확인해 저장을 거절한다. 카드 저장이 먼저 끝나면 파일 삭제의 상태 CAS와 참조 부재 조건이 삭제를 거절한다.
- 거절 시 D1 파일 메타데이터·담당 계정·진행 연결, 업로드 완료 원장과 R2 바이트를 모두 보존한다.
- 아직 포털 카드에 연결되지 않은 업로드 원본의 기존 명시 삭제, 응답 유실 재시도, 동시 삭제 멱등성, 업로드 처리 중 충돌과 레거시 삭제 재시도는 유지한다.
- 기존 운영 원본이나 카드의 자동 삭제·분리·이관, D1/R2 스키마와 보관 정책 변경은 수행하지 않았다.

## 검증

- 수정 전 재현: 저장된 카드가 참조하는 원본의 직접 삭제가 204로 성공하고 카드만 남았다.
- 수정 후: 같은 요청은 409로 실패하고 D1 파일·담당·진행 연결과 R2 원본이 남는다.
- 삭제 결정 직전에 포털 카드가 연결되는 경쟁에서도 삭제를 거절하고 카드와 원본을 함께 보존한다.
- 반복 신청의 두 진행·두 원본은 각각 유지되며 연결 원본 직접 삭제가 진행 연결을 지우지 않는다.
- 미연결 원본 삭제, 동시 삭제, 삭제 실패 재시도와 권한·정지 경쟁 검사는 계속 통과한다.
- Node 자동 테스트 558/558 통과.
- 격리 workerd+D1+R2 검사 347/347 통과.
- 타입검사, 전체 lint, 프로덕션 빌드 통과.
- 로컬 프로덕션 `/`, `/account`, `/account/setup` HTTP 200과 CSP 확인.
- 실제 운영 쓰기, 메일 발송, 유료 AI 요청, 외부 요청 0건.

## 다음 감사

원본 다운로드가 D1 파일 원장과 R2 실제 객체의 크기·삭제 상태를 응답 직전에 다시 대조하는지 점검한다. 손상되거나 교체된 크기의 바이트를 원본으로 제공하지 않도록 하되 본문 해시를 새로 저장하거나 기존 원본을 자동 수정·삭제하지 않는다.
