# 변경 요청 Origin 필수 보안 경계

기준일: 2026-09-05

## 확인한 문제

공용 변경 요청 출처 판별은 `Origin`이 있을 때만 현재 요청 URL과 비교했다. 따라서 ChatGPT 플랫폼 인증 헤더가 유효한 상태에서 `Origin`과 교차 사이트 fetch 메타데이터가 모두 없는 합성 요청은 동일 출처가 증명되지 않았는데도 포털 상태 변경 경계를 통과할 수 있었다. 수정 전 회귀 재현에서는 유효한 관리자 인증으로 `Origin` 없는 상태 저장 요청이 HTTP 200을 반환했다.

## 적용한 경계

- 변경 요청은 `Origin`이 반드시 존재하고 `new URL(request.url).origin`과 정확히 같아야 한다.
- `Sec-Fetch-Site: cross-site`는 일치하는 `Origin`과 무관하게 추가로 거절한다.
- ChatGPT 헤더 인증과 사이트 비밀번호 쿠키 인증에 같은 공용 출처 경계를 적용한다.
- 일반 브라우저의 동일 출처 POST·PUT·DELETE 요청은 기존처럼 동작한다. 인증·본문 형식·권한 같은 후속 조건을 시험하는 합성 테스트에는 브라우저가 보내는 동일 출처 `Origin`을 명시했다.
- 비밀번호 자격 경로의 HTTPS·동일 출처 검사, 인증·권한·CAS·멱등성·D1/R2 저장 경계는 유지한다.

## 검증

- 수정 전: 유효한 ChatGPT 관리자 인증 + `Origin` 없는 상태 PUT이 HTTP 200으로 재현됐다.
- 수정 후: 같은 요청은 저장 전에 HTTP 403으로 차단된다.
- Node 회귀 테스트 485/485 통과.
- 격리 workerd+D1+R2 검사 179/179 통과. 운영 쓰기·이메일·유료 AI·외부 요청은 모두 0건이다.
- 타입검사, 전체 lint, 프로덕션 빌드 통과.
- 로컬 운영 Worker의 `/`, `/account`, `/account/setup` 모두 HTTP 200.

## 저장 상태

기능 커밋 `269449679e7423abdc00a7afa2a94a96abcc24df`를 GitHub `main`과 Sites 소스 저장소에 반영했다. 같은 커밋의 검증된 빌드 산출물을 Sites 버전 118 (`appgprj_6a92514801988191b79eb9bd314e3fcd~appgver_2227582f063c8191ae8656211d639c0e`)로 저장했다.

현재 공개 운영본은 버전 107이다. 버전 108~117은 버전 118로 대체하며 공개 배포하지 않는다. 버전 118도 정확한 운영 배포 승인 전까지 저장 상태로 유지한다. D1 스키마, R2 연결, 공개 범위, 데이터 보관·삭제 정책은 변경하지 않았다.
