# 상담 FLOW 신청자료 목적지 복사 후 원본 경쟁 무결성

기준일: 2026-09-07

## 확인한 경계

대표가 검토한 신청자료 바이트를 안정 예약 키의 목적지 R2 객체에 쓰는 동안 원본이 삭제되거나 교체될 수 있다. 목적지 쓰기 직후부터 마지막 FLOW 접근 검사와 최종 D1 커밋 전까지 원본이 달라지면 오래된 검토본을 FLOW에 확정하면 안 된다. 이미 만들어진 목적지 객체와 `pending` 예약은 모호한 R2 결과의 기존 복구 정책에 따라 보존해야 한다.

## 발견·수정

- 버전 306은 예약 완료 뒤 원본을 다시 확인하고 목적지 R2 쓰기를 시작했다. 쓰기가 끝난 뒤에는 FLOW 접근만 검사하고 원본 스냅샷은 다시 확인하지 않았다.
- 목적지 객체 저장 직후 원본 삭제 tombstone을 만들고 최종 FLOW 쓰기 배치를 차단한 수정 전 회귀는 현재 원본 부재 404 대신 일반 저장 오류 500을 반환했다. 이는 원본 삭제 뒤에도 최종 FLOW 커밋 경로에 도달했음을 증명한다.
- 신청자료 목적지 R2 쓰기가 성공한 직후 현재 기업자료 행·표시 상태·담당 결속·최신 무결성 원장·R2 `head`를 다시 대조한다. 저장 직후 삭제는 404로 끝난다.
- 마지막 FLOW 접근 검사는 비동기 D1 작업이다. 검사 직후 같은 원본 스냅샷을 한 번 더 대조해 검사 중 같은 키·MIME·크기로 교체된 R2 객체를 ETag 불일치 409로 차단한다.
- 두 경쟁 모두 최종 FLOW 쓰기 배치 0회, FLOW 0건이다. 이미 생성된 목적지 객체 1개와 불변 파일 ID·키의 예약 1건은 `pending`으로 보존해 현재 상태 조사와 정확 재시도에 사용한다.
- 이 보강은 목적지 쓰기와 마지막 접근 검사에서 생기는 비동기 창을 닫는다. 최종 원본 재검증 직후부터 FLOW D1 쓰기 배치 안에서 발생하는 D1 tombstone 경쟁은 다음 감사 대상으로 분리한다.
