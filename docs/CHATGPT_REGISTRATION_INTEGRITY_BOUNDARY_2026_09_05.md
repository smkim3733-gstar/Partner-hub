# ChatGPT 가입 계정 상태 무결성 경계

2026-09-05 기준. ChatGPT 인증 사용자의 자가가입 재시도가 대표가 정지한 계정 상태와 회원 명단 revision을 바꾸지 않도록 가입 경계를 보완했다.

## 확인한 위험

- 정지 계정과 같은 검증 이메일로 다시 가입하면 `정지`가 `승인대기`로 바뀔 수 있었다.
- 이미 승인대기인 사용자가 같은 내용을 다시 보내도 회원 명단을 다시 쓰고 revision을 증가시켰다.
- 공개 ChatGPT 가입 경로에는 비밀번호 가입과 같은 반복 요청 제한이 없었다.

## 적용한 경계

- `활성` 계정은 기존처럼 중복 가입을 거절한다.
- `정지` 계정은 HTTP 403으로 거절하고 저장된 상태·권한·회원 명단 revision을 유지한다. 대표 승인 없이 `승인대기`로 되돌리지 않는다.
- 기존 `승인대기` 계정의 이름·전화번호·소속·검증 이메일이 모두 같으면 기존 상태를 그대로 반환한다. 저장과 revision 증가는 발생하지 않는다.
- 변경된 가입 정보가 있거나 초대대기 상태인 경우에만 기존 승인대기 갱신 규칙을 적용한다.
- 동일 출처 확인과 ChatGPT 신원 검증 뒤, 요청 본문을 읽거나 포털 상태를 쓰기 전에 반복 요청을 제한한다.
- Cloudflare 접속 IP는 15분당 30회, 안정적인 ChatGPT 사용자 ID는 IP 변경과 무관하게 15분당 8회까지 허용한다. 초과 응답은 HTTP 429와 `Retry-After: 900`을 반환한다.
- 제한 저장소에는 IP·사용자 ID·이메일 평문 대신 목적·대상 종류·값의 단방향 해시만 기록한다.
- 기존 비밀번호 로그인 제한 키의 `login:email:` 이름을 유지해 배포 시 누적 제한 상태가 초기화되지 않도록 했다.

## 검증

- Node 자동 테스트 467개 통과.
- 격리 workerd/D1/R2 검사 142개 통과.
- 타입검사, 전체 lint, 프로덕션 빌드 통과.
- 로컬 운영 빌드에서 `/`, `/account`, `/account/setup` HTTP 200과 화면 보안 헤더를 확인했다.
- 보호 API `/api/state`, `/api/admin/file-inventory`, `/api/consulting-flow/test-case`는 익명 요청에 HTTP 401과 `private, no-store, max-age=0`을 반환했다.
- 실제 운영 데이터 쓰기, 메일 발송, 유료 AI 호출, 외부 요청은 0건이다.

## 운영 영향

- 기존 회원 기록을 삭제하거나 일괄 재계산하지 않는다.
- DB 스키마, 계정 권한, 보관·삭제 정책은 변경하지 않는다.
- 기능 커밋 `ef1c68db31b1277de4d4b581a4d90c8d3bf3c549`를 GitHub `main`과 Sites 소스에 반영하고 Sites 버전 109 (`appgprj_6a92514801988191b79eb9bd314e3fcd~appgver_fad67ebf1ad0819193504c6e9aa91757`)로 저장했다.
- 현재 공개 운영본은 Sites 버전 107이다. 버전 108은 저장만 되었으며 버전 109로 대체해 공개 배포하지 않는다. 버전 109는 사용자 명시 승인 전까지 공개 배포하지 않는다.
