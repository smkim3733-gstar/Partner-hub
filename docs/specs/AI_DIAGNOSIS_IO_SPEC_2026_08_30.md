# 파트너 허브 AI 자동진단 입력·출력 명세서

| 항목 | 내용 |
|---|---|
| 문서 버전 | 1.0.0 |
| 작성 기관 | 주식회사 한국기업가치평가원 |
| 작성자 | 김성민 대표 |
| 기준일 | 2026-08-30 |
| 적용 기능 | 협업신청 자료 판독 → Step 0 사전가설 → 1차 정밀진단보고서 초안 |
| 연계 화면 | 협업신청, 기업자료함, 기업진단보고서 준비, 컨설팅 진행 현황 |

## 1. 핵심 결론

사업자등록증·CRETOP·녹취자료가 제출되면 자동으로 자료를 읽고 1차 정밀진단보고서 **초안**을 만들 수 있다. 단, 자료 접수와 동시에 무조건 생성하지 않고 다음 3단계 자료 게이트를 먼저 적용한다.

| 수준 | 상태 | 시스템 처리 |
|---|---|---|
| A | 기업 식별자료 + 재무·신용자료 + 상담맥락 확보 | Step 0 생성 후 승인되면 1차 보고서 초안 생성 |
| B | 일부 자료 누락 또는 중요 수치 확인 필요 | Step 0만 생성하고 서류요청 자동 제안 |
| C | 동의 미확인, 악성파일, 기업 불일치, 핵심자료 판독 실패 | AI 처리를 중단하고 관리자 확인 요청 |

AI가 생성한 결과는 곧바로 파트너나 기업대표에게 공개하지 않는다. 반드시 `김성민 대표 검토 대기` 상태로 저장한다.

## 2. 적용 범위와 제외 범위

### 2.1 MVP에서 구현하는 범위

- 협업신청과 기업자료 연결
- 자료유형 자동분류
- PDF·이미지 OCR 및 녹취 변환 결과 수집
- 개인정보 마스킹
- 기업 핵심정보·재무·신용·상담요청 추출
- 근거대장 생성
- 누락자료·충돌자료 판정
- A·B·C 자료 수준 판정
- Step 0 사전가설 생성
- 대표 승인 후 1차 보고서용 구조화 JSON 생성
- DOCX 렌더링 대기 상태 저장

### 2.2 MVP에서 제외하는 범위

- AI가 견적금액을 임의로 산정하는 기능
- AI가 계약조건을 확정하는 기능
- 정책자금·인증의 승인 가능성을 확정적으로 보장하는 기능
- 세무·법률·보험상품의 최종 전문가 판단
- 고객에게 AI 초안을 자동발송하는 기능
- Claude 웹 프로젝트 화면을 자동 조작하는 방식

## 3. 전체 처리 흐름

```text
협업신청 제출
  → 파일 보안검사
  → 동의·권한 확인
  → 자료유형 분류
  → OCR·텍스트 추출·녹취 변환
  → 개인정보 마스킹
  → 핵심 필드 추출
  → 근거대장 작성
  → 누락·충돌·신뢰도 검사
  → 자료 수준 A/B/C 판정
      ├─ A: Step 0 생성 → 대표 승인 → 1차 보고서 JSON → DOCX 초안
      ├─ B: Step 0 생성 → 서류요청 제안 → 보완자료 대기
      └─ C: 처리 중단 → 관리자 보안·자료 확인
```

## 4. 접수 화면 변경사항

### 4.1 기본 입력

기존 파트너 등록정보는 유지한다.

- 이름
- 연락처
- 소속
- 이메일
- 파트너 유형: 한기평 컨설턴트, 타사 컨설턴트, 보험설계사, 기타

### 4.2 협업신청 입력

- 대상 기업명
- 대표자명
- 사업자등록번호
- 대표 연락처
- 요청 솔루션 복수선택
- 대표의 핵심 요청사항
- 상담 희망시기
- 자료제출 권한 확인
- 개인정보 처리 동의
- 제3자 AI 처리 동의
- 녹취자료 처리 동의

### 4.3 업로드 분류

| 화면 분류 | 시스템 코드 | 허용 형태 | 민감자료 기본값 |
|---|---|---|---|
| 사업자등록증 | `BUSINESS_REGISTRATION` | PDF, JPG, PNG | 예 |
| CRETOP | `CRETOP_REPORT` | PDF | 예 |
| 재무제표 | `FINANCIAL_STATEMENT` | PDF, XLSX 변환본 | 예 |
| 신용자료 | `CREDIT_REPORT` | PDF | 예 |
| 녹취 음원 | `TRANSCRIPT_AUDIO` | MP3, M4A, WAV | 예 |
| 녹취록 | `TRANSCRIPT_TEXT` | PDF, TXT, DOCX 변환본 | 예 |
| 인증·특허 | `CERTIFICATION`, `PATENT_CERTIFICATE` | PDF, JPG, PNG | 선택 |
| 법인·지분자료 | `CORPORATE_REGISTRY`, `SHAREHOLDER_LIST` | PDF | 예 |
| 정관·대출·부동산 | 자료별 코드 | PDF | 예 |
| 기타 | `OTHER` | 관리자 허용 형식 | 관리자 결정 |

DOCX와 XLSX는 Claude 문서 블록에 그대로 보내지 않고 서버에서 텍스트 또는 PDF로 변환한다.

## 5. 자료별 추출 필드

### 5.1 사업자등록증

| 필드키 | 추출값 | 필수 | 검증방법 |
|---|---|---|---|
| `company.legal_name` | 법인명·상호 | 예 | 신청기업명과 비교 |
| `company.business_number` | 사업자등록번호 | 예 | 형식검사 후 마스킹 |
| `company.representative_name` | 대표자명 | 예 | 신청정보와 비교 |
| `company.opening_date` | 개업연월일 | 예 | 날짜 형식검사 |
| `company.corporate_number` | 법인등록번호 | 해당 시 | 마스킹·별도암호화 |
| `company.business_address` | 사업장 주소 | 예 | 시·도·시군구 정규화 |
| `company.business_type` | 업태 | 예 | 원문 보존 |
| `company.business_items` | 종목 | 예 | 복수 항목 배열화 |
| `company.tax_office` | 관할세무서 | 선택 | 원문 보존 |
| `document.issue_date` | 증명서 발급일 | 선택 | 최신성 표시 |

사업자등록번호와 법인등록번호는 AI 전달용 데이터에서는 마스킹하고, 실제 문서 표제부에 필요하면 서버 템플릿 단계에서 복원한다.

### 5.2 CRETOP·신용보고서

| 영역 | 주요 추출 필드 |
|---|---|
| 기업기본 | 설립일, 업력, 기업규모, 산업분류, 본점, 사업장 |
| 대표·주주 | 대표이력, 주요주주, 지분율, 관계기업 |
| 신용 | 기업신용등급, 현금흐름등급, 등급기준일, 평가기관 |
| 위험신호 | 연체, 세금체납, 당좌거래, 휴폐업, 소송·공공정보 여부 |
| 차입·담보 | 금융기관 차입, 보증, 담보, 단기·장기차입 구성 |
| 재무 | 자산, 부채, 자본, 매출, 매출원가, 영업이익, 당기순이익, 현금흐름 |
| 비율 | 부채비율, 유동비율, 영업이익률, 순이익률, 이자보상배율 |
| 성장·안정 | 3개년 증감률, 수익성·안정성·활동성 추이 |
| 비재무 | 임직원, 인증, 특허, 연구소, 주요거래처, 수출 여부 |

모든 재무값에는 `회계연도`, `단위`, `연결·별도 여부`, `출처 페이지`를 함께 저장한다. PDF에 표시된 수치와 시스템 계산값을 분리한다.

### 5.3 재무제표

- 최근 3개년 재무상태표
- 최근 3개년 손익계산서
- 현금흐름표 또는 현금흐름 관련 가용정보
- 주요 재무비율 계산용 원천값
- 결산월
- 단위: 원·천원·백만원 중 하나
- 재무제표 종류: 연결·별도·세무조정계산서·내부자료

단위가 확인되지 않거나 서로 다른 자료의 동일 연도 수치가 다르면 `NUMERIC_CONFLICT`로 처리한다.

### 5.4 녹취자료·녹취록

| 영역 | 추출 내용 |
|---|---|
| 발화자 | 기업대표, 파트너, 한기평, 기타, 미확인 |
| 기업현황 | 주력사업, 매출구조, 거래처, 경쟁력, 계획 |
| 자금수요 | 금액, 목적, 희망시점, 기존대출·보증 |
| 인증·R&D | 보유인증, 연구인력, 연구활동, 희망인증 |
| 특허·기술 | 핵심기술, 권리화 여부, 발명자·권리자 |
| 지분·승계 | 주주, 가족관계, 후계자, 법인전환 의향 |
| CEO 자산관리 | 개인·법인 자금흐름, 퇴직·승계 고민 |
| 리스크 | 세무, 법률, 채권, 인력, 규제, 분쟁 |
| 요청사항 | 대표가 원하는 결과, 우선순위, 일정 |
| 약속·후속조치 | 요청자료, 다음상담, 담당자, 기한 |

발언 내용은 `확인된 사실`, `대표 발언`, `AI 추론`으로 구분한다. 녹취 동의가 확인되지 않으면 변환·분석하지 않는다.

### 5.5 기타 기업정밀진단 자료

- 법인등기부: 임원, 자본금, 목적사업, 변경이력
- 주주명부: 주주, 지분율, 특수관계 표시
- 대출내역: 기관, 잔액, 금리, 만기, 담보·보증
- 인증서: 인증명, 번호, 유효기간, 발급기관
- 특허: 출원·등록번호, 명칭, 출원인·권리자, 상태
- 회사소개서: 제품, 고객, 시장, 조직, 경쟁력
- 정관: 주식, 임원, 배당, 퇴직금, 주식양도 관련 쟁점
- 부동산자료: 소재지, 권리관계, 평가기준일, 활용목적

## 6. 근거대장 구조

AI가 보고서에 사용하는 모든 사실과 숫자는 `evidence_items`에 먼저 등록한다.

```json
{
  "evidence_id": "ev_2026_000123",
  "field_key": "financial.revenue",
  "value_text": "12500",
  "value_type": "NUMBER",
  "unit": "백만원",
  "period": "2025",
  "source_document_id": "doc_00045",
  "source_page": 17,
  "extraction_method": "TEXT_LAYER",
  "confidence": 0.98,
  "review_state": "UNREVIEWED"
}
```

### 6.1 근거 우선순위

1. 공식 발급자료·재무제표
2. CRETOP 등 기업신용자료
3. 법인등기부·인증서·특허문서
4. 기업대표의 녹취 발언
5. 파트너 입력·상담메모
6. AI 추론

하위 자료가 상위 자료와 충돌하면 임의로 덮어쓰지 않는다. 두 값을 모두 보존하고 사람의 확인을 요청한다.

## 7. A·B·C 자동생성 게이트

### 7.1 A등급 — 1차 초안 생성 가능

다음 조건을 모두 충족한다.

- 개인정보·제3자 AI 처리 동의 확인
- 녹취 사용 시 녹취 처리 동의 확인
- 악성파일 검사 통과
- 기업 식별자료 1종 이상 확보
- CRETOP 또는 최근 재무자료 확보
- 대표 요청사항 또는 상담맥락 확보
- 기업명·사업자번호·대표자 핵심 불일치 없음
- 핵심 재무수치 단위 확인
- 차단 수준의 미해결 충돌 없음

### 7.2 B등급 — Step 0과 보완요청까지만

다음 중 하나 이상에 해당한다.

- 사업자등록증만 있고 재무·신용자료가 없음
- CRETOP은 있으나 대표 요청사항·상담맥락이 없음
- 재무자료가 1개 연도만 존재
- 신용등급 기준일이 오래되어 최신 확인 필요
- 핵심 수치의 출처가 있으나 단위 또는 기간이 불명확
- 일부 페이지 OCR 신뢰도가 낮음
- 상담 질문을 만들 수 있으나 솔루션 우선순위 확정이 어려움

### 7.3 C등급 — 처리 중단

- 개인정보·AI 처리 동의 미확인
- 녹취 처리 동의 없이 음원 업로드
- 악성파일 탐지
- 암호화·손상 파일로 판독 불가
- 신청기업과 자료의 기업명이 명백히 다름
- 사업자번호가 서로 충돌하고 확인 근거가 없음
- 주민번호·계좌정보 등 불필요한 고위험정보가 마스킹되지 않음
- 자료소유권·제출권한이 확인되지 않음

## 8. 오류코드

| 코드 | 의미 | 처리 |
|---|---|---|
| `CONSENT_MISSING` | 개인정보·AI 처리 동의 없음 | 중단 |
| `TRANSCRIPT_CONSENT_MISSING` | 녹취 처리 동의 없음 | 해당 파일 제외 또는 중단 |
| `MALWARE_DETECTED` | 악성파일 탐지 | 격리·관리자 알림 |
| `UNSUPPORTED_FILE` | 지원하지 않는 형식 | 변환 또는 재제출 요청 |
| `ENCRYPTED_OR_CORRUPT_FILE` | 암호화·손상 파일 | 재제출 요청 |
| `OCR_FAILED` | OCR 실패 | 수동검토 또는 재스캔 요청 |
| `LOW_OCR_CONFIDENCE` | OCR 신뢰도 부족 | B등급 전환 |
| `IDENTITY_CONFLICT` | 기업명·대표자·사업자번호 충돌 | 중단·사람 확인 |
| `NUMERIC_CONFLICT` | 동일 기간 수치 불일치 | 해당 판단 보류 |
| `UNIT_UNKNOWN` | 금액 단위 불명 | B등급 전환 |
| `FINANCIAL_BASIS_MISSING` | 재무·신용 근거 부족 | Step 0만 생성 |
| `CONTEXT_MISSING` | 대표 요청·상담맥락 부족 | 질문·서류요청 생성 |
| `SENSITIVE_DATA_UNMASKED` | 불필요한 민감정보 노출 | 중단·마스킹 |
| `POLICY_SOURCE_STALE` | 정책·법령 기준일 만료 | 공식자료 재확인 |

| `POST /api/ai/diagnosis/preflight` | 자료 판독상태·동의·누락·충돌 검사 |
| `POST /api/ai/diagnosis/runs` | Step 0 또는 1차 생성 실행 |
| `GET /api/ai/diagnosis/runs/{runId}` | 실행상태·오류·결과 조회 |
| `POST /api/ai/diagnosis/runs/{runId}/approve-step0` | 대표의 Step 0 승인 |
| `POST /api/ai/diagnosis/runs/{runId}/request-revision` | 수정 요청 |
| `POST /api/ai/diagnosis/runs/{runId}/request-documents` | 누락자료를 서류요청으로 전환 |
| `POST /api/ai/diagnosis/runs/{runId}/approve-step1` | 1차 보고서 승인 |

### 9.2 입력 스키마

개발용 원본: `partner-hub-step1-request.schema.v1.json`

입력에는 원본파일의 공개 URL이나 사용자가 제출한 Anthropic `file_id`를 넣지 않는다. 서버가 권한을 확인한 뒤 내부 `server_content_ref`를 해석해 API 콘텐츠 블록을 만든다.

### 9.3 출력 스키마

개발용 원본: `partner-hub-step1-response.schema.v1.json`

Claude 응답은 구조화 출력으로 받고 서버에서 한 번 더 검증한다. 핵심질문은 정확히 10개여야 하며, 11개 장과 별첨이 빠지면 DOCX 렌더링 단계로 넘기지 않는다.

## 10. Claude API 요청 구성

### 10.1 시스템 지침 묶음

```text
CORE_RULES
  한기평 정체성, 보안, 면책, 금지표현, 비용노출 통제

STAGE_RULES
  Step 0 또는 1차의 입력·출력·승인조건

CASE_EVIDENCE
  마스킹된 기업정보, 근거대장, 녹취 인사이트, 충돌·누락 목록

APPROVED_PARENT
  대표가 승인한 Step 0 결과

OUTPUT_SCHEMA
  구조화 JSON 스키마

QA_RULES
  수치·출처·질문 10개·비용 0건·면책·다음 행동
```

### 10.2 구조화 출력

현재 Anthropic API의 구조화 출력은 `output_config.format`에 JSON Schema를 넣는 방식으로 사용한다. 모델명은 코드에 영구 고정하지 않고 환경설정으로 관리하며, 운영 전 활성 모델과 가격을 다시 확인한다.

```ts
const response = await anthropic.messages.create({
  model: process.env.ANTHROPIC_DIAGNOSIS_MODEL!,
  max_tokens: 12000,
  system: buildSystemPrompt(promptVersion),
  messages: buildCaseMessages(casePayload),
  output_config: {
    format: {
      type: "json_schema",
      schema: step1ResponseSchema,
    },
  },
});
```

SDK가 일부 JSON Schema 제약을 변환할 수 있으므로, 서버는 응답 후 `질문 10개`, `장 11개`, `근거 ID 존재`, `금액 노출 없음`을 별도로 검증한다.

### 10.3 PDF·파일 처리 방침

- 표준 PDF는 텍스트·표·이미지를 함께 분석할 수 있다.
- 암호화된 PDF는 처리 전에 사용자가 잠금을 해제한 사본을 제출해야 한다.
- PDF는 URL, base64 또는 Files API `file_id` 방식으로 전달할 수 있다.
- DOCX·XLSX는 문서 블록에서 직접 지원되지 않으므로 텍스트 또는 PDF로 변환한다.
- 대용량 PDF는 분할하고, 페이지별 출처를 유지한다.
- MVP 내부 제한은 파일당 20MB, PDF 100페이지로 두고 초과 시 분할한다.

### 10.4 Files API 보안 결정

Anthropic Files API의 업로드 파일은 같은 워크스페이스의 API 접근권한을 가진 주체가 접근할 수 있고, 사용자가 제출한 `file_id`를 신뢰하면 다른 사용자의 파일을 읽게 할 위험이 있다. 또한 Files API는 공식 문서상 ZDR 대상이 아니다.

따라서 MVP 1순위는 다음과 같다.

1. 한기평 서버에서 원본을 보관한다.
2. 마스킹·추출된 텍스트와 필요한 PDF 페이지만 API에 전달한다.
3. Files API를 사용할 경우 서버만 `file_id`를 관리한다.
4. 별도 워크스페이스·제한된 서비스키를 사용한다.
5. 처리 종료 후 삭제정책을 실행하고 감사로그를 남긴다.

### 12.2 DOCX 렌더링

JSON이 검증을 통과한 후 별도 문서 렌더러가 DOCX를 만든다.

- 맑은 고딕 단독 사용

- 자동 번호 매기기 사용 금지

- 표 폭·목차·페이지 번호 검증
- PDF 변환 후 시각검수
- 승인 전 `내부 검토용 초안` 표시

## 13. 화면 상태와 알림

| 시스템 상태 | 파트너 화면 | 관리자 화면 |
|---|---|---|
| `UPLOADED` | 자료 제출완료 | 보안검사 대기 |
| `PREPROCESSING` | 자료 판독 중 | 파일별 진행률 |
| `NEEDS_MORE_DOCUMENTS` | 보완자료 요청 | B등급·누락목록 |
| `BLOCKED` | 관리자 확인 중 | 차단사유·해제버튼 |
| `STEP0_REVIEW` | 기업진단 준비 중 | Step 0 승인대기 |
| `STEP1_GENERATING` | 기업진단보고서 준비 | 생성로그 |
| `STEP1_REVIEW` | 기업진단보고서 검토 중 | 대표 검토·수정 |
| `STEP1_APPROVED` | 승인된 범위만 열람 | 다음 단계 실행 |

## 15. 수용 테스트

1. 사업자등록증+CRETOP+녹취록이 정상 제출되면 A등급으로 판정된다.
2. 사업자등록증만 제출되면 B등급으로 판정되고 재무·신용자료 요청이 생성된다.
3. 녹취 동의 없이 음원을 올리면 분석되지 않는다.
4. 사업자번호가 다른 두 기업자료가 섞이면 C등급으로 중단된다.
5. 동일 연도 매출이 서로 다르면 두 값이 보존되고 `NUMERIC_CONFLICT`가 생성된다.
6. 1차 초안에는 11개 장과 핵심질문 10개가 존재한다.
7. 1차 초안의 숫자는 모두 근거 ID를 가진다.
8. 1차 초안에는 견적금액·성공보수·계약조건이 없다.
9. 대표 승인 전 파트너 계정으로 초안을 열 수 없다.
10. 수정본 생성 시 V1을 덮어쓰지 않고 V2를 만든다.
11. 실패한 AI 실행은 재시도해도 동일 `run_id`를 중복 처리하지 않는다.
12. 삭제정책 실행 후 외부 파일 참조와 내부 감사기록이 일치한다.

### 1순위 — 실제 파일을 AI에 보내기 전 단계

- DB 테이블 추가
- 동의 화면
- 파일 보안검사
- 자료유형 분류
- OCR·녹취 변환 인터페이스
- A·B·C 사전판정 화면

### 2순위 — Step 0 파일럿

- 근거대장
- 누락·충돌 판정
- Step 0 구조화 출력
- 대표 승인·수정·중단

### 3순위 — 1차 보고서 파일럿

- Step 1 구조화 출력

- 2차·3차·4차 산출물 확장

## 17. 리스크·유의점

- Anthropic API 키는 브라우저에 노출하지 않고 서버 환경변수로만 관리한다.
- Claude 모델명·가격·제한은 변경될 수 있으므로 운영 전에 공식문서를 다시 확인한다.
- 고객 원본을 Files API에 저장하는 방식은 별도 개인정보·보안 검토 후 결정한다.
- 정책자금·인증·세무·법률·보험 판단은 생성 시점의 공식 기준을 재확인한다.
- AI가 만든 초안은 전문가의 최종 판단이나 기관 승인을 의미하지 않는다.
- 보험상품 분석·권유 내용이 포함되면 컨설팅 보고서와 분리한다.

## 18. 그래서 지금 무엇을 해야 하는가

다음 작업은 현재 파트너 허브 코드에 `AI 진단 사전점검` 화면과 데이터 구조를 실제로 추가하는 것이다. 먼저 파일을 외부 API로 보내지 않는 상태에서 A·B·C 판정, 누락자료, 동의상태, 근거대장 화면을 가상 데이터로 구현한다. 화면과 상태 흐름을 대표가 승인한 뒤 Anthropic API 키와 실제 고객자료를 연결한다.
