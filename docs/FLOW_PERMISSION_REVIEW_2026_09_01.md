# 순차 점검 3 — 상담 FLOW 단계별 권한·중복 요청

## 점검 범위와 재현

2026-09-01 기존 상담 FLOW의 명령 21종과 API 접근 경로를 기존 테스트와 대조했다. 운영 자료 대신 가상 계정 상태·보고서·첨부·입금 기록과 메모리 DB/R2를 사용했다. 실제 연락·발송·서명·입금·유료 AI 처리는 하지 않았다.

최초 회귀 검증에서 다음 5개 경로가 수정 전 실패했다. 대표 전용 명령 12종의 파트너 거부는 처음부터 통과했다.

- 본문을 받는 동안 계정이 정지된 파트너의 확인 명령이 저장됐다.
- D1 저장 직전 계정이 정지되어도 이전 권한으로 저장됐다.
- 이미 사용한 요청 번호에 다른 명령을 담아도 성공으로 응답했다. 계정과 명령을 함께 검증하는 기록이 없었다.
- 같은 요청 번호의 보고서 본문·첨부 바이트를 바꿔도 중복 성공으로 처리했다.
- FLOW 첨부를 R2에서 읽는 동안 계정이 정지되어도 스트림을 반환했다.

추가 가상 검증에서는 AI 입력 자료를 준비하는 동안 호출 계정이 정지되어도 외부 요청 함수까지 진행되는 것을 재현했다. 외부 요청은 로컬 가짜 응답 함수로 대체했으며 실제 전송·과금은 없었다. 수정 후 이 경로의 호출 횟수는 0회다.

| --- | --- | --- |
| 근거자료 등록·불러오기·제외 | 대표만 변경, 기존 원본 보존·검토·마스킹 조건 | intake-source API, preflight, FLOW 단위 검증 |
| AI 승인·1차 생성·재시도 | 대표의 개인정보·외부 처리·비용 확인, 작업 중복 점유 차단 | FLOW API, 작업 점유·결과 검증 |

담당 계정 ID 및 `ownCases`, 첨부 시 `fileUpload`를 사용하는 기존 권한 체계를 유지했다. 동명이인·다른 파트너·정지 계정이 진행 내용을 열거나 바꾸도록 확대하지 않았다. 권한별 신규 업무 정책은 정하지 않았다.

## 보완한 동작

- 요청 본문·첨부 해시를 읽은 뒤 계정과 진행 접근 권한을 다시 확인한다. 저장 직전에는 같은 계정·담당·첨부 권한과 현재 명단을 재확인한다.
- FLOW 버전과 권한 확인에 사용한 운영 상태가 모두 일치할 때만 D1 변경을 확정한다. 기존 동시 저장 충돌 보호는 유지한다.
- 새 요청은 계정 식별값과 명령·첨부의 SHA-256 확인값을 FLOW 저장과 같은 트랜잭션에 남긴다. 갱신한 화면 버전이나 파일 재선택 시각은 확인값에 넣지 않으며, 같은 내용·첨부의 재시도는 기존 결과를 반환한다.
- 다른 계정, 변경된 명령·본문·첨부, 빠진 첨부를 같은 요청 번호로 보내면 성공으로 표시하지 않는다. 이전 배포에서 만들어져 확인값이 없는 요청 번호는 409와 새로고침 안내를 반환하며, 기존 기록을 변경하거나 임의로 재실행하지 않는다.
- 확인값과 내부 계정 식별 기록은 공개 FLOW 응답·대시보드 투영에서 제외한다. 원본 내용을 확인값 기록에 복제하지 않는다.
- FLOW 첨부 응답 직전에 계정과 첨부 연결을 재확인하고 거부한 스트림은 반환하지 않는다.
- AI 작업 점유 시 현재 권한·운영 상태를 조건부로 확인하고, 원본 준비 뒤 외부 요청 직전에 계정·작업 점유·대표 승인·근거 버전을 다시 확인한다. 거부된 호출은 자동 재시도하지 않으며 실패/보류 상태를 남긴다. 정지된 요청자에게 처리 결과를 반환하지 않는다.

보관 기간·원본 삭제 정책·DB 마이그레이션·사이트 공개 범위·연결 비밀값·AI 모델 설정은 변경하지 않았다. 기존 원본 보존과 불확실한 저장 결과 확인 경로를 유지한다.

## 최종 검증과 완료 경계

자동 테스트 183개와 격리 workerd/D1/R2 검증 110개를 통과했다. 이번 추가 검증은 FLOW API 안전성 9개, 기존에 빠진 상담 취소·서류 발송 확인 기록 2개, 네이티브 FLOW 저장·재시도·계정 경계 등 8개 확인이다. 기존 API의 재시도 검증도 실제 최초 명령과 동일한 동의·첨부를 보내도록 정정했다.

외부 요청 함수 호출 전에 재확인하지만 이미 외부로 보낸 요청의 취소·과금 취소나 이미 반환한 스트림의 회수는 보장하지 않는다. 내부 AI 결과 저장은 이미 시작한 작업의 성공/실패 기록을 잃지 않도록 유지한다. 새 요청 번호로 제출하는 의도적인 별도 입금·상담은 동일 요청 번호의 재전송과 구분한다.

브라우저 클릭·시각 QA·실제 파트너 가입·운영 고객 자료 접근·실제 발송·유료 AI 호출은 수행하지 않았다. 자동 검증은 서비스 전체 침투시험이나 실제 업무 승인 완료를 의미하지 않는다.

선행 운영 버전은 46, 소스는 `a127a12a3493e4c6541d0dacae798756935a7645`다. 최종 lint·타입검사·빌드·정확한 소스와 운영 반영·익명 접근 확인·자동 실행 일시 중지 결과는 `outputs/release/flow-permissions-deployment.json` 및 Sites 배포 이력에 기록한다. 세 점검은 여기서 종료하며 별도 요청 없이 새 후속 업무를 만들지 않는다.
