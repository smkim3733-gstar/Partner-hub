# 협업신청 임시저장 응답 검증 안전성

## 문제

협업신청 화면은 임시저장 조회·저장·비우기 응답을 타입 단언으로 적용했다. 손상된 성공 응답은 잘못된 단계·신청자 유형·서비스·상세 내용을 화면에 복구하거나, 유효하지 않은 저장 버전과 식별값을 다음 요청에 사용할 수 있었다. 비-JSON 오류 응답도 복구 안내 없이 처리될 수 있었다.

## 변경

- 조회·저장·비우기 응답을 공용 클라이언트 경계에서 JSON으로 읽고 구조를 검증한다.
- 저장 버전, 초안 식별값, 접수 식별값, 수정시각과 전체 초안 필드를 검증한 뒤 화면에 적용한다.
- 초안과 식별값, 이미 접수된 진행 식별값의 관계를 함께 확인한다.
- 저장 성공은 초안이 남은 응답, 비우기 성공은 초안이 없는 응답만 허용한다.
- 409 등 안전한 서버 오류 문구와 HTTP 상태는 유지하고, 비-JSON·손상된 성공 응답은 현재 입력 보존 안내로 차단한다.

## 유지한 운영 경계

- `/api/application-draft` 서버 계약·저장·인증·권한·동시성 제어를 변경하지 않았다.
- 기존 초안 내용·접수 진행·원본파일을 읽거나 변경하지 않았다.
- 운영 데이터·DB/R2 스키마·보관 정책, 외부 발송·유료 AI 설정을 변경하지 않았다.
- GitHub 푸시와 공개 Sites 배포는 사용자 승인 전까지 수행하지 않는다.

## 검증

- 자동 테스트: 359개 통과
- 격리 workerd/D1/R2 스모크: 129개 통과
- TypeScript `--noEmit`, 전체 lint, 프로덕션 빌드 통과
- 기존 개발 서버 `/` 응답: HTTP 200
- 검증 중 운영 쓰기·메일 발송·유료 AI·외부 요청: 각 0건
