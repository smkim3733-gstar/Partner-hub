# 상담 FLOW D1 쓰기 직전 계정 정지 경쟁 무결성

기준일: 2026-09-07

## 확인한 위험

파트너의 전사문·음성 2슬롯 업로드가 첫 R2 객체만 저장한 채 실패한 뒤 정확한 재시도를 시작했을 때, 모든 R2 쓰기와 최종 접근 검사가 끝난 직후 대표가 계정을 정지하면 정지 전 권한 상태로 FLOW와 파일 원장을 커밋할 시간차가 생길 수 있다. 반대로 이미 기록된 객체를 오류 처리에서 삭제하면 같은 예약의 안전한 복구를 막을 수 있다.

## 확인한 현재 경계

- 첫 전사문 객체 저장 성공과 두 번째 음성 저장 실패로 두 `pending` 예약이 남은 상태를 결정적으로 재현했다.
- 같은 명령 ID·본문·첨부의 정확한 multipart 재시도가 기존 예약 키에 전사문과 음성 객체를 모두 기록하고 최종 인증·담당 접근·업로드 권한 및 생명주기 검사를 통과하게 했다.
- 최종 검사에서 읽은 포털 상태 증빙을 확보한 뒤 D1 FLOW 트랜잭션 실행 직전에 실제 관리자 상태 저장 경로로 파트너 계정을 정지했다. 안정 ChatGPT 사용자 ID·회원 ID 결속은 정지 중에도 유지된다.
- FLOW 조건부 쓰기는 최종 검사에서 읽은 정확한 포털 상태 payload와 현재 D1 payload를 비교한다. 계정 정지로 값이 달라져 정지 전 권한 상태의 FLOW·명령 영수증·파일 소유권·메타데이터·객체 무결성·완료 원장 커밋을 차단하고 D1 트랜잭션 전체를 원자적으로 되돌린다.
- 응답은 내부 D1 세부정보를 숨긴 503 재시도 안내다. 기존 FLOW와 명령 영수증은 변하지 않고 두 예약은 `pending`, 두 R2 객체는 예약된 파일 ID·키·바이트를 그대로 유지한다.
- 오류 경로는 예약 객체를 삭제하지 않는다. 대표가 계정을 재활성화한 뒤 같은 명령 ID·본문·첨부로 정확히 재시도하면 같은 두 파일 ID·R2 키를 재사용해 FLOW, 명령 영수증, 두 `ready` 예약과 완료 원장을 한 번만 커밋한다.

기존 구현이 최종 계정·접근 검사 결과를 D1 조건부 FLOW 쓰기에 결속하고 파일 원장·완료 원장을 같은 원자적 트랜잭션에 묶어 요구 조건을 만족한다. 런타임 코드는 바꾸지 않고 실제 관리자 계정 정지의 D1 직전 경쟁 회귀 증거를 추가했다.
