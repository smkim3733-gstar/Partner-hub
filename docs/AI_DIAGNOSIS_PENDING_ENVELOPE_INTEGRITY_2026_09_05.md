# AI 진단 생성중 잠금 envelope 무결성 경계

기준일: 2026-09-05

## 문제

애플리케이션은 AI 요청을 보내기 전에 `result_json`에 64자 요청 지문 하나만 넣어 멱등 잠금을 만든다. 기존 D1 삽입 계약은 지문의 존재와 형식만 확인해 예상 밖 키와 과도한 JSON 공백을 포함한 큰 생성중 행을 직접 삽입할 수 있었다. 이 경우 잠금 원장의 의미와 저장 용량이 애플리케이션 계약에서 벗어날 수 있었다.

## 적용

- 생성중 잠금 직렬화 함수를 한 곳에 두고 64자 소문자 SHA-256 요청 지문만 허용한다.
- 생성중 `result_json`은 정확히 `_requestFingerprint` 한 키만 보유하고 256 UTF-8 바이트 이하로 제한한다.
- `0035_ai_diagnosis_pending_envelope.sql`과 런타임 준비의 신규 삽입 트리거가 같은 계약을 D1 직접 삽입에도 강제한다.
- 기존 생성중·완료·실패 행은 바꾸지 않고 이후 신규 잠금만 보호한다.

## 검증

- 애플리케이션 직렬화는 정상 지문을 정확한 JSON으로 만들고 대문자·길이 오류 지문을 거절한다.
- D1 직접 삽입은 추가 루트 키와 256바이트 초과 공백 JSON을 거절하며 정상 생성중 잠금은 유지한다.
- 정상 완료·실패, 멱등 재시도와 terminal 원장 보존 회귀가 유지된다.
- 36개 추가형 마이그레이션을 기존 상태가 있는 격리 D1에 반복 적용해도 기존 상태를 교체하지 않는다.
- Node 회귀 검사 641/641 통과
- 격리 workerd/D1/R2 검사 447/447 통과
- 타입검사, 전체 lint, 변경 파일 포맷, 프로덕션 빌드 통과
- 로컬 운영 Worker `/`, `/account`, `/account/setup` HTTP 200과 CSP, `X-Frame-Options: DENY`, `nosniff`, `no-referrer` 확인
- 실제 운영 쓰기, 이메일 발송, 유료 AI 요청, 외부 요청 0건
