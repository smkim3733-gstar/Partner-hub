# 파트너 계정 편집 무결성 경계

기준일: 2026-09-05

## 확인한 문제

계정관리 화면은 로그인 이메일·파트너 유형·로그인 상태·다섯 권한만 편집하고 안정 ID 기반 표시 이름 변경도 기존 서버 계약에서 지원한다. 그러나 수정 전 관리자 일반 상태 저장은 클라이언트 회원 객체 전체를 신뢰했다. 실제 `/api/state` 요청으로 연락처·소속·기수·역할·담당 수와 임의 필드를 덮어쓰고, 활성 계정을 승인대기로 되돌리거나 가짜 상태·유형·문자열 권한을 넣어도 HTTP 200이었다. 손상된 회원 구조가 이후 인증·권한·계정관리 화면에 전파될 수 있었다.

## 적용한 경계

- 초기화된 운영 상태의 기존 회원은 현재 서버 객체에서 시작해 허용된 편집값만 적용한다.
- 표시 이름은 2~40자와 제어문자 금지를 검증한 뒤 변경한다. 안정 ID 기반 진행·업무·원본 연결은 이름 변경 뒤에도 유지한다.
- 로그인 이메일은 기존 형식·대표 예약·중복 검사를 통과한 뒤 서버에서 소문자 정규화한다.
- 파트너 유형은 네 가지 허용값만 적용하고 승인대기·초대대기 계정 활성화 때 반드시 유효한 유형을 요구한다.
- 상태 전이는 승인대기·초대대기→활성, 활성↔정지만 허용한다. 활성→승인대기와 알 수 없는 상태는 거절한다.
- 권한을 변경할 때는 정확한 다섯 키가 모두 boolean인지 확인한다. 기존 레거시 계정의 불완전 권한 객체는 무관한 저장을 막지 않도록 변경 없이 보존하지만 새 손상값으로 바꿀 수 없다.
- 연락처·소속·기수·역할·담당 수·가입 출처·로그인 통계와 서버에 없던 임의 필드는 일반 저장으로 만들거나 바꾸지 않는다. 전용 가입 경로가 가진 기존 갱신은 유지한다.
- 오래된 회원 revision 요청은 기존 409 명단 충돌을 유지한다.
- 실제 운영 회원·고객 데이터, D1 스키마, R2 연결, 공개 범위, 보관·삭제 정책은 변경하지 않았다.

## 검증

- 수정 전: 비편집 필드·임의 필드와 잘못된 상태·유형·권한이 HTTP 200으로 저장되는 것을 재현했다.
- 수정 후: 비편집 필드는 현재 서버값을 유지하고 임의 필드는 제거한다. 잘못된 이름·상태 전이·상태값·유형·권한은 HTTP 403이며 상태가 바뀌지 않는다.
- 유효한 표시 이름·이메일·유형·상태·권한 편집과 기존 이름 변경 후 담당 접근은 유지한다.
- 관련 Node 테스트 86/86, 전체 Node 회귀 테스트 500/500 통과.
- 격리 workerd+D1+R2 검사 195/195 통과. 운영 쓰기·이메일·유료 AI·외부 요청은 모두 0건이다.
- 타입검사, 전체 lint, 프로덕션 빌드 통과.
- 로컬 운영 Worker의 `/`, `/account`, `/account/setup` 모두 HTTP 200.
