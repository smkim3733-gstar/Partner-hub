# 포털 레코드 ID 무결성 경계

기준일: 2026-09-05

## 확인한 문제

업무·기업자료·일정의 ID가 비어 있거나 중복돼도 관리자 일반 상태 저장이 이를 수용했다. 파트너 저장 병합은 ID별 `Map`을 사용하므로 같은 ID의 여러 신규 기록은 마지막 한 건으로 조용히 합쳐지고, 같은 ID의 기존 기록은 하나의 제출값으로 덮일 수 있었다. 화면의 업무·자료 상태 변경도 ID 기준으로 대상을 찾고 갱신하므로 중복 상태에서는 사용자가 선택한 한 기록을 확정할 수 없다.

## 적용한 경계

- 진행·업무·기업자료·일정 ID는 공백 없는 문자열이며 각 배열 안에서 고유해야 한다.
- 앞뒤 공백이 있거나 중복된 ID를 포함한 관리자·파트너 일반 상태 저장은 403으로 거절한다.
- 이미 저장된 상태가 이 조건을 위반하면 파트너 조회는 403, 관리자 조회와 일반 저장은 503으로 격리한다.
- 파트너 상태 투영 전에 같은 검사를 적용해 손상 원문이나 모호한 목록을 반환하지 않는다.
- ID 없는 레거시 타임라인은 기존 병합 키와 호환을 유지하며 이번 필수 ID 대상에서 제외한다.
- 데이터 자동 수정·중복 레코드 삭제·운영 D1/R2 조회는 수행하지 않았다.

## 검증

- 수정 전 재현: 세 배열의 공백·중복 ID 관리자 저장 200, 파트너 중복 신규 업무가 오류 없이 마지막 항목으로 합쳐짐.
- 수정 후: 공백·중복 관리자·파트너 저장 403, 손상 상태 파트너 403, 관리자 조회·일반 저장 503.
- Node 자동 테스트 515/515 통과.
- 격리 workerd+D1+R2 검사 233/233 통과.
- 타입검사, 전체 lint, 프로덕션 빌드 통과.
- 로컬 프로덕션 `/`, `/account`, `/account/setup` HTTP 200 통과.
- 실제 운영 쓰기, 메일 발송, 유료 AI 요청, 외부 요청 0건.
