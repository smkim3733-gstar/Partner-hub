# 서류 수령 → 대표 검토 간격 지표

## 목적

상담 FLOW의 추가서류 요청에서 현재 제출된 파일이 수령된 뒤 대표가 검토 결과를 기록하기까지의 상태와 시간을 대표 대시보드에 제공한다. 완료된 검토시간과 아직 끝나지 않은 검토 대기 연령을 함께 보여 주되, 식별정보나 개별 시각은 응답에 포함하지 않는다.

## 서버 기록과 최신 주기

- `receive_document`가 실제 새 파일을 연결하거나 요청을 다시 `received` 상태로 전환할 때 서버가 `receivedAt`을 기록한다.
- 이미 검토 대기 중인 같은 파일을 다시 제출한 요청은 기존 `receivedAt`을 유지한다. 응답 유실이나 단순 재시도로 대기시간이 짧아지지 않는다.
- 대표의 `review_document`는 승인과 보완 요청 모두 `reviewedAt`을 기록한다. 기존 `verifiedAt`은 승인 완료에만 계속 사용한다.
- 보완 요청 뒤 다시 제출하면 새로운 최신 검토 주기가 시작되고 이전 `reviewedAt`은 현재 상태에서 제거된다. 이 지표는 과거 모든 검토 주기의 이력 합계가 아니다.
- 서버 기록이 생기기 전의 수령·검토 건은 시각을 추정하거나 소급 입력하지 않고 `기존 기록 측정 불가`로 분리한다.

## 집계 정의

- 현재 운영 상태에 존재하며 가상 예시가 아닌 진행만 집계한다.
- 수령 대기, 대표 검토 대기, 검토 완료, 기존 기록 측정 불가, 시각·상태 이상을 서로 겹치지 않게 분리한다.
- 검토 완료는 승인과 보완 요청을 나눠 표시한다.
- 완료 소요시간은 유효한 `receivedAt → reviewedAt` 5건 이상일 때만 4시간 미만, 4~24시간, 1~3일, 3일 이상 구간으로 표시한다.
- 현재 대기 연령은 유효한 검토 대기 5건 이상일 때만 요청 시각 기준으로 같은 구간을 별도 표시한다. 완료 건과 대기 건의 공개 기준은 각각 적용한다.
- 수령 명령을 실행한 역할을 요청별로 저장하지 않으므로 이 지표를 파트너만의 인계시간으로 해석하지 않는다. 현재 추가서류의 수령 후 대표 검토 간격을 측정한다.

## 개인정보와 저장 경계

- 기존 FLOW JSON에 선택형 서버 시각 두 개만 추가한다. 별도 이벤트 표, 보관 기간, 삭제 작업을 만들지 않는다.
- 공유 FLOW 조회는 요청 상태, 파일 존재 여부, 수령시각, 검토시각만 내부 집계에 사용한다. 요청·회사·담당자·파일 ID, 제목, 수신자, 메모를 지표 경로로 가져오지 않는다.
- 응답에는 합계와 공개 기준을 넘은 거친 시간 구간만 포함하며 대표 `/api/state` 최상위에만 제공한다. 저장 상태 원문과 파트너 응답에는 넣지 않는다.
- 신청·공동분석 지표와 기존의 한 번짜리 `consulting_flows` 조회를 공유한다. 지표 실패는 운영 상태 응답과 추가서류 FLOW를 실패시키지 않는다.

## 검증 결과

- Node 자동 검사 235개 통과.
- 격리 workerd + 실제 D1/R2 검사 120개 통과.
- 타입검사, lint, 프로덕션 빌드 통과.
- 같은 파일 단순 재시도 시각 보존, 보완 요청의 검토시각, 보완 뒤 재제출 시 최신 주기 초기화, 승인 완료시각을 가상 FLOW로 확인했다.
- 완료·현재 대기 구간의 독립 공개 기준, 기존 기록과 잘못된 전환, 가상 예시와 제거된 진행 제외, 공유 조회의 민감 필드 비포함을 확인했다.
- 대표 전용 최상위 응답, 파트너·저장 상태 원문 비노출, 공유 조회 실패 시 `null` 격리를 확인했다.
- 격리 검증의 외부 요청, 운영 쓰기, 메일 발송, 외부 AI 호출은 0건이다.

## Duet 검수

Duet는 동일 파일 재제출이 대기 시작을 초기화할 위험과 완료 건만 보면 현재 적체를 숨기는 편향을 중대 의견으로 제시했다. 동일 파일·동일 대기 상태에서는 시각을 보존하고, 현재 검토 대기 연령 구간을 완료 구간과 독립적으로 추가해 모두 반영했다. 운영 진행 필터, 실패 격리와 응답 경계, 근거 줄 번호도 함께 보완했다.

네이티브 Windows에서는 Duet의 고위험 최종 차이 검토에 필요한 샌드박스 검사를 제공할 수 없어 완료 판정이 제한될 수 있다.
