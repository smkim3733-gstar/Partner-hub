# 상담 FLOW R2 쓰기 결과 불명 복구 무결성

기준일: 2026-09-06

## 확인한 위험

R2가 객체를 저장한 뒤 성공 응답이 애플리케이션에 도착하지 않으면 서버는 저장 실패로 처리하지만 객체는 이미 존재한다. 이 결과 불명 상태에서 객체를 지우거나 새 키를 만들면 저장된 증거를 잃거나 중복 객체를 만들 수 있다.

## 확인한 현재 경계

- R2 쓰기 성공 직후 응답 유실을 결정적으로 재현했다.
- 응답은 내부 저장소 오류를 숨긴 503과 동일 자료 재시도 안내만 반환한다.
- FLOW 본문은 변경하지 않고 실제 R2 객체와 `pending` 예약을 함께 보존한다.
- 새 명령 ID의 같은 첨부 재시도는 기존 파일 ID와 R2 키를 재사용한다.
- 재시도 완료 뒤 객체는 한 개만 존재하고 예약은 `ready`, 완료 원장은 실제 성공 명령 ID를 기록한다.

이 감사에서는 기존 구현이 이미 요구 경계를 만족해 런타임 코드는 바꾸지 않고 회귀 증거를 추가했다.
