# 파일 재고 FLOW 소유 원장 누락 가시성

## 결과

완료 상담 FLOW payload에 저장 키가 있는 파일 항목이 남아 있지만 D1 소유 원장이 누락된 경우에도 관리자 재고에서 사라지지 않는다. 파일은 `inconsistent`·증명 없음으로 한 건만 격리하고 전체 증명 적용 현황에서 `unavailable`로 센다. 개별 현재 R2 확인은 객체를 조회하기 전에 503으로 닫는다.

같은 소유 원장 없는 파일 ID가 여러 FLOW payload에 복제돼도 `source:id`가 같은 응답 항목을 중복 생성하지 않는다. 파일 저장 항목과 달리 저장 키가 없는 파생 `intakeFileId` 참조는 격리 파일로 오인하지 않는다. 스키마와 마이그레이션 변경은 없다.

기능 커밋은 `799d19b3a98b6abb52fe001a92b63638ece2c46d`이다.

## 수정 전 재현

- 정상 완료 FLOW 파일을 만든 뒤 테스트 전용 경계로 소유 원장만 제거했다.
- payload, 메타데이터 원장, 객체 무결성 원장과 R2 객체는 그대로 남겼다.
- 수정 전 재고는 소유 원장을 시작점으로만 FLOW 후보와 증명 적용 현황을 만들었다.
- 따라서 파일이 목록에서 사라지고 `unavailable`에도 포함되지 않았으며, 개별 존재 확인은 파일 기록이 없다는 404를 반환했다.
- 정확한 적색 회귀는 파일 재고 18건 중 17건 통과, 누락 파일의 `unavailable` 증가 기대 1건 실패로 결함을 고정했다.

## 변경

- 전체 FLOW payload의 저장 키가 있는 파일 항목 중 소유 원장이 없는 ID를 별도 격리 후보로 만든다.
- 같은 ID가 여러 FLOW payload에 있으면 한 후보로 묶고, 단일 payload일 때만 길이·형식 경계를 통과한 안전한 표시 메타데이터를 사용한다.
- 손상되거나 모호한 시각은 안전한 정렬값으로 대체하고 내부 저장 키·본문·다이제스트·요청 지문은 응답하지 않는다.
- 소유 원장 없는 payload 후보를 전체 증명 적용 현황의 `unavailable`에 한 번 포함한다.
- 같은 ID의 미완료 예약이 함께 있어도 payload 격리 후보를 우선해 동일 `source:id` 응답 중복을 막는다.
- 개별 존재 확인은 payload 파일 항목을 찾되 소유 원장이 없으면 R2 `head` 전에 원장 무결성 503을 반환한다.
- 저장 키가 없는 파생 파일 참조는 기존 연결 판정에만 사용하고 실제 보관 파일 후보로 만들지 않는다.
