# 포털 상태 메타데이터 무결성 경계

기준일: 2026-09-05

## 확인한 문제

운영 상태의 버전과 상담번호를 서버가 형식 검증하지 않았고, 파트너 명단 revision은 잘못된 값을 0으로 간주했다. 따라서 지원하지 않는 상태 버전, 음수·소수 상담번호와 명단 revision이 관리자 일반 저장을 통과할 수 있었다. 선택적 `diagnosisAssessments`도 배열 항목과 ID를 검증하지 않아 `null` 항목이 화면의 `.find`·`.map` 경로를 깨뜨리거나 중복 ID가 갱신 대상을 모호하게 만들 수 있었다.

## 적용한 경계

- 상태 `version`은 현재 지원하는 정확한 값 `1`만 허용한다.
- `consultationNumber`는 0 이상의 안전한 정수여야 한다.
- 선택적 `membersRevision`은 값이 있으면 0 이상의 안전한 정수여야 한다. 값이 없는 기존 상태는 호환을 유지한다.
- 선택적 `diagnosisAssessments`는 값이 있으면 일반 객체 배열이어야 하며, 각 항목은 공백 없는 고유 ID를 가져야 한다.
- 관리자·파트너 일반 저장의 잘못된 상태는 403으로 거절한다.
- 이미 저장된 손상 상태는 파트너 조회 403, 관리자 조회와 일반 복구 저장 503으로 격리한다.
- 클라이언트 최초 응답 검증에도 같은 숫자·진단평가 ID 조건을 적용해 손상 성공 응답을 화면 상태로 사용하지 않는다.
- 운영 데이터 자동 수정, D1/R2 조회·변경, 외부 전송은 수행하지 않았다.

## 검증

- 수정 전 재현: 지원하지 않는 버전과 잘못된 숫자·진단평가 항목·중복 ID가 관리자 저장 또는 파트너 조회를 통과했다.
- 수정 후: 조작 저장 403, 손상 상태의 파트너 조회 403, 관리자 조회·일반 저장 503.
- Node 자동 테스트 517/517 통과.
- 격리 workerd+D1+R2 검사 253/253 통과.
- 타입검사, 전체 lint, 프로덕션 빌드 통과.
- 로컬 프로덕션 `/`, `/account`, `/account/setup` HTTP 200과 화면 보안 헤더 확인.
- 실제 운영 쓰기, 메일 발송, 유료 AI 요청, 외부 요청 0건.
