# 서버 변경 요청 출처 경계 감사

## 목적

상태 변경 API가 교차 사이트 브라우저 요청을 인증·저장소 접근·외부 처리 전에 일관되게 차단하는지 점검한다.

## 점검 결과

- `Origin` 불일치와 `Sec-Fetch-Site: cross-site`를 공용 판별 함수에서 함께 검사한다.
- `Sec-Fetch-Site` 값은 대소문자와 주변 공백에 관계없이 검사한다.
- 파일 업로드, 파일 삭제, Step 0 생성의 개별 `Origin` 검사도 공용 경계를 사용한다. `Origin`이 없더라도 교차 사이트 신호가 있으면 거절한다.
- 대표 직접등록, ChatGPT 자가가입, 포털 상태 저장, 협업신청 임시저장, 원본 회수는 출처 검사를 인증·D1/R2 조회·요청 본문 처리보다 먼저 수행한다.
- 상담 FLOW 변경·대기 AI 실행과 비밀번호 가입·로그인·로그아웃·설정 경로의 기존 출처 보호를 유지하고 같은 공용 판별 규칙을 적용한다.
- 정적 회귀검사는 주요 상태 변경 라우트의 출처 검사가 민감 작업보다 앞서는지 확인하고, 라우트별 `Origin`·`Sec-Fetch-Site` 직접 파싱 재도입을 차단한다.

## 유지한 경계

- 기존 정상 동일 출처 요청과 응답 형식을 바꾸지 않았다.
- 비밀번호 경로의 HTTPS·필수 `Origin` 정책을 유지했다.
- 인증·역할·담당 계정 권한, revision/CAS, 중복 요청 보호를 바꾸지 않았다.
- D1 스키마, R2 원본, 공개 범위, 보관·삭제 정책을 바꾸지 않았다.
