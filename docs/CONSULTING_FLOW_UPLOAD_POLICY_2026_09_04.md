# 상담 FLOW 목적별 업로드 형식 정책

## 목적

상담 FLOW 화면의 파일 선택 목록과 서버의 목적·차수별 허용 형식이 서로 다른 하드코딩 목록으로 어긋나지 않도록 하나의 공용 정책을 사용한다.

## 확인된 불일치

- 3차 발표자료 화면은 PPTX·PDF만 선택했지만 서버의 1차 형식 검사는 다른 보고서 형식도 허용해 뒤 업무 규칙에서 늦게 실패했다.
- AI 근거자료 화면은 PDF·JPG·PNG·TXT만 선택했지만 서버는 DOCX·XLSX도 저장한 뒤 AI 생성 단계에서 지원하지 않는 형식으로 차단했다.
- 녹취 문서와 보조 음성, 추가서류, 서명 계약서의 화면·서버 목록이 각각 따로 선언되어 이후 한쪽만 수정될 수 있었다.

## 적용 범위

`consulting-flow-upload-policy`가 명령·보고서 차수·첨부 슬롯에 따라 목적, 허용 확장자와 화면 `accept` 값을 함께 제공한다.

| 작업 | 새 파일 허용 형식 |
|---|---|
| AI 근거자료 | PDF, JPG, JPEG, PNG, TXT |
| 1·2·4·5·6차 보고서 | PDF, DOCX, TXT, MD |
| 3차 발표자료 | PPTX, PDF |
| 녹취 문서 | DOCX, TXT |
| 녹취 보조 음성 | MP3, M4A, WAV |
| 추가 요청서류 | PDF, JPG, JPEG, PNG, DOCX, XLSX, TXT |
| 서명 계약서 | PDF, JPG, JPEG, PNG |

서버는 화면에서 선택할 수 없는 3차 DOCX, 일반 보고서 PPTX와 AI 근거자료 DOCX·XLSX를 R2 저장 전에 거절한다. 기존에 저장된 파일을 변경·삭제하거나 자동 이관하지 않는다.

## 유지한 경계

파일별 실제 내용·확장자 일치 검사, 25MB 업로드 상한, AI 근거자료 8개·합계 8MB 제한, 파일명 정규화, 인증·권한·동의, D1/R2 스키마와 보관 정책은 변경하지 않았다. 실제 고객 파일이나 운영 데이터를 사용하지 않았다.

## 재발 방지

목적·차수·문서/음성 슬롯별 허용 목록, 화면의 공용 정책 사용, 화면에서 숨긴 형식의 서버 조기 거절을 자동 테스트로 고정했다.
