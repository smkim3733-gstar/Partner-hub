# 상담 FLOW 서류 검토 효과 무결성

기준일: 2026-09-06

## 문제

`review_document` 명령은 사용자가 선택한 서류 요청을 승인 또는 보완 요청으로 검토하지만, 기존 명령 영수증에는 선택한 요청 ID가 남지 않았다. 상태 검사도 요청 한 건에 유효한 검토 결과가 생겼는지만 확인해, 첫 번째 요청을 선택한 명령의 검토 증거를 두 번째 요청으로 옮겨도 애플리케이션 경계를 통과할 수 있었다. 실패 우선 검사로 이 대상 바꿔치기를 재현한 뒤 앱과 D1에 같은 효과 계약을 추가했다.

## 적용한 경계

- 명령 영수증 `targetId`에 사용자가 선택한 요청 ID를 보존한다.
- 행위자는 논리 대표 `admin:primary`만 허용하고, 계약 체결 뒤 검토 변경은 거절한다.
- 선택 요청은 이전·현재 상태에 각각 정확히 한 건 존재해야 하며, 이전 요청은 `requested`가 아닌 실제 수령 상태와 `receivedAt`·`fileId`를 가져야 한다.
- 선택 요청의 파일은 정확히 한 건 존재하고 용도는 `requested_document`여야 한다.
- 파일 배열은 추가·삭제·재정렬·수정할 수 없다.
- 선택 요청에서는 `status`·`note`·`reviewedAt`·`verifiedAt`만 바꿀 수 있다.
- 승인 결과는 `verified`, 보완 요청은 `needs_fix`만 허용한다.
- `reviewedAt`은 서버 수정시각과 같아야 한다. `verified`는 같은 `verifiedAt`이 필요하고, `needs_fix`는 `verifiedAt`이 없어야 한다.
- 보완 요청은 비어 있지 않은 사유가 필요하며, 메모는 JavaScript `trim()`과 같은 유니코드 공백 정규형이어야 한다.
- 감사기록은 승인 시 `필수 서류 검토 완료`, 보완 요청 시 `서류 보완 요청` 문구에 정확히 결속한다.

애플리케이션 커밋 검사와 D1 트리거가 같은 계약을 독립적으로 강제한다. `0088_consulting_flow_review_document_effect.sql`은 기존 명령 영수증 대상 트리거를 추가형으로 교체해 `review_document`의 `targetId`를 필수화하고 전용 효과 트리거를 추가한다. 기존 저장 영수증은 변경하지 않고 이후 revision에 새로 추가되는 명령만 검사한다.
