# 파일 재고 교차 출처 ID 충돌 격리

## 결과

기업자료와 완료 상담 FLOW 첨부가 같은 원시 파일 ID를 가져도 관리자 파일 재고는 응답 전체를 버리지 않는다. 두 기록을 출처가 다른 독립 항목으로 유지하고 모두 `inconsistent`·`idCollision: true`·증명 없음으로 격리한다.

충돌 항목은 원시 ID만 받는 현재 R2 확인 경로와 자동 복구 대상을 안전하게 특정할 수 없다. 화면에서 두 동작을 중지하고, 서버의 원시 ID 존재 확인도 R2 접근 전에 409로 닫는다. 스키마와 마이그레이션 변경은 없다.

기능 커밋은 `3a9c7043a43eb05ab5e3d0f500d7426b7d945896`이다.

## 수정 전 재현

- 유효한 기업자료와 유효한 완료 FLOW 파일에 같은 원시 ID를 부여했다.
- 서버는 두 항목을 200으로 반환했지만 클라이언트 응답 검증기가 중복 ID로 판단해 `FileInventoryResponseError`를 발생시켰다.
- 첫 페이지 25번째와 둘째 페이지 26번째에 충돌 쌍이 걸리면 기존 `createdAt + id` 커서가 다음 출처 항목을 건너뛸 수 있었다.
- 수정 전 집중 회귀는 15건 중 14건 통과, 충돌 재현 1건 실패로 결함을 고정했다.

## 변경

- 재고 항목 식별을 `source:id` 조합으로 바꾸고 응답에 불리언 `idCollision`을 추가했다.
- D1 단일 스냅샷에서 원시 ID별 후보 수를 계산한다. 둘 이상이면 두 출처 모두 `inconsistent`, 증명 없음, 체크섬 적용 현황의 증명 불가로 분류한다.
- 키셋 커서와 정렬에 `source`를 포함해 같은 시각·같은 원시 ID의 두 출처가 페이지 경계에 걸려도 누락하지 않는다.
- 클라이언트는 같은 원시 ID가 둘 이상일 때 모든 항목이 충돌 표시를 가진 경우만 응답을 허용한다. 같은 출처와 ID의 정확한 중복은 계속 거절한다.
- 화면의 React 키, 현재 R2 확인 상태와 결과도 `source:id`로 분리한다.
- 충돌 경고를 표시하고 현재 R2 확인 버튼을 비활성화한다. 충돌은 `inconsistent`이므로 자동 복구 UI에도 들어가지 않는다.
