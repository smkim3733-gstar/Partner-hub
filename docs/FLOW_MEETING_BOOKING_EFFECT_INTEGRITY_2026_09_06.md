# 상담 FLOW 일정 예약 효과 무결성

기준일: 2026-09-06

`book_meeting` 명령을 명령 ID 기반 새 상담 일정 정확히 한 건에 결속했다. 새 일정은 종류·시작/종료시각·참석 방식·장소·메모를 정규화하고 항상 `scheduled` 상태로 시작한다. 담당 파트너가 예약하면 배정된 회원 ID, 대표가 예약하면 변경 가능한 이메일 대신 안정 신원 `admin:primary`를 생성자로 기록한다.

애플리케이션 커밋 검사와 추가형 `0081` D1 트리거는 기존 일정의 값과 순서를 보존하고 새 일정 ID·정확한 객체 필드·생성자·초기 상태를 독립 검증한다. 공동분석 후 동반 초회상담, 초회상담 완료 후 추가상담, 서류 검토와 5차·6차 준비 후 계약상담이라는 종류별 선행조건도 다시 확인하며 기존 예정 일정과의 시간 중복을 거절한다. 생성자 위조, 예약과 동시에 완료상태 주입, 선행조건 우회, 여분 일정과 기존 일정 변조는 앱 또는 D1 직접 저장 어느 쪽에서도 수락되지 않는다.

검증은 방어 전 다른 파트너를 생성자로 넣은 일정이 수락되는 실패를 먼저 재현했다. 보완 후 Node 686/686, 관련 FLOW 검사 134/134, 집중 검사 92/92, 격리 workerd+D1+R2 508/508, 타입검사, lint, 포맷, 프로덕션 빌드, 로컬 Worker 화면 3곳 200·보호 API 3곳 401과 비공개 무저장 헤더를 통과했다. 검증 중 운영 데이터 쓰기·메일·유료 AI·외부 업무 API 호출은 0건이다.
